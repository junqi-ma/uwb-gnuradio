# QM35 实时解调起点问题与当日进度（2026-08-11）

## 1. 当前结论

X410 接收链路、65/48 PDU 重采样和 GNU Radio 解调器已经能够稳定产出
FCS 正确的 QM35 数据包，但实时结果仍受前导启动瞬态影响。当前问题不是计算速度
不足：失败测试中的 demod 队列高水位为 1、无丢包，失败集中为
`timing_failed`，且失败通常在约 20 us 内结束。

今天已经完成 detector 精相关坐标修正、弱 SYNC 周期回溯，以及 timing 强峰捕获与
真实帧起点的坐标分离。最终版本已通过定向 QA，但用户要求停止继续测试，因此
**最终坐标分离版本尚未重新执行 X410 1 秒硬件验证**。

## 2. MATLAB 对照基线

同一条 X410 737.28 MS/s 采集链路已经由 MATLAB `acceleration` 分支验证：

- 中心频率：6489.6 MHz；
- 原始格式：SC16，737.28 MS/s，10 ms；
- 处理：65/48 重采样到 998.4 MS/s；
- DW1000 配置：code 10、256 SYNC、Decawave SFD；
- 结果：检测 20 包，其中 19 包 FCS 通过；
- 首包位于采集边界，只包含 62 个有效重复，属于采集启动瞬态。

详细逐包结果见仓库根目录的 `X410_737.md`。这证明 RF 采集数据和 MATLAB 完整
解调链路本身是成立的，GNU Radio 侧的问题应继续用 MATLAB 的相关坐标、CIR 和
解扰语义作为基准定位。

## 3. 今天完成的解调修复

### 3.1 DW1000 / MATLAB 语义对齐

- BPRF scrambler 初始状态改为依赖 preamble code index，分别支持 code 9 和
  code 10；未知 code 明确失败，不再静默使用 code 9。
- CIR 重复区间按 MATLAB `acceleration/estimateCir.m` 的显式 skip 语义处理：
  从 `cir_skip_initial_repetitions` 开始取 `cir_repetitions`，不再错误地固定取
  最后若干个重复。
- SFD 搜索从单窗口扩展为 4 个不连续的小窗口：expected、expected−1T、−2T、
  −3T。各窗口仍执行 stride=8 的粗搜和全采样率细化，不进行大范围连续暴力相关。
- runtime profile 与结果元数据补充 code index、preamble repetitions 和 CIR
  配置，便于硬件测试确认实际运行参数。

### 3.2 detector 精相关坐标修正

旧 detector 使用 `fir_filter::filterN` 做 Region 内精相关，再把其卷积输出位置当成
尾随相关的 symbol-end 坐标。在重复 SYNC 波形上，错误坐标可能被相邻重复周期
偶然抵消，导致合成测试看似正确，但对弱首个 SYNC 和真实启动瞬态不可靠。

当前实现改为与 MATLAB 定义一致的前向归一化点积：

```text
metric(j) = |sum(rx[j+k] * conj(template[k]))|^2
            / (sum|rx[j+k]|^2 * sum|template[k]|^2 + epsilon)
```

其中 `j` 直接表示 SYNC 起点，不再经过 FIR symbol-end 坐标换算。相关只在 coarse
peak 附近的有界 ROI 内执行，scratch 在构造阶段预分配；`work()`/热路径没有新增
动态分配，也没有退化为全 Region 全速率相关。

### 3.3 弱启动 SYNC 回溯

detector 先以 0.5 门限确认强 SYNC，随后按一个模板周期向前回溯：

- 回溯半径：±8 原生率样本；
- 弱 SYNC 门限：0.2；
- 最多回溯：3 个周期；
- 任意一步不满足门限立即停止。

PDU 新增诊断字段：

- `start_metric`：回溯后最早 SYNC 的相关度；
- `start_backtracked_symbols`：实际向前回溯的周期数。

### 3.4 强捕获 seed 与真实起点分离

第一次硬件验证表明，直接把弱 SYNC1 写入 `predicted_start_sample` 会使 timing
首次捕获失败，因为 timing 的正常捕获门限为 0.3。最终采用两个坐标：

- `start_sample`：detector 回溯得到的真实 SYNC1，用于决定截窗起点；
- `predicted_start_sample`：0.5 门限确认的第一个强 SYNC，用于 timing 首次捕获。

timing 先在强 seed 的 ±64 样本范围内捕获，再以 0.7×正常门限最多回溯 3 个
周期。对回溯出来的初始弱 SYNC，peak tracking 同样使用放宽门限；进入强 SYNC
区间后恢复正常 0.3 门限。

## 4. QA 与构建结果

最终坐标分离版本已通过以下定向测试：

- `uwb_qa_uwb_detector.cc`；
- `uwb_qa_uwb_detector_sc16.cc`；
- `uwb_qa_uwb_demod_core.cc`；
- `uwb_qa_uwb_realtime_demodulator.cc`。

新增回归用例构造前两个 SYNC 的归一化相关度为 0.25、第三个及以后为强峰，验证：

- FC32 与 SC16 detector 的 `start_sample` 回到真实 SYNC1；
- `predicted_start_sample` 保留在强 SYNC3；
- `start_backtracked_symbols == 2`；
- timing 从强 SYNC3 捕获后回溯两个弱 SYNC，并继续跟踪完整 64 个重复。

完整 CTest 在最终坐标调整前执行过一次：12 项中 11 项通过。唯一失败为已有的
PDU resampler 性能门槛测试，复测约 369 PDU/s，低于硬编码的 400 PDU/s / 2×
200 slot/s 门槛；该测试的重采样数值、端到端 FCS 均通过，失败与本次 detector
功能路径无关。最终版本停止前只重跑了上述 4 项定向 QA，尚未再次跑完整 CTest。

## 5. X410 实测记录

测试配置统一为：6489.6 MHz、737.28 MS/s、gain 60 dB、TX/RX0、code 9、
64 SYNC、4z2 SFD。

### 5.1 弱 SYNC1 直接作为 timing seed 的版本（已被最终设计替代）

1 秒结果：

| 指标 | 数值 |
|---|---:|
| detector regions | 194 |
| resampler recv / emit / drop | 194 / 194 / 0 |
| demod recv | 187 |
| success / FCS pass | 103 / 103 |
| timing_failed | 84 |
| demod queue high watermark | 1 |
| worker utilization | 10.8% |

所有成功包的 PSDU 长度均为 54，载荷一致且 FCS 正确。84 个失败全部为
`timing_failed`，median demod 时间约 18 us，证明不是队列或计算能力不足。

### 5.2 0.2 秒诊断

第一次诊断：40 个 detector PDU，36 个结果，18 success/FCS、18
`timing_failed`。失败包的回溯数分布为 1/2/3 均有，成功包也有相同分布，说明
不能简单用“回溯次数过多”解释失败。

第二次诊断：40 个 detector PDU，35 个 demod 接收，收到 33 个结果，其中
15 success/FCS、18 `timing_failed`。detector 的相邻原生率 seed 间隔稳定在约
3,686,440 样本，符合约 5 ms 周期；成功包的 timing 起点与 65/48 映射后的强
seed 只差约百个样本量级。

诊断最终确认：周期检测稳定，主要错误是把弱首 SYNC 同时当作 timing 的首次捕获
seed。随后已实现 §3.4 的坐标分离，但停止前没有再次连接 X410 验证。

## 6. 当前阻塞与下一步

当前不是外部阻塞，而是验证尚未闭环。下一次继续时按以下顺序执行：

1. 用最终坐标分离版本运行 0.2 秒诊断，确认 timing 首次捕获使用强 seed，且
   `start_sample` 仍指向回溯后的 SYNC1。
2. 运行 1 秒正式测试，记录 detector/resampler/demod 数量、FCS、各失败阶段、
   queue high watermark 和 worker utilization，并与 103/187 基线对比。
3. 若 `timing_failed` 仍高，保存失败 PDU，比较强 seed 周围在 737.28 MHz 与
   重采样后 998.4 MHz 的归一化相关度，确认是否为重采样映射/群时延问题。
4. 让 PDU resampler 保留 `start_metric` 和 `start_backtracked_symbols`，避免硬件
   诊断依赖临时旁路 sink。
5. 在空闲机器上复跑完整 CTest；单独记录 resampler 性能门槛波动，不要把数值
   正确/FCS 通过与主机瞬时吞吐断言混为一谈。
