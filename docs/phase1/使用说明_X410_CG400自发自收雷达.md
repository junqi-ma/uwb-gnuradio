# 使用说明：X410 CG400 自发自收雷达

> 入口脚本：[`gr-uwb/apps/x410_cg400_hrp_echo_cir.py`](../../gr-uwb/apps/x410_cg400_hrp_echo_cir.py)
> 分支：`feature/uwb-monostatic-radar`
> 本机 UHD 无法 `import` 时先看 [`../本机UHD_DPDK_AVX512问题与绕过.md`](../本机UHD_DPDK_AVX512问题与绕过.md)

这是 **自己发、自己收** 的单站雷达。TX 时刻已知，不要并联能量门 Detector
或 `UwbScheduledExtractor`。听外部 QM35 请用 `x410_auto_scheduled_capture.py`。

## 1. 链路

```text
UwbHrpPacketSource          # 998.4 MS/s，code 9，64 SYNC，4z2
  → 32/65 一次下采样        # 491.52 MS/s CG400 原生
  → TimedUhdEcho            # 同一时间基上定时 TX + RX 突发
  → PDU 65/32               # 升回 998.4
  → UwbRadarCirEstimator
  → UwbCirWriter            # 可选 UDP 送 CIR taps
```

CIR 必须留在 998.4 MS/s。CG400 的 ±245.76 MHz Nyquist 比 BPRF 略窄，
65/32 补不回前端丢掉的带沿。

定时突发下 `predicted_sfd` 每发相同（本机 67741 @998.4）。干净 1000 发的
检出 SFD 恒为 predicted+5；有 DW3000 时预测仍锁死，但旧 SFD 门控会
`sfd_failed`。默认 **按预测时刻估 CIR**（`--require-sfd` 才搜 SFD）。

## 2. 硬件

| 项 | 值 |
|---|---|
| FPGA | **CG_400**（原生 491.52 MS/s，不是 UC200 737.28） |
| 地址 | QSFP `sfp1`，默认 `addr=192.168.20.2` |
| TX | 前方面板 ch1 = UHD ch0 / `TX/RX0` |
| RX | 前方面板 ch4 = UHD ch3 / `RX1` |
| 载波 | 6489.6 MHz |
| 增益 | TX 40 dB，RX 50 dB |

```bash
uhd_usrp_probe --args "addr=192.168.20.2"
```

确认镜像是 CG_400，TX/RX 速率为 491.52e6 且未被 UHD coercion。

## 3. 软件前提

在仓库根目录运行。需要已构建的

```text
gr-uwb/build/python/uwb/bindings/uwb_python*.so
```

本机构建 **`ENABLE_UHD_BACKEND=OFF`**：C++ 不链 UHD。射频只走 PyUHD。
Debian 的 `python3` 默认找不到 `/usr/local/.../site-packages`，脚本会自己
补 `PYTHONPATH` 和 DPDK 绕过目录。

本机每次开机后先准备 UHD 绕过（`/tmp` 重启即丢）：

```bash
python3 gr-uwb/apps/prepare_uhd_eal_noret.py
```

无设备时用仿真复刻同一条链：`gr-uwb/apps/uwb_sim_cg400_echo_cir.py`。

## 4. 运行

8 脉冲闭环（默认 20 Hz）：

```bash
python3 gr-uwb/apps/x410_cg400_hrp_echo_cir.py \
  --args addr=192.168.20.2 \
  --gain-tx 40 --gain-rx 50 \
  --cal-delay-native 334 \
  --sfd-search-margin 128 --sfd-threshold 0.12 \
  --sync-refine-margin 32 --sync-refine-threshold 0.02 \
  --tail-guard-us 24 \
  --no-udp \
  --output /tmp/x410_radar_8p
```

100 Hz × 10 s（本机已 1000/1000）：

```bash
python3 gr-uwb/apps/x410_cg400_hrp_echo_cir.py \
  --args addr=192.168.20.2 \
  --rate-hz 100 --duration-s 10 \
  --gain-tx 40 --gain-rx 50 \
  --cal-delay-native 334 \
  --sfd-search-margin 128 --sfd-threshold 0.12 \
  --sync-refine-margin 32 --sync-refine-threshold 0.02 \
  --tail-guard-us 24 \
  --no-udp \
  --output /tmp/x410_radar_100hz_10s
```

`--rate-hz` 会覆盖 PRI：`PRI = 1/rate`，`pulses = round(rate × duration)`。

落盘原生 RX 窗时加 `--dump-sc16`（`capture.iq` + `capture.jsonl` +
`tx_491p52.sc16`）。去掉 STS 时加 `--no-sts`。

## 5. 必须盯住的参数

| 参数 | 建议 | 说明 |
|---|---|---|
| `--sfd-search-margin` | **128（现为默认）** | 8192 时估计器约 181 ms/帧，UDP 会掉到约 5 pkt/s |
| `--code-index` | **9** | preamble code（9/10/11/12）。TX 波形与 CIR 模板必须一致 |
| `--preamble-length` | **64** | SYNC 前导重复数（32/64/128/256/512/1024）。旧 `--sync-reps` 为别名，另外接受 2048 |
| `--cal-delay-native` | **334** | 泄漏峰校准。线性脉冲群时延约 16 native，峰约 `peak_tap=22` |
| `--pulse-shape` | 默认 `linear` | `testdata/uwb_hrp_tx/pulse_trunc_linear_rc183_240.f32` |
| `--no-udp` | 只落盘时加上 | 否则默认发到 `133.133.133.132:12345` |
| `--est-queue` | **64** | 不要设成脉冲数；过大时估计器滞后会被当成“无丢包” |
| `--require-sfd` | 默认关 | 雷达默认用定时回波时刻估 CIR，不搜 SFD。加上则恢复旧门控 |

校准锁在 ±2 样本后不要把 margin 开回 8192。

## 6. 产物与退出码

| 文件 | 内容 |
|---|---|
| `cir.cf32` / `cir_norm.cf32` | 每脉冲 116 tap（16 零延迟前 + 100 后） |
| `cir.jsonl` | `pulse_id`、`status`、`peak_tap`、metric |
| `summary.json` / `echo_timing.jsonl` | 突发计数、PRI、late |
| `--dump-sc16` | `capture.iq`、`capture.jsonl`、`metadata.json`、`tx_491p52.sc16` |

成功退出 **0**。定时 late、CIR 缺号或写盘失败为 **3**。

本机 100 Hz × 10 s 口径：1000/1000 突发、1000/1000 CIR、`pulse_id` 连续、
TX 间隔 10.000 ms。泄漏/弱耦合 metric 约 0.017，不是电缆环回金样。

## 7. 把 CIR 送到另一台机器

对端：

```bash
python3 gr-uwb/apps/cir_udp_recv.py --bind 0.0.0.0 --port 12345
```

本机去掉 `--no-udp`，或 `--udp-host <ip> --udp-port 12345`。

每脉冲固定发一帧（含 SFD 失败）：28 字节 `UCR1` 头 + 116 个 `complex64`
taps（失败时 taps 为 0）。对端应按 **UDP 总速率** 和 **ok 速率** 分别看。
射频 `echo_ok=1000` 只表示定时突发成功，不是 CIR/UDP 成功。运行中每秒一行
`live ... cir_ok_hz=... cir_fail_hz=... est_drop=... udp_hz=...`。

默认不用 SFD 门控时，DW3000 不应再把 CIR 打成 `sfd_failed`；`udp_hz` 与
`cir_ok_hz` 都应接近 PRI。CIR 上会叠干扰能量，主峰仍对准泄漏/目标时延。
若 `est_drop` 增加，是估计器跟不上。加 `--require-sfd` 才恢复旧门控。

纯软件回环 `uwb_radar_cir_udp.py` 仍走旧的 `socket_pdu` taps-only。

## 9. 运行时频率扫描 / 手动跳频（CFO 干扰研究）

入口：`gr-uwb/apps/x410_cg400_hrp_echo_cir_sweep.py`。它 import 基础脚本
复用整条 CIR 链，只在突发之间改 TX/RX 中心频率。**TX 与 RX 同步平移同一
Δ**：自回波相对 CFO 恒为 0，DW3000 相对 X410 的 CFO 就等于 Δ。

`--freq-mode`：

| 模式 | 行为 |
|---|---|
| `fixed`（默认） | 只用 `--freq`，与基础脚本一致 |
| `scan` | 从 `--freq-start`（默认 `--freq`）按 `--freq-step` 递增到 `--freq-stop`，每点 `--freq-dwell` 发；默认**单次**扫完即停（`--freq-scan cycle` 循环） |
| `manual` | 运行时从 stdin 输入频率，下个 burst 边界生效并保持 |

单次扫描示例（±2 MHz，步进 1 MHz，每点 20 发）：

```bash
python3 gr-uwb/apps/x410_cg400_hrp_echo_cir_sweep.py \
  --args addr=192.168.10.2 \
  --freq-mode scan \
  --freq-start 6487.6e6 --freq-stop 6491.6e6 --freq-step 1.0e6 \
  --freq-dwell 20 \
  --rate-hz 100 --duration-s 10 \
  --gain-tx 40 --gain-rx 50 \
  --no-udp \
  --output /tmp/x410_sweep_pm2mhz
```

`scan` 单次模式下 `pulses = n_freq × dwell`，会覆盖 `--pulses`（只作告警）；
`--rate-hz` 仍设 PRI。上例会打印频率表并自动收尾。

手动跳频（跑到输入 `q` 为止）：

```bash
python3 gr-uwb/apps/x410_cg400_hrp_echo_cir_sweep.py \
  --args addr=192.168.10.2 \
  --freq-mode manual --pulses 0 \
  --gain-tx 40 --gain-rx 50 --no-udp \
  --output /tmp/x410_manual_hop
```

命令（交互输入）：

```text
+50              相对标称 +50 kHz（裸数字默认按 kHz）
491              相对标称 +491 kHz
+5MHz            相对标称 +5 MHz（显式单位）
-10e6            相对标称 -10 MHz（科学计数法按 Hz）
6489600kHz       绝对频率 6.4896 GHz
6489.6MHz        绝对频率
off +1MHz        显式偏移
status / ?       打印当前目标频率
q                结束运行
```

**裸数字默认单位 = `--freq-unit`（默认 `khz`）**；带单位后缀
（`GHz/MHz/kHz/Hz`，大小写不敏感）或科学计数法时以显式为准。
`--freq-settle-s`（默认 0.05 s）是每次 retune 后到下个定时突发的间隔。

频率计划/命令解析在无 GR/UHD 依赖的 `echo_cir_freq_plan.py`，单测：

```bash
python3 gr-uwb/apps/test_freq_plan.py
```

`--dry-run` 只打印频率序列，不开 UHD。

**产物**：`echo_timing.jsonl` / `freq_sweep.jsonl` 每脉冲带 `freq_hz`、
`freq_offset_hz`、`tx_freq_actual`、`rx_freq_actual`、`dwell_index`；
`summary.json` 增加 `freq_mode` 和逐频表 `cir_by_freq`（按 `pulse_id` join
`cir.jsonl`，每频点 `n/ok/fail/metric_mean/metric_max`）；`--dump-sc16` 时
`capture.jsonl`/`metadata.json` 也带频率。纯 Python，无 C++ 改动。

**注意**：

- 每次 retune 会重新对时（`now + --freq-settle-s`），所以 `--freq-dwell`
  别设 1；100 Hz 下建议 ≥20 以摊薄 retune 开销。
- `--cal-delay-native` 是固定频点校准，扫频时群时延可能随 LO 微漂 1–2
  样本（主峰会移动）；必要时加 `--require-sfd`。
- 频点超设备范围会保留旧频点并计数 `freq_retune_fail`（非 0 则退出码 3）。
- 尚未做实机扫频 soak 验收，也未做 DW3000 逐频干扰结论。

未声称：200 pps soak、C++ `UhdBurstBackend` 生产验收、与 MATLAB CIR 逐 tap
对照。实测记录见
[`测试报告_X410_CG400_HRP定时CIR_100Hz.md`](测试报告_X410_CG400_HRP定时CIR_100Hz.md)。
