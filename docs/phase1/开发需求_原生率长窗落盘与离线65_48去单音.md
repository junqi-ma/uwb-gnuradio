# 开发需求：原生率长窗落盘 + 采集后 C++ 离线 65/48 与去单音

> 日期：2026-08-19
> 分支：`feature/native-long-dump-offline-resample`
> 主线入口：[`../../开发状态.md`](../../开发状态.md)
> 状态：**需求规划，尚未实现**

本文只规划两件事：

1. 采集热路径允许 **737.28 MS/s 原生 SC16 长窗落盘**，同时实时 65/48 仍只吃 QM35 短窗。
2. 采集结束后，根据解调结果 **自动调用 C++ 工具**：去单音，再把选定 IQ 重采样到 998.4 MS/s。

不在本需求内：SIC、RFNoC、改 QM35 周期、把连续 host 65/48 拉回实时、硬件 soak 验收。

## 1. 背景与问题

当前唯一把“解调 + 写盘”接在同一张图上的是
[`testdata/offline_qm35_auto_lock.py`](../../testdata/offline_qm35_auto_lock.py)。
`--write-sc16` 会把 extractor 几何从解调默认

```text
10 + 190 + 4.1 µs = 204.1 µs   (7373 + 140083 + 3023 @737.28)
```

改成落盘默认

```text
300 + 190 + 100 µs = 590 µs   (221184 + 140083 + 73728 @737.28)
```

然后 **同一条** SC16 PDU 同时进 `UwbPacketWriter` 和
`UwbPduRationalResamplerCcf65_48`。Writer 本身不重采样；FIR 却对整段 590 µs
做 65/48。生产档 `quality_minorder`（每相 H=42）隔离实测大约：

| 窗 | FIR | handler（含 PDU 发布） | 相对 5 ms 槽 |
|---|---:|---:|---|
| 204 µs | 1.6 ms | 2.4 ms | 余量约 2× |
| 590 µs | 4.8 ms | 7.4 ms | **超槽，X410 overflow** |

X410 上已验证：实时解调、不落盘可以通过。一开落盘 overflow，根因是
**FIR 窗被写盘开关放大**，不是磁盘 348 MB/s 写不动。

设计本意（[`下一步_锁定后SC16截取与DW1000头尾预留.md`](下一步_锁定后SC16截取与DW1000头尾预留.md)）
已经写过：落盘走原生 SC16，不要把 65/48 放进写盘热路径。实现没有拆开。

去单音目前只在 Python
[`testdata/cancel_capture_tone.py`](../../testdata/cancel_capture_tone.py)：
按窗拟合 CW，**原地覆盖** `capture.iq`，不留 raw。采集后升到 998.4 也只在
Python/MATLAB `decode_scheduled_sc16_dump`，不会在采集结束时自动跑。

## 2. 目标链路

```text
实时（必须在 5 ms 槽内完成）
  SC16 @737.28
    → Auto/Scheduled extractor
         锁定后截 590 µs 原生窗（300/190/100，可配置）
    → 同一条 SC16 PDU
         ├─ UwbPacketWriter     整窗直写 capture.iq + capture.jsonl
         └─ crop 到 10/190/4.1  → PDU 65/48 → RealtimeDemod
              → schedule_feedback / 解调结果落盘

采集结束（不占 UHD 热路径）
  自动调用 C++ 工具
    读 capture.iq + capture.jsonl + 解调结果
    按窗去单音（不改 raw 文件）
    按解调信息选择升采样范围
    65/48 → 998.4
    写出独立产物 + 报告
```

约束：

- 写盘热路径禁止 65/48，禁止 SC16→CF32→再量化。
- 实时 FIR 禁止吃 590 µs 整窗。`CaptureOnly` 只裁输出，不算少算力，不能当本需求的实现。
- 737.28 raw 必须保留；去单音和 998.4 是派生文件。
- 坐标域不得混用。落盘和下标是 737.28；升采样后按下式映射到 998.4：

```text
map(p) = round((p · 65 + (T − 1) / 2) / 48)
```

`T` 为所用 taps 长度（生产 `quality_minorder` 为 2707）。

## 3. 需求 1：采集路径允许原生率长窗落盘

### 3.1 几何拆开

extractor 与解调不再共用一套 pre/post。

| 角色 | 默认几何 @737.28 | 用途 |
|---|---|---|
| 落盘窗 | 300 / 190 / 100 µs（221184 / 140083 / 73728） | Writer 整窗 SC16 |
| 解调窗 | 10 / 190 / 4.1 µs（7373 / 140083 / 3023） | 65/48 之前的 crop |
| acquisition | 现有能量门短窗（pre=2032） | 不加 300 µs 头 |

`--write-sc16` **只打开 Writer**，不得再改 extractor 的解调几何，也不得把
resampler 的输入换成 590 µs。

允许显式覆盖：

```text
--dump-pre / --dump-capture / --dump-post     落盘窗
--demod-pre / --demod-capture / --demod-post  解调 crop
```

缺省值分别取上表。`capture`（QM35 体）两边默认都是 190 µs，不要为干扰去拉长。

### 3.2 接线

推荐实现（二选一，QA 必须覆盖）：

**A. extractor 出长窗 + crop 适配（首选）**

```text
ext.packet  → writer
ext.packet  → UwbPduWindowCrop（或 resampler 新增 native-crop）
                 按 predicted_start 切
                 [pred − demod_pre, pred + demod_capture + demod_post)
            → UwbPduRationalResamplerCcf65_48
            → demod
```

crop 在 **SC16 域、升采样前** 完成。输出 PDU 更新
`window_start_sample` / `pre_guard_samples` / `capture_samples` /
`post_guard_samples` / `sample_count`，`predicted_start_sample` 不变。
窗首被夹到 0 时允许缩短 pre，并记 status。

**B. extractor 双端口**

`packet` 出解调短窗，`dump` 出落盘长窗。语义清楚，但 scheduled core 要维护
两套窗或一次截长窗再拷短切片。若走 B，长窗仍只 memcpy 一次，短窗是切片而非
第二次从流里截。

禁止：为写盘把 extractor 默认几何改成 590 µs，再把同一 PDU 送进 65/48。

### 3.3 脚本与入口

必须改：

- `testdata/offline_qm35_auto_lock.py`
- 后续接到同一闭环的
  `gr-uwb/apps/x410_auto_scheduled_capture.py --identity demod`
  （今天 x410 路径还没接 65/48 + demod + writer）

`x410_scheduled_capture.py`（已知 t0、RFNoC 998.4）不是本需求主路径；不要把
737.28 长窗契约抄到 998.4 域。

Writer 队列仍为 16。590 µs × 200 slot/s ≈ **348 MB/s**。必须打印
`packets_written` / `packets_dropped` / `queue_high_watermark`。drop > 0
视为采集失败，不得进入需求 2 的自动后处理。

### 3.4 解调结果一并落下

采集结束时写出与 `capture.jsonl` 可按 `packet_id`（及
`schedule_index`）对齐的解调旁路文件，供需求 2 使用。建议：

```text
DIR/demod_results.jsonl
```

每行至少：

```text
packet_id
schedule_index
status
fcs_pass
detected_start_sample      # 998.4 域（resampler 输出）
predicted_start_sample     # 998.4 域
native_predicted_start     # 737.28 域，来自 extractor
native_window_start
resample_us
t_total_us
```

实时解调失败的 slot 仍按 EverySlot 写原生窗；jsonl 里保留
`status != success`。后处理不得丢这些窗的 raw。

### 3.5 需求 1 验收

- 不提供 t0 时仍能锁，再写盘。
- 开 `--write-sc16` 时：Writer 窗 = 590 µs 原生 SC16；resampler 输入样点数 =
  解调短窗（acquisition 除外）。
- 关写盘时：行为与现网短窗实时解调一致。
- `capture.iq[offset:offset+N]` 等于源流 `[window_start, window_end)`（去单音前）。
- 30 s 离线 200 slot/s：writer 0 drop；X410 短测无 UHD overflow（时长先 5–10 s）。
- 相关 CTest 通过。

## 4. 需求 2：采集后 C++ 重采样 / 去单音工具

### 4.1 形态

独立 C++ 可执行文件，不走 GNU Radio `work()`，不接 UHD。

建议路径：

```text
gr-uwb/apps/uwb_offline_postprocess_dump.cc
安装名：uwb_offline_postprocess_dump
```

纯算法放进不依赖 GNU Radio 的 core（与 `RationalResampler65_48Core` 同层），
例如：

```text
gr-uwb/include/gnuradio/uwb/uwb_tone_canceller.h      # 单音估计与相减
gr-uwb/include/gnuradio/uwb/uwb_scheduled_dump_io.h   # jsonl + 交错 SC16 读写
```

FIR 复用已有 `core::RationalResampler65_48Core`。禁止再实现一套 65/48。
禁止在后处理里调 Python `cancel_capture_tone.py` 充当生产路径。

### 4.2 输入

| 文件 | 必需 | 说明 |
|---|---|---|
| `DIR/capture.iq` | 是 | 737.28 交错 LE int16 I/Q，未去单音 |
| `DIR/capture.jsonl` | 是 | 落盘几何与 `file_offset_samples` |
| `DIR/demod_results.jsonl` | 否 | 有则按解调信息选窗/写映射；无则整窗处理 |
| taps | 默认 | `testdata/resampler_65_48/taps_quality_minorder.txt` |

命令行最小集：

```text
uwb_offline_postprocess_dump DIR
  [--center-hz 6489.6e6]
  [--tone-rf-hz 6256.640e6]          # 已知则跳过粗搜
  [--tone-search-hz 80e6]
  [--select all|fcs_pass|scheduled]
  [--emit full|qm35]                 # full=整段落盘窗；qm35=只升解调短窗
  [--taps quality_minorder|PATH]
  [--skip-notch]
  [--dry-run]
```

缺省：`--select all --emit full`，做去单音 + 整窗 65/48。  
`--emit qm35` 用 jsonl 的 `predicted_start` 切 10/190/4.1（与实时 crop 同一套常量）。

### 4.3 根据解调信息做什么

解调结果是 **索引和种子**，不是改 raw 几何的理由。

| 解调字段 | 后处理用途 |
|---|---|
| `packet_id` / `schedule_index` | 与 jsonl 对齐 |
| `fcs_pass` / `status` | `--select fcs_pass` 时只升成功槽；raw 仍全部保留 |
| `native_predicted_start` | `--emit qm35` 的切点；映射 998.4 的 `predicted_start` |
| `detected_start_sample`（998.4） | 写入输出 jsonl，供 MATLAB/`decode_uwb` 当 seed |
| 无解调文件 | 不筛选，不写 detected_start |

后处理 **不重新跑** `UwbRealtimeDemodulator`。解 998.4 产物仍用现有
`decode_scheduled_sc16_dump.py/.m`。

### 4.4 去单音算法

与 `cancel_capture_tone.py` 对齐，必须按窗，因为 `capture.iq` 是拼接的非连续窗，
CW 相位不能跨窗当连续时间。

1. 用第一幅足够长的 `scheduled`/`provisional` 窗估频：
   在 `tone_rf − center` 附近 ±`search` 做 FFT 峰，再做相关细化。
   若调用方给出 `--tone-rf-hz`，可跳过粗搜，仍允许小范围细化。
2. 对每个窗独立：复系数
   `c = ⟨x, s⟩ / N`，`s[n] = exp(j 2π f n / fs)`，`y = x − c s`。
   `n` 从 **本窗起点** 计（与现脚本一致），不要用 `window_start` 当全局连续时间，
   除非后续证明跨窗相位连续（当前 dump 不连续）。
3. 量化回 int16 时 clip；统计 clip 计数。
4. 已知实测 CW：LO 6489.6 MHz 时 RF **6256.640 MHz**（基带约 −232.96 MHz）。
   回归用该值。

默认 **不覆盖** `capture.iq`。去单音后的 737.28 若需要落盘，写
`capture_notch.iq`（可选，`--keep-native-notch`）。生产默认只把去单音当作
65/48 前的内存步骤，减少一份 348 MB/s 磁盘。

### 4.5 65/48

- 每个窗：SC16→CF32（可用 VOLK）→ `reset` + `process` + `flush` → 契约
  `Lout = ceil(((N−1)·65 + T)/48)`。
- 默认 taps：`quality_minorder`。
- 输出默认 **CF32** `capture_998p4.cf32`（与 MATLAB `decode_uwb`、现有 golden
  一致）。若需要 SC16，另加 `--out-format sc16`，量化方式与 Writer 相同并写
  `iq_scale`。
- 同步写 `capture_998p4.jsonl`，字段：

```text
packet_id, schedule_index
sample_rate = 998400000
sample_format
file_offset_samples
sample_count                 # 998.4 域
window_start_sample          # map(native window_start)
predicted_start_sample       # map(native predicted)
pre_guard_samples, capture_samples, post_guard_samples   # 均已 map
detected_start_sample        # 来自解调，已是 998.4；缺失则省略
tone_baseband_hz, tone_coef_re, tone_coef_im
input_native_sample_count
```

`file_offset_samples` 按输出文件计。

### 4.6 自动调用

`offline_qm35_auto_lock.py --write-sc16 DIR` 以及未来的 x410 解调+写盘脚本，
在 `tb.wait()` 且 Writer `packets_dropped()==0` 之后调用该工具。

- 默认开启后处理；`--skip-postprocess` 可关。
- 工具非 0 退出：采集仍算 raw 成功，脚本以警告退出码（建议 4）区分
  “锁+写盘成功、后处理失败”，避免毁掉已落盘的 737.28。
- `--dry-run` 只打印将处理的窗数、几何、taps，不写大文件。

### 4.7 需求 2 验收

- 合成单音 + QM35 短流：估频误差与 Python 参考在细化精度内；单音 bin 抑制与
  `cancel_capture_tone.py` 同量级。
- 同一窗：C++ 65/48 与 `RationalResampler65_48Core` / golden
  `max_abs` 不超过现有 PDU QA（约 1e-6）。
- 去单音后再升采样，QM35 FCS 不低于“仅 Python 去单音再
  `decode_scheduled_sc16_dump`”的对照（mixed / clean 0.5 s 抽样）。
- `capture.iq` 字节与后处理前 bit-exact（默认不覆盖）。
- jsonl 的 998.4 `predicted_start` 等于 `map(native predicted)`。
- CTest：tone core、jsonl 读写、crop、oneshot 65/48、与 Python 单窗对照。
- 0.5 s mixed 100 窗后处理在本机可跑完；不要求实时。

## 5. 明确不做

- 实时路径对 590 µs 做 65/48。
- 用 `CaptureOnly` 冒充升采样前 crop。
- 连续流 host 65/48。
- 后处理里解 DW1000 / 做 SIC（只准备 998.4 IQ + 坐标）。
- 覆盖或删除 raw `capture.iq`。
- 把本需求写成 X410 盲捕获 / soak 验收通过。

## 6. 实现顺序

1. **Crop 块或 resampler 升采样前裁切** + QA（短/长窗、夹到 0、acquisition 不裁成 300 µs）。
2. **拆 `offline_qm35_auto_lock.py` 几何**；开写盘时断言 resampler
   `total_input_samples / pdus` ≈ 解调窗长。
3. **写出 `demod_results.jsonl`**。
4. **C++ tone core + dump IO + 65/48 oneshot 工具** + QA。
5. **脚本在写盘成功后自动调用**；`--skip-postprocess`。
6. mixed / clean 0.5 s 回归：raw bit-exact、后处理 FCS、与 Python 去单音对照。
7. 有余量再接到 x410 `--identity demod`。

## 7. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 热路径 FIR 窗 | 始终 QM35 短窗 | 单帧 ~2.4 ms，5 ms 槽内已通过；长窗 ~7.4 ms 会 overflow |
| 落盘窗 | 590 µs 原生 SC16 | 头尾留给离线 DW1000 / SIC |
| 升采样前裁切 | 必须在 SC16 域 | `CaptureOnly` 不减 FIR |
| 后处理语言 | C++，复用 65/48 core | 与生产 FIR 契约一致；避免再维护一条 Python upfirdn |
| 去单音位置 | 737.28、按窗、升采样前 | dump 非连续；与现网 Python 算法一致 |
| raw 文件 | 不覆盖 | 可回放、可对照 bit-exact |
| 998.4 默认格式 | CF32 | 对接 `decode_uwb` / golden |
| 解调信息 | 选窗 + 写 seed，不重解 | 实时已经解过 QM35；离线工具只做 IQ 变换 |
