# CG600 737.28 MS/s 实时 CIR 锁定测试报告

> 设备：X410 serial 2607179，FPGA 珞光 `CG_600`，UHD 4.6 + DPDK
> 主机：i7-12700，20 逻辑核
> 结论：**737.28 实时 CIR 已锁定**。根因是 CG600 的校准延迟默认值偏小
> ~0.80 µs，把整个 SYNC 顶出了 CIR 窗；修正为 `1092.5` native 后，
> `peak_tap` 稳定在 16，`metric_mean` 从 ~7.8e-4 提升到 **7.0e-2**。

配套：DPDK 启用见 [`../DPDK_X410_CG600启用.md`](../DPDK_X410_CG600启用.md)。

## 1. 症状

`x410_cg400_hrp_echo_cir.py` 在 CG600 / 737.28 下：

- `cir ok` 100/100，但 `peak_tap` 在 **0..115 随机游走**，`metric_mean`
  ~5e-4..2e-3（CG400 同一链 ~5e-2）。
- DPDK 修好 TX 吞吐后依旧（说明与 TX underflow 无关）。
- Python / cpp-pdu 两后端、`legacy`/`linear`/`minphase` 三脉冲、
  `--cal-delay-native 460..610` 扫描都不恢复。

## 2. 方法：采 100 帧离线分析重采样后信号

采集（DPDK 干净 TX，落 native RX 窗 SC16）：

```bash
sudo -E python3 gr-uwb/apps/x410_cg400_hrp_echo_cir.py \
  --use-dpdk --mgmt-addr <RJ45> --dump-sc16 --pulses 100 \
  --output /tmp/opencode/cg600_rx100
```

离线重采样（与 PDU 65/48 block 契约逐样本一致，golden 验证 ≤2.4e-7）：

```python
h = np.fromfile("testdata/resampler_65_48/taps_quality_minorder.txt", np.float32)
y = upfirdn(h, sc16_native/32768.0, 65, 48)     # 737.28 -> 998.4 work
```

关键测量（100 帧）：

| 量 | 结果 |
|---|---|
| SYNC 周期(work) | **精确 1016**（周期度 0.77） |
| CFO | **+24.5 kHz**（每重复相位 +0.157 rad） |
| SYNC 码相位相对预测原点 | **恒为 801 work 样点**（100 帧 std=0） |

`estimate_radar_cir` 对 k=10..63 的重复窗做相干平均、再与理想码相关，
其相关窗只覆盖 tap 0..115。SYNC 在 801，**根本不在窗内** → CIR 是噪声
（`peak/uniform≈2`）。把原点移到 SYNC 处后：

| origin | peak_tap | peak/uniform |
|---|---|---|
| 2704（旧默认） | 30 | 2.20（噪声） |
| 3505（`+801`） | **16** | **14.17** |

## 3. 根因

`cir_origin = window_start + pre_guard + round(cal_work)`，`cal_work`
由 `--cal-delay-native` 经 65/48 映射而来。CG600 的默认是**按率缩放**
CG400 的 334 → 501 native，但 CG600 有 **÷4 DDC**（CG400 无 DDC），
DDC/抽取路径多出 **~0.80 µs** 群时延。

修正：`cal_native = 501 + 801·48/65 = 1092.5` native。

## 4. 修复与实测

`default_cal_delay_native()` 现在按固件给默认值：

| 固件 | native rate | 默认 cal (native) |
|---|---|---|
| CG400 | 491.52 MS/s | 334 |
| **CG600** | **737.28 MS/s** | **1092.5** |

默认运行（DPDK，100 脉冲，`--preamble-length 128 --gain-tx 50 --gain-rx 60`）：

```
native_rate=737.3 MS/s (cg600) ... cal_delay_native=1092.5
radio_ok=100 cir_ok=100 cir_fail=0
peak_tap_min=16 peak_tap_max=16
metric_min=0.0640 metric_max=0.0731 metric_mean=0.0710
```

对照：

| | 修前 | 修后 | CG400 基线 |
|---|---|---|---|
| `peak_tap` | 0..115 游走 | **16（恒定）** | — |
| `metric_mean` | 7.8e-4 | **7.1e-2** | ~5e-2 |

## 5. 备注 / 后续

- `1092.5` 是**当前前端接线**下测得的值；换天线/线缆会改，用 sweep app 的
  `--peak-target-tap` 首峰 servo 在运行中精修。
- CFO +24.5 kHz 仍在（重复间相位漂移 0.157 rad）。当前 54-rep 相干平均
  因此只有 ~0.46 相干增益；若后续要拉高 SNR，可在平均前按重复做相位
  去旋转，或增大 `--publish-native` 后单独估计 CFO。
- 本报告只声明 **CG600 737.28 实时 CIR 锁定**；硬件 soak / overflow
  重捕获仍未做。
