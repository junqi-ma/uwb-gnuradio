# 下一步：锁定后按 QM35 周期截取 SC16，并预留头尾解 DW1000

> 日期：2026-08-14
> 主线入口：[`../../开发状态.md`](../../开发状态.md)
> 状态：**离线已实现**（mixed 0.5 s 100/100 bit-exact）。X410 live dump 未做。

## 1. 目标

`UwbAutoScheduledExtractorSc16`（或已知 `t0` 的 `UwbScheduledExtractorSc16`）
在确认 QM35 并进入 scheduled 之后，把每个雷达 slot 的原生 SC16 窗口落到磁盘，
窗口在 QM35 体前后各留一段，使重叠的 DW1000 整包仍落在同一窗内，便于离线
解调干扰、对照 MATLAB，以及后续 SIC。

目标链路：

```text
SC16 @737.28 MS/s
  → Auto/Scheduled extractor（锁定后 EverySlot）
  → 原生 SC16 PDU
  → UwbPacketWriter（capture.iq + capture.jsonl）
```

可选并行（不经过写盘）：

```text
同一 SC16 PDU → PDU 65/48 → UwbRealtimeDemodulator → lock_obs
```

## 2. 现有能力与缺口

已有、可直接复用：

- 锁定后只按 `t0+kT` 截窗，不再对每个通信包建能量 Region。
- 窗口几何已是 `pre + body + post`；native 默认 `7373 + 140083 + 3023`
  （10 µs + 190 µs + 4.1 µs）。
- SC16 extractor 发出 `s16vector` PDU，**不做**连续流 SC16→FC32。
- `UwbPacketWriter` 已接受 `s16vector`，按字节直写，不再 CF32 再量化。

当前不够用的地方：

| 缺口 | 说明 |
|---|---|
| 默认护栏太短 | 10 µs / 4.1 µs 盖不住一条 DW1000。实测干扰流 256 SYNC / 12 B / 6.81 Mbps，空中时间约 270～300 µs，周期约 513 µs。头尾不够时，重叠包的 preamble 起点落在窗外，无法解调。 |
| 自动提取器元数据缺几何 | `UwbScheduledExtractorSc16` 已写 `pre_guard_samples` / `capture_samples` / `post_guard_samples`；`UwbAutoScheduledExtractorSc16` 的 scheduled PDU 目前没有这三项。 |
| Writer JSONL 丢坐标 | Writer 只落 `start_sample` / `trigger_sample` / `pre_trigger_samples`。后续解 DW1000 需要保留 `window_start_sample`、`predicted_start_sample`、pre/body/post。 |
| 生产脚本未接写盘 | `offline_qm35_auto_lock.py` 只验证锁定与解调，没有 native SC16 dump。 |

本步**不是** SIC，也不是对全部 DW1000 做持续解调。只改截窗几何和落盘契约。

## 3. 窗口几何

坐标域：native 737.28 MHz。禁止把 998.4 的样点数直接拷过来。

```text
window = [predicted − pre, predicted + body + post)
T      = 5 ms = 3_686_400 native samples
```

当前 dump 默认（头按整包 DW1000，尾按“收完从 t0 起的那条”）：

| 段 | 时间 | native samples | 用途 |
|---|---:|---:|---|
| pre | 300 µs | 221184 | 覆盖“起点在 QM35 之前、仍压在前导上”的整条 DW1000 |
| body | 190 µs | 140083 | 现有 QM35 体，不要为了干扰去拉长 |
| post | 100 µs | 73728 | 收完一条从 t0 起算 ≤290 µs 的 DW1000（290−190） |
| 合计 | 590 µs | 434995 | 远小于 5 ms，相邻雷达窗不会重叠 |

`pre`/`post` 必须可配置。先测再固化：用已解调的 974 包起点和 PHR/PSDU 长度估
空中时间，取 P99 + 余量，不要拍脑袋超过一个 DW1000 周期（约 513 µs）。

头尾是**同一窗内的连续 IQ**，不是另开 detector 对通信包建 Region。

## 4. 落盘契约

- 格式：交错 little-endian int16 I/Q，每复样点 4 字节；`sample_rate=737280000`。
- 默认一个 `capture.iq` + `capture.jsonl`。`one_file_per_packet` 只给短调试。
- 禁止 dump 前做 65/48；禁止 SC16→CF32→再量化回 SC16。
- 锁定前的 acquisition PDU 一并写入（首个确认包要可回溯）。
- collision / FCS fail 的 slot 仍按 EverySlot 写盘。

JSONL 每行至少包含：

```text
packet_id
window_start_sample
predicted_start_sample
pre_guard_samples
capture_samples
post_guard_samples
sample_count            # = pre + body + post（文件头被夹到 0 时除外）
sample_rate             # 737280000
sample_format           # "sc16"
iq_scale                # 原生 SC16 用 PDU 自带值，缺省 32768
schedule_index
lock_state / capture_mode
```

读回切片：

```text
qm35  = iq[pre : pre+body]
head  = iq[0 : pre]          # 解起点在雷达之前的 DW1000
tail  = iq[pre+body :]       # 解伸出雷达之后的 DW1000
```

DW1000 解调仍走现有 PDU 65/48 + `UwbRealtimeDemodulator`（code/SYNC/SFD 按
发射配置，不能用 QM35 默认）。可以离线对 `head∥body∥tail` 整窗做，不必在写盘
热路径上解调干扰。

## 5. 带宽与队列

200 slot/s × 434995 × 4 B ≈ **348 MB/s**。当前 204 µs 窗大约 120 MB/s。
原先对称 300 µs 尾约 466 MB/s；CIR 只依赖前导，尾部不必再留一条完整 DW1000。

- 目标盘按 NVMe 估，不要默认机械盘。
- Writer 队列仍是 16 槽；窗变大后必须报 `packets_dropped` / `queue_high_watermark`。
- 验收：200 slot/s 连续写、0 drop、队列不持续爬升。时长先 30 s 离线，再 10 min。

若盘或 host 写不过，只缩小 `pre`/`post`，不要改回连续流落盘，也不要把 65/48
搬回热路径。

## 6. 实现顺序

1. 从现有 737.28 DW1000 捕获量出空中时间，写入 `uwb_defaults.h` 的 native
   interference 护栏常量（与 10/190/4.1 µs 的 QM35 默认分开）。
2. Auto extractor 的 scheduled / acquisition PDU 补齐 pre/body/post。
3. Writer JSONL 原样落下第 4 节字段；`s16vector` 继续直写。
4. 离线脚本：`offline_qm35_auto_lock.py` 增加 `--write-sc16 DIR`，锁定后
   双接 Writer；mixed 文件上核对窗 IQ 与源文件逐样本一致。
5. QA：合成 QM35 + 前后各一条 DW1000，窗长、坐标、IQ 切片和 JSONL 字段断言。
6. 有余量再接 X410 live dump。硬件 soak / overflow 重捕获仍按方案 §18，
   不因本步写盘完成而宣称盲捕获验收通过。

## 7. 验收

- 不提供 `t0` 时仍能先锁再写。
- 每个 slot 一个 native SC16 窗；通信包不额外增窗。
- `capture.iq[offset:offset+N]` 等于源流 `[window_start, window_end)`。
- JSONL 能单独切出 head / QM35 body / tail。
- 窗内完整落入的 DW1000 可用现有解调路径 FCS pass（至少合成 + mixed 抽样）。
- 200 slot/s 写盘 0 drop（先离线）。
- 相关 CTest 通过。
