## 2. M0.1：首批实际开发任务

### A. 配置、profile 与 frame 的唯一来源

1. 先补会失败的测试：原配置/getter/caps 修改不得影响运行快照；PHR=0.85 + data=6.81
   必须接受；现有调制器未实现的高 PHR 速率必须拒绝。
2. 由 frame profile 定义 header、timestamp 数量/宽度、PSDU/FCS 预算；
   当前 v1 固定 14 B，禁止测试再独立维护 7 B 常量。为 wire session ID 定义范围/映射。
3. 加配置→codec→FCS→modulator 的交叉测试，覆盖 Poll/Response/Final 和两端角色；
   同时校验 frame bytes、sample count、timeout/reply budget，没有静默缩窄或截断。
4. C++ 作为执行时权威 validator，经 pybind 暴露；Python 保留便于使用的构建接口。
   若短期保留纯 Python validator，必须共用 profile 数据并对相同 JSON 语料逐项比较
   接受/拒绝、理由和 effective 值，不能仅比较枚举或扫描源文件字符串。
5. 将配置解析、JSON、描述性字符串与逐包类型隔离；避免继续扩充 5000 行单头和
   另一套 5000 行 Python 平行实现。重构只移动职责，保留 API/序列化兼容测试。

### B. 时间数学

1. 区分绝对设备 ticks、相对 interval、API 整数 ns；ToF 禁止使用有损 ns 投影。
2. 把半周期严格边界、wrap±fraction、同 tick 分数排序写成独立小向量。
3. ToF 只接收已经验证的 RMARKER/天线参考面时间；原始 sample timestamp
   必须先经过显式映射、质量判决和校准。记录 planned/scheduled/measured 来源。
4. 定义时间率、量化与舍入规则，测试 int64 极值、浮点转换上界、校准跨零/回绕。
   不把设备 time unit 与 vendor UUS 混用。

### C. 能力和工程交付

1. 能力分级记录 work/native/ToA/hardware/vendor 五类证据；保留当前 fail-closed，
   尚未验证的 128 等长度继续拒绝，但拒绝理由标为当前实现限制。
2. 为同一测试矩阵记录 source revision/工作区 hash、库实际路径、编译器、VOLK、
   测试命令、seed、输出 hash。生成 CSV 默认写 build/test-output，可显式导出到仓库。
3. 注册 Python QA、安装四个头和 Python 模块；用临时安装前缀做外部消费测试。
4. 正确设置 CTest 的库路径；性能项串行运行。历史吞吐失败单列追踪，
   不修改门槛使其变绿，不将新增功能失败归为历史问题。
5. 修订开发报告、设计契约、调度说明和状态入口，解除已被反例否定的“冻结事实”。

## 3. M1：纯 C++ 数学与状态机

### M1-A 数学核心

- 明确 `kAB = fA/fB`；SS 将 B 域回复间隔转换到 A 域后做
  `(RA - kAB*DB)/2`，结果单位明确为 A ticks，再按 A 的频率换秒。
- DS 四个间隔必须先进入明确且一致的单位，才使用
  `(RA*RB - DA*DB)/(RA + RB + DA + DB)`。区分 nominal rate、实际漂移与结果误差，
  不在不同设备的原始 tick 单位间直接套公式。
- 使用相对间隔规避巨大绝对 epoch 消减；乘法考虑溢出和数值稳定性。
  保留负 ToF 原值及失败理由，分母异常、过期 clock ratio、域错误显式失败。
- 独立 MATLAB oracle 从明确的物理传播/时钟模型生成输入与真值，覆盖正负 ppm、
  非对称延迟、跨 wrap、长回复与小 ToF。已有 MATLAB 环境可用时必须实际运行并保存对照；
  Python 高精度参考可辅助，但不把未运行的 MATLAB 脚本写成验证完成。

### M1-B 状态机与 fake 双端点

- 输入值类型事件：RxFrame、TxAccepted/TxFailed、Deadline、Cancel、Overflow、Reset。
  输出：ArmRx、ScheduleTx、TerminalResult；协议 core 不调用 UHD/PMT/系统时钟。
- RxFrame 必须含 FCS 状态及 timestamp 质量；只在地址、session、seq、类型、状态
  全部匹配时推进。两端只看各自事件和接收帧，fake 传输层才持有传播真值。
- delayed Response/Final 先确定量化后的 TX 时刻，再填入 frame；提交失败、设备 late
  和 underflow 都使该 exchange 失败。不能在未知发射时刻时先发送帧内 timestamp。
- 单独测试丢包、乱序、重复、过期回复、停止/取消、重启新 epoch、队列满、慢消费者。
  接受请求数必须等于终态数加在途数；重试有明确 attempt 身份。
- 固定容量状态与 frame storage；格式化/文件 I/O 留在非实时消费端。

完成后提供 Python 配置→两个 fake endpoints→结构化结果的可运行示例。
独立协议核心不依赖 GNU Radio scheduler/UHD；controller 另行适配。

## 4. M2：先证实完整 PHY，再承诺硬件回复预算

### Native PHY 与前导修复

先用既有 `NativeRateProfile.tx_native()` 建立短帧离线参考：
`codec → HRP work IQ → 48/65 或 32/65 → native IQ → 现有 RX resampler → demod`。
实际经过转换后才升级 native evidence。控制器热路径需要 C++、可复用 scratch 的实现，
不把逐包 NumPy/SciPy 复制引入实时回复。

CFO 改为仅拟合实际测得的有效相关峰，明确有效索引/权重；补 64/128/256、
0/正/负 CFO、SNR、多径测试。结合 `UWB_demodulation/` 核对 PHR 的前导时长语义、
RX 边界与长度推断，不用固定 `skip=24` 的副作用决定永久 capability。
暂以 64 SYNC 作为阶段一候选基线，16 不在 ToA 验证前用于测距。

### 时间链和延迟预算

- 从 UHD metadata 保留整秒/分数或精确 ticks，避免先转大 double 秒。
- 明确 raw RX sample → crop/resampler → SFD/PHR → RMARKER → first path →
  antenna plane 的转换，每步记录 offset、率、量化、校准及有效性。
- 分数首径必须在强后径/低 SNR 下能判无效，不能简单把最大 CIR tap 插值当成首径。
- delayed TX 模板复用必须考虑 timestamp 对 FCS/FEC/scrambler/调制数据的影响；
  完整重编码可先作为正确性参考，再按 profiling 优化，不能只改已调制波形中的几个位置。
- 回复预算使用相同 marker：帧尾剩余时间 + RX/解码 + FSM/构帧 + 编码/转换 +
  transport + device lead + margin。分别采集分布及最坏观测值，保留超时失败策略；
  主机 P99 延迟不能证明硬实时保证。

## 5. GNU Radio 集成与性能保护

新增 block 前先查本地 GNU Radio 同类 block，写明 scheduler、所有权、生命周期。
controller 可采用 `gr::block + io(0,0,0)`、短 handler、单 owner 线程。
输入/输出通路必须有容量和背压约束，stop/cancel 能唤醒 worker，禁止 handler 内阻塞 UHD。

| 路径 | 约束与测量 |
|---|---|
| IQ 热路径 | 延续现有候选窗口检测，禁止为 TWR 新增全速全相关；保持现有 VOLK/SIMD 路径 |
| 配置/快照 | 只在配置或 exchange 边界复制；解析、JSON、hash 不进入逐样本路径 |
| Packet buffers | 记录每段 producer max burst、consumer cap、队列深度、in-flight 数；统一 PSDU/sample 上界，超限显式失败 |
| 内存复制 | 列出 codec/FCS/调制/work→native/SC16/UHD/RX-PDU 每次分配和复制；优先复用固定容量 buffer，明确借用数据的生命周期 |
| SIMD | 优先测 SC16转换、缩放、FIR、相关等已有向量路径；小帧 FSM/ToF 标量计算不作为优先 SIMD 对象 |
| stream buffers | 对实际 stream edge 检查 item size、history、forecast、output_multiple、min/max noutput/buffer；PDU 以 bytes/samples/queue capacity 管理，不套用不存在的 stream min/max 配对 |
| 性能门槛 | 同硬件、同构建、同数据和线程/VOLK配置，串行比较旧 radar/TX/RX 的吞吐、CPU、RSS、复制量；TWR 另记 deadline 余量和失败率 |

先保存同环境性能基线再改 hot path；允许的性能浮动根据重复测量噪声明确记录，
不可用不同负载环境的数字声称“无回退”。M0.1 的契约修复应主要留在配置和小包边界。
