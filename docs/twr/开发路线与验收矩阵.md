## 2. 代码组织建议

在实现设计时确认最终类名，建议新增独立文件：

- `gr-uwb/include/gnuradio/uwb/uwb_twr_{types,config,frame,core,timestamp}.h`。
- `gr-uwb/include/gnuradio/uwb/uwb_twr_controller.h` 与 `lib/uwb_twr_controller.cc`。
- radio adapter 复用 `uwb_uhd_burst_backend` 的可复用部分，增加双端资源和 RX 路由；
  不复制整个 radar app，也不直接把 radar echo FSM 扩展成多协议混合状态机。
- `gr-uwb/python/uwb/` 与 `bindings/` 增加类型化 API；CLI/config 复用同一校验逻辑。
- `gr-uwb/apps/x410_twr.py`、双端本机/商用对端示例；`testdata/twr/` 放短向量、
  配置、校准样例、frame golden 与 MATLAB verifier。
- 独立测试 `qa_uwb_twr_{frame,core,timestamp,controller,e2e}`，以及 Python 配置测试。

芯片 adapter 只负责 vendor frame/config/timestamp 语义。测试框架的 USB/SPI 远端
控制可单独实现，不让外部模组固件成为 GNU Radio 库构建的强制依赖。

## 3. 协议与时间 QA 矩阵

| 维度 | 必测内容 | 关联需求 |
|---|---|---|
| 两端隔离 | 私有 RX/TX timestamps 不可互读；删除空口帧后应答不能继续 | SCOPE-02、PROTO-01 |
| 帧 | 正确/错误 FCS，地址/类型/序号，畸形长度，byte order，协议版本 | PROTO-01/06 |
| 算法 | SS 补偿方向；DS 不等回复时间；极小 ToF 与长 turnaround 的数值稳定性 | PROTO-02/03 |
| 时钟 | 不同 epoch/rate、正负 ppm、漂移、40/32 位或 profile 对应回绕、reset | TIME-01/04 |
| PHY | 完整 Poll/Response/Final，code/preamble/SFD/profile 组合，首径与强后径 | PHY-01、TIME-02/05 |
| 时序 | 每包 RX delay/timeout，TX 提前量边界、量化、晚提交、TX async 错误 | API-02、GR-04、ERR-01 |
| 故障 | 丢 Poll/Response/Final/Report，乱序、重复、过期 retry、RX overflow | QA-02 |
| 生命周期 | configure/start/stop/restart/cancel，队列满及慢消费者 | LIFE-01、GR-03 |
| 校准 | 标定集/验收集分离，延迟符号、避免重复补偿、过期 calibration | CAL-01 |

## 5. 精度、性能和完成门槛

在 M0 建立待冻结表，M3 上板前冻结第一阶段目标，M5 前冻结第二阶段目标：

| 指标 | 当前状态 | 报告方式 |
|---|---|---|
| 距离范围与场景（有线/LOS） | 待用户目标与硬件预算确定 | 近/中/远至少 3 点，校准集之外验证 |
| bias、RMSE、P95/P99 绝对误差 | 待时间戳预算与精度目标确定 | 按协议/角色/profile/距离分组，包含仪器不确定度 |
| 首径/异常判决 | 正确识别无效测量为硬要求 | 单列错误有效距离，不能只统计成功帧的均值 |
| 请求频率、成功率、reply delay 下限 | 待 profile/host 时序预算确定 | 所有请求为分母，原始失败和重试后成功分别统计 |
| 持续运行 | 建议每单元 ≥1000 次、≥10 min | 队列、RSS 无持续增长，停止无死锁，结果数守恒 |
| deadline 处理 | 不得静默即时补发 | 失败显式可追踪；报告时间裕量分布和错过次数 |
| 数值一致性 | 复用已知 golden，新增 TWR oracle | MATLAB/C++ timestamps、ToF、帧逐项对照 |

对量化误差、首径拟合、时钟误差、校准和射频链路分别列时间误差预算，汇总为距离
误差门槛；不以提高时间戳存储位数或数字插值率证明物理测距精度。
任何门槛仍为“待定”的阶段只能报告已完成子项，不能报告整阶段验收通过。
