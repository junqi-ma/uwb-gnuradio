## 1. R7：把"证明了什么"和"没有证明什么"拆开

### 1.1 复核基线（本代理独立核对，非引用报告）

`testdata/twr/phy_matrix_737280000.csv`：

| 项 | 实测值 |
|---|---|
| 行数 | 318 |
| `path` 唯一前缀 | 全部为 `work_direct_998p4*`（318/318） |
| `result` 分布 | PASS 283 / FAIL 25 / ERROR 3 / **NOT_RUN 7** |
| `whitelist` 分布 | supported 196 / unsupported 115 / unverified 7 |
| 去重后 (code, SYNC, SFD) supported 组合 | **48** |
| `native_rate_hz` | 317 行 `737280000`；**1 行 `491520000`（NOT_RUN 标签行）** |

结论：318 行证明的是**998.4 MS/s work grid 上本仓库 TX/RX 自洽**。
`native_rate_hz` 是**能力行所挂的键值（目标设备速率）**，不是"曾把帧下采样到该
速率再上采样回来"的证据。ToA、硬件、vendor 三类证据**一行也没有**。

### 1.2 五级证据模型

新增 `gr-uwb/include/gnuradio/uwb/uwb_twr_capability_evidence.h`（独立、header-only、
只依赖 C++ 标准库，**不 include 也不修改** B2 正在编辑的 `uwb_twr_config.h`）。

级差**单调且累积**：达到高级别即隐含所有低级别（每一级都以低级为前提）。

| 级别 | 含义 | M0 是否达成 |
|---|---|---|
| `work_decode_verified` | 本仓库 work grid（998.4 MS/s）上 modulate → loopback → demodulate，字节精确 FCS 通过 | **是，全部 196 个 supported 行** |
| `native_roundtrip_verified` | 帧确实经过 native 速率往返（work→native→work），重采样器与其时间映射受测 | **否，0 行** |
| `toa_verified` | 首径/TOA 精度对照独立 oracle 测量 | **否，0 行** |
| `hardware_verified` | 真实硬件实测，记录 FPGA/UHD 版本与时钟源 | **否，0 行** |
| `vendor_interop_verified` | 对**具名模组**实测，记录 SDK/固件 hash 与帧字节 | **否，0 行** |

**fail-closed 保持不变**：`allows()` / `explain()` 对任何高于既达级别的用途一律
拒绝，理由里同时写出缺哪一级、该去哪里测；没有默认、没有回退到 radar/QM35。

一行可以"work decode verified"而**显式不声称 ToA**：
`not_established_list()` 把未达级别写成数据（`;` 分隔），落在 CSV 的
`evidence_not_established` 列里，不是注释。

### 1.3 CSV 新增列

`phy_matrix_<rate>.csv` 与 `phy_matrix_whitelist_<rate>.csv` 各追加 6 列
（顺序由 `evidence_csv_columns()` 单一来源给出）：

```
evidence_level, evidence_source, evidence_not_established,
evidence_kind, reject_scope, reject_scope_note
```

样例（supported 行，16 SYNC）：

```
...,work_decode_verified,testdata/twr/phy_matrix_737280000.csv#work_direct_998p4,
native_roundtrip_verified;toa_verified;hardware_verified;vendor_interop_verified,
measured,,measured_fcs_pass_byte_exact_on_work_grid_998p4_only_native_toa_
hardware_and_vendor_remain_unverified
```

**已验证的兼容性**：把新 CSV 与仓库已提交的旧 CSV 逐列比对，
**84 行 key 全同，且所有原有列逐字节相同**（`diffs: []`）；
48 个 supported 组合、supported 行 `reject_scope` 全为空。
即：只追加列，不改任何既有数据。

### 1.4 拒绝理由改写为"当前软件实现限制"

R7 要求 128/256/512/1024/2048 的拒绝措辞是**当前软件实现限制**，不是硬件结论。

`reject_scope` 取值（`reject_scope_current_software()` 等）：

| reject_scope | 适用 |
|---|---|
| `current_software_implementation_limit` | 128/256/512/1024/2048、1/2/4/8 SYNC 等本 build 解码器/配置限制 |
| `out_of_scope_phase1` | STS（REQ-SCOPE-04） |
| `not_measured` | 7 个 NOT_RUN 行 |
| `this_build_api_contract` | code 13、reps 100 等本 build API 边界 |
| （空） | supported 行 |

`reject_scope_note` 对 128/… 携带**厂商引用**，并显式写明
`not_a_hardware_claim_qorvo_supports_these_lengths_...`：

- Qorvo DW1000 / DW3000 **确实支持**这些长度；
  依据 DW1000 API Guide v2.7 §5.12 `txPreambLength`，
  以及 DW3xxx API Guide PDF pp. 32–34（其 preamble 枚举含 128/256/512，
  列为 non-standard preamble lengths）。
- 真正失败的是**本仓库解码器**：`uwb_demod_core.h` 只重测最后
  `max(cfo_min_fit_repetitions, 40)` 个 SYNC，而 `cfo_skip_initial_repetitions`
  固定 24，合成零相位峰进入相位拟合（128 SYNC 实测 -16209 Hz，1024 实测 -19901 Hz）；
  另外 `mod::encode_phr19` 把长度映射到 4 值 preamble-duration index。
- 措辞已改为 "refused by this build only"，**不再出现 "structurally
  impossible"**；`qa_uwb_twr_phy_matrix.cc` 文件头注释同步改写
  （§"sync_repetitions whitelist" 段）。

### 1.5 既有 318 行 CSV 能否免重测补列？——能

`derive_row_evidence()` 是**纯函数**，输入只用旧 CSV **已有**的字段
（`path` / `result` / `whitelist` / `sync_repetitions`），不读新列。
因此已提交的 318 行 / 84 行文件**无需重跑任何一次测量**即可补齐证据列。

实测分级结果（对已提交 CSV 逐行套用）：

```
196  work_decode_verified / measured / (无 reject_scope)
112  none / measured / current_software_implementation_limit
  6  none / not_measured / not_measured
  3  none / measured / this_build_api_contract
  1  none / not_measured / out_of_scope_phase1
```

supported 行的级别集合 = `{work_decode_verified}`，唯一。
对应的纯函数性由
`twr_phy_matrix_evidence_annotation_is_pure` 断言（含同输入同输出、
6 列顺序、supported 行的 4 个未达级别列表）。

新增 sidecar `phy_matrix_provenance_<rate>.txt`，与 CSV 同目录，记录 R7 要求的

### 2.4 该测试实际抓到的两个真实缺陷（不是走过场）

1. **新写的两个头自身缺 `<cstddef>`**：`uwb_twr_capability_evidence.h` 里
   `<array>` 在 `<cstddef>` 之前。仓库内构建时别的头先包含了 `<cstddef>`，

全量 `ctest -N` 中出现为 `#48`。

### 3.2 库路径：改在注册处，不依赖操作者 shell

复核发现的问题：GrTest 生成的 `<test>_test.sh` 里是
`export LD_LIBRARY_PATH="":$LD_LIBRARY_PATH`——**追加**调用者的值。
本机默认 `LD_LIBRARY_PATH=/usr/local/lib`，于是测试二进制的 RUNPATH
（正确指向 build/lib）根本没被用到，加载的是**旧的已安装库**；
而 `env -u LD_LIBRARY_PATH ldd` 才显示 build/lib。

`gr-uwb/lib/CMakeLists.txt` 在注册循环之后统一追加：

```cmake
set_property(TEST ${_t} APPEND PROPERTY
    ENVIRONMENT "LD_LIBRARY_PATH=${PROJECT_BINARY_DIR}/lib:$ENV{LD_LIBRARY_PATH}")
```

- build 目录**排在最前**，其余继承路径保留在后面（不删除，避免破坏可用环境）；
- 生成的 `CTestTestfile.cmake` 可见
  `LD_LIBRARY_PATH=<build>/lib:/usr/local/lib:`；
- 独立复现：同一二进制
  - `LD_LIBRARY_PATH=<build>/lib:/usr/local/lib:` → `<build>/lib/libgnuradio-uwb.so.1.0.0`
  - `LD_LIBRARY_PATH=/usr/local/lib:`（旧行为）→ `/usr/local/lib/libgnuradio-uwb.so.1.0.0`

UHD 设备 QA（注册更晚）单独补一次同样的属性。

## 4. 生成物目录：默认不再写源码树

复核 §4 记录：时序 QA 原先硬编码向源树写 CSV，评审不得不编译到树外运行
才避免覆盖 `testdata/twr`。

新增 `gr-uwb/include/gnuradio/uwb/uwb_twr_test_output.h`，规则：

| 场景 | 目录 |
|---|---|
| **默认** | `${UWB_BUILD_DIR}/test-output/twr`（可用 `UWB_TWR_TEST_OUTPUT_DIR` 覆盖）；未编入 build 目录时退到系统 temp，**仍不是源码树** |
| **显式导出** | `UWB_TWR_EXPORT_DIR=<dir>` 才会写入指定树（包括源码 `testdata/twr`） |
| **拒绝** | 未设 export 时若目标解析到源码 `testdata/twr`（含 `..` 词法归一后），直接拒绝并说明原因 |
| 兼容 | `UWB_TWR_PHY_MATRIX_CSV_DIR` 仍然生效（复核用的树外调用） |

无任何可写目录时，emit 用例**跳过并记录原因**，绝不回退到源码树。
`UWB_BUILD_DIR` 由 `lib/CMakeLists.txt` 的
`target_compile_definitions(... "UWB_BUILD_DIR=\"${PROJECT_BINARY_DIR}\"")`
注入（仅这两个 TWR 目标）。

实测：phy matrix sweep 输出到
`/tmp/opencode/b6/build/test-output/twr`，**`testdata/twr` 未被写入**
（318 行与仓库已提交 CSV 同规模、pre-existing 列逐字节相同）。

## 7. 需要补 include 的既有缺陷（顺带发现，非本代理引入）
