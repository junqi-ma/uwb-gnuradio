## 3. 必须关闭的发现

### R01 / P1：TxPlanned 可直接提供 Completed，提前发布成功

位置：`uwb_twr_core.cc::on_tx_planned`（约 958 行），`TxRecord::completed`。

复现：SS responder 接收 Poll，返回携带 `tx_evidence.outcome=Completed` 的计划；
同一批动作输出 SubmitTx 和成功 TerminalResult，尚无任何 outcome 事件。

整改：

- 计划数据与运行发送证据分离。TxPlanned 不得初始化“已发送 / 已完成”状态。
- 对计划中非法携带的运行状态明确拒绝，或通过新类型使其不可表达；不得默默当真。
- G0 明确 token 因果状态和允许的回调顺序。仅合法提交后的关联 completion
  可以闭合发送结果；重复、乱序、过期 token 不得推进或重复提交。
- 不得为修复此项改成“等待 Completed 才构造同一个待发送帧”。

验收：四个协议/角色组合；计划伪带 Completed、仅 Accepted/ACK、重复计划、
乱序 outcome、未知 token 均不提前成功；正常提交和合法 completion 仍可完成。
重新核验 B06、B07、B08。

### R02 / P1：DS initiator 成功只等 Final，遗漏 Poll outcome

位置：`uwb_twr_core.cc::maybe_finish`（约 556 行）。

复现：Poll 已提交但 outcome Unknown；收到 Response，提交 Final；Final Completed
即产生成功终态。之后 Poll Underflow 仅计 token mismatch，不再使交换失败。

整改：为每种协议/角色显式列出成功所需的全部本端 TX 集合。
DS initiator 必须等待 Poll 与 Final 均闭合为 Completed；收到合法 RX 后可以继续
构造后续帧，但不能用 RX 或后续 TX 完成替代此前 TX 证据。
任一相关 TX 的 late/underflow/adapter fault 使尚未闭合交换失败且仅终止一次。

验收：Poll/Final completion 的两种顺序、各自 Unknown/失败、RX 先于 outcome、
重复回调；有限 deadline 下 Unknown 必须收敛为失败。闭合后出现矛盾回调也需有
明确契约违例/会话失效策略，不能无记录地保留已知被污染的成功状态。
重新核验 B07、B08、B14。

### R03 / P1：非估计端绕过本端严格时间/质量准入

位置：`on_rx_frame`、`on_tx_planned`、`maybe_finish` 的 SS responder / DS initiator 分支
（约 604 行），以及仅在计算路径调用的 `admit_local`。

复现：SS responder 接收质量 NotRecorded 的 Poll，TX plan 使用另一设备 domain
及 epoch，随后 Completed，仍报告协议 complete。该探针是组合反例；整改 QA
必须将质量、domain、epoch 等因素拆开，避免互相遮蔽。

整改：

- 明确全部角色的本端 RX、TX 准入点，不能因“不输出 ToF”省略证据检查。
- 在使用本端时间字段驱动定时计划/写入 wire 之前，核对与配置一致的 domain、
  epoch、rate、marker、source、corrections、校准及本端 RX first-path verdict。
- 复用既有严格校验组件；阶段性 TX plan 检查与最终 Completed 检查分层，
  不伪造 completion，不放宽 `admit_ranging_interval()`。
- 无效输入应有明确拒绝/失败原因；不能产生成功终态。
  远端 wire claim 不需要也不能伪造这些本端事实。

验收：SS/DS × initiator/responder；NotRecorded/Failed/域外质量、错 domain/epoch/
marker/source、缺/过期校准、缺 corrections 各自独立负例，以及有效 scheduled TX 正例。
重新核验 B06、B11、B12、B15。

### R04 / P1：reset 清空身份屏障，旧事件和旧帧进入新交换

位置：`EndpointCore::reset`（约 1226–1235 行）、token 比较与 responder `seq_used`。

复现一：取消并消费旧结果，reset 后开始新交换；旧新 token 均为 1，旧计划
被新交换接受并输出 SubmitTx。旧事件没有可被核对的独立 generation 绑定。
复现二：仅更新本地 generation/binding，保持 wire session/seq 不变；旧 Poll
在 reset 后重新触发 PrepareTx。更新一个本地声明不能证明 wire 是新会话。

整改：

- 事件关联身份至少能区分会话代次、exchange/attempt 与 TX token/RX window；
  token 不得在旧事件可能存活时重用。处理器实际核对，而非只增加字段。
- 本地代次变化不能清除同 wire 身份的重放屏障。采用明确的新 wire session
  或有可证明条件的复用屏障；不修改 v1 帧格式，也不声称检测不可观测的远端 reset。
- 同步审查 `configure`、方法 `reset`、Reset 事件、Stop/Cancel，防止旁路入口
  清空在途终态、队列或计数。失败配置/reset 应原子化，不留下半更新配置。

验收：重置前后旧 plan/accepted/outcome/deadline/RX 晚到不影响新交换；
相同 wire Poll 不能仅因本地代次递增获准；真正新会话正常完成；
4/16/64/256 序号模数，未消费结果保留，失败 reset 不改变执行状态。
重新核验 B05、B10、B14。

### R05 / P1：responder 接纳请求未预留结果容量

位置：`on_rx_frame` 的 Adopt Poll 分支（约 784 行），`terminal`（约 346 行）。

复现：结果容量 1，完成第一个 SS responder 交换且不 pop，接纳第二个不同 seq Poll
并完成；得到 accepted=2、terminal=2、results_dropped=1。
动作曾返回终态不等于满足结果队列“不丢失已接受请求结果”的承诺。

整改：initiator Begin 与 responder Poll 采用统一的终态容量预留规则。
满时在接纳前拒绝/计数，不增加 accepted、不发 PrepareTx，不偷删旧结果。
已接纳请求的错误、取消、reset 路径也必须有可用终态位置。

验收：两个角色、两种协议、成功/失败/取消结果、满队列及排空后恢复；
正常合法输入下 results_dropped=0，每个 accepted attempt 有且仅有一个保留结果。
重新核验 B13、B14。

### R06 / P1：域外 outcome 在 idle 生成无请求终态

位置：`on_tx_outcome`（约 1017 行），无在途守卫的 `fail/terminal`。

复现：配置后的空闲核心接收 `TxOutcomeResolved(outcome=99)`，
得到 accepted=0、terminal=1、in_flight=0。

整改：保留 enum 域优先检查，但区分“拒绝非法事件”和“终止其所属在途请求”。
只有能归属当前已接受请求的错误才可以终止它；idle/未知/旧 token 的非法事件
只进入相应拒绝/契约计数，不生成虚假 terminal，也不取消无关正确交换。
给终态出口加防重复/无请求保护，而不是只修该枚举值。

验收：合法域和域外 outcome/adapter fault，分别覆盖 idle、正确 token、未知 token、
旧代次 token、已有 terminal；逐事件断言 accepted=terminal+in_flight。
重新核验 B14、B15；enum switch 保持显式域检查与无 default 风格。

### R07 / P2：证据等待覆盖绝对交换 deadline

位置：`maybe_finish`（约 580–585 行）；DS Response 计划后的 deadline 重设路径。

复现：Begin(0)、exchange_timeout=1000；RX(300)、evidence_wait=1000；
投递 Deadline(1000) 时未终止，因原上限被覆盖为 1300。

整改：分别保存不可延长的 exchange 绝对上限和 evidence 上限；调度提示选有效上限
最早者，不因 RX、plan 或重复事件重新起算整个交换。明确时间域、回绕与安全加法，
不使用可能溢出的 signed 加法。配置必须保证已接纳请求有有限终止条件；
若某个 0 表示关闭该项，必须仍有另一项有限上限，不能依赖外部无限等待。

验收：exchange 上限早于/晚于/equal evidence 上限、DS 回复前后、重复 RX、
plan 永不到、outcome 永远 Unknown、极值/回绕、旧窗口 Deadline；终态仅一次。
重新核验 B03、B07、B10。
