## 2. 冻结的 MAC 帧格式 v1

小端。**FCS 不属于本层**，由 HRP 调制层唯一追加（`UwbHrpPacketSource` 的 `append_fcs` 分支 → `mod::append_ieee_fcs`）。`qa_uwb_twr_frame.cc` 用剥注释的树扫描强制"全仓库只有一个生产调用点"，违反即构建失败。

```
off  size  field          说明
 0    1    version        0x01
 1    1    function_code  0x00 Poll / 0x01 Response / 0x02 Final
                          0x03 保留（Report 本阶段不发送）
 2    2    session_id     u16，与 seq 独立回绕
 4    2    seq            u16
 6    2    pan_id         u16
 8    2    src_addr       u16
10    2    dst_addr       u16
12    2    flags          bit0 ranging；bit1 sts_present（本阶段恒 0，
                          配置 sts_mode != off 显式拒绝）；bit2..15 reserved=0
14    5*n  timestamps     40-bit LE，按 function_code 固定
      2    FCS16          IEEE 802.15.4 CRC-16（HRP 层追加）
```

**时间戳承载**（对齐 Decawave 三报文非对称 DS-TWR）：

| 帧 | n | 内容 | MAC 载荷 | 含 FCS 空口 |
|---|---|---|---|---|
| Poll | 0 | — | 14 B | 16 B |
| Response | 2 | `t2B, t3B` | 24 B | 26 B |
| Final | 3 | `t1A, t4A, t5A` | 29 B | 31 B |

- Response 携带 `t2B/t3B` → **A 计算 SS**：`ToF_A = (RA − kAB·DB)/2`，`RA = t4A − t1A`，`DB = t3B − t2B`（REQ-PROTO-02）。
- Final 携带 `t1A/t4A/t5A`，**不携带 t2B/t3B 回显**（用户决策，参考 Decawave）→ **B 计算 DS**：`ToF = (RA·RB − DA·DB)/(RA+RB+DA+DB)`（REQ-PROTO-03）。
- 满足 REQ-PROTO-05「SS 在 A、DS 在 B」。
- `Report`(0x03) 保留但本阶段拒绝为未实现（用户决策；四报文会使原版互通声明失效）。
- 时间戳位宽/单位由 `FrameProfile` 参数化，**禁止全局混用 DW ticks / UUS / USRP ticks**（REQ-TIME-04）。当前 profile：40-bit / 737.28 MHz 设备 tick。
- 未使用的 timestamp 槽必须为 0（防止陈旧时刻值搭便车）。
- `frame_match` 拒收 `SelfAddressed`（src == 本端地址），环回的 TX 永远不能计为对端测量（支撑 REQ-SCOPE-02）。

**空口 PSDU 长度实测**（64 SYNC / 4z2 / 737.28 native，`packet_samples_998p4`）：

| 帧 | work @998.4 | 时长 | native @737.28 |
|---|---|---|---|
| Poll (16 B) | 117 184 | 117.372 µs | 86 536 |
| Response (26 B) | 127 424 | 127.628 µs | 94 098 |
| Final (31 B) | 132 544 | 132.756 µs | 97 879 |

分段恒定：前导 65 024（65.128 µs）· SFD 8 128（8.141 µs）· PHR 21 504（21.538 µs）。
SFD 长度实测：`4z1=4, 4z2=8, ieee=8, decawave=8, 4z3=16, 4z4=32`。

**TWR 载荷 FCS 实测**（并用 QA 内独立 CRC-16 交叉验证）：Poll `0xdd53` / Response `0xf18d` / Final `0xfcb1` / 127 B `0xe985`。

## 3. 冻结的时间戳契约

`Timestamp{ ticks, frac_num/frac_den, domain, marker, source, applied_corrections, calibration_id, valid }`。

`ClockDomain{ name, tick_rate_hz, epoch_id, timestamp_bits }`：**同一性 = name + 精确 tick 率 + 回绕宽度**；**可比性 = 同一性 + 同一 epoch**。

`timestamp_interval()` 按固定 10 步返回首个失败，**没有静默回退路径**：

1. 结构有效性 / 分数归一 → `InvalidTimestamp` / `FractionNotNormalized`
2. clock name → `DomainNameMismatch` 3. tick 率 → `TickRateMismatch` 4. 回绕宽度 → `WrapWidthMismatch`
5. **epoch → `EpochMismatch`** 6. marker 对合法性 → `MarkerMismatch`
7. 两侧修正链 → `CorrectionsNotApplied` 8. 模解算 → `WrapAmbiguous` / `OrderReversed`
9. 亚 tick 精确合并 → `FractionNotNormalized` 10. 纳秒投影 → `DurationOutOfRange`

**修正链门控**（本设计最重要的一条不变量）：

| marker | 必需修正位 |
|---|---|
| `UhdRxFirstIqSample` | 无（它就是原始读数） |
| `PreambleStart`/`SfdStart`/`PhrStart` | RX 链 6 位 |
| `RmarkerRx` | RX 链 6 位 + `rmarker_offset` |
| `RmarkerTx` | `waveform_geometry` + `tx_command_to_air` + `delayed_tx_quantization` |
| `AntennaPlane` | RX 链 + `rmarker_offset` + `antenna_plane` |
| 未知 marker | `kCorrectionAll+1`（fail-closed） |

即：**裸设备时间戳无法产出协议 interval**。RX 链 = 样点→首径、窗口裁剪、采样率变换、首径分数、波形几何、首径质量门。这把 REQ-TIME-02/03/05 从文档要求变成类型层面不可违反的不变量。`UhdRxFirstIqSample` 与 `RmarkerRx` 之间的唯一合法桥梁是 `retag_marker()`，且要求目标 marker 的全部修正位已记录。

**回绕无歧义窗口 = 半周期**（`2^(bits−1)/tick_rate`），不是需求草稿里的全周期。半周期是数学上正确的界限（超过半周期的模差与负向区间不可区分），且**严格更强**。40-bit 下 X410 半周期 745.7 s、DW 率半周期 8.6 s，均远超任何 exchange 时长。

**M1 必须遵守的两个行为契约**：
1. 存在亚 tick 分数或亚纳秒 tick 率时 `TimeInterval::duration_is_tick_exact == false` → ToF 核心必须用 `ticks` + `frac_num/frac_den`，**不得**用纳秒投影。
2. `timestamp_precedes` 只比较模 tick 距离，忽略亚 tick 分数（已文档化）。

**回绕修正**：`uwb_demod_core.h:2203` 只重测尾部 `max(cfo_min_fit_repetitions, 40)` 个 SYNC，前段峰以 `peak_corr=(0,0)`（相位 0）合成。跳过量 `cfo_skip_initial_repetitions=24` 仅在 64 SYNC 时等于 `64−40`；一般式为 `合成 − 跳过 = max(0, reps−64)`。

## 4. 冻结的能力白名单（实测产生，非假设）

来源 `testdata/twr/phy_matrix_737280000.csv`（318 行）与 `phy_matrix_whitelist_737280000.csv`（84 行），由 `qa_uwb_twr_phy_matrix.cc` 产生。每行都经过
`modulate_one → UwbLoopbackEcho → demodulate_one → FCS pass + 逐字节一致`。

| 轴 | 冻结取值 | 依据 |
|---|---|---|
| native rate | 737.28e6（491.52e6 由 `is_allowed_uhd_native_rate` 允许但无往返） | 见 §7 |
| work rate / 每符号样点 | 998.4e6 / 1016 | 现有几何 |
| preamble code | 9, 10, 11, 12 | `code_index_supported` + 实测 |
| SYNC 长度 | **16, 64** | 见下表 |
| SFD mode | 4z1, 4z2, 4z3, 4z4, decawave, ieee | 24 组合全通 |
| 数据速率 | **仅 6.81 Mb/s** | `encode_phr19` 硬编码 rate index 2；payload 级恒用 6.81 几何 |
| 最大 PSDU | 127 B | `kMaxPsduBytes` |
| 联合白名单 | **48 行**（2 SYNC × 4 code × 6 SFD） | `build_default_capabilities()` |
| 通道 | 仅 5 | REQ-PHY-01/03 |
| PRF 类别 | 仅 `bprf64` | 需求定义 |
| ranging bit | 必须 true | REQ-PROTO-05 |
| STS | **不支持** | 用户决策 / REQ-SCOPE-04 |

### SYNC 长度的逐值实测理由

| 值 | 判定 | 实测理由 |
|---|---|---|
| 1, 2 | 拒 | `stage_cfo` 需 ≥4 个实测峰 → `CfoFailed` |
| 4, 8 | 拒 | `cir_skip_initial_repetitions=10` 超过可用重复 → `CirFailed` |
| **16** | **支持** | 尾部重测覆盖整个前导（`tail_first=0`），`zero_peak_corr=0`，`np(16) ≤ min_fit(32)` 使 skip 退化为 0。CFO 误差 0.000 Hz @0/±1/±5/±20 kHz、0.007 Hz @±100 kHz。`encode_phr19` 对 ≤16 映射 PHR 前导时长索引 **0（=16）**，是合法 BPRF 时长且自描述（实测 `phr_preamble_idx=0`）。24/24 组合、四种载荷、ranging 0/1、延迟/多径/AWGN 全通。**保留：仅解码验证，短积分窗（16.3 µs vs 65.1 µs）下首径/ToA 精度未验证。** |
| 32 | 拒 | CFO 精确且能解出，但 PHR 广播索引 1（=64），不自描述 |
| **64** | **支持** | 参考 profile。CFO 误差 ≤0.007 Hz |
| 128 / 256 / 512 | 拒 | ① PHR 广播 64；② `cfo_skip 24 < tail_first`，零相位点泄漏进最小二乘（20 kHz 注入回 3791 Hz，误差 −16209 Hz） |
| 1024 | 拒 | PHR 合法（索引 2）但 CFO 有偏（20 kHz 误差 −19901 Hz） |
| 2048 | 拒 | PHR 广播 1024；且 CFO 有偏 |
| 非 2 的幂 | 拒 | 不在 API 列表 |

**16 SYNC 的保留意见被编码为可查询谓词**（C++ `twr_sync_reps_needs_toa_validation(n)`，Python 同名镜像）：16 进入白名单是因为它确实往返通过，但它**在 M2 测出首径 ToA 精度之前不能作为测距 profile 使用** —— 测距精度正是首径 ToA 的函数。

**非标准 SFD 长度**：`4z1`(4 符号) 与 `4z4`(32 符号) **不是** IEEE 802.15.4a HRP 的合法 SFD 长度（标准定义 8 和 16 符号形式）。本链路自洽，但 M5 前必须对目标模组重新确认。相位 1 共同 profile 用 `4z2`。

## 5. 配置层契约

`TwrConfig` 覆盖 REQ-API-01 全部参数组：`ConfigMeta` / `SessionConfig` / `PhyConfig` / `FrameFormatConfig`(+`FrameGeometry`) / `TransmitConfig` / `ReceiveConfig` / `RadioConfig`(+`RadioReadback`/`EndpointBinding`/`peers`) / `PerMessageTiming` / `TimeoutConfig` / `TimestampCalibrationConfig`(+`CalibrationRecord`) / `DiagnosticsConfig`。

- **唯一校验器**：`validate()` / `effective_config()` / `capabilities()`，Python 与 CLI 共用。
- **default-deny**：白名单外的组合一律 `Unsupported`，**绝不回落 radar/QM35 默认值**（REQ-SCOPE-01）。每条拒绝都带字段路径、原因、状态与可操作消息。
- **快照不可变**：exchange 进行中改 PHY/频率/增益/地址/校准被拒（REQ-API-03）。`PerMessageOverrides` 在构造上就没有这些字段。
- **时间字段三分**：`TimedField` 携带 `reference`（参考事件）、`domain`、`marker`、`required_quantisation_hz`、`max_quantisation_error_ns`。设备 tick 字段**必须**有 marker，主机单调时钟字段**禁止**有 marker。
- **量化精度拒绝**：`Duration::representable_at()`。实测 491.52 MS/s 下一个 tick = **2.0345 ns**，因此该速率下 `max_quantisation_error_ns=1` 不可达，会被正确拒绝为"计时精度不足"。
- **JSON**：无外部依赖。int64 在 `|v| ≤ 2^53−1` 时不加引号，超出则**加引号的十进制字符串**（读者两者皆可接受）；双精度用 `%.17g`；非有限值导出**失败**，绝不输出 `NaN`。

### M0 期间修正的两处真实缺陷

**1. `frame.need` 与 FCS 计数不一致**（`uwb_twr_config.h: check_frame_lengths`）
原实现把 `fcs_bytes` 加进 `need` 后与**不含** FCS 的 `mac_psdu_bytes` 比较。原先帧头是 7 字节占位值时 `32` 恰好掩盖了矛盾；对齐真实 14 字节头后立即暴露。已拆分为：`need` = MAC 字节（与 `mac_psdu_bytes` 比较），`on_air` = `need + fcs_bytes`（与 127 字节上限比较，符合 `UwbHrpPacketSource` 先 append FCS 再判 127 的实际行为）。

**2. `rate_matches_strict` 接受 `+Inf`**（`uwb_uhd_backend_config.h:195`）
`scale = max(737.28e6, +Inf) = +Inf`，`|diff| = +Inf`，`tol*scale = +Inf`，于是 `+Inf <= +Inf` 为真 —— 设备返回 `+Inf` 速率读回会被当成**匹配的 737.28 MHz 放行**，击穿 `uwb_uhd_burst_backend.h` 声明的"任何静默速率强制转换都是硬失败"保证。已加非有限输入守卫 + 12 条回归断言。`−Inf` 与 `NaN` 原本已因 IEEE 比较巧合而被拒，现在显式拒绝，不再依赖巧合。

## 6. 冻结的架构结论（Model B）

`IRadioBurstBackend` 在 `issue_rx()` **之前**冻结 `RxCommand::rx_ticks`，并按 `schedule_index` 关联结果 —— **反应式触发在结构上无处表达**。TWR 正确形态是本仓库已有的生产实现：`gr::block` + `io(0,0,0)` + 短 handler + 有界队列 + 私有 owner 线程。

**明确排除 `tagged_stream_block`**：其基类在 `general_work` 内分配内存，且长度 tag 不在下一读位置即 `throw` —— 直接违反 AGENTS.md「work/general_work 内不分配内存」。

必须遵守的设备事实：

1. **`EXEC_LATE_CMDS(1)`**（`ctrlport_timer.v:35/159`，`x4xx_core_common.v:428` 硬连线）：X4xx 上**迟到的定时命令立即执行**。迟到检测必须完全由主机在提交前完成，不能依赖设备报错（REQ-PROTO-04）。
2. **设备侧无"最小 TX 提前量"概念**（`radio_tx_core.v:336-343` 的 `ERR_TX_LATE_DATA` 只在带时间戳数据包**到达时**判断）。下界完全等于 `主机计算 + 主机→NIC→FPGA`，**待 M3 实测**，当前无任何数字。
3. **非 `RADIO_SPC` 倍数的样点数被静默向上取整，仅有 warning**（`radio_control_impl.cpp:961-968`）。这是 `开发状态.md` 记录的 radar 逐包 +4 native 漂移的机制来源，已在源码侧独立互证。**TWR 的 RX/TX 窗口几何必须由主机对齐 SPC 栅格并由配置层校验。**
4. **PMT 消息队列无界**（`basic_block.h:70` `std::deque` + 裸 `push_back`，`tpb_thread_body.cc:79` 排空式消费）→ REQ-GR-03 的 queue entries 上限**只能**在 TWR block 自己的有界队列内强制。
5. **`get_time_now()` 在 RFNoC 上是寄存器读、经 MPMD 是 RPC** → 不得进入逐包路径。
6. **本仓库现有 `rx_time_s` 是 double 秒绝对时间**（`uwb_auto_scheduled_extractor_sc16.cc:1009-1016`）→ 1e9 s 运行时 double 的 ULP 在 737.28 MHz 下约 **88 ticks**，对 TWR 不可用。必须用 `(epoch_id, int64 device_ticks)`。
7. 时间锚点映射**已有实测背书**：65/48 与 65/32 的 `map_input_offset_to_output` 全帧遍历 0 处不一致，e2e `predicted` vs `sfd_truth` **残差 0**；FIR 头（群时延）65/48 = 28 work 样点（28.0 ns）、65/32 = 42（42.1 ns）；往返最差 1–2 work 样点。

详见 [M0_调度语义.md](M0_调度语义.md)（含 31 条 M1/M2 checklist 与 12 项未决）。

## 8. 回归基线与两个环境陷阱

**M0 结束时 CTest 47/48 通过**，唯一失败是 `uwb_qa_uwb_pdu_rational_resampler.cc` —— 即 TWR 开发**之前**的历史失败（实测 ≈214 PDU/s 串行 / ≈173 PDU/s `-j8`，阈值 `>400`）。按 REQ-REG-01 标记为历史基线，后续新增失败不得归入此项。详见 [M0_回归基线.md](M0_回归基线.md)。

### 陷阱一：交互 shell 会加载 6 周前的陈旧库

环境里有 `LD_LIBRARY_PATH=/usr/local/lib:`，而二进制携带的是 `DT_RUNPATH` —— 动态链接器**先查 `LD_LIBRARY_PATH`、后查 `RUNPATH`**：

| 运行方式 | 实际加载的 `libgnuradio-uwb.so` |
|---|---|
| 交互 shell | **`/usr/local/lib` 的 2026-08-10 陈旧副本** |
| `env -u LD_LIBRARY_PATH <bin>` | `build/lib` 正确副本 |
| `ctest`（`_test.sh` 前置空项 ⇒ CWD 优先） | `build/lib` 正确副本 |

`ldd` 在这三种方式下给出三个不同答案。**任何手工 `./test_binary` 都可能静默使用陈旧库。** 一律用 `ctest`，或 `env -u LD_LIBRARY_PATH`。根治办法是 `sudo cmake --install gr-uwb/build`（上板前本来就要做）。

该陷阱曾使能力矩阵第一轮全部测在陈旧库上（`sync_reps_supported_list()` 当时是 `32, 64, 128, …`）。**16 SYNC 曾因此被误判为"被生产 block 拒绝"**。重建后复测：16 SYNC 实际可用。

### 陷阱二：吞吐型 benchmark 对负载敏感

`uwb_benchmark_hrp_mod` 在 `-j8` 并发下失败、串行下 0.16 s 通过。**判定测试失败前先串行复跑**，否则会把负载假象记成回归。
