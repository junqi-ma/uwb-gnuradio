## 3. 冻结的契约

### 3.1 类型层（`uwb_twr_types.h`，587 行）

UHD-free / GNU-Radio-free / header-only。四个 header 均可脱离 gnuradio include 路径独立编译（已验证）。

- `Protocol{Ss,Ds}`、`Role`、`FrameType{Poll=0,Response=1,Final=2,Report=3}`
- `frame_type_timestamp_count()` — Poll 0 / Response 2 / Final 3，**数量不符即拒收而非重解释**
- `TimestampMarker` 7 种，明确区分 `UhdRxFirstIqSample` / `PreambleStart` / `SfdStart` / `PhrStart` / `RmarkerTx` / `RmarkerRx` / `AntennaPlane`
- `TimestampSource` — `ScheduledCalibrated` **不能**冒充 `HardwareMeasured`
- `ExchangeStatus` — **REQ-ERR-01 完整 24 个终态**，`exchange_status_yields_range()` 使**只有 `Ok` 产出距离**。每个 exchange 恰一条终态，**无 recovered 路径**
- `Duration` — 整数纳秒；`from_seconds` 拒绝 NaN/Inf/溢出；`ticks_at()` 溢出时 `ok=false`；`representable_at()` 用于 REQ-API-01 的"计时精度不足"拒绝

### 3.2 MAC 帧 v1（`uwb_twr_frame.h`，1167 行）

小端。**FCS 不属于本层**，由 `UwbHrpPacketSource` 的 `append_fcs` 分支唯一追加。

```
 0  1  version=0x01        8  2  src_addr
 1  1  function_code      10  2  dst_addr
 2  2  session_id         12  2  flags (bit0 ranging, bit1 sts_present)
 4  2  seq                14  5n timestamps (40-bit LE)
 6  2  pan_id             ..  2  FCS16 (HRP 层追加)
```

| 帧 | 时间戳 | MAC 载荷 | 含 FCS |
|---|---|---|---|
| Poll | — | 14 B | 16 B |
| Response | `t2B, t3B` | 24 B | 26 B |
| Final | `t1A, t4A, t5A` | 29 B | 31 B |

Response 让 **A 算 SS**（`ToF_A=(RA−kAB·DB)/2`），Final 让 **B 算 DS**（`ToF=(RA·RB−DA·DB)/(RA+RB+DA+DB)`），满足 REQ-PROTO-05。Final 不回显 t2B/t3B（用户决策，参考 Decawave）。`Report`(0x03) 保留但拒绝为未实现；STS 本阶段不开发。

**三条写成了测试而非约定的性质**：
1. **FCS 单层** —— 剥注释的树扫描强制全仓库只有一个生产调用点，违反即构建失败
2. **未用 timestamp 槽必须为 0** —— 防止陈旧时刻值搭便车
3. **`frame_match` 拒收 `SelfAddressed`** —— 环回的 TX 永远不能计为对端测量（支撑 REQ-SCOPE-02）

golden 由**独立序列化器**导出（非跑 codec 得到），在三处交叉断言，并用 3 个反向对照验证过有效性。

### 3.3 时间戳（`uwb_twr_timestamp.h`，1832 行）

**10 步校验**，每步返回可区分的失败，**无静默回退路径**：

结构 → clock name → tick 率 → 回绕宽度 → **epoch** → marker 对 → **两侧修正链** → 模解算 → 亚 tick 合并 → 纳秒投影

**修正链门控（本设计最重要的不变量）**：

| marker | 必需修正位 |
|---|---|
| `UhdRxFirstIqSample` | 无（它就是原始读数） |
| `PreambleStart`/`SfdStart`/`PhrStart` | RX 链 6 位 |
| `RmarkerRx` | RX 链 + `rmarker_offset` |
| `RmarkerTx` | `waveform_geometry` + `tx_command_to_air` + `delayed_tx_quantization` |
| `AntennaPlane` | RX 链 + `rmarker_offset` + `antenna_plane` |
| 未知 marker | `kCorrectionAll+1`（fail-closed） |

即**裸设备时间戳无法产出协议 interval**。这把 REQ-TIME-02/03/05 从文档要求变成类型层面不可违反的不变量。实测确认：带 `kCorrectionNone` 的同域 `RmarkerTx` 配对被拒（`corrections_not_applied`）。

**时间锚点映射已有实测背书**：65/48 与 65/32 的 `map_input_offset_to_output` 全帧遍历 **0 处不一致**；e2e `predicted` vs `sfd_truth` **残差 0**；FIR 头（群时延）65/48 = 28 work 样点（28.0 ns）、65/32 = 42（42.1 ns）；往返最差 1–2 work 样点。

**回绕无歧义窗口 = 半周期** `2^(bits−1)/rate`。**这一条纠正了需求草稿的全周期规定**（见 §7.1）。实测边界精确落在 P/2：`P/2−1 → ok`，`P/2+1 → wrap_ambiguous`。

### 3.4 配置层（`uwb_twr_config.h`，5729 行 + Python 4711 行）

- **唯一校验器**：`validate()` / `effective_config()` / `capabilities()`，Python 与 CLI 共用
- **default-deny**：白名单外一律 `Unsupported`，每条拒绝带字段路径、原因、状态、可操作消息
- **快照不可变**：exchange 中改 PHY/频率/增益/地址/校准被拒；`PerMessageOverrides` 在构造上就没有这些字段
- **时间字段三分**：`TimedField` 携带参考事件、clock domain、marker、所需量化。设备 tick 字段**必须**有 marker，主机单调时钟字段**禁止**有 marker
- JSON：int64 在 `|v| ≤ 2^53−1` 时不加引号，超出用**加引号的十进制字符串**；非有限值导出**失败**，绝不输出 `NaN`

**C++/Python 能力一致性已独立交叉验证**：`sync=[16,64]`、矩阵 48 行、SFD 顺序、ToA 集合 `[16]`、reason 字符串**字节相同**。

## 4. 能力白名单（实测产生，非假设）

来源 `testdata/twr/phy_matrix_737280000.csv`（318 行）与 `phy_matrix_whitelist_737280000.csv`（84 行）。
每行都经 `modulate_one → UwbLoopbackEcho → demodulate_one → FCS pass + 逐字节一致`。

| 轴 | 冻结取值 |
|---|---|
| native rate | 737.28e6（491.52e6 由 `is_allowed_uhd_native_rate` 允许但**无往返**，见 G2） |
| code | 9, 10, 11, 12 |
| SYNC | **16, 64** |
| SFD | 4z1, 4z2, 4z3, 4z4, decawave, ieee |
| 数据速率 | **仅 6.81 Mb/s** |
| 联合矩阵 | **48 行**（2 SYNC × 4 code × 6 SFD） |
| 通道 / PRF / ranging | 仅 5 / 仅 bprf64 / 必须 true |
| STS | **不支持** |

### SYNC 长度的逐值实测理由

| 值 | 判定 | 实测理由 |
|---|---|---|
| 1, 2 | 拒 | `stage_cfo` 需 ≥4 峰 → `CfoFailed` |
| 4, 8 | 拒 | `cir_skip_initial_repetitions=10` 超过可用重复 → `CirFailed` |
| **16** | **支持** | 尾部重测覆盖**整个前导**（`tail_first=0`），`zero_peak_corr=0`，`np(16) ≤ min_fit(32)` 使 skip 退化为 0 → **结构上不可能有零相位泄漏**。CFO 误差：注入非零 CFO 的 97 行中最大 **0.001 Hz**。另有 1 行为
`cfo_inject=0 → cfo_est=146.999 Hz` 但 `result=PASS`（零注入时估计器无参考系，
该绝对值不构成偏差证据）。`encode_phr19` 对 ≤16 映射 PHR 索引 **0（=16）**，是合法且自描述的 BPRF 时长。24/24 组合、四种载荷、延迟/多径/AWGN 全通过 |
| 32 | 拒 | CFO 精确且解出，但 PHR 广播索引 1（=64），不自描述 |
| **64** | **支持** | 参考 profile，CFO 误差 ≤0.007 Hz |
| 128/256/512 | 拒 | ① PHR 广播 64；② `cfo_skip 24 < tail_first`，零相位点泄漏（20 kHz → 3791 Hz，误差 −16209 Hz） |
| 1024 | 拒 | **PHR 合法**（索引 2）但 CFO 有偏（−19901 Hz） |
| 2048 | 拒 | PHR 广播 1024 + CFO 有偏 |

一般式：`合成 − 跳过 = max(0, reps−64)`。这解释了为什么恰好 64 干净而更长者不干净。

### 16 SYNC 的保留意见（重要）

16 进入白名单是因为它**确实往返通过**。但 CSV 自带的 reason 是：

```
decode_verified_only_first_path_toa_accuracy_unverified_for_16_sync_shorter_integration_window
```

即**仅解码验证**，短积分窗（16.3 µs vs 64 SYNC 的 65.1 µs）下**首径/ToA 精度未验证**。而测距精度正是首径 ToA 的函数。

该保留意见已编码为**可查询谓词** `twr_sync_reps_needing_toa_validation(16)`（C++ 与 Python 镜像），**M2 测出前禁止把 16 SYNC 当测距 profile**。这不是文档警告，是可被代码查询的事实。

### 非标准 SFD 长度

`4z1`(4 符号) 与 `4z4`(32 符号) **不是** IEEE 802.15.4a HRP 的合法 SFD 长度（标准定义 8 和 16 符号形式）。本链路自洽，但 **M5 前必须对目标模组重新确认**。相位 1 共同 profile 用 `4z2`。

## 5. 修复的两处真实缺陷

### 5.1 `rate_matches_strict` 接受 `+Inf`（现有生产代码）

```cpp
const double scale = requested > readback ? requested : readback;
return std::fabs(readback - requested) <= rel_tol * scale;
```

`requested=737.28e6`、`readback=+Inf` 时：`scale=+Inf`、`|diff|=+Inf`、`tol*scale=+Inf`，
于是 `+Inf <= +Inf` 为真 → `is_allowed_uhd_native_rate(+Inf)` 返回 **true**。

设备若因传输错误返回 `+Inf` 速率读回，`prepare()` 会当成**匹配的 737.28 MHz 放行**，
击穿 `uwb_uhd_burst_backend.h` 声明的"任何静默速率强制转换都是硬失败"保证。

已加非有限输入守卫 + 12 条回归断言。`−Inf` 与 `NaN` 原本已因 IEEE 比较巧合被拒，
现在显式拒绝，不再依赖巧合。

### 5.2 `check_frame_lengths` 的 FCS 计数矛盾

原实现把 `fcs_bytes` 加进 `need` 后与**不含** FCS 的 `mac_psdu_bytes` 比较。
原帧头是 7 字节占位值时 `32` 恰好掩盖了矛盾；对齐真实 14 字节头后立即暴露
（"final frame needs 31 PSDU bytes but only 29 are negotiated"）。

已拆为：`need` = MAC 字节（对 `mac_psdu_bytes` 比较），`on_air` = `need + fcs_bytes`
（对 127 上限比较，符合 `UwbHrpPacketSource` 先 append FCS 再判 127 的实际行为）。

## 6. 架构结论与运行环境陷阱

### Model B

`IRadioBurstBackend` 在 `issue_rx()` **之前**冻结 `RxCommand::rx_ticks`，并按
`schedule_index` 关联结果 —— **反应式触发在结构上无处表达**，responder 必须在看到
Poll 之前就定死 RX 窗口时刻。

正确形态是本仓库已有的生产实现：`gr::block` + `io(0,0,0)` + 短 handler + 有界队列 +
私有 owner 线程（`uwb_realtime_echo_timer.cc`）。

**排除 `tagged_stream_block`**：其基类在 `general_work` 内分配内存，且长度 tag 不在
下一读位置即 `throw` —— 直接违反 AGENTS.md「work/general_work 内不分配内存」。

### 设备事实（逐条源码核实）

| 事实 | 证据 |
|---|---|
| **`EXEC_LATE_CMDS(1)` 使 X4xx 立即执行迟到定时命令** | `ctrlport_timer.v:35/159`，`x4xx_core_common.v:428` 硬连线。迟到检测必须完全由主机在提交前完成 |
| **设备侧无最小 TX 提前量概念** | `radio_tx_core.v:336-343` 的 `ERR_TX_LATE_DATA` 只在带时间戳数据包**到达时**判定。下界 = 主机计算 + 主机→NIC→FPGA，**待 M3 实测** |
| **非 `RADIO_SPC` 倍数样点数静默向上取整仅 warning** | `radio_control_impl.cpp:961-968` |
| **PMT 消息队列无界** | `basic_block.h:70` `std::deque` + 裸 `push_back`；REQ-GR-03 的 queue 上限**只能**在自己有界队列内强制 |
| `get_time_now()` 走 RPC 时不得进逐包路径 | `mpmd_mb_controller.cpp:160` |

第三条与 `开发状态.md` 记录的 radar 逐包 +4 native 漂移**指向同一机制**，源码侧独立互证。

### 陷阱一：`LD_LIBRARY_PATH` 使 `DT_RUNPATH` 失效

环境有 `LD_LIBRARY_PATH=/usr/local/lib:`，而二进制携带 `DT_RUNPATH` ——
动态链接器**先查 `LD_LIBRARY_PATH`、后查 `RUNPATH`**：

| 运行方式 | 实际加载的库 |

## 7. 需要重点复核的三个判断

以下是本轮中**由我或代理推翻了原始需求/任务书**的地方，请优先审阅。

### 7.1 回绕无歧义窗口应为半周期（推翻需求草稿）

需求草稿与我的任务书写的是 `2^bits/tick_rate`（全周期）。A5 判定应为
`2^(bits−1)/tick_rate`，理由：宽度 `bits` 的计数器模差落在 `[0, 2^bits)`，
若超过半周期则与"负向区间"不可区分，因此正向解释的最大无歧义区间是**半周期**。

该规则**严格更强**（全周期区间也会被拒）。实测边界精确落在 P/2。
40-bit 下 X410 半周期 745.7 s、DW 率半周期 8.6 s，均远超任何 exchange 时长，
**实践影响为零，但规则本身更正确**。已接受。

### 7.2 16 SYNC 支持（推翻了我自己的任务书，也推翻了第一轮测量）

我最初在任务书里要求 A2 验证 16 SYNC 是否可用，并预期会失败。第一轮测量因
`LD_LIBRARY_PATH` 陷阱全部作废。重建后对正确库复测：**16 SYNC 完全可用**，
且机制清晰 —— 它的尾部重测覆盖整个前导（`tail_first=0`），`np(16) ≤ min_fit(32)`
使 skip 退化为 0，**结构上不可能有零相位泄漏**。且 PHR 索引 0（=16）是合法自描述的
BPRF 时长 —— 这与 32/128 那些"广播 64 但不是 64"的情况**本质不同**。

保留意见仅剩首径 ToA 精度（见 §4）。

### 7.3 128 SYNC 不可用（结构性，非配置可调）

两个**独立**且都是结构性的根因：

1. **CFO 拟合结构性失效**：`uwb_demod_core.h:2203` 只重测尾部
   `max(cfo_min_fit_repetitions, 40)` 个 SYNC，前段峰以 `peak_corr=(0,0)`（相位 0）合成。
   `cfo_skip_initial_repetitions=24` 仅在 64 SYNC 时等于 `64−40`；128 SYNC 时
   `tail_first=88`，**64 个零相位点泄漏进 104 点最小二乘**。注入 20 kHz 实测回 3791 Hz
   （误差 −16209 Hz）。把 skip 改成 `128−40=88` 后误差回到 0.00 Hz 且同一帧解出
   —— 双向证明。
2. **PHR 自描述不可能**：`encode_phr19` 把 128/256/512 映射为索引 1（=64）、
   2048 映射为索引 2（=1024）。而 `uwb_radar_pdu_meta.h:82-84` 自己写明
   "IEEE BPRF native PreambleDuration is 16/64/1024/4096; 32/128/256/512/2048
   are custom profiles built by cropping/tiling" —— **128 在 BPRF 里根本不是合法前导时长**。

我最初在计划中把 128 列为"需验证 128"的可能性之一。现结论是**当前实现下不可用**。

> **复核更正**：以上两个根因都属于**本仓库软件实现**的限制。Qorvo 资料（DW1000 API
> Guide v2.7 §5.12；DW3xxx API Guide PDF 第 32–34 页）显示芯片**支持**
> 128/256/512/1024，DW3xxx 将其列为 non-standard preamble lengths。原稿
> "结构性不可能"的表述过强，正确读法是"当前 profile 暂不接受，能力可随实现升级"。

## 7.4 本报告数值与实测 CSV 的自检

对本报告引用的关键实测值直接从 `phy_matrix_737280000.csv`（318 行）复算：

| SYNC | 行数 | `cfo_zero_peak_corr` | `phr_preamble_idx` | 最大 CFO 偏差 | 与 §4 一致 |
|---|---|---|---|---|---|
| 16 | 98 | **0** | **0**（=16，合法自描述） | 0.001 Hz（97 行非零注入） | ✅ |
| 64 | 107 | 0 或 **24**（=64−40，恰好被跳过） | −1 或 1 | 1.405 Hz | ✅ |
| 128 | 90 | **88**（泄漏 64 点） | **1**（=64，不自描述） | 67 624 Hz | ✅ 双重缺陷 |
| 1024 | 2 | **984** | **2**（=1024，PHR 合法） | 19 900 Hz | ✅ 仅 CFO 缺陷 |

`64 SYNC` 的 `zero_peak_corr` 出现 24 而非 0，与"24 个合成峰恰好被 24 个 skip
排除"一致 —— 这正是 64 干净而更长者不干净的原因。`16 SYNC` 的 `zero_peak_corr`
**恒为 0**，从数据侧再次确认它不存在零相位泄漏。
