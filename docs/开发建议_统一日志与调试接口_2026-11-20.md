# 开发建议：统一日志与调试接口（`uwb_log.h`）

日期：2026-11-20
分支：`feature/sic-research`

## 1. 背景与现状

当前仓内原生 C++ 代码在日志和诊断输出上存在明显分层差异：

1. **`uwb_core`（纯 DSP 核心）**：如 `gr-uwb/lib/uwb_demod_pipeline.cc` 等不包含任何 `stdout`/`stderr` I/O，所有诊断指标通过 `DemodResult` 等返回结构体向上层透传。
2. **`uwb_native`（原生运行时）**：`gr-uwb/lib/uwb_uhd_sc16_pipeline.cc` 中有 16 处直接写 `std::cerr`，把正常配置信息（`UHD RX configured:...`）、告警（`warning:`）和致命错误混在一起，无法按级别静默或开启调试细节。
3. **`apps/`（实时接收与工具入口）**：
   - `gr-uwb/apps/uwb_dw3000_live.cc` 内部实现了异步有界队列 `Reporter`（4096 行上限），在 `stdout` 输出 `START`、`PACKET`、`SUMMARY`、`HEARTBEAT`、`COST_TOTAL`、`LOCK_STATS`、`FINAL` 等结构化遥测；错误消息也通过 `report.info("SOURCE_ERROR ...")` / `report.info("WORKER_ERROR ...")` 输出。
   - 其余工具（如 `uwb_uhd_sc16_pipeline_runner.cc`、`uwb_uhd_sc16_capture.cc`）各自直接写 `std::cout` / `std::cerr`，缺少统一级别与格式控制。
4. **下游脚本契约**：`tools/rx/` 下的解析与测试脚本（如 `qa_live_dw3000_console.py`、`run_distance_replay.py`、`low_snr_eval/*.py`）强依赖 `stdout` 行首固定标签（`^LOCK_STATS `、`^COST_TOTAL `、`^RX_GAP `、`FINAL` 等）。

## 2. 技术选型结论

**推荐自研轻量级 header-only `gr-uwb/include/gnuradio/uwb/uwb_log.h`（仅依赖 C++17 标准库），暂不引入第三方日志库。**

- **不直接引入 `spdlog` / `Quill` / `NanoLog` 的原因**：
  - `gr-uwb/CMakeLists.txt` 当前仅依赖 `Volk`、`Threads`、`Boost (unit_test_framework)` 及可选 `UHD`。保持零新增外部依赖，可避免影响 `uwb_native` 和独立安装消费者的跨环境构建。
  - `uwb_dw3000_live` 真正高频的输出（`PACKET` 每秒可达 ~1000 行）属于业务统计与遥测聚合，仍需保留 `Reporter`；而诊断/错误日志本身频率极低，超低延迟日志库（如 `Quill`/`NanoLog`）属于过度设计。
  - 仅当未来明确需要“海量大日志异步落盘 + 自动按大小/时间轮转”时，再考虑切换到 `spdlog`（本机环境已具备 `libspdlog-dev`）。

## 3. 设计约束与接口建议

### 3.1 分层与通道边界

1. **`uwb_core` 继续保持零日志 I/O**：绝不在解调、重采样、SIC 热路径中直接调用日志打印，保持纯函数/结构体返回诊断信息。
2. **结构化遥测（`stdout`）与诊断日志（`stderr`）分离**：
   - `Reporter` 的 `START` / `PACKET` / `SUMMARY` / `HEARTBEAT` / `LOCK_STATS` / `COST_TOTAL` / `FINAL` 格式**保持完全不变**，不得添加 `[INFO]` 或时间戳前缀，以免破坏 `tools/rx/` 解析脚本。
   - 统一日志接口默认输出到 `stderr`（同时支持自定义 sink，如后续需要时路由到 `Reporter` 或独立文件），用于运行期错误、告警、状态流转与调试追踪。

### 3.2 最小接口能力

建议在 `namespace gr::uwb::log` 下提供以下能力：

- **4 个日志级别**：`Error` (`ERR`)、`Warn` (`WARN`)、`Info` (`INFO`)、`Debug` (`DEBUG`)，默认 `Info`。
- **环境变量 + 运行时设置**：
  - 首次使用自动读取 `UWB_LOG_LEVEL`（`error|warn|info|debug|off`）；
  - 提供 `set_level(Level)` / `get_level()`，供 CLI 参数（如 `--log-level`）覆写。
- **惰性求值宏（关闭态零拼接开销）**：
  - 提供 `UWB_LOG_ERR(tag, ...)`、`UWB_LOG_WARN(tag, ...)`、`UWB_LOG_INFO(tag, ...)`、`UWB_LOG_DEBUG(tag, ...)`。
  - 先用 `std::atomic<int>`（`memory_order_relaxed`）检查当前级别，级别不满足时不求值后续流式拼接参数。
- **线程安全与统一格式**：
  - 局部 `std::ostringstream` 组装单行后，在轻量 `std::mutex` 保护下一次输出，格式如 `[WARN][uhd_pipeline] ...`。
  - 提供可选 `set_sink(SinkFn)`，方便测试捕获或接入异步队列。

## 4. 建议落地步骤

1. **阶段 1（基础头文件与单元测试）**：新增 `gr-uwb/include/gnuradio/uwb/uwb_log.h` 及简单单测（级别过滤、惰性求值、自定义 sink、线程安全）。
2. **阶段 2（替换 `uwb_native` 散落 `std::cerr`）**：将 `gr-uwb/lib/uwb_uhd_sc16_pipeline.cc` 中的 16 处 `std::cerr` 按级别迁移至 `UWB_LOG_INFO` / `UWB_LOG_WARN` / `UWB_LOG_ERR`。
3. **阶段 3（`uwb_dw3000_live` 接入）**：在 `uwb_dw3000_live.cc` 增加 `--log-level` 参数，将排障期日志（如锁状态切换细节、自相关暂停/恢复轨迹、异常诊断）接入 `UWB_LOG_DEBUG` / `UWB_LOG_WARN`，保持 `Reporter` 现有 `stdout` 协议不变。
