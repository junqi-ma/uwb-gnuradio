# 原生接收与解调重构执行方案

2026-11-18，适用分支 `feature/sic-research`。本文是待执行方案。目标是让读者从一个入口就能判断一个包将执行哪些计算、什么条件触发重试、最终发布哪次结果，同时守住现有完整帧解码能力、单包耗时和多 worker 吞吐。

## 起点与交付顺序

当前 live 与离线解码器已经共用 `demodulate_one()`，完整包编排位于 `uwb_core`。约 1,200 行的入口仍同时处理同步、旋转缓冲有效性、融合、回退、计时和结果发布。另一个已经实测的问题在 live 的任务提交处。单 worker、盲捕获、SFD-only 且要求 FCS 才能进锁时，同一回放产生 200 个前端候选，队列容量 1 的一次运行只发布了 38 条终态，逐包队列丢弃记录为 0；容量 256 时发布 200 条。小队列的具体数量受调度影响。应先修好分母，才有条件用回放判定后续改动。现有结构和历史数据分别见[代码边界](架构_解调与窗口执行.md)与[开发状态](../开发状态.md)。

| 批次 | 可独立审查的交付物 | 进入下一步的条件 |
| --- | --- | --- |
| 0　冻结基线 | 可重建的工作树、二进制、输入与测试清单 | 同一构建重复运行，能解释固定窗结果和动态波动 |
| 1　修复提交记账 | 复用现有请求类型，补上拒绝终态，删除无调用入口 | 队列满、停止和正常接纳均可按 ID 对账 |
| 2　拆解同步与 CFO | 单独提交旋转范围计算、锚定与重估两步 | 每步逐包等价，默认路径没有增加计算遍数 |
| 3　拆解帧解码与回退 | 共用完整流解码，明确每次尝试的产物与发布者 | 融合成功、融合失败、分数网格和提前结束逐项验收 |
| 4　收窄接口与应用职责 | 减轻公开头依赖，简化 live 调用端 | 安装消费者、阶段 QA 和应用默认配置通过 |
| 5　改进固定周期运行时 | 可选结果留存策略、有序发布与背压 | 顺序、内存、尾延迟和现有消费者分别验收 |

0–3 是解调主线。4、5 可分别交付，固定周期运行时的改造不作为解调重构的前置条件。每个提交只改变一类行为；每批同时对照其父版本和批次 0，防止小幅退化逐步累积。

## 0　固定可重建的参照版本

- 以本次工作树（`82db8d3` 加低 SNR 边界修复和折叠优化）为 A。实施前保存准确的源代码快照，包含参与构建和验证的未跟踪文件，记录提交或补丁哈希、二进制 SHA-256、编译器、CMakeCache、选中的 ISA 和资源文件哈希。单独目录构建 B。已发布的历史均值只作定位线索。
- 保存固定窗的 IQ、包起点、窗口几何、载荷真值和生成参数。零偏差的 200 帧生成器已有仓库入口；将此前六组各 40 帧的生成或导入步骤、CFO/SFO 注入方式、载荷与噪声种子、输入哈希一并固化，避免依赖某台机器的临时目录。[回放工具与数据口径](../tools/rx/low_snr_eval/README.md)
- 在目标机器先用 A 对 A 做串行重复，记录 1 worker 和 4 worker 下各指标的自然波动。单独保存软件回放、paced 回放和硬件测量结果。当前可用低 SNR 证据来自软件，AVX-512 实机、UHD 上板及 MATLAB 逐样点对照按实际完成范围记录。

## 1　统一提交结果，保留两套调度的时序

从 [live 的 Workers 和提交调用点](../gr-uwb/apps/uwb_dw3000_live.cc) 入手。让 `submit` 接受已有的 `PacketRequest` 与窗口数据来源，给返回值加 `[[nodiscard]]`。当前唯一拒绝原因是槽已用完时，可沿用布尔返回值。核实所有构建目标后删除无调用的 `submit_buffer()`。一个窗口持续使用同一 ID；准入时只做现有的环形缓冲到任务槽复制。

明确两个记账时刻：提交方负责拒绝或取消，worker 负责已接纳任务的完成或失败。根据来源更新候选或目标槽统计，在对应流中各记一次。关联去重、主动忽略、尚未装满就 EOF、历史覆盖和意外 gap 各自保留原因；计划中的 timed 间隙维持原语义。分别报告前端种子、提交尝试、已接纳、因队满拒绝、完成解调、完整帧 FCS。对照历史报表时注明盲捕获漏记对分母的修正。

验收用一个可控 worker 占住唯一槽，提交第二个任务，确定性断言第一次成功、第二次拒绝、停止后两者各有一条可核对的结局。再跑上述 200 帧过载回放，核对 ID 与来源；测试断言对账成立，不固定线程时序下的 38。live 完成后立即推送观察，由 RX 线程更新锁；固定周期路径按 `window_id` 发布。两套规划者和队列继续各自满足其顺序要求。

## 2　拆解同步与 CFO，显式传递可用样点范围

改动中心为[完整包编排](../gr-uwb/lib/uwb_demod_pipeline.cc)，复用[整数网格准入](../gr-uwb/include/gnuradio/uwb/uwb_demod_execution.h)。先在同一编译单元内提取私有函数，便于编译器内联，也便于逐次比较。建议分两次提交。

1. **提取范围计算。** 先列出 bootstrap SFD、尾部 CIR、最终 SFD、PHR 前缀和 payload 各自会读取的窗口内样点。把预测覆盖与锚定后实际覆盖中相同的几何计算收在一处，保留各自的起点、保护区和截断规则。用半开区间表达范围，记录该区间对应的 CFO 和相位基准。仅有相同的最高样点索引不足以证明前面的样点都有效。对窗口两端、空区间、重新拟合 CFO 以及宽 SFD 救援分别测试。
2. **提取锚定与重估。** 顶层保留可见的调用顺序：初始 timing → 包级网格准入 → 初始 CFO 与 bootstrap SFD → 尾部重跟踪和 CFO 选择 → 最终 SFD。该段交出最终接受的 timing、CFO、SFD、已旋转的有效范围或明确的失败阶段。大数组留在 worker scratch，阶段间传引用或移动已有结果。保留单符号延迟粗 CFO、原门限、符号偏移窗内逐样点搜索、宽网格救援及最终 SFD 不一致时的重试。

原始 profile 描述请求，`PacketExecutionPlan` 记录本包允许使用的路径。审查每处读取原始或有效 profile 的理由，特别是预测范围、实际旋转、前缀预算和融合准入；先固定现有决策次序与数值。若发现可省一次旋转或一次尾部搜索，另立优化提交，单独证明所有读取的相位和覆盖区间等价。此前 `LockedBounded` 尾部重试原型在 +27 ppm 动态回放存在波动，继续保留现有生产路径。

## 3　整理帧解码，给每层重试一个所有者

| 决策位置 | 输入与产物 | 必须保留的行为 |
| --- | --- | --- |
| 包入口 | 工作速率的绝对预测起点、窗口起点；各阶段使用窗口相对样点 | 每次完整尝试调用 `begin_packet()`，退出时统一发布、按字段转换坐标一次；SFD-only 在最终 SFD 后返回 |
| 融合或按需前缀路径 | 已验证的网格、有效旋转区、CIR、NS-SFD；PHR 解出长度后确定 payload 范围 | PHR 硬判决与 LLR 仅供本次尝试，同包可复用；保持已有按需扩展、软判决与 FEC 救援顺序 |
| 完整 soft-chip 路径 | 有效 profile、完整覆盖的输入、选定 timing/CFO | 分数网格使用请求的 CIR 模式；保留逐样点插值。融合/按需失败按既有条件执行一次完整流回退 |
| live 的 auto CIR | 单包结果、独立 CRC、调用者选择的模式 | 由现有 `PacketProcessor` 决定是否用 Full CIR 重跑整包，复用本窗重采样数据；离线完整包 API 保留其现有语义 |

先把“生成完整 soft-chip → NS-SFD → PHR → payload/FCS”提取为直接调用的私有函数，供普通完整流与包内回退复用。两者显式传入原有 profile、输出位置与计时方式，保留首次尝试的逐阶段计时和回退的独立累计。随后提取快速尝试和最终发布逻辑。回退失败时，状态、CIR、PHR 和 payload 均取自实际决定终态的那一次尝试。单阶段函数只处理该阶段输入和工作区；计时器、Reporter、锁状态机和 UHD 对象无需传入算法内核。[完整流与回退实现](../gr-uwb/lib/uwb_demod_pipeline.cc) · [外层重试](../gr-uwb/apps/uwb_live_packet_processor.h)

热路径约束：每 worker 继续持有一份预分配 scratch，保持跨包模板缓存与包内决策缓存各自的重置点；`corr` 和需要跨阶段存活的 `softchip_corr` 分开。逐样点、逐 chip、逐 tap 循环沿用编译期 SIMD 和直接调用。检查热身后的每包堆分配、IQ/soft-chip 复制量、CFO 旋转样点数、FIR 与解码遍数相对 A 的变化；诊断插桩单独运行，正式测速关闭它。

## 4–5　收窄接口，拆开固定周期的排序与留存

**公开接口与 live。** 先画出安装消费者实际包含的头。移走仅供实现使用的依赖；对需要完整定义才能实例化的 `DemodScratch`，保留现有包含及构造方式。只有实测仍有必要时，才增加每 worker 构造一次、私有持有 scratch 的完整包接口，并让兼容入口共用同一实现。live 入口保留参数解析、资源组装和生命周期，提取按来源提交窗口与处理终态的逻辑。验收独立安装消费者、单阶段 QA、原生离线与 live，以及 Python 的 `--` 透传。C++ 默认 fused/on、CIR/full、eq16，Python 默认 CIR/auto，timed 无 replay 返回 2。[公开入口](../gr-uwb/include/gnuradio/uwb/uwb_demod_pipeline.h) · [构建与入口契约](原生UHD与C++构建使用说明.md)

**固定周期运行时。** 单独改造 `commit_result()` 与停机 flush 共用的发布逻辑。默认保留 `results()` 全量留存，增加显式的仅回调模式。先在锁内确认连续可发的 ID，再由唯一发布者按序在锁外调用用户回调，保证回调期间结果对象有效，保持原 `commit_time` 计时边界。给乱序跨度与待发数量设可观测上限；容量用尽时在接纳新任务前执行背压或显式拒绝，为最早未完成窗口预留完成空间。停止时先排空已接纳任务，再完成发布。用慢回调、首窗延迟、队满、取消空洞和 EOF 验证无死锁、顺序和恰好一次通知；测 RSS 随运行时长的趋势、重排峰值、回调等待和吞吐。仅回调模式的留存内存应达到平台期。[固定周期结果提交](../gr-uwb/lib/uwb_uhd_sc16_pipeline.cc)

## 验收矩阵与退回条件

| 层次 | 必跑用例 | 判定依据 |
| --- | --- | --- |
| 构建与 API | Release，AUTO 记录实际选择；SCALAR、AVX2、AVX-512 分档；隔离安装消费者 | 同一 ISA 比对 A/B，维持既有 QA 容差。无对应 CPU 的档位标“仅编译”。使用 `env -u LD_LIBRARY_PATH` 与临时安装前缀 |
| 固定窗 DSP | 已有 +4/−12/−14 dB 固定窗；六组各 40 帧覆盖强信号、两组弱信号、+10/+40 kHz CFO、+27 ppm SFO。另覆盖整数/分数网格、融合开/关、auto Full、边界截窗与连续包缓存污染 | 同窗逐包核对状态、SFD 样点、CFO、PHR、载荷字节、FCS、非耗时诊断；有真值的夹具再独立核对载荷。既有 +40 kHz、+27 ppm 分别为 38/40、37/40。失败帧也须逐项一致 |
| 调度与正确性 | acquire、locked、timed replay；队满、gap、停止排空、乱序完成。−14 dB 加 SFD-only；噪声输入检查误报 | 分开报告前端种子、SFD 锁定、完整 FCS 和队列拒绝。用相同完成事件序列确定性比较反馈；动态回放另看 FCS、进锁、失锁与丢弃。记账修复单列预期差异 |
| 时间与吞吐 | +4 与 −12 dB，1 worker/队列 256、4 worker/队列 24；加测 +40 kHz、+27 ppm 及频繁回退场景。每次串行 ABBA，必要时反序复测 | 记录单包 demod、compute、排队到完成、吞吐及成功帧数。逐包原始记录计算全流 P95/P99；延长同条件回放或独立重复以获得足够尾部样本。各档单列，不跨档抵消 |

先用 A/A 报告测量噪声和可分辨的退化幅度，确定业务可接受的最小差异并在看 B 之前写入基线记录。以独立 ABBA 批次为单位计算 A/B 配对相对变化和置信区间。对延迟看区间上界，对吞吐看区间下界，只有落在预登记的非劣界内且无可重复的恶化趋势才通过。噪声大到无法判断时，固定 CPU 与负载、增加独立批次再测，结果记为待定。历史四 worker 两轮耗时变化方向相反，单轮加速和单轮减速都不足以签收。对稳定的 0 ppm、−12 dB 200 帧场景，另核对既有 191/200 与零队列丢弃。若 CFO/SFO 下动态路径分叉，先取相同窗口和调度事件复查，再以相同 pacing 重测端到端。

**执行入口。** 对 A、B 各按[原生构建说明](原生UHD与C++构建使用说明.md)构建；在仓库根目录设置 `BUILD_B`、`DECODER_A/B`、`LIVE_A/B`（分别指向两个版本的对应二进制）、`FIXTURES` 和 `RUN_DIR`。例中为已归档的零偏差用例；注入 CFO/SFO 的用例使用批次 0 固化的独立起点与真值。

```sh
env -u LD_LIBRARY_PATH ctest --test-dir "$BUILD_B" --output-on-failure -j1
env -u LD_LIBRARY_PATH python3 tools/rx/low_snr_eval/compare_packets.py \
  "$DECODER_A" "$DECODER_B" --fixtures "$FIXTURES" --out "$RUN_DIR/fixed"
env -u LD_LIBRARY_PATH python3 tools/rx/low_snr_eval/ab.py \
  "$LIVE_A" "$LIVE_B" "$RUN_DIR/locked-w1.json" --fixtures "$FIXTURES" --only=-12/locked/w1
env -u LD_LIBRARY_PATH python3 tools/rx/low_snr_eval/ab.py \
  "$LIVE_A" "$LIVE_B" "$RUN_DIR/locked-w4.json" --fixtures "$FIXTURES" --only=-12/locked/w4
```

`ab.py` 的 summary 与 packets 来自两次运行，summary 的批次 P95 均值不能充当全流 P95。另存逐包输出及调度统计，随报告记录源版本、CPU、ISA、编译选项、频率/亲和性、worker/queue、完整命令、种子和输入哈希。触及检测位置或样点换算时，按同 IQ、同起点与 [MATLAB 参考实现](../UWB_demodulation/)逐包逐样点交叉检查，记录索引基准；未完成的项目显式列为待验。

**发布与回退。** 每批交付代码、针对该风险的 QA、逐包差异和配对性能摘要。出现未预期字段差异、完整帧倒退、热路径新增整窗复制或重复计算、可重复的耗时退化时，停在该批并定位首个差异提交。已验收的记账修复可独立保留；撤回引入差异的实现后，用相同输入重跑。软件、MATLAB 与上板证据分别注明适用范围。
