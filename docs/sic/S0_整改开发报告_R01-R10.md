## 2. R01：实际输出的消除效果未被指标覆盖

**根因**：原实现把“完整重构 `i_hat` 与真值 `i` 的 NMSE”当成消除效果，但真正提交到
输出的相减量（`delta_actual = y − y_clean`）可能只覆盖 `i_hat` 的一小段符号；未 commit
时也按“已消除”统计。完整重构极准 ≠ 干扰被去掉。

**代码位置**：`gr-uwb/apps/uwb_sim_preamble_sic.py`（`i − i_hat` 计算，原 `:1764`）；
`gr-uwb/lib/uwb_preamble_sic_core.cc`（实际相减 mask，原 `:1379`）。整改后：
新增字段在 app 的 `recon`/`summary.effect`，独立复算在
`tools/sic/verify_s0.py`（R01 段，`verify_s0.py:340` 起）。

**反例修复前-后结果**：
- 修复前：只报重构 NMSE/抑制度，无 ACTUAL 口径；行为无法把
  “`i_hat` 准但只相减少量符号”的窗口判为不足。
- 修复后（真实 run）：
  - `case_a_tiny_mask`（完整 `i_hat` 准、只相减小 mask）：`recon_suppression=28.283 dB`
    但 `actual_suppression=1.256 dB`、`coverage=0.2515` → **`judged_insufficient=true`**。
  - `case_b_uncommitted`（有 `i_hat` 但未 commit）：`actual_suppression=0.0`、
    `recon=0.0` → **`judged_not_cancelled=true`**。
  - 名义 cell（`c24_isr10_off0_cfo0_single`）：**ACTUAL 12.047 dB**，
    重构诊断 28.333 dB。
  - 主矩阵总体（7200 窗）：**中位 ACTUAL 11.9417 dB**、`frac_actual_ge_3db=1.0`、
    `coverage` 中位 **0.9390**。
  - verifier 从 `recon/window_*.npz` 的 `y/y_clean/i/i_hat` 数组在**真值重叠区**
    `[overlap_lo,overlap_hi)` 上复算 ACTUAL，不从声明 mask 合成输出。

**命令**：

## 3. R02：效果/性能配置不一致，相减长度与验证长度耦合

**根因**：benchmark 固定 fit=8/validation=8；效果脚本曾把 validation 静默调到 56；
核心以 `confirmed*sps + post_tail` 定义支持长度，`confirmed` 又受
`fit_reps + validation_reps` 限制；搜索 ROI 与相减 ROI 混用，用候选起点范围截掉了
自然拖尾。

**代码位置**：`gr-uwb/apps/benchmark_preamble_sic.cc`（原 `:628` 固定 8/8）；
`gr-uwb/apps/uwb_sim_preamble_sic.py`（原 `:1227` 自动改 8/56；整改后
`:2217`–`:2250` 的显式窗口处理与 `--sic-cover-preamble`）；
`gr-uwb/lib/uwb_preamble_sic_core.cc`（原 `:1238` 支持长度定义）。

**反例修复前-后结果**：
- 修复前：8/8 与 8/56 的观测被程序无声改写；相减支持长度受 `roi_hi` 截断。
- 修复后：
  - 明确命名并逐窗记录：`fit_len`、`estimation`（含 CFO/路径/分数/增益所需数据）、
    `online_validation`、`independent_eval`、`signal_start/stop`、`sub_lo/sub_hi`
    （`main_r10` 名义窗：`fit_len=8128`、`online_validation=[10125,62957)`、
    `eval=[62957,67021)` 长 4064、`subtraction_roi=[1997,63057)`、
    `coverage=0.9390`）。
  - **搜索 ROI 与相减 ROI 分开**：`search_roi=[1997,67021)`、
    `core_roi/subtraction_roi=[1997,128081)`（`roi_semantics` 明确二者语义）。
  - 去除静默提升：短观测得到**真实的 partial mask**并如实上报 coverage/partial；
    全覆盖是显式 `--sic-cover-preamble`（`fit_reps_source=explicit_cover_preamble`，
    记录并计时）。
  - 不可满足配置 `fit_reps+validation_reps > sync_reps` 直接拒绝，不改写。
  - `effective_config_hash=d559bdea…`；8/8、8/16、8/52、8/56 的差异可解释。

**命令**：

## 5. R04：目标保护使用逐窗 L2-normalized CIR 幅度

**根因**：`target_amp` 取自 `cir_norm`（逐窗 L2 归一化）。归一化会抵消共同增益变化，
把残余能量变化混入目标幅度比，且全局最大峰不等于预设弱目标峰。

**代码位置**：`gr-uwb/apps/uwb_sim_preamble_sic.py`（原 `:1959` `target_amp` 来自
`cir_norm`）。整改后：固定校准 ROI 配置 `testdata/sic_preamble/cases/target_roi.json`，
raw CIR 指标在 app 与 verifier。

**反例修复前-后结果**：
- 修复前：只有归一化幅度，无法区分“整体衰减、形状不变”。
- 修复后：固定目标 ROI `[51,60)`（sensing profile `code9-64SYNC-4z2`，校准集冻结，
  `roi_fixed_across_windows=true`，参考幅度 `0.115741`），使用**未做逐窗 L2 归一化的
  复数 CIR**：
  - 主矩阵 raw 目标（**池化总体，7200 窗**，`main_sweep_r10b/main_matrix.json` 的 `overall`）：
    `target_amp_abs_err_db_p95=0.4737314363684091`≈**0.474 dB**。
    另一聚合（回归脚本 `main_sweep_r10/r10_regression_summary.json` `raw_target`，按 cell 先聚合）
    报 `amp_abs_err_db_p95=0.295 dB`、`amp_abs_err_db_max=0.525 dB`；
    `target_phase_err_deg_p95=3.13°`（max 5.27°）、`target_peak_shift_max=0`、
    `weak_target_detected_frac=1.0`、`false_peak_max=7`；`frac_amp_le_1db=1.0`。
    **两聚合不是同一量，以池化总体 0.474 dB 为准**。
  - 名义 cell：`target_amp_abs_err_db_p95=0.238`、峰移 0、弱目标检出 1.0。
  - L2-normalized 指标保留为**形状诊断**（`normalized_target_amp_*`），不再作为 gate。
  - 对抗测试项：整体衰减/形状不变、主峰保持但弱目标丢失/移动两类反例由 verifier 判定。

**命令**：同 §3 的 `main_r10` run；独立复算
