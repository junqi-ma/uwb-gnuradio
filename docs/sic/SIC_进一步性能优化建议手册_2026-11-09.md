## 三、 路线一（Full-packet SIC & 通信/感知解调器）修改详解

### OPT-NEXT-01：消除 `stage_sfd` 中冗余的尾部 40-SYNC 重跟踪与重复 CFO 旋转（E0 级，立省 ~180–250 µs）

* **文件与位置**：`gr-uwb/include/gnuradio/uwb/uwb_demod_core.h`
  * 初次 64-SYNC 跟踪与初次 CFO 拟合：`L2874-L2910`
  * Bootstrap SFD 搜索：`L2919-L2950`
  * 尾部 40-SYNC 重跟踪与 CFO 重拟合 `run_tail_and_cfo_refit`：`L2981-L3145`
  * 最终 SFD 验证 `run_final_sfd`：`L3148-L3195`
* **根因剖析（代码级实证）**：
  1. 在 `L2874` 的初次 `stage_timing(rx, n, ...)` 中，算法已经在**原始未旋转信号 `rx`** 上跟踪了全部 64 个 SYNC（`k = 0..63`），每个符号调用 `local_best(want, radius=8, threshold=0.20)`，得到了 `res.timing.peak_samples[0..63]`、`peak_metrics[0..63]` 和 `peak_corr[0..63]`。
  2. 在 `L2885` 的初次 `fit_cfo` 中，当 `detected_peaks == 64` 时，`skip = 24`，使用 `res.timing.peak_samples[24..63]` 与 `peak_corr[24..63]`（即**后 40 个峰**）拟合出 `res.cfo.cfo_hz`。
  3. 随后 `bootstrap_sfd` 找到 `bootstrap_sfd_start`，并在 `L2971` 计算尾部 40 个 SYNC 的起点：
     ```cpp
     const int64_t tail_start = bootstrap_sfd_start -
         static_cast<int64_t>(std::llround(static_cast<double>(tail_repetitions) * period_hint));
     ```
  4. 紧接着在 `L2987`，`run_tail_and_cfo_refit` **再次在同一个原始未旋转信号 `rx` 上调用 `stage_timing(rx, n, anchor, template_wf, tail_start, ...)`**！
     * 请注意：当 `res.timing.detected_peaks == full_repetitions`（64 峰完整）且 `bootstrap_sfd` 锁定的 `tail_start` 与初次跟踪的第 24 个符号起点 `init_tail_start = res.timing.peak_samples[24] - (L - 1)` 差值在窄搜索半径内（实际上正常帧 `bootstrap_sfd` 无整符号回退时，`tail_start` 落点使 `local_best(tail_start, 8, ...)` 找到的 `first_start` **严格等于 `init_tail_start`**！）时：
     * 第二次 `stage_timing` 对 `k = 1..39` 计算的 `want = first_start + k * 1016` 与第一次 `stage_timing` 对 `k = 25..63` 计算的 `want` **完全相等**，调用的 `local_best` 参数（`radius = 8`, `threshold = 0.20`, 输入 `rx`, 模板 `template_wf`）**100% 相同**！
     * 换言之，程序花费了 **171.5 µs**（640 次 1016 点 VOLK 点积）去重新计算数组中已经存好的 `res.timing.peak_samples[24..63]`！
  5. 不仅如此：由于这 40 个尾部峰与初次完全一致，接下来的 `fit_cfo`（`L3067`）算出的 `res.cfo.cfo_hz` 与初次 `cfo_hz` **逐位相等（Bit-exact）**！
  6. 然后 `derotate_cfo_range`（`L3134`）用完全相同的 `cfo_hz` 对 `[sec_lo, sec_hi)` 重新旋转（把刚刚在 `L2899` 已经旋转过的 `[boot_sfd_lo, boot_sfd_hi)` 又覆盖旋转了一遍），最后 `run_final_sfd`（`L3151`）又在完全相同的 `scratch.derotated` 数据上把 `stage_sfd` 重跑了一遍（耗时 **78.5 µs**）！
* **修改方案（严格 E0 逐位等价快速路径）**：
  1. **尾部 40 峰直接复用**：在 `run_tail_and_cfo_refit` 中，若初始 `res.timing.detected_peaks == full_repetitions`（64），先仅对 `tail_start` 做一个单符号 `local_best(tail_start, seed_radius, 0.20f, &first_tail_pos, ...)`（仅 16 次点积，耗时 ~4 µs）：
     * 若 `first_tail_pos == res.timing.peak_samples[full_repetitions - tail_repetitions] - static_cast<int64_t>(template_len - 1)`（即起点与首遍第 24 个峰完全重合），则后续 `k = 1..39` 的 `want` 必然与首遍 `k = 25..63` 完全一致，直接从 `res.timing` 切片复制后 40 个峰的 `peak_samples`、`peak_metrics`、`peak_corr`，并按那 40 个峰做一次 `O(40)` 线性拟合得到 `tail_timing.measured_period`，**直接省去 39 个符号的 624 次 1016 点相关（立省 ~165 µs）**！
     * 若 `first_tail_pos` 不重合（例如发生了整符号跳变或弱前导偏移），则无条件走原有 `stage_timing` 完整重跟踪，保证所有边界场景 100% 兼容。
  2. **增量 CFO 旋转与跳过冗余 `final_sfd`**：
     * 记录首次 CFO 频率 `boot_cfo_hz` 与首次旋转区间 `[boot_sfd_lo, boot_sfd_hi)`。
     * 若重拟合后的 `res.cfo.cfo_hz == boot_cfo_hz`（浮点逐位相等）：
       * `derotate_cfo_range` 仅需补旋转 `[sec_lo, boot_sfd_lo)` 与 `[boot_sfd_hi, sec_hi)` 差集区间，无需重复旋转 `[boot_sfd_lo, boot_sfd_hi)`（省 ~15 µs）；
       * 若此时 `cfo_timing` 计算出的 `expected_sfd` 与 `bootstrap_sfd` 的 `expected` 相同，则 `run_final_sfd()` 的输入数组、参数、搜索窗口与 `bootstrap_sfd` 100% 逐位一致，可直接复用 `res.sfd` 结果（再省 **78.5 µs**）！

### OPT-NEXT-02：`stage_sfd` 波形域相关的符号折叠与零符号稀疏化（E0/E1 级，省 ~60–110 µs）

* **文件与位置**：`gr-uwb/include/gnuradio/uwb/uwb_demod_core.h:L730-L868`
* **根因剖析**：
  * SFD 序列长度为 8 个符号（`sym = 1016` 样点），模板为 $\text{sfd\_tmpl} = c_{\text{norm}} \cdot (\text{sfd\_sequence} \otimes \text{template\_wf})$，总长度 `sfd_len = 8128`。
  * 在 IEEE 802.15.4a/4z 标准与 QM35 配置中，8 符号 SFD 序列元素属于 $\{-1, 0, +1\}$（例如 `kQm35LegacySfd = {0, 1, 0, -1, 1, 0, 0, -1}` 中有 **4 个符号全为 0**，仅 4 个符号非零；4z2 SFD 同样仅由 $\pm 1$ 极性组成）。
  * 当前 `sfd_dot(j)`（`L770-L777`）对每个候选偏移 `j` 直接调用 `rxopt::conjugate_dot(rx + j, sfd_tmpl, 8128)`，每次执行 **8,128 点复数乘加**（32 个候选点共计 260,096 次复乘），其中包含大量与 0 的无效乘法以及与同一 `template_wf` 的 8 次重复相关。
* **数学恒等变换**：
  * 利用内积的线性性质：
    $$\langle \text{rx}[j : j + 8L],\, s \otimes w \rangle = \sum_{m=0}^{7} s_m \langle \text{rx}[j + mL : j + (m+1)L],\, w \rangle = \left\langle \sum_{m:\, s_m \ne 0} s_m \cdot \text{rx}[j + mL : j + (m+1)L],\; w \right\rangle$$
  * 先在 `scratch` 的 1016 点临时缓冲中将非零符号段 `rx[j + m*1016 ..]` 按极性 $s_m \in \{+1, -1\}$ 做向量加减折叠，再与单个归一化 `template_wf`（长度 **1016**）做**一次** `volk_32fc_x2_conjugate_dot_prod_32fc_u`：
    * 复数乘法次数从 **8,128 次骤降至 1,016 次（减少 87.5%！）**；
    * 此外，`sfd_tmpl` 不再占 64 KB（超出 L1 Data Cache 32 KB），而 `template_wf` 仅占 **8 KB**，完全常驻 L1 Cache！

### OPT-NEXT-03：`stage_timing` 窄半径跟踪与稀疏抽样 SYNC 跟踪（E1 级，省 ~200–260 µs）

* **文件与位置**：`gr-uwb/include/gnuradio/uwb/uwb_demod_core.h:L374-L526`、`gr-uwb/apps/fullpacket_rx_pipeline.h`
* **根因剖析**：
  * 初始 `stage_timing` 耗时 **376.6 µs**，其中：
    1. **种子搜索过宽**：在全包 SIC 中，前缀估计器 `estimate_discrete_cir` 已经在粗 ROI 内以步长 1 找到了精确的通信包起点 `q`，并传给 `FastRxPipeline` 作为 `rel_seed`。但若 `timing_seed_refine_radius` 未收紧，`local_best` 仍按 `legacy_seed_radius = 256`（512 个点，即 512 次 1016 点点积！）搜索第一个峰。
    2. **64 个符号逐一宽半径（$\pm 8$）搜索**：在 `L511-L526` 循环中，对 `k = 1..63` 每个符号都在 `want = start + k * 1016` 附近搜索 `radius = 8`（16 个点），共做 $63 \times 16 = 1,008$ 次 1016 点复数点积。然而物理上，UWB 晶振 SFO（通常 $< \pm 20\text{ ppm}$）在单个符号（1.018 µs）内的漂移小于 **0.02 个样点**，即使跨越全部 64 个符号总漂移也不足 1.3 个样点！
* **修改方案**：
  1. **SIC 种子直通模式**：当 `rel_seed` 来自已确认的 SIC 前缀估计器 `q` 时，首符号捕获半径设为 `timing_seed_refine_radius = 4`（失败再回退 `256`）。
  2. **两级自适应跟踪半径（Adaptive Track Radius）**：
     * 在 `L511-L526` 跟踪循环中，维护当前实测位置 `last_pk`（而非死板锚定 `start + k * period`）。每个后续符号的期望位置更新为 `want = last_pk + period`。
     * 先在窄半径 `radius_narrow = 2`（仅 4 个点，计算量减少 **75%**）内搜索；仅当某符号峰值低于阈值时，才对该符号回退到 `radius = 8` 搜索。
  3. **可选：间隔抽样跟踪（Decimated SYNC Tracking）**：
     * 如 `SIC完整流水线与MATLAB对齐_2026-11-08.md` 所规划，先在 MATLAB 对齐验证每隔 $D = 2$ 或 $4$ 个符号抽样跟踪并插值，确认在弱起始 SYNC 与大 CFO 下解调无损后移植至 C++，可将跟踪点积次数再砍掉 50%~75%。

### OPT-NEXT-04：稀疏脉冲重构与 ROI 相减原位融合，省去 1 MB `ihat` 清零（E0 级，省 ~55–75 µs）

* **文件与位置**：`gr-uwb/lib/uwb_discrete_cir_reconstruct.cc:L605-L674`
* **根因剖析**：
  * 根据最新剖析数据（`SIC完整流水线与MATLAB对齐_2026-11-08.md` 第 6、7 节），在施加信道（`110.8 µs`）与相减（`98.8 µs`）共 **209.6 µs** 中：
    * **重构缓冲区清零**（`std::fill_n(recon, recon_len, 0)`，写 `133,588` 个 `complex<float>` = 1.07 MB）耗费了 **52.1 µs**；
    * **AVX2 20-tap 事件 CIR 叠加**（写 `recon`）耗费 **55.2 µs**；
    * **ROI 相减与两侧复制**（读 `y` 和 `recon`，写 `out[j] = y[j] - recon[j]`）耗费 **98.8 µs**。
* **修改方案（当调用方不需要单独导出 `ihat`，即 `ihat == nullptr` 时）**：
  1. 先执行 `std::copy_n(y, n, out)`（或对相减区间 `[sub_lo, sub_hi)` 拷贝 `y -> out`）。
  2. 在 `accumulate_pulses_tap20_avx2` 中，将目标指针直接指向 `out + support_lo`，并把内核中的累加符号反转（即 `out[pos + l] -= pulse_val * g[l]`；零 CFO 下 `sign > 0` 执行 `_mm256_sub_ps`，`sign < 0` 执行 `_mm256_add_ps`）。
  3. **收益**：
     * **彻底消除 `recon` 缓冲区的 1.07 MB 清零（立省 52.1 µs）**；
     * **彻底消除第二遍遍历 `recon` 和 `out` 的 `out[j] = y[j] - recon[j]` 循环（再省 ~25 µs）**；
     * 由于每个脉冲事件直接原地修改 `out`，加减法顺序与先加到 `0` 再从 `y` 减去仅在多重叠脉冲尾数舍入上有 $10^{-7}$ 级差异（若要求严格 E0 逐位一致，可仅对 `[sub_lo, sub_hi)` 内的 `recon` 做按块 L1 Cache 分块清零+相减，每次只处理 4096 点 = 32 KB，同样可消除 2 MB 跨 L2/L3 Cache 的内存带宽瓶颈）。

### OPT-NEXT-05：前缀估计器粗 ROI 搜索步长优化（E0/E1 级，省 ~65–85 µs）

* **文件与位置**：`gr-uwb/lib/uwb_discrete_cir_estimator.cc:L810-L855`
* **根因剖析**：
  * `estimate_discrete_cir` 总耗时 `211.9 µs` 中，**检测与重复确认占了 `130.1 µs`（61.4%）**。
  * 原因是在粗 ROI `[1792, 2304)`（512 个样点）上，代码以步长 `stride = 1` 密集调用了 512 次 `1016` 点复数点积。
* **修改方案**：
  * 由于此处使用的是**带脉冲成形（RRC/升余弦，2 sample/chip）的公开 SYNC 波形**，其自相关主瓣半宽 `autocorr_half >= 2` 样点，相邻 1~2 个样点的归一化相关值高度连续且单峰平滑。
  * 采用与 `uwb_preamble_sic_core.cc` 相同的 **两级搜索（Coarse Stride = 2 或 4 + 粗峰附近 $\pm \text{stride}$ 步长 1 细搜）**：
    * 当 `coarse_stride = 4` 时，点积次数从 $512$ 次降至 $512 / 4 + 7 = 135$ 次（**减少 73.6%**），检测耗时可从 `130.1 µs` 压降至 **~35–45 µs**，而细搜仍保证最终锁定完全相同的整数峰值起点 `q`！

## 四、 路线二（Preamble-only SIC 核心 & GR 适配层）修改详解

### OPT-NEXT-06：落地 `P3-A`（去 CFO 域拟合）+ `P3-B`（8 符号周期训练行压缩）（E1 级，省 ~450–550 µs）

* **文件与位置**：
  * `gr-uwb/lib/uwb_preamble_sic_core.cc`：`estimate_impl`（`L1738-L2050`）
  * 设计依据：`docs/sic/SIC重复训练压缩设计_2026-10-19.md`
* **根因剖析**：
  * 在 `estimate8`（~1,185 µs）中，训练窗口长度 $M = 8 \times 1016 = 8,128$。
  * 当前 `refine_init_columns`（121.5 µs）、`refine_init_qr`（131.0 µs）、`refine_resid`（177.3 µs）、`refine_candidate`（148.2 µs，生成 63 列 × 8128 点）、`refine_project`（106.3 µs，63 次 8128 点点积）以及最终 `gain_fit`（~160 µs）全部在 **$M = 8,128$** 的全展开维度上运算。
* **修改方案**：
  1. **开关化实现 `UWB_SIC_DEROT_FIT` (P3-A) 与 `UWB_SIC_ROW_COMPRESS` (P3-B)**：
     * 先利用 `fill_rot` 生成的旋转向量将训练段观测 $y[\text{fit\_lo} \dots]$ 去旋转一次得到 $z = D^H y$。
     * 利用前导训练段由 8 个周期为 `sps = 1016` 的相同 SYNC 符号构成的性质：对于最大多径跨度 $\tau_{\max} < \text{post\_tail}$，仅首符号头部 `[0, post_tail)` 与末符号尾部存在跨周期边界效应，中间约 $7 \times 1016$ 行在周期 `1016` 下完全重复！
     * 利用正交分解恒等式：
       $$\sum_{r=0}^{R-1} |z_r - u h|^2 = R |\bar{z} - u h|^2 + \sum_{r=0}^{R-1} |z_r - \bar{z}|^2$$
       将重复的 $R$ 行压缩为单行 $\sqrt{R} u$ 与 $\sqrt{R} \bar{z}$，并保留常数能量项 $E_{\text{const}} = \sum |z_r - \bar{z}|^2$ 用于恢复精确的 `fit_residual`。
  2. **收益**：
     * 压缩后有效行数从 $M = 8,128$ 降至 $M' \approx 1,016 + \text{边界行} \approx 1,100$（**缩减约 7.4 倍**）。
     * 63 次候选列构造、63 次点积、残差更新与两次 Householder QR 的耗时同步缩减约 **70%~80%**，预计直接节省 **450 ~ 550 µs**。

### OPT-NEXT-07：整数 CIR 初筛改用 VOLK 单精度点积 / 稀疏三元相关（E1 级，省 ~150–170 µs）

* **文件与位置**：`gr-uwb/lib/uwb_preamble_sic_core.cc:L1577-L1592`
* **根因剖析**：
  * 当前代码在 `estimate_impl` 的步骤 `5b. cir` 中计算 `nd = 108` 个整数延迟的 CIR 幅度：
    ```cpp
    for (size_t idx = 0; idx < nd; ++idx) {
        ...
        dcp acc(0.0, 0.0);
        const dcp* sc = scratch.sync_conj_d.data();
        const cplx* yy = y + pos;
        for (size_t k = 0; k < Ls; ++k)
            acc += sc[k] * dcp(yy[k]);
        c = cplx(static_cast<float>(acc.real()), static_cast<float>(acc.imag()));
        ...
    }
    ```
  * 该段对 `108 × 1016 = 109,728` 个点执行标量 `std::complex<double>` 乘加，最后又强转回 `float` 存入 `scratch.cir[idx]`，且该结果**仅用于选出前 $K$ 个局部极大值的整数索引 `cand_delay`**（后续会做 0.05 样点精度的分数时延精化与双精度 QR 拟合）。
* **修改方案**：
  * 将内层标量双精度循环替换为 `volk_32fc_x2_conjugate_dot_prod_32fc_u(&c, yy, syncn, static_cast<unsigned>(Ls))`（与 `norm_at` 完全一致的 VOLK AVX2/FMA 内核）。
  * 耗时可从 **~202 µs 骤降至 ~25–30 µs**（立省 **~170 µs**），且由于仅用于整数粗峰位置排序，单精度 AVX2 累加的 7 位有效数字对局部峰排序完全充裕。

### OPT-NEXT-08：消除 `gain_fit` 前冗余全矩阵 `isfinite` 扫描并跨阶段复用训练段 `ihat`（E0 级，省 ~50–70 µs）

* **文件与位置**：`gr-uwb/lib/uwb_preamble_sic_core.cc:L2034-L2088`
* **根因剖析**：
  1. 在 `L2034-L2040` 中，每次调用 `detail::qr_cond_solve` 前都会遍历 $K \times 8128$ 个 `complex<double>`（65,024 个 double）检查 `std::isfinite`；但进入 `qr_cond_solve` → `qr_factor_rhs`（`L533-L540`）后，第一件事就是计算每一列的平方和范数 `nrm` 并检查 `if (!(nrm > 0.0) || !std::isfinite(nrm)) return false;`。根据 IEEE-754 浮点标准，任何元素为 `NaN` 或 `Inf` 必然使 `nrm` 为 `NaN` 或 `Inf`，因此外层的独立全矩阵扫描完全冗余。
  2. 在 `L2073-L2088`（`model_prepare`，耗时 ~51 µs）中，为了计算 `fit_residual`，调用了 `reconstruct_region(fit_lo, Mfit, model, ...)` 生成了训练区间 `[fit_lo, fit_lo + Mfit)`（8,128 点，即 2 个 4096 重建块）的 `ihat`。但 `reconstruct_region` 在入口（`L394`）无条件把 `s.recon_valid = false`，导致紧随其后的 `apply_model`（`backfill` 阶段，耗时 ~50 µs）又对完全相同的 `[fit_lo, fit_lo + Mfit)` 重新跑了一遍多相累加、CFO 旋转和类型转换！
* **修改方案（严格 E0 逐位一致）**：
  1. 移除 `L2034` 的外层 `std::isfinite` 循环（保留 `qr_factor_rhs` 内部的列范数与对角元 `isfinite` 检查，所有 R05 注入 NaN/Inf 的 QA 用例 100% 保持原样拒绝）。
  2. 在 `scratch` 中保存 `model_prepare` 阶段生成的训练段 `ihat[0..Mfit)` 及对应的 `(model_id, fit_lo, Mfit)` 标签；当 `apply_model` 处理 `[fit_lo, fit_lo + Mfit)` 覆盖的整块时直接从该缓存拷贝，**省去 `backfill` 阶段重复重构 8,128 点（立省 ~45 µs）**。

### OPT-NEXT-09：GNU Radio 适配层 `pmt::dict_add` 链表拷贝消除（E0 级，实测降至 72.6 µs，节省 ~382 µs / 84%）

* **文件与位置**：`gr-uwb/lib/uwb_preamble_sic.cc`
* **状态**：**已实施并实测验证通过（2026-11-09）**
* **根因剖析**：
  * 在 GR 模式 benchmark 中，优化前 `adapter PMT wrap` 平均耗时高达 **454.6 µs**（p50=416.0 µs, p95=625.0 µs, p99=1110.0 µs）。
  * 原因是：
    1. `copy_dict(p.meta_in)` 逐项提取 $O(N)$ 并用 `pmt::nth`（$O(N)$ 遍历）和 `dict_add` 重建，耗时严重；由于 PMT 字典本为不可变引用计数结构，完全无须深拷贝；
    2. `dict_add` 每次执行都会线性扫描整个链表比对 key，连续写入 60+ 个键引发 $O(K^2)$ 次遍历与堆分配；且每键通过 `pmt::mp` / `pmt::string_to_symbol` 查询全局哈希表加互斥锁；
    3. `publish_status` 原本将 `extra` 解包后再逐项 `dict_add`，产生重复遍历。
* **修改方案（已合入）**：
  1. **静态预驻留 PMT Symbol 单例**：定义 `struct SicPmtSymbols` 静态单例，集中预初始化所有端口、状态、输入输出键与事件枚举 Symbol，运行期完全消除字符串哈希查找与全局锁。
  2. **直接复用并 $O(1)$ 头插新键**：
     * `meta` 直接以不可变 `p.meta_in` 为基底；
     * 针对 SIC 输出专有键（互不重叠），统一采用 `pmt::dcons(pmt::cons(sym.key, val), meta)` 执行 $O(1)$ 头插，复杂度由 $O(K^2)$ 骤降至 $O(K)$；
     * `publish_status` 直接以 `extra` 字典为基底反向头插通用状态计数器，完全消除 `dict_items` 解包与 `pmt::nth` 嵌套循环。
* **实测效果对比（200 窗基准测试）**：
  * `adapter PMT wrap` 平均时延：**454.6 µs → 72.6 µs**（**降低 84.0%，加速 6.26x**）
  * `adapter PMT wrap` p50 时延：**416.0 µs → 59.0 µs**（**降低 85.8%，加速 7.05x**）
  * `adapter PMT wrap` p95 时延：**625.0 µs → 81.0 µs**（**降低 87.0%，加速 7.72x**）
  * `adapter PMT wrap` p99 尾部时延：**1110.0 µs → 114.0 µs**（**降低 89.7%，加速 9.74x**）
  * 正确性与回归：`uwb_qa_uwb_preamble_sic`、`uwb_qa_uwb_preamble_sic_core`、`verify_s2b --self-test` 全部 100% 通过；E0 级输出字典键名、类型、数值逐位严格保真。

## 五、 关于多线程加速的工程评估与定位

针对是否引入多线程（Multi-worker / OpenMP）提升速度，结论与架构原则如下：

1. **单窗内细粒度多线程（OpenMP / 线程分块）：不推荐**
   * 单窗 Core 总耗时仅 1.4 ~ 1.8 ms，内部单个子阶段仅数十至百余微秒。在 Linux 下线程唤醒、屏障同步（Barrier）与跨核 L1/L2 Cache 失效的开销（10 ~ 50 µs）会严重吞噬收益，并导致 P99 尾部时延恶化。单窗内的数据级并行应坚持使用 **AVX2/FMA SIMD 与 VOLK 内核**。
2. **窗口级多 Worker 线程池（Inter-window Pipeline Parallelism）：仅用于未来高吞吐扩展，不解决单窗时延门限**
   * 在 `UwbPreambleSic` 适配层将单 worker 扩展为 $N$ 个 worker 可以近线性提升系统的**饱和吞吐率（windows/s）**，但**不会缩短单个窗口的处理时延（Wall Latency）**，且必须额外引入**保序重排缓冲区（Reorder Buffer, ROB）**与 $N$ 倍的 `SicScratch` 内存预分配。
   * 依据 `AGENTS.md` 契约（*“默认单 worker，scratch 预分配……不用增加 worker 冒充算法加速”*），现阶段应优先实施上述 **OPT-NEXT-01 ~ OPT-NEXT-09** 单核优化。
