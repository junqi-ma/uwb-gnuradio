### R01：实际输出的消除效果未被指标完整覆盖

**证据**：`gr-uwb/apps/uwb_sim_preamble_sic.py:1764` 计算 `i-i_hat`；
`gr-uwb/lib/uwb_preamble_sic_core.cc:1379` 定义的实际相减 mask 可能只覆盖重构的一部分。
完整 `i_hat` 与实际提交到输出的相减量不是同一个量；未 commit 时也不能计作已消除。

在同一存档窗口上，仅改变 validation_reps，其他配置保持一致：

| fit/validation | 输出支持区间 | 完整重构抑制度 | 按实际输出计算的整段抑制度 |
|---|---|---:|---:|
| 8/8 | `[1997,18353)` | 28.28 dB | **1.25 dB** |
| 8/56 | `[1997,67121)`，实际还受 ROI 裁剪 | 28.28 dB | **26.54 dB** |

以上是单窗复现，不是新的矩阵中位数。即使模型准确，未实际相减的其余干扰仍存在。

**整改要求**：保留原 reconstruction NMSE，同时新增以真实输出计算的 acceptance 指标：

```text
delta_actual = y - y_clean
residual_interference = i - delta_actual
actual_nmse = ||residual_interference||² / ||i||²
actual_suppression_db = -10 log10(actual_nmse)
```

评估区间由 verifier/真值侧定义，不能依据估计 mask 缩到最有利的区间。
主效果 gate 使用实际消除指标；partial 情况同时报完整重叠区、确认相减区和覆盖率。
保留逐位旁路、mask 外不变检查。零干扰能量时抑制度标为 N/A，负样本按误 commit
和输出改动验收，不能以约定的 60 dB 混入正样本效果统计。

**关闭标准**：新增“完整 i_hat 很准，但只相减少量符号”的回归用例，必须被正确判为
实际消除不足；新增未 commit 但已有 i_hat 的用例，不得记为消除通过。
独立 verifier 从选定存档窗口的 `y/y_clean/i` 数组复算，不从声明的 mask 合成输出。

### R02：效果与性能配置不一致，相减长度与验证长度耦合

**证据**：benchmark 在 `benchmark_preamble_sic.cc:628` 固定 fit=8、validation=8；
效果脚本在 `uwb_sim_preamble_sic.py:1227` 自动改为 8/56。
核心在 `uwb_preamble_sic_core.cc:1238` 以 `confirmed*sps+post_tail` 定义支持长度，
而 confirmed 的扫描范围受 fit+validation 限制。

**整改要求**：明确区分以下概念，不能再通过偷偷增加 validation_reps 修复覆盖范围：

- 参数拟合长度；CFO/路径估计实际使用的样点范围；
- 在线验证长度；独立评估长度；
- 有信号证据支持的前导起止/重复范围；最终相减 mask。

确认完整支持若需扫描更多符号，应显式实现、计时并记录；不能无证据按已知名义
64-SYNC 无条件外推。起止不可辨识时只做有标注的 partial 或旁路。
搜索 ROI 与相减 ROI 分开定义，避免用“候选起点范围”的 roi_hi 截掉自然拖尾。

生成 effective runtime config 和 hash；功能、core、GR、native benchmark 使用同一
case/config/template/输入长度，差异必须显式标注。拒绝无法满足的配置，不自动改写。

**关闭标准**：统一名义 case 上同时报告效果、覆盖率、实际参数范围和耗时；
8/8、8/16、8/56 的差异可解释且不会被程序无声覆盖；短观察的延迟结论包含真实
支持确认/门控所需的观察等待。

### R03：benchmark 负载与“主配置”的绑定不成立

**证据**：`benchmark_preamble_sic.cc:324` 使用伪随机 ±1 chips、9-tap Gaussian
pulse，自变量 code 只是伪随机种子；`:388` 只生成干扰加噪声，没有 sensing。
`:273` 的 consumer 选项改变窗口长度，但不能证明运行了完整 sensing demod/CIR。

**整改要求**：正式 benchmark 加载或预生成与效果集相同的真实 code9/code10 HRP
波形、脉冲/信道/ISR/SNR、完整 sensing RX，记录所有 hash 和实际配置。
当前 synthetic 模式可保留，但重命名并明确它只是独立 microbenchmark。

分开测 SIC-only、SIC→radar CIR、SIC→完整 sensing demod；consumer 选项必须真正
连接/调用该消费者。计时前生成至少 64 个不同内容窗口，计时中消费并校验终态。
除了调用返回 true，还须核验 committed/bypassed/failed 和实际输出效果，防止测到
提前退出/部分相减后仍宣称完整处理速度。

**关闭标准**：正式性能表能逐项绑定一份已通过效果核验的 case；结果中包含实际
下游终态和输出摘要。旧 synthetic 的 235–247/228 窗/s 不再被当作生产 profile 的验收证据。

### R04：目标保护不能使用逐窗 L2-normalized CIR 幅度

**证据**：`uwb_sim_preamble_sic.py:1959` 的 target_amp 来自 cir_norm。
独立 L2 归一化可能抵消共同增益变化，或把残余能量变化混入目标幅度比；
全局最大峰不等于预设弱目标峰。

**整改要求**：固定目标 ROI 与参考尺度，使用未作逐窗 L2 归一化的复数 CIR 或
固定匹配投影。报告目标幅度误差、相位误差、局部峰位偏差、检出/假峰率。
原 normalized CIR 指标可作为形状诊断保留，不能替代目标绝对幅度 gate。
目标 ROI 在校准集固定，不能在 SIC 结果上重新寻找最有利目标。

**关闭标准**：新增“输出整体衰减、归一化形状不变”的反例，必须判目标保护失败；
同时包含“主峰保持、弱目标丢失/移动”的反例。重算主矩阵 raw 目标指标。
本次名义窗口 raw 幅度误差约 -0.150 dB、归一化误差约 -0.032 dB；
这说明两者不同，并不表示该窗口 raw 目标已超出 1 dB 门槛。

### R05：对角元比值不是矩阵条件数

**证据**：`uwb_preamble_sic_core.cc:534` 将 `max|Rkk|/min|Rkk|` 等同 cond(A)，
最终在 `:1422` 按 `<1e6` 判定。现有 QA 使用同一比值作为目标值，形成共同错误约定。

直接调用当前动态库的求解器，对如下矩阵：

```text
A = [[1, 1],
     [0, 1.5e-6]]
库报告 gain_condition ≈ 666669.93，门槛会接受
NumPy SVD cond(A) ≈ 1333333.33，超过 1e6
```

参考：[NumPy 条件数定义与 SVD 计算](https://numpy.org/doc/stable/reference/generated/numpy.linalg.cond.html)。
double 精度能改善累积误差，但不能修正错误的条件数定义，也不消除正规方程的条件数平方问题。

**整改要求**：采用有定义和误差边界的条件估计/秩判定；可选 QR/SVD 或可靠的
小矩阵条件估计与必要回退，避免显式求逆。若保留 Gram/Cholesky 快路，明确适用
范围，不能把 pivot ratio 命名为准确 cond(A)。数值不可靠时 fail-closed。

**关闭标准**：用独立 SVD/lstsq 参考验证不同列尺度、近相关列、列置换、阈值两侧
和病态用例；既核验条件判定，也核验解误差/残差。上述反例不得通过条件门槛。
报告重新评估 F2 的“安全整改完成”结论，并重新测量修复后的成本。

### R06：holdout 与 CFO 估计/在线门控共用

**证据**：`uwb_preamble_sic_core.cc:1125` 用 fit+validation 的重复估计 CFO；
`:1420` 用 validation 区间决定 commit；`uwb_sim_preamble_sic.py:1777` 又将同一区间
称为 holdout。它只与增益 LS 的拟合区间分开，并未独立于参数估计与门控。

**整改要求**：明确估计、在线验证、最终离线评估三个区间。估计区包含 CFO、
路径选择、分数时延和增益拟合所使用的全部数据；最终评估区不能用于这些估计或
门槛校准/commit。保持校准/验收 seed 分离，记录区间与数据依赖。
检测粗搜可见全候选窗的事实需披露，不把它描述为完全未见的盲测试数据。

**关闭标准**：新增数据依赖测试：改变最终评估区间内容不能改变已固定的参数拟合
和在线门控结果；独立评估指标会相应变化。若当前全前导观察设计没有独立区间，
需调整实验或降级结论，不把 validation 更名为 holdout 后直接关闭。

### R07：comm 前导末端混入 SFD

**证据**：`sic_preamble_sim.py:270` 生成完整 comm 包，再截取到
`sync_reps*1016+pulse_taps`。完整包已在 SYNC 之后叠加 SFD，该截取把首段 SFD
贡献留在所谓前导尾部。现有 `uwb_hrp_mod_core.h` 的 ensure_prefix 可确认这一顺序。

**整改要求**：由有限长 SYNC 码脉冲直接成形，保留仅由 SYNC 产生的自然滤波尾部；
实际通信包截取模式若另行保留，必须单独命名并声明 SFD 范围。
更新 Python/C++/MATLAB 模板生成和 hash，不覆盖旧 canonical fixture。

**关闭标准**：独立的“有限码脉冲卷积”参考逐样点一致；修改后续 SFD/PHR/payload
不影响 preamble-only 波形；边缘/拖尾单列测试。旧模板上的效果数字不能直接沿用。

### R08：native 仿真 CLI 尚未实现

**证据**：`uwb_sim_preamble_sic.py:1100` 对非 work 输入直接报
“not implemented in S0-A”；报告的 CG400 CLI 复现命令不能完成所述闭环。
独立 benchmark 不包含三路效果验收，也不能取代该路径。

**整改要求**：按原任务接入 491.52 MS/s 的 RX/注入、公共 SC16 缩放/clip 统计、
PDU 65/32 和 work SIC，保留时间映射。三路用相同滤波与有效区间约定。
SC16 量化非线性，不能分别量化真值分量后假定其和等于量化混合信号。

**关闭标准**：报告内 native 命令可执行，产出 clean/raw/sic 实际效果与计时。
按原范围不修 resampler 已知 SIMD 问题，但应记录重复运行差异、reference/scalar
对照和误差地板。受阻则保持 native 未通过，独立工作继续完成。

### R09：定速端到端未通过，解调成本证据不足

**证据**：现报告 paced200 实际约 7.44 窗/s，2232/12000 完成，2232 窗全部超时。
完整解调主要来自 8/16 窗；已有 SIC-only benchmark 没有代替完整消费者测量。
因此当前“core/GR 达到 200 窗/s”只能限定在其 synthetic 测量，不能用于 S0 链验收。

**整改要求**：

1. 定速计时区只运行目标处理路径；clean/raw 配对评估、数组落盘和绘图离线执行。
   使用预生成窗口、有界 in-flight/字节预算和明确的绝对计划提交时间。
2. 分开统计 planned、offered、admitted、missed/deadline、completed，未按期提交也
   计失败；禁止终态串行等待自然拖慢源后用 admitted 速率代替计划负载。
3. 单独测量生成器、PMT 包装、消息入口、worker、消费者、sink；在有证据前不能把
   paced200 的全部失败笼统归因 Python 或生成器。RSS 和 CPU 时间按 run 区间计差，
   不把跨多次同进程运行的累计值当单 case 资源开销。
4. 实际完整 sensing 包对比 demod bypass/full/RAKE Top-4，以及 radar 搜索/计划坐标
   两路径。参数和正确性绑定同一 case，失败路径也计时，not_run 不伪造为零耗时。
5. 保留七阶段及 SFD/CIR 子计时，父子不二次累加；补插桩开关对照。
6. 同一有效配置先做核心/GR/完整链分层计时，再做 200/s、60 s 定速；通过后才做
   10 min 和更高速探索。性能基准按原任务完成重复次数/样本量，未完成要写明。

**关闭标准**：在同一已通过效果核查的负载上给出饱和容量与定速延迟两份独立结论。
原目标仍为 SIC mean≤0.5 ms、P99≤1 ms、200/s 时 CIR 终态 P99≤5 ms、无缺号/丢弃
和持续积压。不能达到则明确失败、瓶颈与可运行窗口率，不能将目标门槛改成单纯
`1000000/mean_us≥200`。full demod 与 native 分开判断。

### R10：verifier、版本绑定和报告结论同步整改

**整改要求**：

- verifier 检查实际输出残余、raw 目标指标、独立区间以及效果/性能配置同一性；
  新增损坏 mask/不 commit/整体衰减/虚假 consumer 等对抗性反例。
- 必须存档足够的实际 `y/y_clean/i/i_hat` 与 raw CIR 以独立复算选定窗口；全量可
  流式统计，明确哪些窗口有数组证据，不能把缺失数组默认为已复核。
- manifest 绑定实际生效参数、模板/输入 hash、库/benchmark 文件 hash、commit 与
  dirty patch 标识。一次测量记录不能代表其间多次优化的所有代码版本。
- 不再使用静态 not_run 模板冒充实际执行状态；区分 false（已测失败）与 null/未测。
- MATLAB 明确包含“已实跑/未实跑”、命令与日志。环境不可用时保留可运行脚本，
  继续独立工作，不能用 Python 一致性或旧 code9 golden 代替新 code10 独立验收。
- 最新数值修复后的 8 窗 smoke 不能替代完整矩阵回归；测试通过后需要重跑受影响
  的效果矩阵、负样本和性能实验，旧结果保留并标注 superseded。
- 对一次性 QA flake 保留失败证据和环境。未复现可作为状态描述，但没有根因证据
  时不直接断言一定由 LTO 导致或不属于功能问题。

**关闭标准**：结果产物、开发报告、API 文档和 AGENTS 状态一致；能从一条明确命令
复现指定 case，错误/缺少输入返回非零。原报告“已提交/全部未提交”等残留矛盾清理。
复跑相关 QA、完整既有回归和针对性 verifier；性能测试串行且失败单列。

## 4. 推荐执行顺序与回交

1. **先修测量合同**：R01、R04、R05 的反例测试与实现；冻结新字段及 gate。
2. **统一真实信号与数据依赖**：R07、R02、R06；重生成并冻结模板/fixture。
3. **先做少量真实窗口闭环**：确认实际输出抑制度、目标 raw 指标、PSDU/FCS，
   再整改 R03 的 benchmark。不能先优化一个尚未满足效果的简化负载。
4. **补接入与负载测试**：R08、R09；测量中持续输出进度，不无限等待。
5. **全量回归及归档**：R10，逐项回填整改表。

回交文件：`docs/sic/S0_整改开发报告_R01-R10.md`，同时修订原开发报告但保留旧结果
的版本说明。每项包含：根因、代码位置、反例修复前/后结果、命令、artifact 路径、
实际版本/配置、关闭/未关闭/受阻状态。

最终仍需分别回答：实际消除和目标保护是否通过；SIC 新增成本多少；完整解调成本
多少；work/native、CIR/full demod 各自在哪些窗口率与延迟下可用。
