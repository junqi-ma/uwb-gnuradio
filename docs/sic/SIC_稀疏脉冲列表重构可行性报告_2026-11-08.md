# Ipatov SIC 稀疏脉冲列表与 CFO 融合重构可行性报告

日期：2026-11-08  
工作区：`.worktrees/sic-fullpacket-compare`，分支 `feature/sic-fullpacket-compare`  
起点：HEAD `06ef10abe5139ce548d1bc5492fb2762ab0f147d` 加既有未提交修改  
结论：**可继续采用，但仅作为显式实验开关；不替换默认后端。**

## 1. 结论摘要

- 新增 `--sparse-pulse-reconstruct`，只对 `--reconstruction ipatov_cir` 生效，默认关闭。
- 调制器不再生成整包实数波形，而是返回严格递增的脉冲位置/符号列表；前导事件缓存，PHR/payload 按段追加。32 B 包为 8,384 个事件 / 133,568 采样；127 B 包为 15,616 / 249,280。
- 重构按 `c_i = sign_i * exp(j*omega*(q + m_i - anchor))` 在脉冲位置计算相位并叠加冻结 CIR，不再做整包 CFO 旋转。零 CFO 用专用加/减，非零 CFO 用逐事件复数 AXPY。
- 功能：5 个正常格各 8 窗 + 127 B/损坏包各 2 窗，comm/sensing PSDU、FCS、状态、PHR bits/长度/SECDED、committed/reason 全部一致；无新增解码失败；损坏包 2/2 零提交且逐位旁路。
- 效果：正常格聚合抑制下降（旧−新）为 −0.0001～0.741 dB，满足“聚合不超过 1 dB”的目标；最差单窗下降 1.446/−1.665 dB（−50/+50 kHz），单窗并不总在 1 dB 内。
- 性能（最终二进制、干净重复 `_5`）：32 B 分数多径调制 56.8→35.1 µs、信道重构 712.3→600.6 µs、总 SIC 2713.7→2559.7 µs（0.943）；+50 kHz 60.7→33.9 µs、723.0→603.6 µs、2759.4→2568.4 µs（0.931）。信道重构和总 SIC 的 mean/P95 均下降；调制子项在 +50 kHz 的一次重复中出现慢跑，未把它当作稳定收益。
- 边界：只测两格计时；CIR 仍为原 128 点相关响应；未改估计器、tap 支持或 3 参数约束；SYNC 碰撞约 19.32 dB 的已有退化未修复；PHR R1–R3 未处理；未验证 MATLAB、native、FPGA/硬件、paced、P99 或实时目标。

## 3. 实现

### 3.1 稀疏脉冲接口

在 `uwb_hrp_mod_core.h` 中新增：

```cpp
struct PulseEvent { uint32_t sample_offset; int8_t sign; };
struct PulseList  { const PulseEvent* events; size_t count; size_t packet_samples; };
```

- 位置相对整包起点，位于 `[0, packet_samples)`；符号只能是 ±1。
- 位置必须严格递增；同点脉冲直接失败，不静默覆盖。
- `packet_samples` 由 PHY 几何独立计算，不由最后一个事件推导，尾部零区保留。
- `HrpModScratch` 新增 `pulse_events`、`pulse_count`、`pulse_packet_samples`；`reserve()` 按最大包长预留事件容量，热路径不扩容。
- `HrpPrefixCache` 新增事件缓存（`events`、`event_count`、`events_valid`），与波形缓存共享 profile key；key 变化时两种表示一起失效。
- 新入口 `mod::modulate_pulse_list()` 复用既有 RS/PHR/卷积编码/BPM 扩频决策，只输出事件；不生成实数/复数波形，也不通过扫描旧波形提取事件。
- 失败时 `PulseList` 清零、`pulse_count=0`，不留下可被消费的半包；实际事件容量不足明确失败。

### 3.2 事件重构

在 `uwb_discrete_cir_reconstruct.cc` 中新增 `apply_discrete_cir_pulses()`：

```text
c_i = sign_i * exp(j*omega*(q + m_i - anchor))
yhat[q + m_i + lag_lo + j] += c_i * taps[j]
```

- `anchor == q`，所以实际相位为 `exp(j*omega*m_i)`；代码仍保留参考点语义检查。
- 每个事件只计算一次相位；非零 CFO 使用 1024 点绝对相位表加按块基准，基准按真实采样位置推进，不按事件序号推进。
- 零 CFO（`model.cfo_hz == 0.0`）走专用 `fused_addsub()`，保持旧单位实数路径的逐 tap 累加顺序，QA 中与旧路径逐位一致。
- 非零 CFO 走 `fused_axpy()`；输出重构缓冲仍先清零，重叠响应仍累加。
- 不做整包 CFO 旋转；`DiscreteCirResult::cfo_us` 在稀疏路径为 0，新增 `zero_us`、`phase_us`、`check_us` 子计时。
- 保留绝对坐标、support 截断、ROI 交集、有限值检查、FCS/PHR/profile 门槛和逐位旁路。`ihat == nullptr` 时也在 support 两侧恢复 `out == y`。
- `fullpacket_cancel_discrete()` 在 `model.impulse_template && scratch.sparse_pulse_reconstruct` 时分派到稀疏路径；旧单位实数路径仍可直接配对运行。

### 3.3 CFO 近似误差

本轮按任务书故意忽略 CIR 持续期间的 CFO 相位 `omega*k_j`。实测冻结 CIR 的 hull 为 `lag_lo=-8`、`tap_count=128`，即 lag `[-8, 119]`，最大 `|k_j|=119`。998.4 MS/s 下：

- 50 kHz、12 个采样间隔约 0.216°；
- 50 kHz、128 个间隔约 2.308°；
- 按实际最大 lag 119 计，约 2.146°。

相位小不等于抑制无损；实测聚合与最差单窗结果见下表。零 CFO 的逐位一致性是**精确零模型**的结论；名义零 CFO 格里估计器仍会给出约 −7.6～+2.2 Hz 的小 CFO，因此这些格走非零近似分支，输出不是逐位一致，但聚合差异约 1e-4 dB。

## 4. 定向 QA

构建目标：`uwb_qa_uwb_hrp_mod_core.cc`、`uwb_qa_uwb_discrete_cir_estimator.cc`、`uwb_qa_uwb_discrete_cir_reconstruct.cc`；三项 CTest 全部通过。通信解码未改，未重跑完整通信 QA 矩阵。

### 4.1 调制器

- 2/32/127 B 三种长度：事件列表展开后与旧 `modulate_unit_impulses` 的实数序列逐样点一致；`packet_samples`、位置、符号、尾部零区一致。
- 事件数组预分配后不扩容；`iq_re` 和 `prefix.samples` 保持为空，证明没有生成整包波形。
- 采样容量不足、事件容量不足均返回失败且 `PulseList` 清零。
- 事件数：32 B 为 8,384；127 B 为 15,616。

### 4.2 重构

- 零 CFO：同一模型/同一事件顺序下，稀疏路径的 `ihat` 与旧单位实数路径 `memcmp == 0`。
- 非零 CFO：与独立 double 标量实现直接比较近似公式，覆盖 `q`、负 lag、anchor、重叠累加；最大误差低于 `2e-5`。
- 重复/乱序事件 → `invalid_pulse_list`；首 SYNC 符号不符 → `pulse_template_mismatch`；support 截断 → `context_truncated`；均保持 `out == y`、`ihat == 0`。
- 可选 `ihat == nullptr` 路径、support flank 恢复、FCS/PHR/profile 既有测试均通过。
- 事务路径的稀疏 scratch 中，旧 `waveform`/`scaled_waveform` 被填 NaN 后仍能完成，确认未读写旧整包中间缓冲。

### 6.1 重复性

同一最终二进制的 `_4` 首次计时：

- 分数多径：调制 0.597、信道 0.857、总 SIC 0.968；
- +50 kHz：调制 1.001、信道 0.769、总 SIC 0.933。

`_4` 的 +50 kHz 调制子项出现一次系统慢跑（`r3_new` 均值 90.9 µs，其他新跑 33～37 µs；最大值 218 µs），因此该格的调制比值不可用。按任务书只补一次同规模配对得到 `_5`；`_5` 的调制比值为 0.558。信道重构和总 SIC 在两个最终二进制计时中都下降，方向可重复；调制子项只在 `_5` 和更早的 `_3` 中稳定为约 0.54～0.63，`_4` 的 +50 kHz 例外已如实保留。

## 7. 失败与限制

- **不是默认路径**：开关默认关闭；没有替换默认后端，也没有把 `ipatov_cir` 之外的路径切到稀疏事件。
- **单窗退化**：+50 kHz 最差单窗下降 1.665 dB，−50 kHz 最差 1.446 dB；聚合满足 1 dB，但单窗不满足，不能宣称所有窗口无损。
- **CFO 近似**：忽略 `omega*k_j` 的最大相位按实际 hull 约 2.146°；这是任务书指定的近似，不是精确 CFO 方案。若后续要求更深抑制，需要另做精确 CIR 内相位方案，本轮未开发。
- **零 CFO 逐位结论的边界**：只在模型 `cfo_hz == 0.0` 的 QA 中逐位一致；名义零 CFO 源窗经估计器仍有约 −7.6～+2.2 Hz，故端到端不是逐位一致，聚合差异约 1e-4 dB。
- **CIR 未变**：仍是原 128 点 Ipatov 相关响应；未改估计器、tap 支持、3 参数约束、SYNC 碰撞退化或 PHR R1–R3。本轮 `sync_base` 实测约 19.32 dB；历史材料约 19.63 dB 的口径/窗口不同，本轮只比较新旧增量，未重新标定绝对基线。
- **测试范围**：功能只到 5 个正常格 × 8 窗 + 127 B/损坏包 × 2 窗；计时只到两格。没有重跑完整通信 QA 矩阵，没有做 32-cell 全矩阵、长稳、负样本扩展、MATLAB、native resampler、FPGA/UHD/硬件、paced 到达、P99 或实时吞吐验证；`mean≤0.5 ms`、`P99≤1 ms`、200 窗/s 仍未实现、未宣称。
- **未提交**：当前工作树基于 HEAD `06ef10a` 加未提交修改；`_4`/`_5` 运行时的 code-tested tracked patch 为 `29182d75...`，之后只更新报告与 `OPENCODE_START.md`，没有重建或改源码；新 runner 与报告为新增文件。没有创建提交，因此没有 code-tested commit SHA。
