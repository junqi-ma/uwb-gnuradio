# PHR 解扩 CMF 融合验收复核

复核 HEAD：`06ef10a`，工作树原本 clean。结论：**既定 PHR/payload 路径功能与性能证据成立，完整验收前关闭以下三项缺陷。** 本次未修改实现；只运行四项相关 QA、核对原始数据及三个小型反例，不重跑性能矩阵。

## 待关闭问题

### R1：通用相关内核只用最后一个候选计算尾界（P2）

位置：`gr-uwb/include/gnuradio/uwb/uwb_rx_fused_cmf.h:405–417`。

`correlate_field()` 接受自定义 Geometry，但用 `candidate_chip_offset[3]` 代替所有候选的最大偏移。输入候选 `{0,320,64,0}`、64 chip/burst、512 chip/symbol、一个 symbol、38 tap、chip_start=37、field_start=0、n=164 时检查通过，第二个候选实际读取到 sample 803。

独立反例用 804 sample 的物理缓冲但声明 n=164，避免测试自身发生物理越界；只把声明范围以外的值从 1 改为 2，第二个指标从 2432 变为 4864，两次均返回 true。这证明内核读取了 API 长度外的输入。当前固定 PHR/payload Geometry 最后一个偏移最大，正常路径不触发。

修复：用所有候选的最大偏移计算尾界，或明确拒绝非支持几何；同步修正 burst 位于 symbol 内的条件为 `offset + chips_per_burst <= chips_per_symbol`（当前减去 burst−1 多放行一格）。增加一个非末项最大偏移、一个恰好跨 symbol 的针对性 QA。

### R2：FIR 诊断重放缺少右端 IQ 边界检查（P2）

位置：`gr-uwb/include/gnuradio/uwb/uwb_softchip_fir_diag.h:151–162`。

整数网格只检查左端，直接把 `rx+win` 交给 dot，未检查 `win+tap_count <= n`。函数接收 n，却没有限制 total_chips 对应的最终 sample。

独立反例：38 tap、chip_start=37、spc=2、total_chips=10、n=40；物理分配 56 sample，仅更改 n 外的值，最后输出从 38 变成 54，函数两次返回 true。当前生产调用使用由实际 IQ 长度推导的 chip 数，本轮记录不受影响，但新安装的诊断 helper 本身不安全。

修复：入口检查算术溢出和最终采样范围，不足直接失败；或与参考路径一致做有界边缘计算。增加恰好可读和少一个 sample 的 QA。

### R3：计时脚本只比较每个 window_id 的首次观测（P2）

位置：`tools/sic/run_fused_phr_compare.py:671–699`。

ABBA 四轮中 window_id 重复，`old_by_id/new_by_id` 只保留第一次，因此 r3_new/r4_old 的解码内容不参与比较。内存中加载正式 payload_base 四轮，仅将 r3_new 第一行 `comm_psdu_hex` 改为 `00`，`timing_protocol()` 仍返回 passed=true、decode_mismatch_count=0。磁盘原始记录未修改。

修复：按 source_window 绑定参考结果，比较每一轮、每一次观测的全部功能字段；保留 window_id、源窗映射与行数检查。用这个单行扰动例验证脚本能拒绝即可，无需重跑完整矩阵。
