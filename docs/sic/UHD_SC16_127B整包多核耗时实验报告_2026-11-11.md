# UHD SC16 127-Byte 整包多核耗时实验报告（2026-11-11）

## 1. 实验目标

对 **64 SYNC / 127 Byte PSDU / 6.81 Mb/s** 的标准 UWB 包（IEEE 802.15.4z
最大帧长），在 `dsp_workers ∈ {1, 2, 4}` 下测量从 UHD SC16 读入到整包 SIC
消除完成的端到端时间开销。

---

## 2. 被测包的物理层规格

工作采样率 998.4 MS/s（每前导符号 1016 点，每 chip 2 点），原生采样率
737.28 MS/s（重采样比 65/48）。

| 字段 | 参数 | 工作样点 | 空中时长 |
| :--- | :--- | ---: | ---: |
| SYNC | 64 符号 × 1016（`code=10`） | 65,024 | 65.13 µs |
| SFD | 8 符号 × 1016（`4z2`） | 8,128 | 8.14 µs |
| PHR | 21 符号 × 512 chip × 2 | 21,504 | 21.54 µs |
| Payload | 127 B @ 6.81 Mb/s（1208 BPM 符号） | 154,624 | 154.88 µs |
| **整包合计** | | **249,280** | **249.68 µs** |

调度窗口取 **200,000 原生样点**（271.27 µs），包置于窗口内 offset 4000 原生
样点处，前后各留 4000 点保护。经 65/48 重采样后窗口为 **270,860 工作样点**，
包占据 `[5430, 254,710)`，完整落在窗口内（满足 `apply_discrete_cir` 的
`context_truncated` 约束）。

---

## 3. 实验前必须修复的两个缺陷

直接拿现有工具跑这组实验只能测到一条**假路径**，因此先做了两处修复
（提交 `986e4bb`）。

### 3.1 Runner 从未配置 `sic_cfg`（fail-closed 到空跑）

`uwb_uhd_sc16_pipeline_runner.cc` 完全没有触碰 `PipelineConfig::sic_cfg`，
于是 `SicUnifiedConfig` 的默认值生效：`roi_lo = roi_hi = 0`、
`max_window_samples = 0`。`prepare_sic_unified()` 因 scratch 容量为 0 而失败，
`sic_process_unified()` 每个窗口立刻返回 `invalid_buffers_or_scratch`，
耗时仅剩一次 2.2 MB 的 `std::copy`（**约 196 µs**）。

历史上所有 `--consumer sic` 的 SC16 流水线报表（含 2026-11-11 报告里的
"`sic_us` P50 = 30.99 µs"）测到的都是这条早退路径，**不是真实 SIC**。

修复：新增 `--sic-policy / --sic-backend / --sic-comm-code /
--sic-sync-template / --sic-roi-margin / --sic-tap-count`，并从窗口几何自动
推导 `samples_per_symbol=1016`、`sync_reps=64`、scratch 容量、以及以
"pre_guard 映射到工作网格"为中心的搜索 ROI。

### 3.2 SYNC 模板被硬编码为感知码 9

`load_sync_pulse_template()` 固定加载 `testdata/reference_preamble.bin`。
实测该文件与 `code=9` 的 SYNC 归一化复相关为 **1.000000**，与 `code=10`
仅 **0.125**。通信包用 code 10 时，`demodulate_one()` 用错模板做定时相关，
必然 `TimingFailed`，SIC 无法提交。

修复：新增 `PipelineConfig::sic_sync_template_file`，为空时保持原有行为
逐位不变。

### 3.3 附带发现的静默回退（未改行为，仅加告警）

`find_testdata_file()` 依赖相对路径。若进程 cwd 不在仓库内，65/48 抽头
加载失败，代码会**静默**退化为 `65×64` 个 `1/48` 的平坦盒式滤波器：
重采样耗时翻倍（668 → 1375 µs）且通带被破坏，下游全部检测失效。本次实验
最初就是被它误导（矩阵脚本以 `/tmp/opencode` 为 cwd，100 窗全部 0 提交）。
现已在回退处打印显式 `std::cerr` 告警，行为未改。

## 4. 测试信号生成

1. `mod::modulate_one()` 生成 998.4 MS/s 的 127 B 整包波形（249,280 点）。
2. `scipy.signal.resample_poly(x, 48, 65)` 降到 737.28 MS/s（184,084 点）。
3. 按调度几何放置：窗口 0 的包在 offset 4000，窗口 `k≥1` 的包在
   `k × 200,000`（因为窗口起点是 `k·period − pre_guard`）。
4. 量化为 SC16，峰值 0.853，100/300 窗各生成一份（80 MB / 240 MB）。

> 放置规则是必须的：若按"每 200,000 点块内 offset 4000"平铺，只有第 0 窗
> 命中 ROI，其余窗口包位置偏移 4000 点，表现为"1/3 窗提交"。

环境：i7-12700（8 P-core + HT），RX 绑核 0，Worker 绑 2/4/6/8，
独占 `/tmp/uwb-sic-benchmark.lock`，池容量 ≥ 窗口数（零丢弃），
`--consumer sic --sic-policy fullpacket --sic-comm-code 10`，
**所有配置 100% 提交、账本守恒 PASS**。

## 6. 分析：为什么 N=4 只有 2.88× 而不是 4×

1. **单包延迟本身随 N 上升**：e2e Mean 2350 → 2459 → 2883 µs（+23%）。
   仅此一项就把 4× 压到 `4 / (2883/2350) = 3.26×`。
2. **剩余损失来自 Worker 启动与尾部**：100 窗口径下 N=1 只跑到 2.16×，
   300 窗升到 2.88×，说明启动摊销是主要差异。按 `wall = S + 100·e2e/N`
   反解：N=1 时 S≈20 ms，N=4 时 S≈42 ms（每个 Worker 各自
   `prepare_sic_unified` + 分配 scratch）。
3. **根因是 L3 容量，不是同步开销**。单个 Worker 的活跃工作集：
   slot 800 KB + `cf32_work` 2.17 MB + `sic_out` 2.17 MB + `sic_ihat`
   2.17 MB + SIC scratch ≈3.5 MB + 模板 0.52 MB ≈ **11 MB**。
   L3 为 25 MB：N=2 恰好装得下（e2e 仅 +4%），N=4 需要 44 MB，
   溢出近一倍（e2e +23%，resample P95 从 837 涨到 1259 µs）。
4. **不是 RX 生产者**：300 窗 240 MB 在 0.253 s 内处理完（≈0.95 GB/s），
   RX 单线程读 + 拷贝 200,000 点约 45–50 µs/窗，远低于 843 µs/窗的
   DSP 周期。

**结论**：整包 127 B 场景下 N=2 已达 **92% 并行效率**（1.84/2），是性价比
最优点；N=4 仍有 2.88× 收益但效率降到 72%，且单包延迟上升 23%。若要多核
继续线性扩展，优化对象是**降低单 Worker 工作集**（复用 `sic_out`/`sic_ihat`、
把 `cf32_work` 与 SIC 输入合并、缩小 scratch 到实际包长），而不是内核算力。

## 7. 明确的边界

- **未上板**。全部数字来自文件回放（`--replay-mode fullspeed`），UHD 实机
  接收、`recv` 溢出、paced 到达均未验证。本文的"窗间隔"是吞吐上限，
  不是实时调度下的实际出包间隔。
- 测试信号为**零背景 + 单包**，未叠加感知信号与多径。抑制比 41.49/44.21 dB
  低于独立基准的 63.3 dB，原因是经过了 `重采样 → int16 量化 → 重采样`
  以及 65/48 群延迟补偿误差；这属于测试链路损失，不是 SIC 算法退化。
- 未做 MATLAB / native / FPGA 交叉验证；SIC 数学与重采样内核本次未修改。
- 结论绑定本机 8 P-core / 25 MB L3 拓扑；换平台需重测 N 的甜点。
- `quality_minorder` 在 N=4 出现个别长尾（resample Max 8010 µs），
  P95 已列于 5.1 表中，不可只引用 P50。

## 8. 复现

```bash
# 1. 生成 998.4 MS/s 包波形（一次性工具）
/tmp/opencode/gen_pkt --code 10 --psdu 127 --out /tmp/opencode/pkt_c10
# 2. 降采样到 737.28 MS/s SC16 并按调度几何放置
python3 /tmp/opencode/gen_sc16_127b.py \
    /tmp/opencode/pkt_c10_wave.cf32 /tmp/opencode/uhd_sc16_127b_300w.bin 300
# 3. 多核测量
cd /home/junqima/workspace/uwb-gnuradio
env -u LD_LIBRARY_PATH ./gr-uwb/build-sc16-pipeline/apps/uwb_uhd_sc16_pipeline_runner \
  --source replay --file /tmp/opencode/uhd_sc16_127b_300w.bin \
  --native-rate 737280000 --work-rate 998400000 \
  --pre-guard 4000 --capture 192000 --post-guard 4000 --period 200000 \
  --max-windows 300 --consumer sic --resampler-profile realtime_minorder \
  --dsp-workers 4 --cpu-rx 0 --cpu-dsp 2,4,6,8 --pool-size 320 \
  --sic-policy fullpacket --sic-comm-code 10 \
  --sic-sync-template /tmp/opencode/pkt_c10_sync.cf32 --sic-roi-margin 256 \
  --benchmark
```

> 生成器与探针为一次性工具，未进入仓库；`--sic-*` 选项与
> `sic_sync_template_file` 已随 `986e4bb` 提交。
