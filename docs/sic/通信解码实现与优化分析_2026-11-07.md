# 通信解码实现与优化分析（2026-11-07）

结论：当前约 2–3 ms 的通信解码开销主要是同步、CFO 旋转及软码片匹配滤波，
不是 Viterbi/RS/CRC。先优化等价计算，再缩小合法处理范围；不直接删掉二次
同步/CFO，不直接把 SIC 的离散 CIR 当作接收匹配滤波器。
本轮只分析和运行独立诊断，没有修改生产算法。

## 1. 真实执行路径

`apps/benchmark_fullpacket_compare.cc` → `apps/fullpacket_rx_pipeline.h` →
`include/gnuradio/uwb/uwb_demod_core.h::demodulate_one`。
FastRxPipeline 使用 Default profile，改 code=10、search_margin=256、stride=1；
实际快速可执行文件用 `-march=native`，38 tap soft-chip FIR 已启用 AVX2/FMA。
“已用 SIMD”不代表整条链全部向量化。

1. SIC 估计器仅把整数 origin 作为 seed 交给 RX，没有传入 CIR/CFO。
2. `stage_timing`：seed 附近搜索、回退、64 SYNC 跟踪、周期拟合。
3. `stage_cfo`：相关峰相位拟合 CFO，对整个输入窗旋转。
4. bootstrap SFD 搜索 → 40 个尾部 SYNC 重跟踪 → CFO 重拟合并再旋转整个窗 →
   final SFD 搜索。以上四项都在 `stage_sfd_us` 父计时内。
5. 54 个 SYNC 相干平均得到 38 tap 接收 CIR；对 chip 网格进行匹配 FIR；
   最后 32 SYNC 确定相位，整条 soft-chip 流旋转实部、最大值归一化。
6. chip 域 NS-SFD → PHR → payload BPM/BPSK、Viterbi、RS、CRC。
   正常解码先走固定 PHR 长度与硬判决；失败才试长度邻域/两种极性/soft Viterbi。

接收端默认 CIR 为 pre=8、post=30，即 38 tap，Auto 且 rake_top_k=0 使用完整 FIR。
它与 SIC 的 3/12 个离散等效信道 tap 不同；前者是 chip 匹配接收，后者是用已成形
TX 波形重建干扰。不能直接互换系数、方向、归一化或时标。

## 3. 优化点，按优先级

### P0：SFD 长相关复用已有 VOLK dot（低风险，先做）

位置：`uwb_demod_core.h:573` 的 `stage_sfd`。粗搜和细搜仍用普通 C++
复数累加循环，每个候选相关 8128 点；本轮 final 搜索每包 17 次粗相关、15 次细相关，
前后执行两次 SFD。现有 timing 已用 `timing_conjugate_dot` 的 VOLK 长向量内核，
可以复用相同数学，不改候选集、能量归一化、阈值和搜索顺序。

同时按 profile/template 缓存已归一化 SFD 模板，避免每包两次构造、归一化。
潜在优化覆盖本例约 0.40 ms 的 SFD 搜索，而不是整个 0.95 ms 父阶段；实际收益待测。
归约顺序会变化，应比对峰位置、阈值附近接受/拒绝、PSDU/FCS，不能只对浮点误差。

### P0：明确尾部种子搜索半径（小改动但属于行为变化）

位置：`stage_timing` 约 275 行，首次 local_best 使用硬编码
`max(256,stride)`；约 2223 行尾部调用虽设置 `timing_search_margin=0`，
仍会搜索 ±256。per-SYNC tracking 的 radius=8 只控制后续符号。
因此“尾部只在局部精修”的注释与首次搜索行为不一致，每次尾部调用仍有约
512 个长度 1016 的 dot。coarse_search_us 还不包含这次种子搜索，不能用它代表
全部 acquisition 成本。

建议显式引入 seed refine radius：普通捕获保持原值；SFD 已锚定的尾部首符号
先尝试 ±8，失败回退原范围，计数分别记录。不要全局缩小半径，否则可能破坏真实
设备的启动瞬态/偏移恢复；即便通过阈值，也需检查 SFD/周期一致性。先测代表种子
偏移与弱前沿，不把全 0 CFO 的通过当作真实捕获覆盖。

### P1：CFO 估计与旋转分离，减少两次全窗处理

位置：`stage_cfo` 约 453 行。相位拟合只处理几十个峰，但每次都旋转 n 个样点；
当前四条 float 递推链不是 SIC 那个 VOLK 块旋转。payload_base 两次 CFO 合计
约 0.547 ms，其中拟合与旋转尚未单独计时，不能把全部值说成旋转。

第一步只换等价旋转内核：1024 点绝对相位锚定 + 向量复乘，或实/虚分量 SIMD，
保留负号、原点、精度与失败行为；不要用旧 8 SYNC 的 CFO 直接替代尾部 refit。
第二步让 bootstrap 只生成 SFD 搜索可能读取的窗口，final 才旋转后续实际需要范围。
必须覆盖 ±4 符号 fallback、模板尾部与全局索引，不凭注入起点裁剪。

### P1：减少实际不消费的 soft-chip 计算（收益空间大，需分阶段解码）

位置：`stage_cir_softchips` 约 852 行。预算按 max_psdu_bytes=127 的宽裕长度
计算，再由 n 截断，而不是按已解码 PHR 的实际包长。payload_base 输入 n=236416，
生成约 117174 chip；32 B 通信波形只有 133568 样点，约 66784 个 chip。
较长输入窗是为了保留 sensing 包，并非 comm 必须滤波的长度。

因此当前约四成输出范围在名义通信包之外；本例 CIR+softchip 在大窗上约 1.04 ms，
其中 FIR 0.83 ms、后处理 0.176 ms。建议先处理相位对齐所需 SYNC、SFD、PHR，
解出有效长度后再扩展 payload，失败有公开最大长度回退。更进一步可跳过前 32 个
SYNC 的 soft-chip FIR，但需要逻辑 chip offset，不能破坏既有索引。

注意当前归一化最大值来自整条流；改变范围可能改变 LLR 尺度、阈值和错误恢复。
不能简单把 n 截到“知道的 32 B”，不能把完整 sensing 窗裁掉。收益是机会估计，
不能将四成 chip 减少直接声称为总解码四成提速。

### P2：38 tap soft-chip FIR 优化 / 有条件 RAKE

当前整数网格每输出一个 chip 调用内联固定38 AVX2/FMA点积，对 tap 维向量化，
每输出做水平归约；相邻输出窗口只移 2 样点，高度重叠。可尝试一次处理4/8个
输出，复用系数、减少水平归约，保持全38 tap，先与现有内核配对比较。
这里是滑动点积，不应直接搬用刚完成的 SIC tap-major 融合循环。

代码已有 Top4/Top8 RAKE 及跨4输出 SIMD，但默认关闭。可以作为显式质量/性能
实验，不能把改成4 tap算作等价性能优化；CIR弱分量可能影响多径解码率。

SFO 时 `abs(spc-round(spc))>1e-9` 会走标量分数网格路径，每 chip 两次 dot
再线性插值。本次三个格全部 spc=2，未测该性能。若面向真实采样时钟失配，
应单列此路径并复用整数位置滤波结果/向量化双点积；不能强行舍入 spc 加速。

### P3：模板缓存、scratch复用与失败路径

BuildSampledCode、preamble/SFD 模板和码扩展可按 profile 缓存。TimingResult、
pcode、CIR values、Viterbi/RS 临时 vector 仍有逐包分配，reserve scratch 并不
覆盖所有局部 vector。值得小改，但没有分配 profiling 前不要称其为毫秒主因。

payload 正常路径约22微秒，优先优化 Viterbi/CRC 收益很小。失败路径最多额外
尝试5种长度×2种极性 soft decode，可能放大尾延迟；重复 PHR 解调与 LLR 可缓存。
本次全为成功包，失败路径成本未测，不削减重试来美化延迟。

## 4. 建议的最小下一轮

先只做 SFD VOLK 点积 + 固定模板缓存。复用现有计时字段，并把 SFD 子项、
CIR 子项、num_chips/spc 与失败状态输出到原 runner，避免再建一套验证框架。
下一步再单独做尾部 seed 半径或 CFO 旋转，一次只改一类因素。

验证按风险分级：等价内核用现有 RX QA、代表整数/分数多径及非零 CFO 的同窗
解码对照；搜索范围变更补偏移/弱前沿；chip裁剪补16/32/127 B与PHR失败回退。
只跑受影响检查，正式性能独占锁、同编译参数/库绑定、同输入新旧配对，输出总
comm时间与子项，不把子项收益累加成未经测量的总 SIC 收益。

不需要重写成熟解调链，也不应直接删除 tail tracking/CFO/SFD：这些步骤是为
真实接收前导瞬态和 SFO/CFO 稳健性加入的。SIC 前8符号 CIR/CFO可以作为初值，
但当前 RX 的模板定义、训练长度和采样网格不同，复用最终估计属于后续算法实验。
