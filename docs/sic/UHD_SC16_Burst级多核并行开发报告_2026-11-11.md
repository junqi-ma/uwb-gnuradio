# UHD SC16 Burst 级多核并行开发报告（2026-11-11）

## 1. 任务与结论

针对 `docs/sic/UHD_SC16_65_48重采样优化性能评估报告_2026-11-10.md:44-90`
暴露的问题——**单 Burst 内部切分多核（`--resampler-workers N`）实测慢于单核**——
本任务改为 **Burst 级多核分发（Per-Burst Run-to-Completion）**：UHD 读出的一段
窗口整体交给某个 DSP 核，该核独立完成 `SC16 重采样 → SIC → 雷达/通信解调`
全流程。

**结论：Burst 级分发在持续吞吐上全面胜出，且不牺牲单包延迟。**

| 56,000 点窗口（100 窗，`realtime_minorder`） | Resample 均值 | Resample P50 | 总墙钟 | 相对单核 |
| :--- | ---: | ---: | ---: | ---: |
| 单核（基线） | 205.48 µs | 185.65 µs | **28 ms** | 1.00× |
| 旧：单 Burst 内切 `--resampler-workers 2` | 314.32 µs | 199.11 µs | **41 ms** | **0.68×（退化）** |
| 旧：单 Burst 内切 `--resampler-workers 4` | 221.11 µs | 203.45 µs | **30 ms** | **0.93×（仍退化）** |
| 新：`--dsp-workers 2` | 198.34 µs | 183.37 µs | **13 ms** | **2.15×** |
| 新：`--dsp-workers 4` | 210.56 µs | 184.39 µs | **13 ms** | **2.15×（已转 RX 受限）** |

旧方案的退化在本次独立复测中被**完整重现**（2 路内切 41 ms vs 单核 28 ms），
新方案在同样的 100 个 56,000 点窗口上把总墙钟压到 13 ms，且**单包
`resample_us` 均值与 P50 基本不变**（205→198→211 µs 均值，185→183→184 µs P50）。

## 2. 架构实现

### 2.1 每 Worker 私有 SPSC 环形池

`UhdSc16Pipeline` 从单个 `pool_` 改为 `pools_[0..N-1]`。`rx_thread_` 是**唯一
生产者**，逐池仍是严格的 1P/1C，因此 `Sc16WindowRingPool` 的无锁语义
（`write_idx_` / `read_idx_` 单所有者）无需任何 CAS 即可保留。

派发策略（契约 §1.2）：对窗口 `k` 优先尝试 `pools_[k % N]`，满载则顺序探测
`(k+1)%N … (k+N-1)%N`；**全部满载**才计入 `dropped_admission`。slot 发布到它
实际来源的池，绝不发布到"首选池"。RX 永不阻塞、永不上溯背压（契约 C7）。

实测 round-robin 严格成立：`dsp_workers=4` 的 `worker_id` 序列为
`0,1,2,3,0,1,2,3`；16 窗负载分布 `4/4/4/4`，`Load Balance (max/min) = 1.00x`。

### 2.2 单核满血内核

每个 Worker 在**函数栈内**独立持有 `RationalResampler65_48Core`（或 65_32）、
`SicUnifiedScratch`、`SicUnifiedTemplates`、`RadarCirCoreScratch` 与
`cf32_work` / `sic_out` / `sic_ihat` 缓冲。重采样器强制
`set_num_workers(1)`，确保每个 Burst 都走平坦的
`run_macroblock_sc16` + `fir_avx2_sc16_4x` 4 路批量归约路径，不再退化到
`run_mt_sc16` 的单路 `filter_window_sc16` + 串行建表。

这是旧方案慢于单核的**首要原因**，也是新方案单包延迟不升的关键。

### 2.3 Worker 退出闸门：只用 `rx_finished_`（关键缺陷修复）

开发过程中发现并修复了一个会导致账本守恒律破裂的真实竞态。原契约把
`stop_requested_` 也作为 Worker 退出条件，存在如下交错：

1. Worker `w` 看到自己池空且 `stop_requested_ == true`，退出循环；
2. RX 生产者已越过本轮 `stop_requested_` 检查，把窗口 `k` 写入 `pools_[w]`
   并发布 `Ready`，随后才在下一轮退出；
3. 该窗口已计入 `admitted_windows`，但永远没有 Worker 处理它；
4. `admitted != completed + failed + invalid_gap_after`，`verify_invariants()`
   失败。

修复：Worker 退出条件**只能是** `rx_finished_`（`release` 存储 /
`acquire` 读取）加一次双检重取。`stop()` 时 RX 在下一轮检查即退出并置位
`rx_finished_`，Worker 仍会排空所有已准入窗口后才退出。回放源实测
`stop()+wait()` = 0.0 ms；UHD 源受既有 0.5 s `recv` 超时约束，仍远小于
2000 ms 门槛。

### 2.4 保序提交与丢弃语义

多个 Worker 完成顺序天然乱序，因此引入 reorder buffer。实现上采用
**相对索引**：`pending_results_` 的下标是 `window_id - next_commit_id_`，
因此下标 0 永远是下一个待发窗口，`next_commit_id_ == first uncommitted
window_id` 字面成立，且缓冲区基址不需要额外成员。

> 这一处修正了原契约的自相矛盾：原文同时要求"按 `window_id + 1` 绝对扩容"
> 与"裁剪已消费前缀并回退偏移"，一旦裁剪就没有绝对索引的映射基础，字面实现
> 会把新到达的结果存到错误的槽位并永久停滞。相对索引把内存约束从
> "绝对窗口号"变成"乱序跨度"，实际只需数条。

丢弃窗口（`DroppedAdmission`）由 RX 线程走**同一个** `commit_result()`，
`worker_id = -1`。因此对外恒有：

```
results().size() == admitted + dropped_admission + invalid_gap_before_admission
count(state != DroppedAdmission) == admitted_windows
```

`flush_pending_results()` 在 `wait()` 中所有线程 join 之后调用，按升序吐出
残余结果，处理 `max_windows` 提前结束或 `stop()` 产生的尾部空洞。

### 2.5 绑核

`cpu_cores_dsp` 非空时要求长度恰为 `dsp_workers`，否则 `initialize()`
**fail-closed** 返回 false 并打印明确错误；否则 `cpu_core_dsp >= 0` 时
第 `w` 个 Worker 绑到 `cpu_core_dsp + w`。

本机 i7-12700 拓扑为 8 个带超线程的 P-core（兄弟对 `0-1, 2-3, …, 14-15`），
基准一律使用**独立物理核** 2/4/6/8，RX 绑核 0，避免超线程争用。

### 4.3 瓶颈定位：单 RX 生产者

去掉重采样（`native_rate == work_rate == 998.4 MS/s`）、56,000 点窗口、
只跑 SIC：

| | SIC 均值 | 窗间隔 |
| :--- | ---: | ---: |
| N=1 | 19.22 µs | 69.04 µs |
| N=4 | 21.73 µs | 52.50 µs |

SIC 只占约 20 µs，其余 45–50 µs 是 RX 读取 + 拷贝 + 提交路径。这解释了
N=4 之后不再线性扩展：**RX 生产者是串行阶段**，100 个 56,000 点窗口
（22.4 MB）的下限约 13 ms（≈430 MS/s 有效窗口载荷）。

N=8 的回落（146 µs/窗）还叠加了每 Worker 各自加载 SIC 模板
（64×1016 CF32 ≈ 520 KB）与 scratch 的内存带宽争用。

**因此下一步若要把吞吐继续推高，优化对象不是重采样内核，而是 RX 生产者**
（减少 `stream_buf` 的 `resize`/`erase`、把 slot 直接读入以省掉一次 memcpy、
按窗口对齐读取、或双 RX 线程分片）。

## 6. 明确的未验证项

- **未上板**。全部数字来自文件回放，UHD 实机多核、`recv` 溢出行为、
  驱动缓冲区交互均未验证。
- **paced 到达未验证**。回放是 `fullspeed`，RX 生产者不等待真实时间，
  因此本文的"窗间隔"是处理能力上限，不是实时调度下的实际出包间隔。
- **`dsp_workers=8` 已出现回落**，不建议在生产使用 N>4；该结论绑定本机
  20 逻辑核 / 8 P-core 拓扑。
- **`quality_minorder` 的 P95 未全部列出**；56,000 点 N=4 的
  `resample_us` Max 达 1,669.88 µs（单次抖动），P95 为 272.59 µs。
- 未做 MATLAB / native / FPGA 交叉验证；本次改动不涉及 DSP 数学，
  逐窗位级一致性由 QA 覆盖。
- 未测 `stop()` 在 UHD 源上的实际延迟（仅回放源实测 0.0 ms，
  UHD 路径的理论上界为既有 0.5 s `recv` 超时）。
