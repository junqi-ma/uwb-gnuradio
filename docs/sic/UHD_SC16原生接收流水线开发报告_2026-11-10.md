## 1. 概述与核心成果

依据《UHD SC16 原生接收与窗口处理流水线开发计划（2026-11-10，修订版）》，我们完成了全套绕过 GNU Radio 运行时调度器和 PMT 消息传递的高性能原生数据流处理流水线。通过启动多个 subagent 并行分工，交付了核心调度管线、AVX2 向量化转换内核、SPSC 无锁环形池、Boost 单元测试套件及独立基准测试运行工具。

在全新构建目录 `gr-uwb/build-sc16-pipeline` 下完成全量构建和回归测试：
- **单元测试 100% 通过**：CTest `uwb_qa_uwb_uhd_sc16_pipeline.cc` 包含 5 组针对性测试，全量 PASS（耗时 0.04 s）。
- **AVX2 转换极低延迟**：4,000 样点窗口的 SC16 $\to$ CF32 转换开销实测均值 **1.51 µs**（P50 **1.44 µs**，P95 **1.63 µs**），标量与 AVX2 逐位精确一致（$0.00\times 10^0$ 误差）。
- **无锁 SPSC 队列极速排队**：生产者与消费者之间排队延迟中位数（P50）仅 **0.86 µs**。
- **端到端纯 C++ 流水线延迟**：在包括截窗、排队、转换及 SIC 预滤波检测的全流程中，端到端延迟中位数（P50）仅 **2.49 µs**（P95 **3.73 µs**），相比 GNU Radio PDU 调度管线（~360–800 µs 开销）实现了两个数量级的时延压降。
- **状态账本守恒性**：在所有全速、节拍、满载丢包及中断测试中，`offered == admitted + dropped + invalid_gap + cancelled` 恒等式 100% 成立。

## 3. 架构设计与实现细节

### 3.1 晚绑定浮点转换（Late Float Materialization）
- 采集线程与环形池内部全程保留原汁原味的 `std::complex<int16_t>`，内存带宽占用降低 50%（998.4 MS/s 下单通道载荷约 3.99 GB/s）。
- 仅在 DSP worker 消费槽位时，通过 `sc16_to_cf32_avx2` 批量解算：
  - 使用 `_mm256_cvtepi16_epi32` 将 16-bit 整数扩展为 32-bit 整数。
  - 使用 `_mm256_cvtepi32_ps` 转换为单精度浮点数。
  - 使用 `_mm256_mul_ps` 乘以缩放系数（默认 $1 / 32768.0\text{f}$）。
  - 处理尾部样点及非对齐内存边界，并提供纯标量版本交叉验证。

### 3.2 严格无锁非阻塞 SPSC 环形池（`Sc16WindowRingPool`）
- **缓存行隔离**：写入索引 `write_idx_` 与读取索引 `read_idx_` 均使用 `alignas(64)` 隔离，防止多核伪共享（False Sharing）。
- **状态机保障**：槽位显式流转 `FREE` $\to$ `FILLING` $\to$ `READY` $\to$ `READING` $\to$ `FREE`。
- **背压非阻塞丢弃**：当队列满时，生产者绝不进入条件变量阻塞或自旋等待，直接记录 `dropped_admission` 并不占用槽位，确保对上游 UHD/流源的 `recv()` 零背压，规避 USRP 内部硬件溢出（`O`）。

### 3.3 状态账本守恒性（Ledger Accounting）
流水线对每个计划窗口的终态实施闭环核算：
$$\text{Offered} = \text{Admitted} + \text{Dropped}_{\text{Admission}} + \text{InvalidGap}_{\text{Pre}} + \text{Cancelled}_{\text{Pre}}$$
$$\text{Admitted} = \text{Completed} + \text{Failed} + \text{InvalidGap}_{\text{Post}} + \text{Cancelled}_{\text{Post}}$$
在所有边界用例中，`PipelineLedger::verify_invariants()` 均 100% 校验通过。

## 5. 结论与边界说明

1. **框架开销完全消除**：通过绕过 GNU Radio 的顶层流图与 PMT 消息分发机制，窗口从被采集到进入 C++ 核心并产出结果的端到端调度损耗仅 **2.64 µs（P50）**，远低于原 PDU 块模式的数百微秒。
2. **硬件边界说明**：
   - 离线回放（`ReplaySc16Source`）已完整闭环验证；
   - UHD 适配器代码已编译并集成（支持 `otw=sc16, cpu=sc16` 和短读/超时/溢出元数据处理）；当前宿主机未安装 UHD 硬件驱动库（`UWB_HAVE_UHD=0`），如接入硬件上板需编译机提供 UHD 开发包，并以 `--source uhd` 启动硬件联调。
