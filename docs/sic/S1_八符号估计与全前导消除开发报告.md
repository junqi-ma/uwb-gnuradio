## 2. S1-01：相减支持解耦（R02/R06）

**根因**：S0 core 用 `detected_start + confirmed*sps + post_tail` 定义支持，`confirmed`

（`cfo_failed`）；“训练了多少个符号”与“能减多少个符号”被错误耦合。

**代码位置**：`gr-uwb/lib/uwb_preamble_sic_core.cc`
- 支持预测：`:1420-1436`（`predicted_support_hi = min(n, origin+sync_reps*sps+post_tail)`，
  `support_source="configured_nominal_prediction"`；`ConfirmedLegacy` 走 `confirmed*sps+post_tail`）；
- 许可相减区：`:1444-1482`（`predicted_support ∩ sub_roi`，否则 `∩` 公开 ROI）；
- 严格前缀：`:916`（`resolve_visible_end`）、`:1046`（`estimate_impl` 全部读受 `visible_end` 约束）。
- app 侧：`gr-uwb/apps/uwb_sim_preamble_sic.py:2816`（传 `--sic-model-mode`）、
  `:3550`（默认 `estimate8_frozen`）、`:3465`（`--sic-cover-preamble` 仅为
  `confirmed_legacy` 别名）。

## 12. 六个收尾问题的回答

**(a) 剩余前导是否实际消除**：**是**。
support 覆盖 `coverage=1.000`（名义 `c24`），support 长度 `65124 = 64·sps + post_tail`
（`sps=1016`、`post_tail=100`），由公开 profile 预测（`support_source=configured_nominal_prediction`）。
末 4 SYNC **实际相减**：名义 `c24` tail 28.3055 dB（终版功能 smoke `s1_smoke_final` tail
28.2688 dB），native tail 11.9138 dB；core QA `s1-full-support` 尾部 `out==y-i_hat`
max|diff|=0，clean 环境 tail4=54.63 dB，**legacy 模式 tail4=0.00 dB**（旧缺陷复现）。
不是“只消除了 8 个符号”。

**(b) 参数是否仅来自前 8 个 SYMBOL**：**是（含显式 +8 样点可见性 guard）**。
- 前缀隔离 QA：3 个独立尾部变体（加性扰动/清零/无关噪声）使 `model_id` 与**全部模型字段**
  完全一致；`mmap PROT_NONE` 在 `observed_end` 后 64 样点仍得到**相同模型**
  （`s1-prefix-guard-page`）。
- 数据依赖：`eval_feeds_estimation=false`、`eval_feeds_gate=false`、
  `online_is_used_for_cfo=false`、`estimation_includes_online=false`。
- 声明：`estimation_ranges={cfo/cir/training:[1997,10125)}`（= 8·sps）、
  `estimation_ready_sample=10133`、`observed_end_sample=10133`、
  `visibility_guard=8`、`strict_8sync=false`、`guard={pre:0, post:8}`。
  **如实标注**：训练只用前 8 个 SYNC；另有 8 样点后置可见性 guard（供向量化越读），
  因此**不称“严格 8-SYNC 模式”**（与指示 §4.1 一致）。

**(c) 独立区能否恢复解调**：**能**。
名义 `c24`：**`sic_ok=100/100` vs `raw_ok=0/100`**（`raw_fail_sic_ok=100`、
`psdu_ok=200`、`failing_stages=["raw"]`）；native **`sic_ok=32/32` vs `raw_ok=0/32`**。
旧 8/52 配置为 `sic_ok=0/100`（`cfo_failed`）。独立评估区 `[10125,67021)` 只评估、不反馈，
其 ACTUAL 抑制度 `c24`=28.3134 dB。

**(d) 冻结模型稳定性**：**稳定**。
- chunk 不变性：整窗 vs 47 固定分块 vs 34 随机分块，`out` 与 `i_hat` **逐位一致**
  （`s1-chunk-invariance`：0 diffs）；C++ `kReconBlock=4096` 绝对块栅格 + 绝对 CFO 相位锚定。
- apply 不重拟合：`apply.refit_count=0`、`param_deltas={}`。
- 前缀变更不改模型：`s1-prefix-isolation` 与 `s1-cfo-isolation`（后置 +80 kHz 相位跳变）
  下模型**完全一致**；`s1-cfo-isolation` 独立区 ACTUAL 抑制度 72.54 → −3.08 dB，证明评估真实。

**(e) 训练与 apply 各需多少时间**：见 §11.2。
8-SYNC 估计（`estimate8`）**约 1.53–1.64 ms**（`train_total` 1.74–1.87 ms），
`apply` **约 0.50–0.54 ms**（apply 吞吐 3.19 ns/sample、~314 Msample/s、K=4 时 32 flops/sample）。
观测时间 8·sps≈8.14 µs **不是** CPU 参数就绪时间。

**(f) 纯目标链是否达到原性能门槛**：**否**。
- **SIC mean≤0.5 ms：NO**（真实负载 SIC 步 mean **2.5–3.3 ms**）；
- **P99≤1 ms：NO**；

## 14. 已解决发现（本轮修复，含修复前后）

### 14.1 app 侧竞争：`ResultSink` 陈旧读取（已修复）

**根因**：`ResultSink._handle` 在 GNU Radio 消息线程运行，而驱动在主线程轮询 `count`
并读取 `latest`。原实现**先发布 `count` 再更新 `latest`**，等待者可能观察到新 `count`
但 `latest` 仍是**上一窗**的 dict——于是把上一窗的旁路元数据配到当前窗的 `y` 上，
产生“旁路输出与自身 `y` 非逐位一致”的假象。

**代码位置**：`gr-uwb/apps/uwb_sim_preamble_sic.py:171-211`
（新增 `threading.Lock` + `snapshot()`，`count`/`retained`/`latest` 同锁更新；
`wait_sic:2182`、`wait_for:2199` 改用 `snapshot()` 原子读取）。

**修复前后反例**（同一负样本命令，acceptance seeds）：

| 指标 | `s1_accept_negative_v2`（修复前） | `s1_accept_negative_v3`（修复后） |
|---|---:|---:|
| 旁路逐位一致 | **4999/5000**（`very_weak_isr` 999/1000） | **5000/5000** |
| `bypass_all_identical` | **false** | **true** |

另将“是否改变输出”的判定统一到单一谓词 `iq_bit_identical`（`:406`，CF32 逐字节，
同位置 NaN 视为相同），使 `bypass_bit_identical` 与 `recon.output_changed` 不可能互相矛盾。

### 14.2 两处 verifier 放宽（已实现，含声明约束）

`tools/sic/verify_s0.py`（S1 段）：
1. **独立评估/尾部区定义为 nominal ∩ 相减 ∩ 真值重叠**（原要求“必须完全落在已相减区”）。
   现在允许运行**显式声明**裁剪：`cancellation_clipped` / `eval_covered_frac` /
   `tail_covered_frac`（`S1_CLIP_FLAG_KEYS`、`S1_EVAL_COVERED_KEYS`、`S1_TAIL_COVERED_KEYS`），
   声明分数必须与复算交集一致；若区域越出 `sub`/重叠却仍声称满覆盖则 **FAIL**。
   修复前：无法相减整段名义区的运行被一律判 FAIL；修复后：如实声明即通过，虚报仍 FAIL。
2. **重建归档策略**：允许只归档部分 `recon/window_*.npz`，但须声明
   `archive_policy`（`per_cell`/`archived_ids`/`total_windows` + 未归档限制），
   且每 cell/case 归档 **≥ `S1_MIN_ARCHIVED=4`**（`s1_accept_main_v3` 每 cell 8 窗、
   `s1_accept_negative_v3` 每 case 8 窗）；无策略则保留全数组要求。
   修复前：72×100 全归档约 36 GB、不可行；修复后：verifier 只复算归档窗（≥4/ cell），其余按声明跳过。
3. 聚合根交叉校验：`cells/` / `cases/` 根的 `main_matrix.json` / `negative_table.json`
   必须与子 `summary.json` 一致（`_AGGREGATE_CHILD`、`_s1_lookup_any:5639`）；
   零 commit 的运行（全旁路）其模型证据族 **SKIP 而非 FAIL**。
