先生成一次输入，以后复用 `results/perf_bench/real_inputs`。生成命令是 benchmark 自己的 `--generate-inputs`，目录里已有 64 个 `win_*.cf32`。`config_hash` 为 `48f207c2c97b28f93fe48cf41636dbc030c1191d1d9fc28a797bdbc258e8ea19`。

正式行持有锁。失败就停，不要并跑第二份。cwd 会进入 `provenance`：要让 `git_branch` 写成 `feature/sic-perf`，就在性能 worktree 里启动。本轮锁内脚本的 cwd 是主检出，那些行的 `git_branch` 因此写成了 `feature/sic-research`。库路径仍然是对的。

```bash
exec 9>/tmp/uwb-sic-benchmark.lock
flock -n 9 || exit 1
BIN=gr-uwb/build-sic-accum/apps/benchmark_preamble_sic
BUILD=gr-uwb/build-sic-accum
EFFECT=$BUILD/results/s1_effect_perf01
INPUTS=$BUILD/results/perf_bench/real_inputs
env -u LD_LIBRARY_PATH "$BIN" \
  --preset main --mode core --consumer sic \
  --model-mode estimate8_frozen \
  --input-source real \
  --windows 10000 --rounds 3 \
  --inputs "$INPUTS" \
  --effect-run "$EFFECT" \
  --build-dir "$BUILD" \
  --output "$BUILD/results/perf_bench/formal_cand_g1"
```

基线把 `BIN`、`BUILD` 换成 baseline worktree 的路径。`--effect-run` 和 `--inputs` 仍指向候选构建下已经生成的那两份目录。三组目录名是 `formal_base_g1`…`formal_cand_g3`。顺序是 base、cand、base、cand、base、cand。

资格行把 `--windows 400 --rounds 1`，输出目录：

| 目录 | 额外环境 |
|---|---|
| `short_base_core` | 基线二进制，无 |
| `short_cand_core` | 候选二进制，无（默认开） |
| `short_cand_diag0` | `UWB_SIC_REFINE_DIAG=0` |
| `short_cand_nocache` | `UWB_SIC_COL_CACHE=0` |
| `short_cand_noself` | `UWB_SIC_SELF_ENERGY=0` |
| `short_cand_fused` | `UWB_SIC_FUSED_SCORE=1` |
| `short_cand_incr` | `UWB_SIC_INCR_RESID=1` |

环境变量写在命令前面，例如 `env -u LD_LIBRARY_PATH UWB_SIC_FUSED_SCORE=1 "$BIN" ...`。默认候选资格行是进锁之前单独跑的。

GR 行是一组，不是三组：`--mode gr --windows 2000 --rounds 3`，`--consumer` 依次为 `sic`、`cir`、`demod`，目录 `gr_sic_base`、`gr_sic_cand`、`gr_cir_base`、`gr_cir_cand`、`gr_demod_base`、`gr_demod_cand`。这些行的 `formal_perf` 是 false。

warmup 由二进制固定为 200，统计排除它们。summary 里的 `resources.warmup_windows` 应为 200。`resources.win_per_s` 是饱和串行完成率。没有 `--rate` 或 `--duration` 的成功记录。

读结果用 `core_sic_summary.json` 或 `gr_*_summary.json` 的 `timings_all.core_total`。精化子计时只在 `core_sic_windows.csv`，不要加回 `estimate8_us` 或 `core_total`。
