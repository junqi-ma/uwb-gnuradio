## 1. B-R01：PER 置信区间方向修正

**缺陷**：`per_psdu()`/`per_fcs()` 与驱动 `per_metric()` 用**成功数**算 Wilson 却写成
`per_wilson95`，`s2b_aggregate.py` 又把该区间画到 PER 曲线上。clean/sic 0/100 被报
`[0.963,1]`，正确 PER 区间是 `[0, 0.037]`。

**修改**：
* `tools/sic/payload_metrics.py` 新增 `per_ci(errors,total)=wilson(errors,total)`；
  `per_psdu`/`per_fcs` 返回 `per_wilson95`（**误差比例**）与独立的 `success_wilson95`。
* 驱动 `per_metric()`/`summarize_run()` 用误差比例算 CI，并新增 `per_fcs`/`per_fcs_errors`/
  `per_fcs_wilson95` 持久化（不只在打印时复算）。
* `tools/sic/s2b_aggregate.py` 的 CSV/figure_data/图全部改用 PER（误差）区间，列名
  `per_ci_lo/hi` 与 `success_ci_lo/hi` 分开。
* 报告与 README 的 CI 口径同步修正。

**数值参考 QA**：`test_sic_payload.py::per_ci_error_direction_reference` 用独立闭式
参考实现 + 字面锚点校验：`0/100→[0,0.036995]`、`100/100→[0.963005,1]`、`52/100`、
`0/1000`、`7/30`、`1/1`；`n=0`/`k>n`/`k<0` → `(None,None)`；并断言
`per_ci(0,100) != wilson_ci(100,100)`、`per_ci(52,100) != wilson_ci(48,100)`。零错误仍给
上界，不宣称 PER=0 能力。

**关闭证据（对原 21100 窗派生重算，不改原 run）**：
`gr-uwb/build-sic-payload/results/s2b_matrix_ci_fix/`：
* `derived_from.json` 记录原 matrix 路径、`matrix.json` sha256、逐 cell `windows.jsonl`

## 2. B-R02：B3 补齐与统一 four-path

**缺陷**：原 B3 只有 6 cell（2 位置@SNR30 + 4 CFO@ISR10），且 `channel_paths()` 自定义
`delay=[0,37,74,111]` 衰减 gain，不是约定 profile。

**修改**：
1. 主 four 恢复为 `testdata/sic_preamble/cases/main.json` 的冻结 profile 并绑定 hash：
   ```
   delay 0    gain (1.0,0.0)
   delay 7.4  gain (0.0,0.5)
   delay 23   gain (0.276,-0.116)
   delay 51.2 gain (0.2,0.0)
   ```
   驱动常量 `FOUR_PATH_PROFILE`；旧整数 4 径降级为显式 `custom_integer_four` 诊断，
   不再称"沿用"。plan/manifest/stages.json 均记录该 profile 与 id。
2. 过渡 SNR 用**校准记录**冻结为 `-3.5 dB`（calibration clean：-5 全错、-3.5 1/100、
   ≥-3 0/100），不挑 acceptance。
3. B3 12 cell（每 cell 500 acceptance 包）：early/late × {trans=-3.5, 30}（4）+
   CFO±50k × ISR{0,10} × {single,four}（8）。
4. `--comm-channel` 真正进入生成器（`channel_paths(args.comm_channel)`），未支持值显式拒绝。
5. `stages.json` 唯一权威冻结配置；旧 SNR 点 `[12,15,18,22,30]` 与旧 6 cell 移入
   `superseded`，消除"配置文件与实际执行各说一套"。

**结果（rectification matrix，acceptance，每 cell 500，PER 为误差比例 Wilson 区间）**：

| B3 cell | clean | raw | sic | rescue | damage | 中位抑制度 |
|---|---:|---:|---:|---:|---:|---:|
| pos_early_trans (−3.5 dB) | 20/500 | 357/500 | 20/500 | 337 | 0 | 24.90 dB |
| pos_late_trans (−3.5 dB) | 20/500 | 343/500 | 20/500 | 323 | 0 | 24.76 dB |
| pos_early_snr30 | 0/500 | 293/500 | 0/500 | 293 | 0 | 41.33 dB |
| pos_late_snr30 | 0/500 | 281/500 | 0/500 | 281 | 0 | 40.93 dB |
| cfo−50k isr0 single | 0/500 | 0/500 | 0/500 | 0 | 0 | 15.11 dB |
| cfo+50k isr0 single | 0/500 | 0/500 | 0/500 | 0 | 0 | 14.91 dB |
| cfo−50k isr0 four | 0/500 | 0/500 | 0/500 | 0 | 0 | 12.51 dB |
| cfo+50k isr0 four | 0/500 | 0/500 | 0/500 | 0 | 0 | 12.37 dB |
| cfo−50k isr10 single | 0/500 | 29/500 | 0/500 | 29 | 0 | 25.11 dB |
| cfo+50k isr10 single | 0/500 | 29/500 | 0/500 | 29 | 0 | 24.81 dB |
| cfo−50k isr10 four | 0/500 | 2/500 | 0/500 | 2 | 0 | **22.63 dB** |
| cfo+50k isr10 four | 0/500 | 3/500 | 0/500 | 3 | 0 | **22.64 dB** |

**结论**：
* 过渡 SNR（−3.5 dB）下 clean 自身失败 20/500，**SIC 与 clean 完全一致**（同 20 个
  噪声受限失败），raw 0.71；rescue 远大于 damage（337 / 0）——SIC 不引入损伤。
* **official four-path + CFO 的抑制度 ~22.6 dB**，远高于初版自定义整数 4 径的 3.64 dB；
  初版"四径+CFO 深度仅 3.64 dB"的观察**只属于旧自定义信道，已 superseded**。
* 全部 12 cell damage=0；困难条件未转化为 PER 损失。CFO 使 raw 失败率下降的现象在
  official profile 下同样出现（ISR10 single raw 0.058、four raw 0.004–0.006），
  仅作为实测记录，不再推断为"CFO 失效"的唯一机制。

## 3. B-R03：verifier fail-closed 与独立复算

`tools/sic/verify_s2b.py` 重写为**自包含**（不 import `payload_metrics` 计算关键统计；
Wilson/PER/CRC/抑制度在本文件独立实现），新增检查：

1. **plan（计划分母）**：`plan.json` 必存且 `planned_windows==行数`、`window_ids`/`seed`
   绑定、`case_config_hash` 在 plan/summary/manifest/index 一致；缺记录/跳号/唯一终态冲突
   FAIL。
2. **库严格性**：`realpath(loaded_library)` 必须存在**且严格位于本 run 的 `build_dir/lib`**；
   拒绝 `/usr/local`、父仓库、另一 worktree（`sic-sensing-accum`）与伪造字符串；复算
   sha256 与记录一致；bindings hash 与 source hash 齐全（repo 可达时逐文件复算）。
3. **provenance**：driver/generator/metrics/verifier/core_header/core_src/adapter_src
   全绑定（不只 driver）；dirty patch 必存。
4. **归档严格**：`archive_policy.archived ≥ min(8,计划窗数)`；声明文件必须存在；
   shape/有限性检查；从归档**独立复算**抑制度、mask 外逐位不变、training 有限；缺文件/
   空 out/NaN/Inf **FAIL 不 SKIP**。
5. **包评分**：从 decoded hex 与 truth hex 重算 `psdu_match`/长度；**独立 CRC** 复核
   wire PSDU 的单次 FCS 与 `fcs_pass` 一致性；FCS 失败/无 bits 路径显式定义。
6. **边界**：training 区间必须完全落在 payload 未知区；ROI/overlap/support/finite 干扰
   均在窗口内；在线 meta 白名单不含真值。
7. **双 PER**：PER_PSDU 与 PER_FCS 分别独立复算，CI 必须是误差比例区间且**不等于**成功
   区间；status 分布求和 == 计划总数；paired 计数复算。
8. **矩阵**：`matrix.json` 存在时 expected cell 集合与子目录核对，缺失/rc≠0 FAIL。

**负样本**（`--self-test`，17 个变体**全部被抓**，保留原 6 个）：
`wrong_denominator / missing_failure_row / bad_roi_order / double_fcs_length /
training_out_of_payload / fake_psdu_match / fake_fcs_pass / delete_failure_and_summary /
wrong_ci_direction / forged_external_library / library_hash_mismatch /
delete_all_archives / delete_one_archive / empty_out_array / zeroed_out_array /
wrong_library_usrlocal / missing_matrix_cell`。（二次复核后增至 **19 变体**，见 §5。）

原 6 个 self-test 保留未删（对齐整改书"不能删原检查来使新版通过"）。

  逐窗输入 sha256**（不匹配则拒绝归档，不伪造），再跑 SIC 落盘，`index` 分列
  `archive_fixed_windows` / `archive_worst_windows`。池化统计始终用**全部行**，最差样本单列。
* **`--comm-channel`**：真正进入生成器；choices 含 `single/four/custom_integer_four`。
* **B0**：补足 100 个无干扰高 SNR closure cell。
* **双 PER**：`summary.per[path]` 同时给 `per`/`per_wilson95`（PSDU）与
  `per_fcs`/`per_fcs_errors`/`per_fcs_wilson95`；逐包 `demod[path].fcs_pass` 归档。
* **BER**：解调未暴露对齐 bits → `not_run` 明确 `N/A / 未实现`，不宣称整体 BER=0。
* **CRN 说明**：同一 cell 内 clean/raw/sic 共用 payload/noise/信道（有意 common-random-

* **报告矛盾修正**：原报告 §3 "PSDU=96 B（不含 FCS 也是 96，含 FCS）"自相矛盾，已改为

## 5. B-N01（二次复核）：库路径信任根与联合篡改拒绝

**证据（复核版本 `b28ad34`）**：`verify_s2b.py::check_manifest()` 以 manifest **自报**
`provenance.build_dir` 为信任根，只把 `loaded_library` 与它比较。**同时**篡改
`build_dir` 与 `loaded_library`（并给出外部库的**正确** sha256）即可让父仓库库被接受，
得到 `manifest_library_strict=PASS`。**注意：本仓库实际运行的 B 库路径/hash 一直正确，
这是校验漏洞，不是"实际加载了错误库"**；ISR20 等效果数据不因此失效。

**修改**（`tools/sic/verify_s2b.py`，修订号 `VERIFIER_REVISION="2026-10-18b"`）：
* 允许的 build/lib 由**可信当前 worktree 根**推导：默认取本 verifier 源码所在仓库
  `<root>`，允许 build = `realpath(<root>/gr-uwb/build-sic-payload)`；或显式
  `--repo`/`--trusted-build`（可审计离线模式）。
* `manifest_build_dir_trusted`：`realpath(build_dir)` 必须**严格等于**可信允许 build，
  不再让两个自报路径互相背书；父仓库 `gr-uwb/build-sic`、另一 worktree、软链接逃逸
  （`realpath` 解析后不在允许目录）一律拒绝。
* `manifest_library_strict`：`realpath(loaded_library)` 必须**严格位于**可信
  `<allowed_build>/lib` 之下（`commonpath`），并存在、非目录本身；`realpath` 解析软链接，
  指向外部的库被拒；配合 `manifest_library_sha256` 复算。
* `manifest_bindings_strict`：bindings 真实路径必须位于可信 build 之内**并**复算 sha256
  （仅存在 path/hash 字段不算核验）。
* 运行决定性文件（driver/generator/metrics/core_header/core_src/adapter_src）**硬复算**；
  **verifier 自身**在源码变化时输出 `manifest_verifier_revision` **NOTE**（历史产物按
  版本说明做 review-side 验证），**不**静默补写旧 manifest。

**新拒绝 QA**：`--self-test` 保留原 17 变体，新增
`co_tamper_builddir_and_library`（同步改 build_dir+library+**正确外部 hash**）与
`bindings_hash_mismatch`，共 **19 变体全部被抓**。

**独立复现（本整改实测）**：加载真实 B1 run，仅改 manifest 内存副本
`build_dir=/home/junqima/workspace/uwb-gnuradio/gr-uwb/build-sic`、
`loaded_library=该目录/lib/libgnuradio-uwb.so.1.0.0.0`（真实文件）、
`loaded_library_sha256=该文件真实 sha256` → 新 verifier 得
`manifest_build_dir_trusted=FAIL`、`manifest_library_strict=FAIL`（联合篡改被拒）；
未篡改的真实 manifest 四项库检查全 PASS。

**历史产物处理**：不为修 verifier 重跑 24200 包；32 cell 用新修订号复核
`verify_failures=[]`、`matrix_problems=[]`；历史 run 的 verifier 源码 hash 与当前不同，
以 `manifest_verifier_revision` **NOTE** 标注为 review-side 验证，**未**改写任何旧 manifest。
