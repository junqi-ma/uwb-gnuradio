## 二、 性能优化修改详解（OPT-01 ~ OPT-11）

### OPT-01：稀疏脉冲重构内核开启 AVX2/FMA 并消除 `noinline` 逐事件调用

* **文件与位置**：
  * `gr-uwb/lib/uwb_discrete_cir_reconstruct.cc`：`fused_axpy`（`L84-L99`）、`fused_addsub`（`L104-L123`）、`apply_discrete_cir_pulses_impl`（`L634-L659`）
  * `gr-uwb/lib/CMakeLists.txt`（或函数级 target 属性）
* **核实依据**：
  1. 在 `uwb_discrete_cir_reconstruct.cc:L84` 与 `L104` 中，`fused_axpy` 和 `fused_addsub` 被显式标注了 `__attribute__((noinline))`：
     ```cpp
     __attribute__((noinline)) void fused_axpy(std::complex<float>* __restrict dst,
                                               const std::complex<float>* __restrict src,
                                               std::complex<float> scale,
                                               std::size_t n) { ... }
     ```
  2. 在 `apply_discrete_cir_pulses_impl`（`L634-L659`）中，针对 `pulses.events`（32B 包为 **8,384** 个事件，127B 包为 **15,616** 个事件），外层循环按事件逐个调用 `fused_axpy(recon + pos, model.taps.data(), c, tap_count)`，其中 `tap_count = 20`（仅 40 个 `float`）。
  3. 同时，`libgnuradio-uwb.so` 编译选项仅含 `-O3 -DNDEBUG -fPIC`，未开启 `-mavx2 -mfma`（参见 `docs/sic/通信解码加速开发报告_2026-11-07.md:L129-L131`），导致 `fused_axpy` 退化为 128-bit SSE2 指令且每次调用都要重新从内存读取 `model.taps[0..19]`。
* **修改方案**：
  1. 移除 `fused_axpy` 和 `fused_addsub` 上的 `__attribute__((noinline))`，改为 `inline` 并添加 `#if defined(__x86_64__) || defined(_M_X64)` 下的 `__attribute__((target("avx2,fma")))` 特化版本。
  2. 针对主路径 `tap_count == 20`（恰好 `20 × 2 = 40` 个 `float` = **5 个 AVX2 `__m256` 寄存器**），提供专用的批处理函数 `accumulate_pulses_tap20_avx2(recon, pulses, taps, ...)`：在进入 8,384 次事件循环前，将 `model.taps[0..19]` 一次性加载到 `t0..t4` 五个 `__m256` 寄存器中常驻；循环内每个脉冲仅对 `recon + pos` 执行 5 条未对齐 load + FMA + store（零 CFO 下若 `sign > 0` 直接 `_mm256_add_ps`，`sign < 0` 直接 `_mm256_sub_ps`，连复数乘法都可省去！）。
* **对零 CFO 分支的额外简化**：
  * 注意在 `L636-L638` 零 CFO 分支中：
    ```cpp
    const cd c = (e.sign >= 0) ? cd(1.0f, 0.0f) : cd(-1.0f, 0.0f);
    fused_axpy(recon + pos, model.taps.data(), c, tap_count);
    ```
    此时缩放因子 `c` 仅为实数 `±1.0f`！却调用了通用的复数乘加 `fused_axpy`（内部做 `sr * cr - si * ci` 和 `sr * ci + si * cr` 四次乘法两次加减）。在零 CFO 分支下，直接按 `e.sign > 0` 对 `recon[pos + k]` 加或减 `model.taps[k]`，算术指令数直接减少 **75%**！

### OPT-02：非零 CFO 稀疏脉冲重构的 `block_base` 预计算表化

* **文件与位置**：`gr-uwb/lib/uwb_discrete_cir_reconstruct.cc:L640-L658`
* **核实依据**：
  * 当前代码在事件循环内维护 `current_block`，每当 `b = e.sample_offset / kPhaseBlock`（`kPhaseBlock = 1024`）变化时调用一次 `std::exp`：
    ```cpp
    if (b != current_block) {
        current_block = b;
        block_base = std::exp(cd(0.0, omega * static_cast<double>(b * kPhaseBlock)));
    }
    ```
* **修改方案**：
  * 由于 `pulses.events` 的 `sample_offset` 单调递增且最大偏移不超过 `pulses.total_samples`（~133k 样点，最多 ~135 个 1024 块），在 `L617-L629` 的 `phase_us` 阶段用 `block_step = std::exp(cd(0.0, omega * 1024.0))` 递推填充一个栈上小数组 `std::array<cd, 256> block_bases`，事件循环内直接写 `block_bases[e.sample_offset >> 10] * scratch.rotation[e.sample_offset & 1023]`，彻底消除条件分支与 `std::exp`。

### OPT-03：融合旁路拷贝、缓冲区清零与 ROI 相减（消除 `out` 双写与冗余 `ihat` 清零）

* **文件与位置**：
  * `gr-uwb/lib/uwb_discrete_cir_reconstruct.cc`：
    * `fullpacket_cancel_discrete`（`L731-L733`）
    * `apply_discrete_cir_pulses_impl`（`L605-L615`, `L669-L674`）
    * `apply_discrete_cir_impl`（`L342-L353`, `L479-L484`）
* **核实依据**：
  1. `fullpacket_cancel_discrete`（`L731-L733`）在入口无条件执行：
     ```cpp
     std::copy_n(y, n, out);
     if (ihat != nullptr && ihat != out) {
         std::fill_n(ihat, n, cd(0.0f, 0.0f));
     }
     ```
     在 `n = 236,416` 下，这两步分别写入 1.89 MB（共 3.78 MB），耗时 **~117 µs**（见 `docs/sic/SIC_帧与输入验证耗时拆解_2026-11-08.md`）。
  2. 随后在 `apply_discrete_cir_pulses_impl`（`L672-L673`）中，又对 `[sub_lo, sub_hi)`（`133,588` 样点，1.07 MB）执行：
     ```cpp
     for (std::size_t j = sub_lo; j < sub_hi; ++j) {
         out[j] = y[j] - recon[j];
     }
     ```
     不仅把 `out[sub_lo..sub_hi)` **重写了第二遍**（耗时 **81.1 µs**），而且当 `ihat != nullptr` 时，`apply_discrete_cir_pulses_impl`（`L611-L614`）在 `bypass_prepared == false` 时还会再次清零。
* **修改方案**：
  1. **延迟旁路拷贝（Lazy Bypass Copy）**：在 `fullpacket_cancel_discrete` 中不要一上来就全窗 `std::copy_n(y, n, out)`；封装一个内联 lambda `ensure_bypass_out()`，仅在验证失败早退分支时才执行 `std::copy_n(y, n, out)`。
  2. **正常路径分段单次写 `out`**：在 `apply_discrete_cir_pulses_impl` 确定 `[sub_lo, sub_hi)` 后：
     * 仅对 ROI 两侧的非相减区执行拷贝：`std::copy_n(y, sub_lo, out)` 和 `std::copy_n(y + sub_hi, n - sub_hi, out + sub_hi)`；
     * 对 ROI 内部 `[sub_lo, sub_hi)` 直接计算 `out[j] = y[j] - recon[j]`（或使用 VOLK `volk_32f_x2_subtract_32f(reinterpret_cast<float*>(out + sub_lo), reinterpret_cast<const float*>(y + sub_lo), reinterpret_cast<const float*>(recon + sub_lo), 2 * (sub_hi - sub_lo))`），消除 1.07 MB 的重复写入。
  3. **支持 `ihat == nullptr` 原地相减快速路径**：当调用方不需要单独导出重构波形 `ihat`（即 `ihat == nullptr`）时，甚至无需分配/清零 `recon` 缓冲区，只需 `std::copy_n(y, n, out)` 后在脉冲循环内直接对 `out[pos + k]` 减去 `c * taps[k]`，可同时省去 `ihat` 清零（~52 µs）和 `subtract_us`（~81 µs）共 **~130 µs**。即便需要 `ihat`（如诊断对比模式），也只清零一次 `ihat[0..n)`。

### OPT-04：可信事务内跳过 `pulse_list_failure` 的 8,384 事件二次扫描

* **文件与位置**：`gr-uwb/lib/uwb_discrete_cir_reconstruct.cc:L208-L249, L557-L561`
* **核实依据**：
  * `modulate_pulse_list_impl`（`gr-uwb/include/gnuradio/uwb/uwb_hrp_mod_core.h:L854-L870`）通过 `add_pulse_event` 生成脉冲列表时，已经对每一个事件强制执行了 `sample_offset < total_samples`、严格单调递增 `sample_offset > back.sample_offset` 以及 `sign == ±1` 检查。
  * 但紧接着 `fullpacket_cancel_discrete`（`L803`）调用 `apply_discrete_cir_pulses_impl`（`L557`）时，后者又无条件调用 `pulse_list_failure(pulses, cfg, scratch)`，把全部 8,384 个事件及首 SYNC 127 个脉冲重新遍历比对一遍（`docs/sic/SIC_帧与输入验证耗时拆解_2026-11-08.md` 实测该步耗时 **9.63 µs**）。
* **修改方案**：
  * 在 `apply_discrete_cir_pulses_impl`（`L557`）中，改为仅在 `!transaction_prepared` 时调用 `pulse_list_failure(pulses, cfg, scratch)`；当由 `fullpacket_cancel_discrete` 内部刚生成的 `scratch.modulator.pulses` 传入（`transaction_prepared == true`）时直接跳过。

### OPT-05：可信解码输出跳过重复的 CRC-16 与 PHR-19 重算

* **文件与位置**：
  * `gr-uwb/lib/uwb_discrete_cir_reconstruct.cc`：`frame_verification_failure`（`L174-L206`）及调用点 `L754`
  * `gr-uwb/lib/uwb_fullpacket_sic_core.cc`：`frame_verification_failure`（`L61-L97`）及调用点 `L133`
* **核实依据**：
  * 在 `demodulate_one` 中，只有当 PHR SECDED 与 Payload CRC-16 校验通过后才会置 `demod.fcs_pass = true`。
  * 但 `frame_verification_failure` 每次收到 `demod` 后，除了检查状态标志位外，还在 `L192-L204` 重新调用 `crc(demod.psdu_bytes.data(), payload_len)` 计算一遍 CRC-16，并调用 `mod::detail::encode_phr19` 重算一遍 19-bit PHR 与 `demod.phr_bits` 逐比特比对。
* **修改方案**：
  * 在 `DiscreteCirConfig`（或接口参数）中区分外部不可信 `DemodResult` 与流水线内部已验帧，或将 CRC-16 查表化；若保留校验，将逐比特 CRC-16（`8 × payload_len` 次分支移位）改为 256 项 `uint16_t` 查表实现。

### OPT-06：移除 `estimate_discrete_cir` 中 100% 重复的前缀 `finite_cf` 扫描

* **文件与位置**：`gr-uwb/lib/uwb_discrete_cir_estimator.cc:L730-L733` 与 `L799-L808`
* **核实依据**：
  * `L730-L733` 遍历 `y[0..visible_end)` 检查有限性：
    ```cpp
    for (std::size_t i = 0; i < visible_end; ++i) {
        if (!finite_cf(y[i])) {
            return fail(SicFailureReason::NonFiniteInput);
        }
    }
    ```
  * 仅隔 65 行后，`L799-L808` 再次遍历完全相同的 `y[0..visible_end)` 计算能量前缀和并检查 `std::isfinite(acc)`：
    ```cpp
    double acc = 0.0;
    for (std::size_t i = 0; i < visible_end; ++i) {
        scratch.energy_prefix[i] = acc;
        acc += static_cast<double>( std::norm(y[i]) );
    }
    scratch.energy_prefix[visible_end] = acc;
    if (!std::isfinite(acc)) {
        return fail(SicFailureReason::NonFiniteInput);
    }
    ```
  * 根据 IEEE-754 浮点规范，只要 `y[0..visible_end)` 中任一元素的实部或虚部为 `NaN` 或 `±Inf`，`std::norm(y[i])` 必为 `NaN` 或 `+Inf`，累加后的 `acc` 必不满足 `std::isfinite(acc)`。
* **修改方案**：
  * 直接删除 `L730-L733` 的循环（若希望在搜索前尽早拦截非有限输入，可将 `L799-L808` 的 `energy_prefix` 构建移至 `L730` 处执行一次即可）。

### OPT-07：优化 `estimate_discrete_cir` 的 Ipatov 训练残差检查 `fit_check_us`（单周期重构替代 8 周期双精度重构）

* **文件与位置**：`gr-uwb/lib/uwb_discrete_cir_estimator.cc:L969-L995`
* **核实依据**：
  * 当前 `estimate_discrete_cir` 总耗时 `215.0 µs`，其中 `fit_check_us`（`L969-L995`）独占 **~86 µs（高达 40%）**！
  * 查看 `L969-L995` 代码：
    ```cpp
    std::fill_n(scratch.z.data(), rows, c64(0.0, 0.0));
    for (std::size_t k = 0; k < train_reps; ++k) {
        const std::ptrdiff_t sym_base = static_cast<std::ptrdiff_t>(k * sps);
        for (std::size_t m = 0; m < kCodeLen; ++m) {
            const std::ptrdiff_t center = sym_base + static_cast<std::ptrdiff_t>(m * kSpc);
            const double s = static_cast<double>(scratch.code[m]);
            for (std::size_t idx = 0; idx < K; ++idx) {
                const std::ptrdiff_t row = center + static_cast<std::ptrdiff_t>(lags[idx]);
                if (row >= 0 && row < static_cast<std::ptrdiff_t>(rows)) {
                    scratch.z[static_cast<std::size_t>(row)] += s * h_est[idx];
                }
            }
        }
    }
    double resid_energy = 0.0;
    ...
    for (std::size_t m = 0; m < rows; ++m) {
        if ((m & (kPhaseBlock - 1U)) == 0U) {
            block_anchor = std::polar(1.0, omega * static_cast<double>(m));
        }
        const c64 phase = block_anchor * scratch.phase_Step_table[m & (kPhaseBlock - 1U)];
        const c64 obs = static_cast<c64>(y[q + m]);
        const c64 pred = scratch.z[m] * phase;
        resid_energy += std::norm(obs - pred);
    }
    ```
  * 为什么这段代码存在巨大的计算冗余？
    1. **训练序列具有严格的周期性（周期 `sps = 1016`）**：对于 `K = 20`、`lag_lo = -1`、`lag_hi = 18`，每个 SYNC 内部的最后一个脉冲位于 `126 * 8 = 1008`，加上最大正抽头 `lag_hi = 18` 后为 `1008 + 18 = 1026`，仅向下一个周期溢出 `1026 - 1016 = 10` 个样点；负抽头 `lag_lo = -1` 仅从上一个周期借入 1 个样点。因此：
       * 第 `k = 1..6` 个周期的完整重构波形 `z[k * sps + t]`（`t = 0..1015`）**完全恒等于同一个单周期波形 `z_per[t]`**！
       * 第 `k = 0` 个周期仅在开头缺少来自 `k = -1` 的跨周期拖尾（`t < lag_hi - 8` 的最多 10 个样点），第 `k = 7` 个周期仅在末尾最后一个芯片（`t >= 1008 + lag_lo`）缺少向 `k = 8` 的借位。
       * 当前代码却用双精度对 `k = 0..7` 重复跑了 8 遍完全相同的 `127 × 20` 双重循环！
    2. **前一步（`L930-L940`）已经把 8 个周期的去 CFO 叠加均值算在了 `avg[0..1015]` 中**：
       * 在 `L930-L940` 中，代码刚刚把 `y[q + k*sps + t]` 乘以 `conj(rot)`（即去除了 CFO 相位）并求出了 8 个周期的均值 `avg[t]`（且总观测能量 `y_energy = scratch.energy_prefix[q + rows] - scratch.energy_prefix[q]` 已在 `L903` 算出，因为相位旋转保持模长不变，`norm(obs - z * phase) == norm(obs * conj(phase) - z)`！）。
       * 即便保留逐点残差定义以确保与现有阈值完全 bit-exact / 数值等价，也只需构造 **1 个周期 `z_per[0..1015]`**（外加 `k = 0` 头部的 10 个修正点与 `k = 7` 尾部的 1 个修正点，共 `127 × 20 = 2,540` 次单周期累加，而非 `8 × 2,540 = 20,320` 次），即可减少 **87.5%** 的重构运算量；若进一步复用 `L930-L940` 已去 CFO 的样本（或帕塞瓦尔展开 $\sum_{k=0}^{7} \|y_{\text{derot},k}[t] - z_k[t]\|^2 = E_y - 16 \operatorname{Re}\langle \text{avg}, z_{\text{per}}\rangle + 8\|z_{\text{per}}\|^2 + \Delta_{\text{edge}}$），甚至无需再跑 `8,128` 点的相位旋转与减法循环，直接将 `fit_check_us` 从 **~86 µs** 压至 **< 10 µs**！
* **修改方案**：
  1. 只对单周期 `t ∈ [0, sps)` 累加一次 `z_per[t]`（处理跨周期环绕索引 `(center + lag + sps) % sps`），单独记录 `k = 0` 头部跨界项与 `k = 7` 尾部跨界项的边界修正量。
  2. 利用恒等式 $\sum_{k,t} \|y_{k,t} e^{-j\omega(k\cdot\text{sps}+t)} - z_{k,t}\|^2 = E_y + \sum_{k,t} (\|z_{k,t}\|^2 - 2\operatorname{Re}(y_{k,t}^* e^{j\omega(k\cdot\text{sps}+t)} z_{k,t}))$，直接用单周期 `avg[t]`（已在 `L930-L940` 算好！）在 `1,016` 个点上完成内积与能量计算，并对首尾最多 11 个边界样点做精确修正。该恒等式在数学上与原 `8,128` 点循环完全等价，且省去了 `8,128` 点 `scratch.z` 清零、7/8 的重构循环和全部 `8,128` 点的二次相位旋转。

### OPT-09：`stage_cir_softchips` 38-tap CIR 估计稀疏化与移除无效的 `soft_chips` 清零

* **文件与位置**：`gr-uwb/include/gnuradio/uwb/uwb_demod_core.h:L998-L1003, L1354-L1355`
* **核实依据**：
  1. **稠密零乘问题（`L998-L1003`）**：
     ```cpp
     for (int nn = 0; nn < tap_count; ++nn) {
         std::complex<float> acc(0.0f, 0.0f);
         for (int m = 0; m < sps; ++m) {
             acc += std::conj(scratch.work[static_cast<std::size_t>(m)]) *
                    scratch.corr[static_cast<std::size_t>(nn + m)];
         }
         values[static_cast<std::size_t>(nn)] = acc;
     }
     ```
     此处 `tap_count = 38`、`sps = 1016`，共执行 `38 × 1,016 = 38,608` 次复数乘加。然而查看上方 `L969-L977` 可知，`scratch.work[m]` 是由长度为 127 的三元码按 `spc = 8` 零插值构造的：**8 个样点中有 7 个严格为 `0.0f`**，仅有 `m = 8 * c`（`c = 0..126`）处的最多 127 个位置非零（且三元码中还有一半为 0，非零值仅为实数 `+1` 或 `-1`）！
     （注：同文件中的 `sync_phase_gain` [`uwb_rx_softchip_opt.h:L87-L94`] 已经利用了只遍历 `8 * c` 的稀疏性，但 `stage_cir_softchips:L998` 仍保留了 `m = 0..1015` 的稠密循环。）
  2. **无效清零问题（`L1354-L1355`）**：
     ```cpp
     if (skip_sync_fir && post_first > 0) {
         std::fill(scratch.soft_chips.begin(), scratch.soft_chips.begin() + post_first, 0.0f);
     }
     ```
     当 `skip_sync_fir == true`（默认开启）时，每包仍将 `scratch.soft_chips` 的前 `post_first = 32,504` 个 `float`（**130 KB**）清零，而后续所有阶段（SFD、PHR、Payload）均只访问 `post_first` 之后的索引（或直接走 fused CMF 根本不读 `soft_chips`）。
* **修改方案**：
  1. 在 `stage_cir_softchips`（`L998-L1003`）中，仅遍历三元码中 `code[c] != 0` 的非零芯片索引（127 长三元码中仅 **64 个非零脉冲**！），根据符号 `+1/-1` 直接对 `scratch.corr[nn + 8 * c]` 做复数加减法：运算量从 `38,608` 次复数乘加骤降至 `38 × 64 = 2,432` 次复数加减（**减少 93.7% 运算量**），且结果在数学上与原式 100% 逐位等价（因为 `0.0f * x == 0.0f`）。
  2. 删除 `L1354-L1355` 对 `soft_chips[0..post_first)` 的无条件清零（仅在诊断导出 `soft_chips` 时按需清零）。

### OPT-11：TX 扩频序列生成 `fill_bprf_spread` 消除逐比特 `memmove` 与重复 LFSR 推进

* **文件与位置**：`gr-uwb/include/gnuradio/uwb/uwb_hrp_mod_core.h:L742-L787, L923-L960`
* **核实依据**：
  1. 在 `fill_bprf_spread`（`L773-L785`）中：
     ```cpp
     auto next_bit = [&]() -> uint8_t {
         const uint8_t out_bit = r[0];
         const uint8_t fb = static_cast<uint8_t>(r[0] ^ r[1]);
         std::memmove(r, r + 1, 14);
         r[14] = fb;
         return out_bit;
     };
     for (std::size_t i = 0; i < start_bit; ++i) {
         (void)next_bit();
     }
     for (std::size_t i = 0; i < count; ++i) {
         dst[i] = next_bit();
     }
     ```
     每生成 1 个 bit 就调用一次 `std::memmove(r, r + 1, 14)`！
  2. 更糟糕的是，在 `modulate_pulse_list_impl`（`L923-L955`）中，刚为 PHR 调用 `fill_bprf_spread(code_index, 0, 1344, ...)` 生成了前 `1,344` 个 bit，紧接着在 `L954` 为 Payload 调用 `fill_bprf_spread(code_index, 1344, nsym * 8, ...)` 时，函数内部又从头跑了一遍 `for (i = 0; i < 1344; ++i) next_bit()` 把前 `1,344` 个 bit 重新算一遍并丢弃！

  1. **用 15-bit 整数位运算替代 15 字节数组 + `memmove`**（每次推进仅需 3 条位运算指令：`out = reg & 1; fb = ((reg ^ (reg >> 1)) & 1) << 14; reg = (reg >> 1) | fb;`）。
