# 通信解码加速：OpenCode 执行任务书

## 1. 目标、基线与范围

工作目录 `.worktrees/sic-fullpacket-compare`，分支 `feature/sic-fullpacket-compare`，
基线 `c13253b`。先读 `docs/sic/通信解码实现与优化分析_2026-11-07.md`，不要重做分析。
本任务优先于入口中的旧任务；用户要求快速开发、多个 subagent 并行、必要验证即可。

目标：保持通信/感知解码结果与失败保护，降低 full-packet SIC 的 comm demod 和
总 SIC 时间。工程目标为 payload_base 通信解码 mean 降低至少 20%，P95 不增加；
其他代表场景不出现明显退化（mean 增加不超过 5%）。目标不是已实现事实。

背景：payload_base RX 独立回放约 2.76 ms：同步/重跟踪 0.69、两次 CFO 0.55、
两次 SFD 搜索 0.40、soft-chip FIR 0.83、后处理 0.18 ms；payload 位解码仅0.022 ms。
正式收益必须本轮同条件配对，不能拿上述独立诊断当端到端对照分母。

必须完成 A/B 的等价计算优化、尾部种子半径修正，以及 C 的按需 soft-chip 路径。
后者先作为显式实验选项，保留完整旧路径回退；未通过则报告具体失败并保持关闭，
不拖延已经正确的 A/B 交付。不开发新 RAKE/FFT/38-tap 多输出 SIMD，不优化
Viterbi/RS/CRC，不改 SIC CIR 估计器、FCS 门槛、重构 FIR、硬件或默认 PHY。

## 3. 各任务的最小改动

### A：同步和 SFD

- `stage_sfd` 两处8128点相关改用现有 `timing_conjugate_dot`/VOLK；候选位置、
  搜索顺序、能量归一化、阈值和 fallback 不变。按 template/profile 缓存归一化
  SFD 模板，避免每包两次构造；不依赖共享 work/corr 缓冲中的临时内容存活。
- `stage_timing` 首次 local_best 目前硬编码 ±max(256,stride)，使尾部调用的
  search_margin=0 失效。新增独立 seed_refine_radius，普通捕获默认仍为256；
  SFD锚定尾部首次用±8，后续跟踪仍±8。
- 保留原±256回退。小范围失败、后续尾部跟踪不足或最终SFD/周期一致性失败时，
  允许一次原路径重试；不能仅因局部峰过阈值就吞掉原可恢复包。
- 首次窄搜与回退分别计数，明确首轮 seed 搜索不属于现有 coarse_search_us。
  不删40符号尾部跟踪、第二次CFO或最终SFD。

### B：CFO旋转

- 将 `stage_cfo` 中峰相位拟合与旋转实现分开，保留两次拟合与原调用顺序。
- 第一版只替换旋转内核：1024点绝对相位块 + VOLK 复乘或实/虚部向量化，
  不再依赖4条逐样本float递推链。保留负号、window-relative坐标、块边界、尾部。
  可参考SIC旋转思路，但接收去CFO符号相反，不能原样复制。
- scratch预分配；不加全库 `-march=native`/fast-math。复用已有native/portable
  构建选择。旋转误差应相对独立double参考检查，不仅比较解码FCS。
- 本轮不做 bootstrap 局部窗口旋转，避免与 C 同时改样本范围。该项留待本轮
  结果确认后再决定，不因分析文档列出了机会就同时实现全部机会。

### C：按PHR长度生成soft chips

- 当前 max_psdu_bytes=127 导致32B场景生成约117174chip，包本身约66784chip。
  先将CIR估计与soft-chip范围生成拆开，复用同一组38tap，不改变tap选择。
- 第一段仅生成相位对齐所需SYNC、SFD、PHR及原有搜索guard；解出有效PHR后，
  按现有编码几何计算payload所需chip，生成缺失范围。保留原chip索引语义，
  不截断完整接收IQ，不将注入长度或sidecar传入在线函数。
- 保留匹配滤波halo、分数spc插值与最后有效样点规则；所有累计输出不超过n。
  packet长度必须来自校验过的PHR，不能在32B测试中硬编码32。
- 相位估计仅计算一次。明确旧全流最大值归一化与分段归一化的关系：PHR用其
  可见范围归一化，扩展后按最终需要范围重新统一缩放已有soft chips；该变化
  属于实验行为，不能宣称逐位等价。不得在两段使用不一致增益送入联合解码。
- PHR失败、范围不足或payload FCS失败时最多回退一次完整旧soft-chip流程，
  保留原长度邻域/极性重试；记录fallback次数和耗时，不能只统计快速成功包。
- 不同时跳过前32SYNC，不启用Top4/8 RAKE，不强行将分数spc取整。

## 4. 集成与最少验证

保留基线 build，新建 `gr-uwb/build-sic-fullpacket-rxopt`，Release 配置与旧fast
runner一致，ldd核实实际加载库。使用显式RX选项保留原路径，便于同binary配对；
配置放在实验wrapper，默认已有调用者不变。头文件改动须重建实际fast runner。

每个 subagent 只做本模块针对性检查；主 agent 集成后跑一次受影响RX QA与以下
同源窗功能集合，禁止每个agent重复跑整套smoke/历史矩阵：

- 复用现有 sync_base、payload_base、payload_four_frac、payload_cfo_m50k/
  p50k、payload_len16/127、payload_snr8，沿用每格16源窗，不重新造大数据集。
- 比对逐源窗comm/sensing PSDU与FCS，不只比较成功总数；无新增旁路或误提交。
- A补一个seed偏移/弱前沿局部回退用例；B补块边界、非向量整倍长度与正负CFO；
  C补PHR失败、错误长度/截断回退、分数spc。复用已有QA覆盖的项目，不重复新增。
- 数值参考、门槛及允许变化先写清；不为通过而放宽既有门槛。C若改变软值，
  报告解码、失败回退和时标变化，不以“本来就不逐位一致”跳过质量检查。
- 全部为软件离线验证；MATLAB未跑写未验证，不展开硬件/历史全矩阵。

## 5. 计时与交付

复用原benchmark输出，增加已有的SFD子计时、CIR子计时、CFO拟合/旋转子计时、
num_chips/spc、fallback计数；不要另建大runner/verifier。父子不重复累加。

质量通过后只测 sync_base/payload_base/payload_four_frac 三格：16源窗，
每变体16预热、128观测×2轮，旧→新/新→旧。一次配对即可；只有改码或明显
运行异常才重测。锁 `/tmp/uwb-sic-benchmark.lock`，清理LD_LIBRARY_PATH，
绑定干净提交、profile、n、编译参数、库hash。保存源窗重复和失败行。

报告 comm总时间、总SIC、SFD各子项、CFO、CIR估计/FIR/后处理、fallback；
mean/P95即可，不借小样本承诺实时P99。按需模式与完整路径分别列出是否达标。
