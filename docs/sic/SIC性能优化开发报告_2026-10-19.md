# SIC 性能优化开发报告（2026-10-19）

本报告只覆盖 `feature/sic-perf`。没有合并回 `feature/sic-research`，没有推送，没有移动 tag `sic-s2-ab-integrated-20261018`。

## 1. 结论

默认路径保留了不改变运算顺序的复用（E0）：路径列缓存、1024 点相位基表、单块重建缓存、自能量表、整窗只复制一次。融合评分和增量残差的指纹与冻结库逐位一致，资格行更慢，保持关闭。

同一台机器、同一 64 窗真实语料上，正式 core 三组（每组 10000 窗 × 3 轮，warmup 200 不计）为：

| 组 | 冻结基线 core mean | 候选 core mean | 差值 |
|---|---:|---:|---:|
| 1 | 2379.8 μs | 1855.6 μs | −524.1 μs |
| 2 | 2497.7 μs | 1804.0 μs | −693.7 μs |
| 3 | 2390.9 μs | 1812.5 μs | −578.5 μs |

三组等权平均：基线 2422.8 μs，候选 1824.0 μs，差 598.7 μs。三组候选均值都在 1.90 ms 以内，最慢的一组是 1.856 ms。这是本轮要看的量级。

历史目标 mean≤0.5 ms、P99≤1 ms、按 offered/admitted/missed-admission 计量的 200 窗/s 都没有达到。三组候选的 core P99 分别是 4129、3107、3103 μs。每一组 30000/30000 窗都超过 1 ms 和 0.5 ms 的 deadline 计数。没有跑带速率的 admission 回放。

B 的 32 格 / 24200 包正式矩阵没有跑。B 的结论是：候选实现，尚未最终验收。11 格 smoke 只是回归。

## 12. 风险

- 只在这一台 WSL 主机、这一份 ISR 10 dB / K 配置为 4、实际精化 K=3 的语料上有正式三组。B 的 payload 碰撞前缀更长，没有单独的配对计时，不能把这个加速比套到全部 B 场景。
- 第 1 组候选 P99 没有好于基线。尾部仍有 10 ms 以上的窗。
- 自能量填表在第一窗的 `core_total` 里。短进程或每个窗重新 `prepare` 的用法看不到 warmup 后的均值。
- 诊断子计时和额外 PMT 键有开销。正式 core 数字含着诊断开。
- 效果绑定的 8 窗 run 与 12 格 A、11 格 B smoke 都不是 B 的 24200 包矩阵。
- 没有上板，没有 TWR，没有新的 GNU Radio block 类型。调度语义没有改。
