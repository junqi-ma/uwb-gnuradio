# 低 SNR 进锁阶段（`ACQUIRE -> VERIFY -> LOCKED`）实验、修改与快速验证方案

**日期**：2026-11-17  
**目标**：解决低带内 SNR（`-6 dB ~ -14 dB`）下前端捕获漏检、种子偏移过大以及进锁闭环失败问题，用最少测试轮次快速验证可行性。

---

## 1. 已证实的根因与基线数据（无需重复排查）

在 `737.28 MS/s` 采样率、Code 10、`256` SYNC 符号（原生长度 `192,071` 样点 ≈ `260.5 µs`）下，已完成以下定量验证（数据见 `docs/performance/data_awgn_snr_20261117/`）：

1. **前端自相关积分长度与抽样损失（[uwb_dw3000_live.cc](../../gr-uwb/apps/uwb_dw3000_live.cc) `Acquisition::scan`）**：
   - `64k / step=8`（`N=8,000` 对）：`-14.0 dB` 下 0.5 s 纯噪声最大峰 `0.001477` 高于信号中位数 `0.001392`（仅 `41.0%` 帧高于噪声峰值），且平台宽度达 `173 µs`，上升沿触发位置随 SNR 漂移超过 `36,864` 样点（`±50 µs` 目标锁关联窗）。
   - `192k / step=8`（`N=24,000` 对）：隔 8 点抽样损失约 `5.2%` 弱包（`474/500`）。
   - **`192k / step=1`（`N=192,000` 对，整段 Preamble 滑窗）**：
     - `0.5 s` 纯噪声最大值为 **`0.0000523`**（理论均值 `5.21e-6`）；
     - `-14.0 dB` 500 帧信号峰值为 **`min=0.000371 / med=0.000619 / max=0.000850`**（最差包仍为噪声最大值的 **7.1 倍**，`500/500 = 100.0%` 零重叠分离）；
     - 因窗长等于整段 Preamble，自相关曲线呈**无平台三角形**，顶点 `argmax` 天然对齐包起点 `pkt_start`（`p05 = -3,420`、`med = -546.5`、`p95 = +2,180` 样点，**100% 落在 `±36,864` 样点关联窗内**）。
2. **进锁闭环的第二道卡点（Worker 反馈 -> `TargetLockCore::apply_observation`）**：
   - `TargetLockCore` 从 `ACQUIRE` 进入 `VERIFY` 只需 **1 个有效观测**，集齐 `verify_observations=3` 个即进入 `LOCKED`（[uwb_target_lock_core.h](../../gr-uwb/include/gnuradio/uwb/uwb_target_lock_core.h) L847–L935）。
   - 但当前进锁反馈在低 SNR 下被两处拦死：
     1. **[uwb_demod_core.h](../../gr-uwb/include/gnuradio/uwb/uwb_demod_core.h) `stage_timing` 单符号门限**：在 `-14.0 dB` 下，256-SYNC 联合 CIR 输出 SNR 高达 **`35.9 dB`**（`200/200` 零误差），但 `stage_timing` 第一步只用**单个** SYNC 符号（`L=1016`）过门限（`0.25`），导致 `-14 dB` 下 `timing_ok = 0/50`。
     2. **[uwb_target_lock_core.h](../../gr-uwb/include/gnuradio/uwb/uwb_target_lock_core.h) L634 `cfg_.require_fcs` 默认 `true`**：127 B BPRF payload 的译码极限约 `-4.5 dB`；在 `-6 ~ -14 dB` 下即使 `timing_ok && sfd_ok && cir_ok` 全过，只要 `require_fcs=true`，`identity_matches()` 就会按 `FcsFailed` 丢弃观测，永远无法进入 `VERIFY/LOCKED`。

## 2. 修改方案（分三步、职责正交）

### 修改 A：前端 `Acquisition` 改为「64 点分块全采样累加 + 三角形峰顶触发」（[uwb_dw3000_live.cc](../../gr-uwb/apps/uwb_dw3000_live.cc)）

1. **消除 `step=1` 的单核 CPU 瓶颈（分块框和，数学等价于 `step=1`）**：
   - 保持全采样积分对数 `N = 192,000`（`span = 192000`），但不再每 `1` 个样点更新一次环形缓冲、做一次 `double` 除法与状态机分支；
   - 改为每 **`B = 64` 个连续样点**（`86.8 ns`）作为一个累加块 `BlockPair`：内层循环对 `64` 对 `stream[probe + k]` 与 `stream[probe + 750 + k]` 连续累加 `re, im, e1, e2`（编译器在 `-O3 -mavx2` 下自动向量化，或显式用 `int32/float` 累加），外层每 `64` 个样点才入环（环长仅 `192000 / 64 = 3000`）、计算一次 `metric` 并走一次状态机。
   - 由于 `192k` 三角形底宽 `521 µs`，`86.8 ns` 采样步进对峰值的损失 `< 0.03%`，而状态机/除法开销降低 **64 倍**，环形缓冲区缩至 `3000` 项（L1 cache 常驻）。
2. **用「三角形峰顶 `peak_at` 触发」替代「上升沿 `first + seed_shift` 触发」**：
   - 当 `metric >= low_thr` 时，除了记录 `first`、`last`，同时记录当前簇的最大值位置 **`peak_at`**（当 `metric > peak` 时更新 `peak = metric; peak_at = at;`）。
   - **提交条件**：已满足 `at - first >= min_persist && peak > peak_thr`，且出现以下任一峰后回落信号时立即提交：
     - `metric <= peak * 0.6`（已滑过三角形顶点），或
     - `at - peak_at >= 16384`（顶点后已走过 `~22 µs`）。
   - **提交种子**：直接返回 **`seed = peak_at`**（不再加固定 `seed_shift`）。
   - **收益**：无论在 `+10 dB` 还是 `-14 dB`，`192k` 滑窗的峰值位置 `peak_at` 恒定落在 `pkt_start ± 4,000` 样点内，彻底消除高/低 SNR 上升沿早晚差 `150,000` 样点的顽疾。
3. **默认/推荐低 SNR 参数**：
   - `span = 192000`、`step = 64`（内部 `64` 点全采样块求和，有效对数 `N = 192,000`）
   - `low_thr = 0.00009`、`peak_thr = 0.00018`（位于 0.5 s 噪声最大值 `0.0000523` 的 `3.4` 倍、`-14 dB` 最弱包 `0.000371` 的一半，双侧均有充足余量）
   - `min_persist = 12000`

### 修改 B：`stage_timing` 增加「多 SYNC 周期折叠相干粗搜/精搜」（[uwb_demod_core.h](../../gr-uwb/include/gnuradio/uwb/uwb_demod_core.h)）

当单符号（`L = 1016`）搜索未过门限时，在 `stage_timing` 中启用多符号周期折叠兜底（仅在单符号失败时触发，不影响高 SNR 耗时）：

1. **折叠窗口构造**：
   - 给定候选起点范围 `[w0, w1]`（在 `LockedBounded` 下为 `seed ± roi`；在 `AcquireLegacy` 下由于修改 A 的 `peak_at` 已准确定位在 `±5,500` 工作样点内，只需搜索 `seed ± 8192` 工作样点）：
   - 取 `K_fold = 64` 个 SYNC 符号，按标称周期 `P_nom = 1016` 样点把接收序列折叠累加到一段长度 `(w1 - w0) + L` 的临时缓冲 `folded[i] = sum_{m=0}^{63} rx[w0 + i + m * 1016]`（对 `350 Hz` 典型 CFO，`64` 符号相位旋转仅 `0.14 rad`，损耗 `< 0.05 dB`，信噪比提升 **`+18 dB`**）。
2. **在 `folded` 上执行原有的 `local_best` / 步进搜索**：
   - 折叠后 `-14 dB` 等效提升至 `+4 dB` 单符号水平，峰值归一化相关度与 PAR 均大幅超过门限，直接定出 `first_start`。
3. **周期与 CFO 估计适配**：
   - 若单符号峰值低于跟踪门限，改为按 **每 `16` 个 SYNC 符号相干折叠成一个超级符号（共 `16` 个超级锚点覆盖 `256` SYNC）**，在每个超级锚点 `±8` 样点内取峰值位置与复数相位，完成线性周期拟合 `measured_period` 与 `stage_cfo` 相位斜率拟合。

### 修改 C：目标锁支持无 FCS 的前导/SFD 进锁模式（[uwb_target_lock_core.h](../../gr-uwb/include/gnuradio/uwb/uwb_target_lock_core.h) & [uwb_dw3000_live.cc](../../gr-uwb/apps/uwb_dw3000_live.cc)）

- 在 `uwb_dw3000_live.cc` 增加 CLI 开关 `--lock-fcs on|off`（默认 `on` 保持现有行为不变；低 SNR 锁定/感知测试设 `--lock-fcs off` 映射为 `lock_cfg.require_fcs = false`）。
- 当 `require_fcs = false` 时，只要 `timing_ok && sfd_ok`（或启用 `--stop-after-sfd`）且 `observed_origin` 残差合规，即可正常驱动 `ACQUIRE -> VERIFY -> LOCKED` 状态机闭环。

## 3. 快速验证与测试方案（避免重复/全网格慢测）

**原则**：不跑多点全量 SNR 扫描，只用 **3 个锚点 SNR（`+10 dB` 高信噪比边界、`-10 dB` 中低信噪比、`-14 dB` 目标极限）+ 1 段纯噪声**，单次验证控制在 **15 秒以内**。

### Step 1：纯前端 `Acquisition` 独立微基准（耗时 < 3 秒）
复用独立测试程序（不启动解调 worker），只跑以下 4 组输入（每组 `100` 个 1 ms 时隙 = `0.1 s`，纯噪声跑 `0.5 s`）：
1. **纯 AWGN 噪声（`0.5 s = 368,640,000` 样点）**：
   - 验收标准：`false_alarms == 0`，且单线程处理耗时 `< 100 ms`（即 `< 20%` 单核实时预算）。
2. **`+10 dB`、`0 dB`、`-14.0 dB` 各 `100` 个包**：
   - 验收标准：
     - 检测率均为 **`100 / 100 (100%)`**；
     - 种子误差 `|seed - pkt_start|` 在三个 SNR 下 **100% 落在 `[-8000, +8000]` 原生样点（`±10.8 µs`）内**（证明三角形顶点触发消除了高/低 SNR 漂移）。

### Step 2：单包进锁与定时微基准（`50` 帧 `-14.0 dB`，耗时 < 5 秒）
在 `50` 个 `-14.0 dB` 窗口上运行修改 B 后的 `demodulate_one`：
- 验收标准：
  - `timing.ok` 由修改前的 `0/50` 提升至 **`>= 48/50 (96%+)`**；
  - `|timing.preamble_start_sample - true_start| <= 2` 工作样点；
  - `cir.ok == true` 且 `cir_peak_metric >= 0.65`。

### Step 3：`uwb_dw3000_live` 端到端进锁闭环验证（只测 `-10 dB` 与 `-14 dB` 各 `200` 帧，耗时 < 10 秒）
生成 `0.2 s`（`200` 包，1 ms 周期）的 `.sc16` 文件，直接运行：
```bash
./gr-uwb/build-native/apps/uwb_dw3000_live \
  --replay /tmp/sim_m14.sc16 --seconds 0 --period-ms 1.0 \
  --mode continuous --sync locked --workers 4 \
  --cir full --fused on --taps eq16 --tone off --lock-fcs off
```
- 验收标准（直接看最后一行 `FINAL` 与 `LOCK_STATS`）：
  1. `raw_drop_samples=0`、`dropped_queue=0`；
  2. `lock_entries=1`、`reacquire_entries=0`、`final_state=LOCKED`（证明前 3 包顺利完成 `ACQUIRE -> VERIFY -> LOCKED` 且后续全程稳锁）；
  3. 回归跑一次 `ctest --test-dir gr-uwb/build-native --output-on-failure` 确保既有 51 项原生 QA 零退化。
