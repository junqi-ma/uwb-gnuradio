### R01：缓存判断使用共享对象自己的身份

文件：`uwb_demod_core.h::stage_cir_softchips()`、`uwb_sync_cir_core.h`及QA。

   用共享对象自身ready、实际模板fingerprint/code identity判断。
2. 检查avg/raw/norm各自所需长度、size/capacity，不仅检查raw容量；热调用不得
   因cache miss判断错误反复prepare，也不得以每包重建模板掩盖失效问题。
3. 保持comm原运算和归一化顺序。清理冗余缓存仅在确认没有其他消费者后进行。
4. 新增真实接入层QA：同scratch按9→10→11→12→9处理；同tap切码、38→116→38、
   相同总tap但pre/post变化、失败后恢复。每步和新scratch对照。
5. 先证明新增QA在921c38f失败，再证明整改通过；同时验证PSDU/FCS，不能只
   单独测试 `prepare_sync_code()` 而绕过有缺陷的调用点。

### R02：scratch所有权归worker

文件：`uwb_radar_cir_estimator_block.cc`及block QA。

1. 消息线程只验证、组装任务和投递，不reserve/resize/prepare worker的scratch。
2. 有公开最大长度时启动前预留；动态长度由worker在任务开始前独占扩容，
   记录容量增长次数/开销，不以持有队列锁执行整段DSP解决问题。
3. 原生pipeline保持每worker私有scratch和初始化预留，不引入跨worker缓存。
4. 测试worker正在处理时，消息入口连续投递交替增大的窗口，覆盖队列积压、
   drain/stop及失败恢复。检查与串行参考一致。可用时补TSAN；未运行明确注明。
5. 仅“重复固定长度不崩溃”不能作为关闭证据。

### R03：CFO策略和每个消费者的覆盖一致

文件：radar core、estimator block、公共前端及相关QA。

1. 普通检测模式估计目标码CFO；定时模式已知CFO则直接补偿，已知零也须显式。
2. 定时模式CFO未知时走共享前端估计；不可估计则失败关闭或要求公开校准值。
   `cfo_epoch=0`标签不能替代缺失补偿，也不能在未知CFO下输出默认成功CIR。
   弱回波场景若无法捕获，明确报告限制，不偷偷降低门限或把oracle接到线上。
3. 根据实际P、TX轴、pre/post、skip/count规划最终补偿，不能用名义P规划、
   改用测得P读取而不检查/补齐范围。最终补偿始终从raw计算，禁止double rotation。
4. `publish_alongside_average()` 的skip/count可不同于主CIR；按额外消费者的
   真正窗口并集扩展补偿或失败。现有直接读取derotated指针的方式不足以证明覆盖。
5. 同时检查逐重复输出：用于正式感知的结果应使用同一final CFO；若只能保留
   raw诊断，明确命名/元数据，不能把它与补偿后平均CIR混作同一质量口径。
6. 明确window absolute origin、局部去旋转锚点及跨窗相位关系；单窗sample0
   不是全局sample0。保留TX距离轴与raw复幅度，不用检测峰重新归零。
7. QA覆盖0/±50kHz、bootstrap≠final、主skip10/额外skip0和不同count、分数P、
   首中末SYNC及失败后恢复。用相同估计CFO的double参考隔离数值误差。
