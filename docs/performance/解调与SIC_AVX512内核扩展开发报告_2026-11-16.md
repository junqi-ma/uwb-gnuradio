## 1. 结论摘要

1. **只有一类内核真正受益：无归约、无跨 lane 重排的逐元素/多 lag 宽内核。**
   最终默认准入只对 `sync` 组打开 AVX-512：

   | 内核 | 相对 AVX2 | 决定 |
   | --- | --- | --- |
   | real-template **8-lag** 点积（L=1016） | **−37.1…−37.4% / lag** | 采纳 |
   | SFD 折叠 `fold_sfd_window`（批处理） | **−24.0…−26.7%** | 采纳 |
   | 逐元素 `accumulate` / `scale`（n≈1k） | **−28.6…−30.3% / −39…−57%** | 采纳 |
   | 逐元素 `sub`（n≈1k） | −13.2…−14.9% | 采纳 |
   | 逐元素 `accumulate`/`sub`（n=135568） | −3.8…−9.2%（带宽受限） | 采纳（收益小） |
   | 逐元素 `scale`（n=135568） | −23.5…−34.6% | 采纳 |
   | 20-tap SIC 脉冲重构累加 | **+1.9…+2.2%** | **拒绝，保持 AVX2** |
   | fused CMF 52 点复相关 | **+29.2…+29.6%** | **拒绝，保持 AVX2** |
   | 固定 38-tap CIR FIR | **+94.0…+96.3%** | **拒绝，保持 AVX2** |

2. **端到端（同一二进制、同一输入、ABBA、5 轮 × 3 次独立会话）**：

   | 单元 | Preamble-only | Full-packet |
   | --- | --- | --- |
   | A 参考（全 AVX2） | +0.14% / −0.20% / +0.49% | +0.78% / +0.10% / +0.18% |
   | **B 解调（sync=AVX-512）** | **−7.68% / −8.08% / −7.32%** | **−6.13% / −5.77% / −5.62%** |
   | C SIC 专有（cir/sic_*=AVX-512） | −1.42% / +0.63% / +1.48% | −0.65% / +0.24% / +1.14% |
   | D 全开 | −7.97% / −7.60% / −7.76% | −6.06% / −5.83% / −5.24% |

   B 与 D 在三次会话里都跨轮同向、都过 ≥5% 门槛；C 三次都不过门槛且方向不稳定
   （一次 −1.4%，一次 +1.5%），因此 SIC 专有组保持 AVX2。
   `timing` 阶段 **79.2 → 59.2 µs（−25.2%）** 是唯一系统性变化的阶段。

3. **等价性**：全部候选与 AVX2 **逐位一致**；SIC 输出 `sic_out_preamble.bin` /
   `sic_out_fullpacket.bin`（各 1,084,544 B）在 A 与 D 之间 **逐字节相同**；
   抑制比 63.29/63.33 dB、`OUTPUT_L2` 完全一致。

4. **AVX-512 在这台机器上不是"有指令集就更快"**：512 位复乘（`moveldup`/`movehdup`/
   `permute_ps` 三个 512 位 lane 内重排）反而慢 1.3–1.9 倍，所以 D2 的复相关内核
   全部拒绝。这与第一阶段"重采样 SC16 只有 H_pad 24/48 过门槛"是同一类结论：
   **按内核、按长度分别准入，不按 CPU 能力整体切换。**

## 3. 方法与契约

### 3.1 数值合同（默认准入的硬条件）

AVX2→AVX-512 必须保持 lane 映射、FMA 使用、累加顺序和归约树，**逐位一致**。
本轮靠两个机制做到：

- **逐元素内核**（`accumulate`/`sub`/`sub3`/`scale`/`fold`）本身没有归约，加宽透明。
- **8-lag 点积**把 lag m 与 lag m+4 放进同一个 512 位寄存器：一次
  `_mm512_loadu_ps(rx + (k+m))` 的低半部正好是复样点 (k+m … k+m+3)、高半部是
  (k+m+4 … k+m+7)，于是低半部 lane j 累加的抽头与 AVX2 累加器 lane j 对 lag m
  完全相同，高半部对 lag m+4 相同；最后归约复用 AVX2 的标量树
  `tmp[0]+tmp[2]+tmp[4]+tmp[6]`。

未引入 `-ffast-math`；`-ffp-contract=off` 保持；既有 QA 容差未放宽。

### 3.2 分派与批处理

- 复用第一阶段的 `UWB_SIMD` / `uwb_simd_config.h` / baseline-ISA 探针，不新建 CPU 识别，
  不给整个库加全局 `-mavx512*`。
- 新增 AVX-512 代码全部在独立 TU `gr-uwb/lib/uwb_demod_sic_avx512.cc`，只带函数
  `target("avx512f,avx512bw,avx512dq,avx512vl")`，以**非向量类型接口**供 header-only
  核心调用（`uwb_demod_sic_avx512.h`），避免 ODR 不一致。
- **按批调用**：一次 8 个 lag、整段逐元素、整个 SFD 折叠各一次调用；不在每个
  tap/chip/样点上分派。`fold_sfd_window` 的符号循环整体搬进宽 TU，折叠从 8 次调用
  降为 1 次。
- 分派只在批边界发生（`resolve_backend()` 一次 relaxed 原子读）。

### 3.3 强制后端与默认策略

新增 `uwb_kernel_backend.h` / `uwb_kernel_backend.cc`（编进 baseline-ISA 的
`uwb_simd_probe` OBJECT 库，因此选择器本身不可能执行宽指令）：

- 分组：`sync`（D1）、`cfo`（D3）、`cir`（D2）、`sic_reconstruct`（S1）、
  `sic_energy`（S2）。
- 诊断覆盖：`default|scalar|avx2|avx512`。**缺实现/缺 ISA 显式抛错**，不静默回退后
  仍记为 AVX-512。
- 默认策略是**测量表**，不是 CPU 能力表：
  `sync=avx512`，其余四组 `avx2`。
- 覆盖只供 QA/benchmark 使用，不进入任何生产 PHY profile；
  `bench_unified_timing` 通过环境变量 `UWB_KERNEL_BACKEND="sync=avx2,cir=avx512"`
  读取，用于 A/B/C/D 同二进制对照。

### 3.4 顺带关闭的范围外缺口

`uwb_rx_sync_opt.h` 里的手写 AVX2 内核原本只靠 `has_avx2_fma()` 运行时分派，
**绕过了 `UWB_SIMD=SCALAR`**。本轮把这些内核统一门控在 `UWB_SIMD_HAVE_AVX2` 上，
并给标量回退补上与 AVX2 相同的 `L == 0 || L > 65536` 长度契约（此前标量回退没有
上界检查，`L > 65536` 会越界读；生产路径 L ≤ 1016，从未触发）。

**仍未纳入门控的范围外路径**（如实列出，不宣称"全项目纯标量"）：
`uwb_discrete_cir_reconstruct.cc` 的 AVX2 脉冲内核仍靠 `has_avx2_fma()` 分派；
`uwb_rx_cfo_opt.h` 的旋转由 VOLK 自行分派；`uwb_cir_fir_simd.h` 已由
`__AVX2__ && __FMA__` 正确门控。

## 5. 逐内核测量与准入决定

`apps/bench_demod_sic_kernels`，3 次独立运行（`--rounds 15 --iters 600`），
样本循环在计时之外，参考臂强制 `sync=avx2`。原始输出：
`data_demod_sic_avx512_20261116/kernel_bench_avx512_run{1,2,3}.txt`。

| 内核 | 规模 | AVX2 ns | AVX-512 ns | 变化 | 逐位一致 |
| --- | --- | --- | --- | --- | --- |
| real-template 8-lag 点积 | L=1016，每 lag | 45.2 | 28.3–28.4 | **−37.1…−37.4%** | 是 |
| `fold_sfd_window` | 8 符号，fold=700 | 488–492 | 358–371 | **−24.0…−26.7%** | 是 |
| `accumulate` | n=1053 | 61.6–63.9 | 44.0–44.5 | **−28.6…−30.3%** | 是 |
| `scale` | n=1053 | 65.0–94.2 | 39.6–41.3 | **−39.0…−56.6%** | 是 |
| `sub` | n=1053 | 61.6–63.6 | 52.5–55.2 | −13.2…−14.9% | 是 |
| `accumulate` | n=135568 | 16.0–16.2 µs | 15.4–15.5 µs | −3.8…−4.5% | 是 |
| `sub` | n=135568 | 16.2–17.0 µs | 15.4–15.5 µs | −4.6…−9.2% | 是 |
| `scale` | n=135568 | 11.1–13.1 µs | 8.5 µs | **−23.5…−34.6%** | 是 |
| 20-tap 脉冲累加 | 4096 事件 | 28.3–28.5 µs | 29.0 µs | **+1.9…+2.2%** | 是 |
| `dot_fixed52`（payload CMF） | 52 复点 | 5.6 | 7.3 | **+29.2…+29.6%** | 是 |
| `dot_fixed38`（CIR FIR） | 38 复点 | 3.7 | 7.1–7.2 | **+94.0…+96.3%** | 是 |

**为什么复相关变慢**：`cir_fir_avx2_group4` 每 4 个复样点用 5 条指令
（`moveldup`/`movehdup`/`permute_ps`/`mul`/`fmaddsub`）。512 位版本把 8 个复样点
压进一条，指令数减半，但这三条 lane 内重排在 Zen 5 上是**半速**的 512 位操作，
于是每 8 个复样点约 6.7 周期，而 AVX2 每 4 个复样点约 2.4 周期。实测与
"512 位重排半速"完全吻合。逐元素内核没有重排，因此不受影响。

**为什么 20-tap 脉冲累加没有收益**：脉冲偏移相邻 2 个样点（一个 chip），
相邻事件的目标区间重叠，内核受 store-to-load forwarding 限制而不是指令吞吐，
加宽只会让重叠更大。

**为什么 `accumulate`/`sub` 在 n=135568 没有收益**：3.25 MB 的读-改-写已经
超出每核 L2，进入 L3 带宽限制（约 155 GB/s），512 位无法突破内存带宽。
`scale` 因为只有 2.17 MB 且是读-改-写同一缓冲，仍有 −34%。

准入决定（写入 `kAvx512Default`）：

| 组 | 默认 | 依据 |
| --- | --- | --- |
| `sync` | **avx512** | 8-lag −37%、折叠 −24…−29%、逐元素 −12…−57% |
| `cfo` | avx2 | VOLK 拥有旋转，本轮未转换 |
| `cir` | avx2 | 52/38 点复相关 +29%/+94% |
| `sic_reconstruct` | avx2 | 20-tap 累加 +2%（无收益） |
| `sic_energy` | avx2 | 本轮未转换，无实测候选 |

## 8. 等价性证据

### 8.1 逐位一致（算子级）

`qa_uwb_demod_sic_avx512.cc` 16 个用例，覆盖：

- 8-lag 点积：L = 0…2033 共 26 个长度、`L > 65536` 守卫、8 个非对齐偏移、
  全零/极端幅值（3e18 与 1e-18 混排）/NaN+Inf/次正规数、以及独立标量参考
  （容差 1e-4 相对，因为标量参考必然改变求和顺序）。
- 逐元素：n = 0…4097 共 18 个长度 × 4 个非对齐偏移，逐字节比对；
  NaN/±Inf 传播位型一致。
- SFD 折叠：6 种符号图样（首符号 +1 / −1、前导零、内部零、全零、单个非零），
  与"逐符号参考实现"逐字节比对；退化参数必须不改输出。
- 强制后端：`avx2` / `scalar` / `avx512` 三条路径输出逐字节相同；
  `resolve_backend()` 报告的名字与实际一致；不可用的强制请求抛异常。

- 8-lag 内层循环就是设计的那条：`vbroadcastf32x8` + 4 × `vfmadd231ps` on `zmm`。
- 链接后的 `bench_unified_timing`：AVX-512 构建 **58 条 zmm**，
  AVX2 与 SCALAR 构建 **0 条**。

生成 ISA 级别不是命中证明，所以另配强制路径 QA（§8.1 的强制后端用例）与
上面的符号级反汇编。

## 9. 未验证项与已知限制（不得当作已通过）

- **未上板**；未做 UHD 实机、paced 到达、溢出交互、8 worker、负载下 P99。
  本报告全部是离线固定窗口数字。
- **未做 MATLAB 交叉验证**；未做多径 / AWGN / ISR / CFO 扫频 / SFO 场景。
- **未在其它 CPU 型号上验证**。§5 的复相关结论（512 位重排半速）是本机
  Zen 5 的证据，不能外推到 Intel 或 Zen 4；`cir`/`sic_*` 组在别的机器上可能不同。
- **`timing` 的 `pw` 滑动功率循环（约 35 µs，占 full-packet 9.4%）与 `sfd` 的
  8128 点功率循环未优化**：它们是严格串行的浮点累加链，任何向量化都会改变
  求和树，从而可能改变峰值选择。按数值合同本轮不动。
- **`cfo` 组未转换**：旋转由 VOLK 拥有（`volk_32fc_x2_multiply_32fc`、
  `volk_32fc_s32fc_multiply_32fc`），本轮不改 VOLK 分派；该阶段仅占 1.6%。
- **`sic_energy` 组未转换**：`compute_roi_energies` 与估计器热点本轮没有实测候选，
  保持 AVX2，没有收益也没有退化证据。
- **S3 相减改走共享内核在端到端上收益很小**（两次会话 −0.63% / −2.55%，与
  A 参考臂噪声底同量级）：135k 样点的三缓冲读写已经带宽受限，隔离内核也只有
  −4.6…−9.2%。保留该改动是因为它逐位一致、把 S3 并入共享 D1 内核（规划要求
  "不得复制一套 SIC 私有解调内核"），不是因为它带来了显著收益。
- **`uwb_discrete_cir_reconstruct.cc` 的 AVX2 脉冲内核仍绕过 `UWB_SIMD=SCALAR`**，
  `uwb_rx_cfo_opt.h` 的旋转仍由 VOLK 分派——范围外遗留路径，未纳入本轮门控。
- **动态 locked 逐包一致性限制仍然存在**，本轮未触碰锁定反馈。
- 本报告不是独立验收：默认准入表（`kAvx512Default`）需要后续独立审查确认。

## 10. 复现

```sh
cd /tmp/uwb-gnuradio-avx512

# 算子级：逐内核 + 逐位一致门

for b in build-avx512-demod-sic build-avx2-demod-sic build-scalar-demod-sic; do
    (cd gr-uwb/$b && env -u LD_LIBRARY_PATH ctest -j1)
done
```
