## 3. 热点根因（代码级）

### 3.1 cir 10.3ms（占 59.5%）—— 最大瓶颈
核心循环（软芯片 FIR，`stage_cir_softchips`）：
```cpp
for (i in 0..num_chips-1) {            // num_chips ≈ 154578
    acc = 0;
    for (k in 0..37)                   // tap_count = 38（pre=8 + post=30）
        acc += conj(values[37-k]) * rx[base-k];   // ← 关键行
    corr[i] = acc;
}
```
- 运算量本身只有 **≈5.9M 复 MAC**（~47 MB 读），理论上应 <1 ms；实测 ~10 ms ≈ 0.6 G 复MAC/s，**严重未向量化**。
- 根因 ①：`acc += …` 是**严格串行归约链**，未开 fast-math 时编译器不允许重排，内层 38 次为依赖链 → 每 chip ~300 cycles 延迟。
- 根因 ②：`conj(values[37-k])` 每次迭代重算（应预计算一次，~5% 收益）。
- 根因 ③（固有，可不处理）：芯片网格步长 2 → 相邻 chip 窗口重叠 36/38，存在 2× 重复 MAC。
- 注：FIR 抽头是 **38 个稠密 CIR 值**，不是稀疏码 → "稀疏码 64/508 非零"的技巧**不适用于**这段热点。

### 3.2 cfo 3.5ms（占 20.5%）
- 相位线性拟合（54 点最小二乘）本身是微秒级。
- 瓶颈在**去旋转**：`derotated[i] = rx[i]·e^{-jωi}`，**每样本两次三角函数**（窗口 319168 → ~64 万次 sin/cos）。
- 经典修复：**递推旋转** `rot[i] = rot[i-1]·e^{-jω}`（每样本 1 次复乘），每 1024 样本重归一化防累积误差。

### 3.3 其余
- sfd 2.1ms 已做 coarse-to-fine（stride 8 + 滑动功率 + 全速率细化 ±D），11× 已兑现。
- timing 1.1ms 较小；ns_sfd/phr/payload 合计 ~0.2ms 可忽略。

## 4. 优化建议（按预期收益排序）

| # | 阶段 | 方案 | 预期效果 | 风险 |
|---|---|---|---|---|
| 1 | **cir** | 内层复点积**多累加器展开**（4~8 路独立 acc，不依赖 fast-math，保序）或直接调 **VOLK** `volk_32fc_x2_conjugate_dot_prod_32fc`（GR 自带依赖） | 10.3 → **1.5~3 ms**（3–7×） | 中：需与 golden 逐比特对照 |
| 2 | **cfo** | sin/cos → **递推旋转** | 3.5 → **~0.4 ms**（~8×） | 低：CFO 误差累积需验证（<50 kHz 时应安全） |
| 3 | cir | 预计算 `conj(values)` 一次 | ~5–10% | 低 |
| 4 | timing | 种子搜索窗口缩小/分档粗化 | 1.1 → ~0.6 ms | 低 |

**合计预期：total 17.3 → ~4–6 ms** → 4 workers 理论 ~700–1000 pkt/s；或 2 workers 达 ~350–500 pkt/s（可省核）。

## 5. 待外部分析确认的问题

1. **热点判断是否成立**：cir 串行归约链 + cfo 逐样本 sin/cos，是否符合性能常识？有没有我们漏掉的开销（如 `scratch.corr`/`derotated` 的 resize、缓存/预取）？
2. **cir 方案选型**：手工多累加器（保序、可逐比特验证）vs VOLK（更快但改数值路径）vs 局部 `-ffast-math` 编译单元——各有什么坑，推荐哪个？
3. **数值风险**：cfo 递推旋转在 203776–319168 样本、CFO ≤50 kHz 时累积误差可接受吗？重归一化周期该取多少？
4. **架构级**：如果单 job 优化到 ~5 ms，4 workers 下 p95 延迟 28 ms（含排队）会明显改善吗？是否应把 `queue_capacity`/worker 数与延迟的关系纳入再评估？
5. 优化后是否需要调整 worker 数策略（目标 100/200 pkt/s 下 2 workers 足够 → 省 2 个核给检测/采集）？

### P0 关键正确性修复
- **CFO 用匹配滤波峰值复相位**（`peak_corr`），非 `arg(rx[peak])`；相邻峰值相位 unwrap（±50kHz 会绕 2.7π）。
- **stage_sfd 改用 CFO 补偿后的 `scratch.derotated`**——原用原始 rx，±50kHz 下 8-symbol 模板内旋转 2.6 rad 使 metric 掉到 ~0.5，sweep 高频端会失败。
- **新增 QA 共 21 用例**：CFO sweep（0/±1/±5/±10/±25/±50 kHz，clean + 20dB AWGN，全链 FCS 0x584b）；SFD 偏移（+7 samples）、SFO（200ppm）、AWGN、多径（0.4×@150 samples）鲁棒性。CTest 7/7。

### 经验（P2 已验证）
- **`std::complex` 逐元素乘 GCC 不 SIMD**：查表版 5.4ms、递推版 2.5ms、4 独立链 0.44ms——打破串行依赖 + 提供 ILP 是 `-O3 -march=native`（无 fast-math）下的正确姿势。
- cir 细分计时确认：**soft-fir 占 85%**、postprocess 14%、estimate <1%——P2 目标锁定 FIR 主循环。
- **固定长度 SIMD 内核 > VOLK > 多累加器**（38-tap）：AVX2/FMA 双累加器 1.3ms vs VOLK 1.6-1.9ms（154k 次短调用 dispatch 税）vs MultiAcc8 4.9ms。手写 4-complex FMA 组（`moveldup`/`movehdup`/`permute` + `fmaddsub`）是关键技巧。
- 最终：**remaining 瓶颈 timing ~1.5ms（38%）> cir ~1.8ms（46%）**。若要再压，timing 的 local_best 相关是下一个目标（但收益有限）。
