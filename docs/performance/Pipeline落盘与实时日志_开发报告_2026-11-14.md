### 2.3 线程与内存契约

```
RX 线程 ──SPSC ring──▶ DSP worker 0..N-1 (Resample → SIC → Radar/Comm)
                            │ 窗口结束时 try_acquire_slot() + 拷贝 taps/PSDU
                            ▼
                       commit_result() 按 window_id 顺序 emit
                            │ O(1) try_submit()（队满即丢，绝不阻塞）
                            ▼
                       单后台 I/O & Logger 线程 ──1 MiB/50 ms 聚合──▶ .ucr4 / .jsonl / run.json / stdout
```

- 关闭时：`output_writer_ == nullptr`，热路径只多一次空指针判断；0 分配、0 锁、0 时钟读取。
- 槽位池：`max(queue_capacity + 32, 64)` 个预分配槽位，`cir_taps`/`psdu_bytes` 在 `start()` 里
  `reserve()` 到 `cir_pre+cir_post` / 127 B，之后每窗只 `clear()` + 填充，不再分配。
- `results_` 仍只保存 POD 字段；变长 taps/PSDU 只存在于槽位，写完立刻归池。

## 3. 集成阶段修掉的 7 个真实缺陷

三个 Track 各自的 QA 都通过了，但合并后暴露出下列问题。它们不是风格问题，而是
单 Track 视角看不到的语义错误。

1. **`peak_tap` 用了错误的范数**。`OutputWindowRecord` 原本没有该字段，writer 只能
   用 `argmax(max(|re|,|im|))`（L∞）重算，而 CIR 内核发布的是 `argmax(std::abs())`（L2），
   且 `cir_peak_metric` 就是该 tap 的 L2 幅度。两者可能给出不同的 tap，于是发布出
   一对**用两个范数量出来的 (tap, metric)**。现在 record 直接携带内核的 `peak_tap`。
2. **`sfd_start_sample` 装的是 SYNC 原点**。同一根因：record 没有 SFD 起点，writer 把
   `radar_detected_origin`（`== cir_res.detected_sync_origin == preamble_start_sample`）
   写进了 `sfd_start_sample`。这两个是不同的量，而旧 `cir.jsonl` 契约里该键指 SFD 起点。
   现在 record 携带 `cir_res.sfd_start_sample`。
3. **槽位重排缓冲是进程级全局 `std::map`**（按 pipeline 地址做键 + 全局互斥）。Track 2
   因为头文件冻结只能这么写。协调者拥有头文件，已改为 `pending_slots_` 私有成员，
   与 `pending_results_` 同受 `commit_mutex_` 保护——去掉全局可变状态和每次提交一次的全局锁。
4. **`pending_slots_` 的 erase 越界**。它只在 writer 启用时才被 resize，却按
   `flushed` 无条件 erase，于是**每个 pipeline QA 都段错误（exit 139）**。改为
   `min(flushed, size())`。
5. **顺序性用例断言了 pipeline 不做的事**。它用 `ConsumerMode::Both` 跑，却断言
   `demod_results.jsonl` 有 16 行；而 `Both` 就是 `SicPlusSensing`，**从不跑 comm**。
   现在两种 consumer 各跑一遍，各自断言自己真正产生的文件，并且**不再 skip**。
6. **runner 用弱符号绑定 `output_writer_stats()`**。弱引用在链接到旧库时会静默报告
   "disabled"——正是本项目禁止的 fail-open。改为直接调用。
7. **runner 无法请求全窗感知搜索**，导致 E2E 永远只能产出失败帧。新增
   `--radar-full-window [0|1]`（显式域检查，无静默回退），并直接设置
   `radar_cfg.full_window_search`——`build_effective_radar_cfg()` 只在
   `use_predicted_timing == false` 时才认 PipelineConfig 上的那个标志。

## 5. 未验证 / 已知边界

- **成功路径不在 CTest 里**。仓库内 737.28 MS/s fixture 在 runner 默认搜索下
  不产生可检测包，所以 CTest 的 E2E 只能钉住**失败帧契约**（`tap_count: 0`、
  不写 UCR4、`file_offset_taps` 不推进、`status=sfd_failed`）。真正的成功路径
  证据是 §4.4 的手动 E2E，以及 writer QA 里用合成 taps 覆盖的记录→文件映射。
  要把它自动化需要一个能检测的 fixture，本轮没有把二进制加进仓库。
- **未上板**：无 USRP、无 paced 到达、无 UHD `recv` 溢出交互。
- **未做 MATLAB `read_uwb_cir.m` 实跑交叉验证**；只保证格式契约与独立 Python
  解析器一致，并在真实 `UwbCirWriter` 产出的 999 行历史 `cir.jsonl` 上复核了
  `file_offset_taps` / `peak_delay` / `zero_delay_tap == cir_pre_samples` 三条不变式（0 违反）。
- **真实磁盘饱和未测**：慢写只用 1 ms/帧的合成 hook 模拟，没有做真实 I/O 压力。
- **`encode_cir_sc16` 与 `UwbCirWriter` 在非有限输入上不同**：参考实现用
  `std::max` 不传播 NaN，内部 NaN 会被裁成 −32767；本实现按文档语义**零填充**
  （`scale=0`）。全有限输入下逐位相同。
- **`OutputPayloadSlot::clear()` 需要显式 `visibility("default")`**：该聚合体不是
  `UWB_API`，而库用 `-fvisibility=hidden`。写在 `.cc` 里，头文件未改。
- **`events` 模式没有"按采样步长打印 CIR 峰值"选项**：只在 SFD 检出状态变化时打印。
- **`taps > 65535` 直接失败关闭**为 `cir_failed`，不像 GNU Radio block 那样静默截断。
- **`compute_unified_template_hash` 仍只按指针识别 preamble**（改动前既有行为）。
- 候选不标记为全面验收通过，不合并主分支，未推送、未安装到系统、未移动 tag。
