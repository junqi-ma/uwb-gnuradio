# X410 固定单音消除链路：DW3000 实采解码测试（2026-11-15）

## 结论

生产单音消除前处理在本轮实采数据上有效。**连续 1 秒、200 个包，消除后 200/200 完整解码且 FCS 通过；同窗未消除为 193/200。** 这里使用了针对既有 256-SYNC CFO 缺陷的测试配置修正（`cfo_skip_initial_repetitions=216`），不是当前默认原生端到端链路的直接验收通过。未修改生产代码、未提交或安装。

## 硬件与信号

- 源码 HEAD：`b573195ea9d0a2af41e1b2c54c6ed8d6bb5685e9`。
- X410：192.168.10.2，serial 2607179，CG_600；通道 3，UHD 天线 `RX1`（此前确认的第二接收连接器），6489.6 MHz，737.28 MS/s，60 dB。
- 用户确认：4z 8-symbol SFD、6.8 Mb/s、PHR 850 kb/s、STS 关闭；波形验证 code 10、256 SYNC、127 字节，周期拟合 4.999863760 ms。
- 100 ms 预试：73,728,000 样点，0 UHD 错误，20 包；随后独立 1 秒采集：737,280,000 样点，0 UHD 错误，分块硬件时间戳连续（浮点换算最差误差 1.2e-7 样点）。
- 1 秒原始 IQ SHA256：`bb885e458fad18bd4a8d0c124bbac93a44a4e20e549248be31c50ae6702d71af`。

## 测试方法

1. Python UHD 指定通道和天线，保存连续原始 SC16。正常终止用户授权的占用进程 PID 2182863 后开始。
2. 用已构建生产程序 `fixed_tone_cancel_replay`，运行真实 `FixedToneCancelSc16Source` 状态机：固定 −232.96 MHz、每 20 ms 用前 0.5 ms 估计、288 点 LUT、256 点交叉渐变。
3. 对消除后数据计算延迟自相关：D=750、W=6000、步进 100，归一化平方阈值 0.15、30,000 样点合并间隔。预试后固定候选资格：峰值 >0.5，跨度 >36,864 样点（50 µs）。1 秒数据共 325 候选、200 个合格包；其余 125 个被资格规则拒绝。此为离线 Python 分析，**未新增生产自动捕获器**。
4. 使用同一组 200 个合格包种子配对截窗。每窗提前 14,746 点、总长 390,000 native 样点；现有 `RationalResampler65_48Core` quality_minorder/fixed_phase → 998.4 MS/s，再调用现有纯 C++ `demodulate_one`，Full CIR、code10/256/4z2。
5. 四格均启用相同 fast SFD/CFO rotation/tail seed/on-demand softchip 选项，关闭 PHR/payload fusion；唯一算法配置差异为 CFO skip=24 或 216。保留另一次 fusion 尝试的独立日志，结果相同。
6. 对所有解码成功 PSDU，Python 独立按反射多项式 0x8408、初值 0 计算 CRC，与末尾 little-endian FCS 比较；与 C++ 判定一致。

## 配对结果（独立 1 秒数据）

| CFO 配置 | 单音消除 | 前导成功 | SFD 成功 | PHR 成功 | FCS / 独立 CRC |
|---|---|---:|---:|---:|---:|
| 默认 skip=24 | 关闭 | 198/200 | 0/200 | 0/200 | 0/200 |
| 默认 skip=24 | 开启 | 200/200 | 162/200 | 162/200 | 0/200 |
| 尾部实测 skip=216 | 关闭 | 198/200 | 196/200 | 196/200 | 193/200 |
| 尾部实测 skip=216 | 开启 | 200/200 | 200/200 | 200/200 | **200/200** |

成功包均为 127 字节。100 ms 预试在尾部实测配置下为开启 20/20、关闭 19/20。

关闭消除的 200 包与开启消除共用从干净数据得到的包窗，评价的是**同窗解码改善**，不能把 193/200 称为原始数据盲捕获率。200 个包也不等于已验证长时间 PER 或所有信道条件。

## 重现的长前导 CFO 缺陷

`uwb_demod_core.h` 的 SFD 锚定过程只实测尾部 40 个 SYNC，重建全 256 个相关值时将前 216 个填为复零；随后 `fit_cfo(..., profile, ...)` 仍按默认 skip=24 拟合，包含 192 个补零相位，导致严重偏差。首包原始全前导估计约 176.7 kHz，错误尾部重估约 11.9 kHz；测试配置 skip=216 后约 177.1 kHz，FCS 恢复。

该问题已有 `qa_uwb_twr_phy_matrix.cc::twr_phy_matrix_128sync_cfo_cause` 诊断测试和说明。本轮将它在真实 DW3000 256-SYNC 数据上重现，未宣称是单音消除引入的缺陷。测试配置只跳过虚构相位，并未修改数学核心或阈值。

## 失败尝试与实时边界

- 第一轮 1 秒直接采集在约 325.975 ms 报 UHD overflow，原始记录和 IQ 保留为 `*_attempt1.*`。接收大数组预触页、UHD num_recv_frames 4096→32768 后，第二轮取得完整 1 秒无错误。这只能证明本轮连续片段完整，不是长时间零溢出的证明。
- 离线输出整个 clean IQ 会带来额外磁盘写入。首次 unpaced 回放即便队列 8192 块仍丢 53,018,624 样点；日志保留为 `cancel_1s_unpaced_attempt1.log`，该输出被重跑结果替换，**没有用于最终解码**。最终 paced 回放、队列 8192 块（2 GiB）输出全部 737,280,000 样点，0 丢块、0 gap、50 次模型更新、0 拒绝。这里的大队列用于保存整段 IQ 的离线验证，不能当默认 8 MiB 队列的实时通过证据。
- 另一次默认 32×65536 队列的原生 UHD runner 接收尝试完成 200 个计划窗、UHD 0 overflow，但原始环记录 9 次丢块 / 589,824 样点，最大 backlog 2,070,216 样点，不能声称零丢样。没有记录丢弃时间分布，不能判定其仅发生于收尾。
- 原生 `UhdDeviceSc16Source::open()` 设置调谐/增益时没有传所选接收通道，调谐默认通道为 0，而 streamer 可选 3；没有天线设置。这次 runner 的指定 RF 端口配置不能作为通过证据。它的 consumer=sensing 使用默认雷达参数和未对齐的计划窗，0/200 SFD 不用于评价 DW3000 完整包解码。
- 最终解码为文件回放的逐窗处理。当前测试配置单窗服务耗时约 20–25 ms（详见 summary），尚未验证以 5 ms 周期持续实时完整解码；不能用前处理吞吐或 FCS 成功率替代端到端实时验证。
