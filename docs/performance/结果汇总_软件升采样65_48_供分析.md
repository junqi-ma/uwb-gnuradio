## §1 任务目标与速率合同

在主机 GNU Radio（软件）中实现并验证 UWB 信号的连续流数字上变频：

```
X410 / RFNoC RxStreamer   CF32/SC16 @ 737.28 MS/s
        │
        ▼
GNU Radio 65/48 有理重采样（固定、无热路径分配）
        │
        ▼
CF32/SC16 @ 998.4 MS/s
        │
        ├── UwbScheduledExtractor（已知 t0/T 周期截窗）
        └── UwbDetector（未知 packet 时刻）
```

精确速率合同：`737.28e6 × 65/48 = 998.4e6`，`gcd(65,48)=1`（最简有理数）。

**目标优先级**：①输出波形/绝对样本坐标与 MATLAB `upfirdn` 一致；②跨任意
GNU Radio `work()` chunk 结果不变；③不破坏 UHD `rx_time`/overflow/采样率
metadata 语义；④建立内置块真实性能基线；⑤基线不足时实现固定 65/48 优化
C++ block；⑥判断单通道连续 737.28→998.4 MS/s 能否在目标主机持续实时。

**本阶段明确不做**：RFNoC/FPGA resampler、改写 998.4 MHz MATLAB 解调算法为
原生率、GPU/CUDA、多通道、以牺牲滤波质量换取吞吐。升采样只把已有信号映射到
998.4 MHz 数字网格，不产生新的射频信息。

## §2 环境与源码调查（Phase 0）

| 项 | 值 |
|---|---|
| GNU Radio | **3.10.1.1**（Ubuntu 包），VOLK **2.5.1**，gcc 11.4.0 |
| CPU | i7-12700，20 逻辑核，AVX2+FMA（无 AVX-512），VOLK machine `avx2_64_mmx_orc` |
| scipy/numpy | 1.8.0 / 1.21.5（本机无 MATLAB/octave，golden 用 scipy 作 upfirdn 等价） |

**GNU Radio 内置 `rational_resampler_ccf` 语义**（依据官方 v3.10.1.1 源码调查）：

- **Block 类型**：`gr::block` + `forecast()` + `general_work()`（不是 sync/interp/decim）。
- **taps 拆相**：末尾补零到 `interpolation(=65)` 的整数倍，`xtaps[i % 65][i / 65] = taps[i]`，
  每个 arm 是 `kernel::fir_filter`，`set_history(ceil(len/65))`。
- **`general_work`**：整数 phase 计数器 `d_ctr`；每输出 `out[i] = d_firs[ctr].filter(in)`，
  `ctr += 48`，`ctr >= 65` 时消费一个输入。
- **tag**：`gr::block` 默认 **TPP_ALL**（按 float relative rate 映射 offset）。
- **SIMD**：内核用 `volk_32fc_32f_dot_prod_32fc_a`（已用 VOLK）。
- **无 SC16→SC16 内置块**（仅有 scc:int16→complex 与 fsf:float→int16）。

**关键实测发现（与内置块数值对照）**：内置块对 DC 输入稳态输出 ≈1.0（与 upfirdn
一致），但边界语义**前向非因果**——首输出即为稳态（无暖机瞬态），对起点 impulse
几乎全零，有限长输出比 upfirdn 少约 2×群时延（4096 输入：GR 5436 vs upfirdn
5658）。自定义 block 契约定为**与 upfirdn 完全一致**。

## §3 滤波器设计与 golden（Phase 1）

**信号带宽实测**（998.4 MHz cfile，IEEE 802.15.4a HRP code-9，64-SYNC）：
90% 能量 ≤ 231 MHz、99% ≤ 287 MHz、99.9% ≤ 330 MHz、−50 dBc 至 422 MHz。
737.28 MHz 输入 Nyquist = ±368.64 MHz。

**anti-image 滤波器设计规则**（在虚拟速率 65×737.28 = 47.9232 GHz 设计）：

- passband `[0, B]`；stopband 从首镜像 `R_in − B` 开始（周期响应自动覆盖全部镜像）。
- transition = `R_in − 2B`（最大可用宽度 → 最少 taps）。

| 档位 | 通带 B | taps | arms | DC(sum) | 通带纹波 | 阻带最差 | 群时延(输出样本) |
|---|---|---|---:|---:|---:|---:|---:|
| **quality** | 330 MHz | 5363 | 83 | 65.0 | 0.00 dB | **−97 dB** | 55.85 |
| **realtime** | 290 MHz | 2635 | 41 | 65.0 | 0.00 dB | **−96 dB** | 27.44 |

规格：纹波 ≤ 0.1 dB、阻带 ≥ 70 dB，均大幅满足（经验验证，非公式估算）。
单输出 MAC：quality 83、realtime 41。taps 已含 ×65 缩放（DC sum = 65）。

**Golden 契约 = scipy/MATLAB `upfirdn`**（输入两侧零填充的完整卷积）：

- 输出长度：`Lout = ceil(((N−1)·65 + T) / 48)`（逐 N 验证）。
- 相位律：`y[m] = Σ_k h[(m·48 mod 65) + 65k] · x[floor(m·48/65) − k]`。
- 7 组 golden：impulse / dc / tone_low(10M) / tone_pb(300M) / tone_sb(420M) /
  random / uwb（998.4 cfile preamble 窗口经 48/65 抗混叠抽取模拟 X410 捕获）。
- **三重验证一致**：scipy upfirdn == 手写多相实现 == golden 文件（逐样本 ≤2e-7）。
- 增益定义：滤波器 DC(sum)=65；重采样器对常数输入**平均增益 = sum/L = 1.0**
  （逐样本按相位 arm 变化，这是 polyphase 固有行为，需在文档固定，避免误判为幅度误差）。

## §4 Level A：内置块基线（Grok Build 实测）

`benchmark_resampler_65_48`（7 轮 median，2e9 输入/轮 + 30s sustained；无 Throttle、
无 timed-path 文件 I/O、FNV checksum 防优化消除）。

| 模式 | taps profile | 实际 taps | arm | 输入 MS/s | 输出 MS/s | RT ratio¹ |
|---|---|---:|---:|---:|---:|---:|
| source_only（无 resampler） | — | — | — | **1359** | — | — |
| built-in | default（GR 自设计） | **2145** | 33 | **67.2** | 91.0 | 0.091 |
| built-in | quality | 5395 | 83 | **44.4** | 60.1 | 0.060 |
| built-in | realtime | 2665 | 41 | **49.3** | 66.8 | 0.067 |

¹ `realtime_ratio = 输出 MS/s / 998.4`。

- **Source-only 1359 MS/s（1.36× RT）** → 内存/调度路径不是瓶颈；瓶颈在 resampler。
- 默认档反而最快（tap 数最少 33 arm）；quality 最慢（83 arm）。
- **结论：Level A 最优化仅约 9% 实时率，未达最低门槛 → 必须进入 Level B。**

## §5 Level B：固定 65/48 block（正确性 100%，性能未达）

### 5.1 实现

- **core**（纯算法头文件，无 GNU Radio/PMT 依赖）：
  `RationalResampler65_48Core`——构造期拆 65 相、预计算 65 步 phase 调度；
  `process()` 返回 `{produced, consumed}`，跨调用保持 phase+delay 线；
  `flush()` 零填充尾使总长 = `ceil(((N−1)·65+T)/48)`；热路径无分配；
  **scalar 参考核保留**，可选 VOLK `volk_32fc_32f_dot_prod`。
- **block**：`UwbRationalResamplerCcf65_48`，`gr::block` + `forecast/general_work`，
  `set_relative_rate(65,48)`、`set_output_multiple(65)`、`set_max_noutput_items(1<<20)`、
  **TPP_DONT + 手动 tag 映射**。不用 `set_history`（延迟线在 core 内）。
  `make(taps_file_or_profile="quality", tag_propagation_enable, reset_on_discontinuity)`。
- **tag 映射律**：`m = round((p·65 + (T−1)/2) / 48)`（群时延中心约定，p=0→56，impulse
  QA 固定）；`rx_time` 值不变、offset 映射；`rx_rate/sample_rate` → 998.4e6；
  `rx_freq` 不变；`overflow/discontinuity` → `core.reset()` + `resampler_reset` tag
  + epoch 递增。

### 5.2 正确性（全部通过）

| 项 | 结果 |
|---|---|
| golden 逐样本（7 组） | max_abs ≤ 4.8e-7，corr 1.0（impulse 精确 0） |
| chunk 不变性（oneshot/48/4096/mixed） | **逐样本一致** |
| 短输入长度（N=0,1,47,48,49,95,96） | 精确满足长度公式 |
| scheduler（forecast 无活锁 / EOS / 小 buffer / stop-restart） | PASS |
| tag/rx_time（offset 0/1/47/48/49、跨 chunk、overflow） | PASS |
| scalar vs VOLK | 逐样本 max_abs = **0** |
| CTest | **11/11**（原 9 + core + block） |

### 5.3 性能（未达门槛）

| 模式 | profile | kernel | 输入 MS/s | RT |
|---|---|---|---:|---:|
| block | quality | volk | 56.8 | 0.077 |
| block | realtime | volk | 67.2 | 0.091 |

仅比内置块快 ~1.37×。**单核 AVX2 理论上限 ≈36 GMAC/s**（2 FMA×8 fp32×~4.5GHz）
→ quality 需 82.9 GMAC/s（**2.3 核**）、realtime 需 40.9 GMAC/s（**1.14 核**）。
当前实现仅 ~4 GMAC/s（~10% 单核效率），有优化空间但**单核无法达实时**。

## §6 Phase 3：逐项优化（Grok Build，evidence-first）

### 6.1 Profile 归因（core，20e6 输入，chunk 1M）

| profile | kernel | 组装 | schedule | **FIR** | 输入 MS/s | GMAC/s |
|---|---:|---:|---:|---:|---:|---:|
| quality | volk_legacy | 2.8% | 0% | **97%** | 53.6 | 6.0 |
| quality | volk_macroblock | 3.4% | 1.8% | **91%** | 56.8 | 6.4 |
| realtime | avx2_fma_macroblock | 4.5% | 2.9% | **87%** | 79.5 | 4.4 |

**FIR 算力是唯一显著瓶颈**（87–97%），组装/schedule/调度开销可忽略。
kernel 模式比 block 慢是 checksum 同线程所致（block 经 GR 调度与 sink 重叠）。

### 6.2 单核优化 A/B（7 轮 median，50e6 in）

| 模式 | profile | kernel | 输入 MS/s | 输出 MS/s | RT | GMAC/s | vs legacy |
|---|---:|---:|---:|---:|---:|---:|---|
| kernel | quality | volk_legacy | 47.6 | 64.4 | 0.065 | 5.3 | 1.0× |
| kernel | quality | volk_macroblock | 55.4 | 75.0 | 0.075 | 6.2 | 1.16× |
| kernel | realtime | avx2_fma_macroblock | 76.7 | 103.9 | 0.104 | 4.3 | 1.56× |
| block | quality | volk_macroblock | 62.1 | 84.2 | 0.084 | 7.0 | 1.21× |
| block | realtime | **avx2_fma_macroblock** | **88.1** | 119.3 | **0.120** | 4.9 | **1.65×** |

宏块展开（65 输出一次，预计算 65 步 schedule，消除每输出分支/函数调用）+ 
AVX2 FMA（H≤48 用 AVX2，H≥64 用 VOLK）。scalar 参考核保留，逐样本一致。
**单核天花板诚实检查**：即便 100% 效率，quality 也仅 0.43×、realtime 0.88× →
单核不能达实时，进入多 worker。

### 6.3 有序 multi-worker（plan §10.4，持久线程池）

设计：每 worker 处理不相交输入区间 + 小 halo（H−1），起始 phase 由绝对输入
offset 推导（确定性），有序输出组装 + 有界队列 + 固定内存池；discontinuity
统一原子 reset；**输出与单线程逐样本一致（QA 验证）**。

| profile | workers | 输入 MS/s | 输出 MS/s | RT | GMAC/s | 缩放 |
|---|---:|---:|---:|---:|---:|---:|
| quality | 1 | 59.7 | 80.8 | 0.081 | 6.7 | 1.0× |
| quality | 8 | 167 | 226 | 0.227 | 18.8 | 2.8× |
| quality | 20 | 184 | 249 | 0.249 | 20.7 | 3.1× |
| realtime | 1 | 88.2 | 119 | 0.120 | 4.9 | 1.0× |
| realtime | 8 | 211 | 286 | 0.287 | 11.7 | 2.4× |
| **realtime** | **20** | **217** | **294** | **0.294** | 12.1 | 2.5× |

**缩放 ~8 worker（≈P 核数）后饱和**：串行 schedule 走查 + 滑动窗口 cache 流量
+ 超线程过订阅限制。

## §7 最终裁决与停止条件

| 门槛 | 要求 | 最优配置 | 结果 |
|---|---|---|---|
| **最低实时** | ≥737.28 in / ≥998.4 out | block realtime, workers=20: **217/294 MS/s (0.29×)** | **FAIL** |
| 生产 1.2× | ≥884.7 / ≥1198 | 同上 | **FAIL** |

**命中停止条件（任务书 §12 第 1 条）**：已完成 profile + 两种独立 kernel 优化
（宏块 AVX2/VOLK 单核、有序 multi-worker），flowgraph 仍低于实时 15% 以上
（0.29 ≪ 0.85）。

**根因**：连续 998.4 MS/s CF32 需 41–83 GMAC/s，multi-core 只交付 ~12 GMAC/s。
单核已达理论上限附近，多核被串行 schedule 走查与缓存流量限制。

**任务书推荐转向**：
1. **原生率 scheduled 截窗 + PDU 级 65/48**：用 `UwbScheduledExtractor` 在
   737.28 MS/s 原生率截取已知 `t0/T` 的短窗口，只对截取的 packet IQ 做 65/48
   （短数据量，吞吐轻松达标）。天然契合项目现有 scheduled 路径。
2. **RFNoC/FPGA 连续升采样**。

**正确性基线全程保持**：golden max_abs ≤ 4.8e-7、chunk 不变、tag/rx_time 全过、
scalar 参考保留、**11/11 CTest**、`git diff --check` 干净。

## §10 建议供 GPT 分析的开放问题

1. **多 worker 缩放瓶颈**：8→20 worker 只 +3–13%，profile 显示串行 schedule
   走查 + 滑动窗口 cache 流量 + 超线程过订阅。是否有可能重构去掉串行 schedule
   （如每 worker 独立调度 + 无锁队列）达到近线性？还是这个瓶颈是 GNU Radio
   单 block 模型的结构性限制，必须换架构？
2. **转向方案 1 的可行性**：PDU 级 65/48（只升采样截取的 packet IQ）——量级
   估算（如 264k 样本/window × N window/s），是否彻底消除吞吐压力？scheduled
   提取器在 737.28 原生率的坐标契约、tag 映射（往返群时延 83 样本如何补偿）？
3. **滤波档位与信号保真**：realtime（B=290MHz）vs quality（B=330MHz）在
   FCS/解调指标上的差异是否需要实测（§8.5 目前 quality 通过，realtime 未单独测）？
   若 FCS 在 realtime 也过，是否可接受用更短 taps 换余量？
4. **多核的替代组织**：把「连续流重采样」整体交给多核是否合理，还是应该接受
   停止条件、把重采样下沉到 RFNoC/FPGA，主机只做 scheduled 截窗？
5. **GNU Radio 单 block 并行化的成熟度**：项目自研 ordered multi-worker 与
   GNU Radio 官方 `gr::sync_block` 多线程/`tpb` 调度的权衡，是否有更标准做法。
6. **验证盲区**：X410 实机（Phase 5）未跑（无硬件）；30s sustained 的 RSS
   一次性抬升 ~34MB（buffer bring-up）未见泄漏，但未做 10 分钟 soak；MATLAB
   decoder 对照仅在 golden 层面验证，未在本机跑完整 `decode_uwb`。
