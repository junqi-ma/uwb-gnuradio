## 1. 测量合同（P0 冻结项）

### 1.1 被测对象

唯一被测二进制：**冻结副本 `/tmp/opencode/bench_avx2_baseline`**（`UWB_SIMD=AVX2` 构建，
SHA256 见 §2.5）。build 树里的 `gr-uwb/build-avx2/apps/benchmark_sc16_burst_core`
只是它的拷贝来源；矩阵的每一次运行都调用副本，从不调用 build 树路径。
它测量的就是生产 `uwb_uhd_sc16_pipeline.cc` 的每窗序列：

```
core.reset();
r = core.process_sc16(in, N, scale, out, cap);   // cap = expected
produced = r.produced;
while (produced < expected) { n = core.flush(out + produced, cap - produced); if (!n) break; produced += n; }
```

字段口径（与 `benchmark_sc16_burst_core.cc` 头部注释一致，不得改写）：

- `reset` = `core.reset()`；`process` = 仅 `process_sc16()`；
- `core` = `reset + process`（窗内非 flush 部分）；
- `flush` = 整个 flush-to-completion 排空；
- `total` = `core + flush`，与 pipeline 的 `WindowResult.timing.resample_us` 可比。
- 吞吐由 `total` 的**均值**推导；"窗"= 一个 N 个 native 输入样点的测量窗。

### 1.2 计时方法

- **一次 repeat = 一个窗**：`--length N` 个 native 输入样点，输出 `expected` 个 CF32。
- 所有缓冲在第一个测量 repeat 之前预分配；测量区内**无分配、无 I/O、无参数解析**
  （`prepare_us` 单列，不计入任何计时字段）。
- 输入是确定性 LCG（`s=s*1664525+1013904223; v=(int32)(s>>16)-32768`，seed
  `0x01234567`），默认 `--input random`；本矩阵未使用 `rails/impulse/zero`。
- 输出校验和 FNV-1a 64 覆盖一次 repeat 的整个 CF32 输出（`produced*8` 字节），
  在**计时区之外**每 repeat 重算：既阻止编译器消除工作，也证明 repeat 间确定性。
  任一次 repeat 校验和不一致 → `checksum_stable=false` 且进程非零退出。
- 百分位定义（取自 benchmark 头注释）：**nearest-rank**，
  `index = ceil(p/100 * R) - 1`，clamp 到 `[0, R-1]`。本矩阵 `R=50`。
- 每格参数固定：`--reps 50 --warmup 10`，`--scale-mode unit`（默认，1/32768），
  `--kernel avx2`。3 个独立轮次，每轮独立进程。
- **串行执行**：任意时刻只有一个 benchmark 进程（驱动脚本 `run_matrix.sh` 顺序调用），
  避免自造争用。

### 1.3 正确性伴随条件（本轮全部满足）

60 次运行全部：

- `length_ok = true`（输出样点数等于 `expected`）；
- `checksum_stable = true`（50 个 repeat 输出逐字节一致）；
- 同一 `(rate, taps, length)` 下 3 轮校验和相同（跨进程可复现）；
- **`--fixed-phase 1` 与 `--fixed-phase 0` 的输出校验和完全相同**（8 个
  `(rate, taps, length)` 组合逐一核对），即 C1 固定相位调度只改调度不改数学；
- 二进制反汇编 `zmm` 引用数 **0**（`ymm` 2443、`vfmadd` 1344），证明 AVX2 基线
  制品里没有 AVX-512 指令。

### 2.4 CMake 配置

CMake 不把命令行写入 cache，以下由 `gr-uwb/build-avx2/CMakeCache.txt` 与
`compile_commands.json` 逐项还原（`UWB_SIMD=AVX2`、`CMAKE_BUILD_TYPE=Release`、
`UWB_BUILD_GNURADIO=OFF`、`ENABLE_UHD_BACKEND=OFF`、generator `Ninja`、
`CMAKE_HOME_DIRECTORY=/tmp/uwb-gnuradio-avx512/gr-uwb`）：

```sh
cd /tmp/uwb-gnuradio-avx512
cmake -S gr-uwb -B gr-uwb/build-avx2 -G Ninja \
      -DCMAKE_BUILD_TYPE=Release \
      -DUWB_SIMD=AVX2 \
      -DUWB_BUILD_GNURADIO=OFF \
      -DENABLE_UHD_BACKEND=OFF
cmake --build gr-uwb/build-avx2 --target benchmark_sc16_burst_core
```

实际编译命令（`compile_commands.json` 中 `benchmark_sc16_burst_core.cc` 一条）：

```
/usr/bin/c++ -DUWB_TESTDATA_DIR="..." -I... -O3 -DNDEBUG -O3 -mavx2 -mfma -std=gnu++17 \
  -o apps/CMakeFiles/benchmark_sc16_burst_core.dir/benchmark_sc16_burst_core.cc.o -c ...
```

关键点：**只有 `-mavx2 -mfma`，没有 `-march=native`**，因此 AVX-512 不可能被偷带进来
（与 §1.3 的 `zmm=0` 反汇编证据一致）。全库 75 个 TU 使用同一组 `-O3 -mavx2 -mfma`。

**被测二进制的确切编译选项**（拷贝时读取 `compile_commands.json`，该文件此刻
`ffp-contract` 出现次数 = 0）：

```
-O3 -DNDEBUG -O3 -mavx2 -mfma -std=gnu++17
```

即：`CMAKE_BUILD_TYPE=Release` 的 `-O3 -DNDEBUG`，加上 `UWB_SIMD=AVX2` 提供的
`-mavx2 -mfma`，**没有 `-ffp-contract=off`**。该选项是在本二进制构建**之后**才加入
中央 flags 的（用于保持原标量浮点语义），因此本数据集代表的是**未关闭 FMA 收缩**的
AVX2 制品。这不影响 AVX2↔AVX2 的重复性（同一二进制），但意味着：
**后续以最终 build（含 `-ffp-contract=off`）做的 ABBA 对照才是权威**，本基线是
"当前已有 AVX2 制品"的参照点，不能直接当作最终 AVX2 交付基线。
本轮不重建任何东西。

生成的 `gr-uwb/build-avx2/include/gnuradio/uwb/uwb_simd_config.h`（有效行）：

### 3.5 观察（仅描述基线，不作 AVX-512 结论）

- 成本随 Hpad 单调上升：56000/fp1 下 93.95（16）→ 120.52（24）→ 145.05（32）→
  230.19（48）µs，与"内核成本正比于 Hpad 而非 T"的既有结论一致。
- `fixed-phase 1` 在全部 16 个 `65_48` 格上都快于 `fixed-phase 0`
  （56000：−15.5% / −13.5% / −13.1% / −5.2%），与 C1 是生产默认相符。
- `flush` 相对 `core` 很小（56000/fp1 eq16：93.95 对 93.80 µs，约 0.16%），
  说明该路径的 flush 尾部不是瓶颈。
- 65/32 因输出/输入比 65/32 > 65/48，同长度耗时高约 1.46–1.48 倍，属预期。

## 4. 边界与后续

- **本文全部是 AVX2/FMA 基线数字，不是 AVX-512 结果。** 本轮未构建、未运行
  `build-avx512`，`uwb_rational_resampler_avx512.cc` 未参与编译（`compile_commands.json`
  中不存在该 TU）。
- 后续 P2 的 AVX-512 对照必须：同一 worktree 快照、同一 CPU/编译器/VOLK、同一 taps
  哈希、同一 `--reps/--warmup/--kernel` 语义、同一长度与 fixed-phase 组合，
  按 **ABBA 交替、≥3 轮** 配对，并在同一次会话内完成；不得夹带换 taps、改 worker
  或改算法。
- **权威对照以最终 build 为准**：本基线二进制早于中央 flags 加入 `-ffp-contract=off`，
  且 AVX-512 实现会改变编译选项与（可能）求和树。因此本轮数字是"现有 AVX2 制品"的
  参照点；最终验收必须用**同一最终 build 体系**重新生成 AVX2 与 AVX-512 两侧，
  在同一次 ABBA 会话内配对，那一组才是权威数据。本数据集用于：确认测量合同可执行、
  给出量级与轮间抖动、以及为后续配对提供先验。
- 若最终 build 的 AVX2 侧与本表出现系统性差异，必须先归因到编译选项
  （`-ffp-contract` 等）而不是直接记为 AVX-512 收益。
- 准入门槛（规划 §验收）：目标生产格中位收益 ≥5% 且跨轮同向；其他生产格不得出现
  可重复退化。否则保持 AVX2 默认，AVX-512 仅显式实验启用。
- 本基线**不证明**：UHD 实机、paced 到达、多 worker 争用、完整解调 PSDU/FCS、
  MATLAB 交叉验证。这些都不在 P0 范围。
- 数值一致性合同：AVX-512 内核若改变求和树，必须先给出容差合同与独立数值参考，
  不能静默放宽断言；本基线提供的 `checksum_fnv1a64` 可作为"逐位一致"目标的对照值
  （注意：不同 ISA 的 FMA 归约顺序可能不同，届时以容差合同而非校验和相等为准）。
