# Clean comm 接收（256 SYNC / 127 B / 有 CFO）1·2·4 worker 耗时与分解

日期：2026-11-15　基线：`acffbba`（含前导 CFO 拟合修复）
数据：`docs/performance/data_clean_comm_256_127_cfo_20261115/`
工具：`tools/sic/run_clean_comm_workers.py` + `tools/sic/benchmark_chain_workers.cc`（新增 `clean_comm` 任务）

## 结论

1. **单包干净通信接收（无干扰、无 SIC、无 sensing）在 256 SYNC / 127 B / +50 kHz
   CFO 下，单 worker 单包 2.76 ms，其中重采样 1.68 ms（60.7%）、完整 comm 解调
   1.09 ms（39.3%）。**
2. **1→2→4 worker 的完成间隔为 2766.6 / 1446.7 / 818.4 µs，即 1.91× / 3.38×。**
   4 worker 仍未线性（理想 4×），因为单包服务时间随并发上升：
   2764→2890→3255 µs（+4.5% / +17.8%）。
3. **comm 解调内部最大项是 timing（427 µs，39.3%）和 payload（291 µs，26.8%），
   其次是 SFD（200 µs，18.4%）与 CIR（115 µs，10.6%）。** SFD 里 167 µs
   （83%）是 SFD 锚定后的第二次 CFO 拟合+去旋转，不是 SFD 相关本身。
4. **+50 kHz CFO 相对 0 Hz 的额外开销在噪声内**（N1 总均值 2764 vs 2755 µs，
   −0.3%）。CFO 估计在全部 18 次运行、9216 个任务上精确等于注入值
   （50 000.00 Hz / 0.00 Hz），FCS 与 PSDU 逐字节 100% 通过。
5. **这不是实时能力**：该包在 737.28 MS/s 原生流中占 449.4 µs，单 worker
   慢 6.16×、4 worker 仍慢 1.82×；等效原生吞吐 119.8 / 229.0 / 404.9 MS/s。

## 场景与测量方法

- **信号**：单个 code-9 包，**256 个 SYNC 重复**、**127 B PSDU（含 2 B FCS）**，
  `4z2` SFD、峰值幅度 0.8。**干净**：无干扰码、无 AWGN、无 SIC、无 sensing。
- **CFO**：在 work 网格（998.4 MS/s）上对整窗乘 `exp(j2πf n/fs)`，再经 48/65
  合成到原生 737.28 MS/s SC16。这样 CFO 由夹具携带，必须由生产的 65/48
  重采样器恢复。主测 `+50 kHz`，另跑 `0 Hz` 作对照。
- **每个任务**：`SC16 65/48 重采样（737.28→998.4 MS/s）` + `demodulate_one`
  完整 comm 解码（timing → CFO → SFD → CIR → NS-SFD → PHR → payload/FCS）。
  **不执行** SIC 与 sensing，也不准备它们的 scratch。
- **窗口**：16 个 seed 的连续池，每窗 331 331 原生样点（≈449.4 µs），
  包起点 work `q=512`，公开名义起点 542，搜索/ROI 与生产一致。
  全池共用一个 ADC 尺度，无逐包归一化，SC16 零削顶。
- **并发**：真实 OS 线程，worker 固定亲和 CPU `[4,6,8,10]` 的前 N 个，
  协调线程 CPU0；动态领取 512 个整包任务；每 worker 预热 128 次后 barrier 同步。
- **统计**：3 轮，轮内 worker 顺序升/降/升；**CFO 块也跨轮交替顺序**，避免
  热漂移被误读成 CFO 效应。表中为各轮统计量的三轮中位数；分位数直接由逐任务
  时间计算，不相加各阶段 P50。
- 运行串行持有 `/tmp/uwb-sic-benchmark.lock`，清除 `LD_LIBRARY_PATH`，
  实际加载库/二进制/源码 hash、CPU 拓扑、夹具 hash 全部归档在 `provenance.json`
  与 `fixture.json`。

### 计时口径：单音消除不在本路径

- 本基准直接调用 `RationalResampler65_48Core`，**没有** `FixedToneCancelSc16Source`
  装饰器，夹具里也没有固定单音。因此 `resample_us` 只是
  `reset + process_sc16 + flush`：实测 `process_sc16` 占 99.9%（N1 1655.5 /
  1677.2 µs），`reset` 0.1 µs、`flush` 0.7 µs。SC16→CF32 转换融合在
  `process_sc16` 内，属于重采样。
- 生产 pipeline 中单音消除是**窗口装配之前**的源装饰器
  （`uwb_uhd_sc16_pipeline.cc:812`），worker 的 `t_resamp_start` 紧贴
  `resampler.reset()`（`:2003`），`e2e_us` 从 worker 取得 slot 开始（`:1985`），
  两者都不含它；它有自己的 `cancel_us` 计数器
  （`uwb_fixed_tone_cancel_source.h:107`）。
- 若要把它算进来，需要夹具注入已知固定单音并启用装饰器。按上一轮实测
  `cancel_cpu = 66–69 ms/s` 折算，449.4 µs 窗约 **30–31 µs**（约 +1.1%），
  但这是吞吐折算估算，不是本轮实测，也未含读线程/队列/交叉渐变开销。

## 完成间隔、吞吐与单包时间

`quality_minorder`，单位 µs/窗；间隔 = 稳态首尾任务时间差 / 任务数。

| Worker | 完成间隔 | 加速比 | 窗/s | 原生吞吐 | 单包均值 | P50 | P95 | 单包相对 N1 |
|------:|--------:|------:|-----:|--------:|--------:|----:|----:|-----------:|
| 1 | 2766.6 | 1.00× | 361 | 119.8 MS/s | 2764.3 | 2712.9 | 3177.1 | — |
| 2 | 1446.7 | 1.91× | 691 | 229.0 MS/s | 2889.6 | 2789.3 | 3445.2 | +4.5% |
| 4 | 818.4 | 3.38× | 1222 | 404.9 MS/s | 3255.2 | 3089.8 | 4401.4 | +17.8% |

- 单 worker 间隔 ≈ 单包均值（无排队、单线程顺序执行），说明该基准没有把
  排队/提交算进单包时间。
- 4 worker 的服务时间比单 worker 高 17.8%，是吞吐只有 3.38× 而不是 4× 的
  直接原因。与之前完整链路实验一致，但本轮**没有**硬件计数器证据区分
  cache / 内存带宽 / 频率 / 宿主调度，不能单独归因于某一项。
- 该包在原生流中占 449.4 µs：单 worker 慢 6.16×，4 worker 仍慢 1.82×。
  **连续 737.28 MS/s 的 256-SYNC/127-B 包流在本机 4 worker 下仍不可持续。**

## 时间开销分解（teardown）

### 顶层：重采样 vs comm 解调（均值，µs）

| Worker | 总时间 | 重采样 | 占比 | comm 解调 | 占比 |
|------:|------:|------:|-----:|---------:|-----:|
| 1 | 2764.3 | 1677.2 | 60.7% | 1086.4 | 39.3% |
| 2 | 2889.6 | 1717.7 | 59.4% | 1170.9 | 40.5% |
| 4 | 3255.2 | 1863.6 | 57.2% | 1409.5 | 43.3% |

重采样内部：`process_sc16` 占 99.9%（N1 1655.5 µs），`reset` 0.1 µs、
`flush` 0.7 µs。**256 SYNC 让窗口长达 331 k 原生样点，重采样是最大单项成本**；
comm 解调只占四成。

### comm 解调内部（均值，µs；括号为占 comm 的比例）

| 阶段 | N1 | N2 | N4 | 说明 |
|------|----:|----:|----:|------|
| timing | 427.4 (39.3%) | 443.5 (37.9%) | 479.7 (34.0%) | 粗检测 + 细跟踪 + 前导起点 |
| CFO | 15.9 (1.5%) | 16.6 (1.4%) | 22.1 (1.6%) | 首次 CFO 拟合（父阶段） |
| SFD | 200.4 (18.4%) | 225.8 (19.3%) | 312.2 (22.1%) | 含第二次 CFO 拟合与去旋转 |
| CIR | 115.2 (10.6%) | 136.6 (11.7%) | 187.7 (13.3%) | 信道估计 + soft-chip FIR |
| NS-SFD | 10.0 (0.9%) | 9.7 (0.8%) | 10.0 (0.7%) | 软 chip 上的 SFD 定位 |
| PHR | 19.0 (1.7%) | 20.1 (1.7%) | 22.3 (1.6%) | 融合 PHR 解扩/译码 |
| payload | 290.9 (26.8%) | 314.3 (26.8%) | 372.4 (26.4%) | 融合 CMF/解扩 + BPM/FEC/FCS |
| other | 4.2 (0.4%) | 4.1 (0.4%) | 4.5 (0.3%) | 父阶段求和余量 |
| **合计** | **1086.4** | **1170.9** | **1409.5** | 与上表 comm 列一致 |

父阶段之和与 `comm_us` 的差 ≤0.4%，可直接相加。**timing + payload 已占 comm 的
66%**，SFD 18%，CIR 11%。

### SFD 子项（N1，µs；父阶段 `SFD=200.4`）

| 子项 | 时间 | 占 SFD |
|------|-----:|-------:|
| bootstrap SFD | 14.1 | 7.0% |
| tail 重跟踪 | 0.0 | 0.0% |
| **SFD 锚定后 CFO 拟合+去旋转** | **167.2** | **83.4%** |
| final SFD | 13.7 | 6.8% |
| 余量（检查/网格/夹紧） | 4.3 | 2.1% |

**SFD 阶段的主要成本不是相关，而是第二次 CFO 估计与整段去旋转。** 这与
`acffbba` 改为「只用实测尾部峰值、按前导长度锚定」的拟合方式一致：
拟合本身很小（`cfo_fit` 全流程合计 4.8 µs），成本在去旋转。

### CIR 子项（N1，µs；父阶段 `CIR=115.2`）

| 子项 | 时间 | 占 CIR |
|------|-----:|-------:|
| 信道估计 | 60.1 | 52.2% |
| soft-chip FIR | 26.9 | 23.4% |
| 后处理 | 27.1 | 23.5% |
| 余量 | 1.5 | 1.3% |

### 去旋转总量（跨阶段诊断，**不可相加**）

`comm_cfo_rotate_us` 汇总首次 CFO、SFD 重拟合与 payload 三处的去旋转，
N1 为 **267.4 µs**（N2 305.3、N4 434.1）。它是跨阶段诊断桶，**已经包含在**
`CFO`、`SFD`、`payload` 三个父阶段里，不能再次累加。

## 0 Hz 对照

| Worker | 0 Hz 间隔 | +50 kHz 间隔 | 0 Hz 单包 | +50 kHz 单包 | 0 Hz CFO 阶段 | +50 kHz CFO 阶段 |
|------:|----------:|-------------:|----------:|-------------:|--------------:|-----------------:|
| 1 | 2756.9 | 2766.6 | 2754.7 | 2764.3 | 12.3 | 15.9 |
| 2 | 1475.7 | 1446.7 | 2944.3 | 2889.6 | 14.2 | 16.6 |
| 4 | 848.9 | 818.4 | 3382.2 | 3255.2 | 20.1 | 22.1 |

- CFO 阶段本身只多 3–4 µs；总时间差在 ±1% 内且方向不一致，**+50 kHz 不构成
  可分辨的额外成本**。
- 首轮曾把 CFO 块串行跑完再跑 0 Hz，得到「0 Hz 反而慢 2.9%」；改为跨轮交替
  顺序后该差异消失。说明那 2.9% 是热漂移，不是 CFO 效应，已按交替顺序重测。

## 功能与一致性

- **18 次运行 × 512 任务 = 9 216 个任务全部 FCS 通过、PSDU 逐字节一致**
  （`psdu_exact=1`），0 次 soft-chip/payload/PHR 回退。
- CFO 估计：注入 50 000 Hz → 估计 50 000.00 Hz；注入 0 Hz → 0.00 Hz，
  18 次运行全部如此。
- SFD 起点在所有运行、所有 worker 数下相同（均值 260 643.5），说明并发与
  CFO 都没有改变检测坐标。
- 各 worker 任务数均衡（N2 约 253–259，N4 约 121–135），无任务饥饿迹象。
- 基线 `acffbba` 的 `uwb_qa_uwb_demod_core.cc` 在本 build 中重建并单独通过
  （1/1，1.99 s）；既有 `all`/`pipeline` 任务用 64 SYNC/32 B 冒烟复跑正常，
  说明新增 `clean_comm` 分支未改变原任务路径。

## 结论边界（未验证）

- **未上板、未接 UHD**；不含 RX `recv`、队列、提交、PMT 与 paced 到达。
  这些数字是 DSP 算力容量，不是端到端实时延迟。
- 只测 `quality_minorder`；`quality_eq32` / `realtime_*` 未测。
- 只测单径、无噪声、无干扰的**干净**包。多径、AWGN、ISR 干扰、混合码重叠
  下的 256 SYNC/127 B 未测。
- 只测 +50 kHz / 0 Hz 两个 CFO 点；未扫频、未测 SFO、未测 CFO 随时间漂移。
- **未含固定单音消除**（`FixedToneCancelSc16Source`）；本路径不启用该装饰器，
  夹具也没有单音。见「计时口径：单音消除不在本路径」。
- 未做 MATLAB 交叉验证、PSDU/FCS 之外的 PER 统计、8 worker、P99 验收。
- 单包 P95 随 worker 增加而变差（3177→4401 µs），增加 worker 只解决吞吐，
  不解决单包尾部延迟。
- 本机为 20 逻辑 CPU 的虚拟机拓扑，不保证宿主物理核映射或频率；跨机不可直接比较。

## 复现

```bash
cmake --build gr-uwb/build-sc16-r1r2 \
  --target experiment_preamble_recovery benchmark_chain_workers -j16

python3 tools/sic/run_clean_comm_workers.py \
  --out /tmp/uwb-clean-comm-run --measure 512 --warmup 128 --reps 3 \
  --workers 1 2 4 --cfo-hz 50000 0
```

输出目录必须不存在。大 IQ 在临时目录，完成后删除；保留 `provenance.json`、
`fixture.json`、`summary.json`、`aggregate.json` 与逐任务 CSV，可由同一脚本重生成。
