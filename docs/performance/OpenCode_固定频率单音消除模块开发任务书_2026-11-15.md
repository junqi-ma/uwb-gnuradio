# OpenCode任务书：UHD原生C++固定频率单音消除

## 1. 目标与明确范围

用户授权的方案：每20 ms用该周期开始0.5 ms原始样点，仅估计已知单音的幅度与相位，外推并从本周期样点连续相减。作为UHD输出后的公共前处理，保护截窗、检测、重采样、解调、SIC、CIR。首版不处理训练窗与UWB包重叠问题，不检测/搜索/跟踪频率，不使用FFT，不把任务扩大为新的到达时间检测器。

只接现有原生UHD＋C++路径`UhdSc16Pipeline`。本轮不新增GNU Radio block、GRC、PMT消息或Python binding。固定频率是配置的**接收基带频率**，不是RF中心频率。首版默认参数737.28 MS/s、−232.96 MHz、20 ms更新周期、0.5 ms训练；显式开关默认关闭，用户启用时生效。更换接收频率/采样率后不得默默沿用错误的表。

当前HEAD `0e0c230`，工作区存在用户未提交修改，特别是`uwb_uhd_sc16_pipeline.cc`、捕获应用和defaults等；先检查diff并兼容，不覆盖或回退。单独build `gr-uwb/build-fixed-tone-cancel`，不覆盖旧build，不安装/usr/local，不推送，不自动上板或再次采集。

前置证据：

- `docs/performance/固定频率单音消除_C++开销重测_2026-11-15.md`
- `docs/performance/data_fixed_tone_cost_20261115/benchmark_fixed_tone.cc`：仅成本原型，不可直接当完整模块。
- `testdata/capture_compare_20261115_ch3/rx_ch3_rx1_40ms.sc16`及capture.json，40 ms连续实采，8组code10前导；大IQ不得加入Git。
- Python未知频率原型用于历史参考，正式C++必须固定频率；不得把此前频率优化结果替代本任务的固定频率算法。

## 2. 放置位置

当前实际链：`UhdDeviceSc16Source::read_samples → UhdSc16Pipeline::rx_producer_loop 按时间表拼SC16窗口 → 窗口池 → dsp_consumer_loop process_sc16重采样 → sic_process_unified/radar_cir_one`。

目标：`UHD持续recv → 有界原始SC16队列 → 固定频率消除 → 现有SC16窗口拼装/分发 → 原有DSP`。

必须在**截窗之前**连续处理；不能放到dsp_consumer_loop，否则已丢弃窗间训练数据，且不能保护前面的捕获。不能每个burst重置相位。文件回放也通过同一消除核心，便于同输入验证。

建议以`ISc16StreamSource`装饰器承载：关闭时保持原source直接路径；开启时包装UHD/replay source。新增一个专用原始读取线程，持续将source数据写到预分配有界块池；现有RX producer读取装饰器输出，消除与现有storage写入尽量融合，避免先清理整流再memcpy整流。算法核心与source/线程分离。

`start_stream()`仍严格在现有所有DSP worker Ready屏障之后调用；open只能分配和准备，不能提前启动UHD采样。装饰器的EOF、停止、致命错误、is_gap和时间戳必须逐层传递，不能被伪装为普通短读。保留原始RX计数口径，新增前处理计数，不能把两层read_calls混为硬件recv调用数。

若验证表明现有RX producer同步处理不会妨碍UHD持续读取，也只能在有持续recv解耦的证据下简化线程；不能仅以微基准快于实时就取消溢出验证。

### 2.1 原地与搬运融合：本次明确优化要求

新增参考原型见`docs/performance/data_fixed_tone_fused_20261115/fixed_tone_sc16_kernel.h`，附scalar/AVX2独立QA与ABBA benchmark。它尚未接入生产库，不能把其核心测试算作pipeline验证。

根据缓冲所有权二选一：

- 已持有可修改的唯一SC16缓冲，且下游可直接消费：调用`cancel_in_place`，不新建clean缓冲。
- raw队列必须搬到现有storage：用`copy_cancel(raw, storage, count, phase)`替代“memcpy到storage，再原地减”的两遍处理。直接在一次加载→相减→写入中完成必要搬运。不能另外分配clean流再拷贝一遍。

这里两种模式是不同所有权条件下的选择，不能先原地消除又融合减一次。已clean的storage复制到窗口slot时只做现有复制，不再次消除；重叠窗口同样只能对原始流消除一次。模型、phase、raw/clean状态需明确记录，防止重复消除。

原始训练样点必须在首次原地改写之前完成fold或保存在raw训练缓存；对同一缓冲有日志/旁路/训练等只读借用时，不得无条件原地改写。需要保留原始IQ存档时，raw分支明确在修改之前取样，不能把clean数据标raw。

单位复数288点基底仅初始化一次。每20 ms只对基底做复系数旋转/缩放与量化，不重复sin/cos；不改变固定频率及时间原点。跨任意read分块连续推进phase；关闭模式走原有复制/数据路径，保持逐位一致。

正常流不分配全流CF32或20 ms单音数组，不在窗口slot复制时补做消除。无需同时强制原地和融合这两种互斥缓冲策略。

AVX2与scalar输出需逐位相等，并有CPU能力分派；不能为新内核给整个库无条件启用AVX2。本原型的packed-int16接口移入生产时必须保证复数SC16存储布局和合法访问方式。

测量证据与门槛：整20 ms大缓冲融合相较复制再减，ABBA配对中位改善约26–29%；16k/64k小块没有稳定收益，64k复测甚至回退约11.7%，且墙钟波动很大。因此仅凭减少一遍访存不能宣布实时提速。必须保留可比较的两遍参考路径，在真实read块大小下串行配对；任何“默认选择融合能提升吞吐”的结论都需要接入后测量支持。原始结果全部保留于上述数据目录，详见本轮优化报告。

## 3. 数学与最省成本实现

已知ω=2πf0/fs，训练起点为样点epoch，训练长Nt：

`c = sum(x[epoch+n] * exp(-jωn))/Nt`

`i_hat[epoch+n] = c * exp(jωn)`

复系数同时包含幅度与相位。以同一epoch外推，首个周期从启动后的首个连续有效样点开始；以样点数定20 ms周期，不用主机wall clock。当前Nt=368640，Np=14745600。

本配置f0/fs=−91/288，可做严格周期288的优化：

1. 将0.5 ms训练样点按n mod 288折叠，I/Q使用int32精确累加；本配置每位置1280点，最大绝对值41943040，安全。
2. 对288个折叠结果做double复数投影，求c；等价于全训练窗单频投影，不是FFT，不是估计频率。
3. 初始化时缓存288点单位复数基底，每次更新只用复系数缩放/旋转得到预测单音表，明确SC16量化规则；之后AVX2加载→整数饱和减法→写回，每向量8个复样点。
4. LUT相位索引严格由(epoch-relative sample index) mod 288确定。跨read分块、尾部和20 ms边界不得错相。

首版只需支持上述已验证配置；对没有短周期的其它参数，显式初始化报unsupported，或实现固定频率NCO通用后端并分别QA，不能近似为288点周期后静默运行。不要求首轮增加通用频率后端。

SC16输出规则建议固定为`out=saturate_int16(in-round(tone))`，舍入模式固定nearest-even，不随外界fenv改变。半整数时与`round(in-tone)`可能有1LSB差别，报告要承认。预计单音幅度在SC16可表示范围内；若模型分量超范围，使用宽减法或显式拒绝该模型，绝不先夹断单音再宣称正确消除。

保持SC16单位：估计/查表用ADC整数单位，无需全流CF32转换；与既有`UnitRange/RawInteger`下游scale模式不冲突。CF32/double仅作独立参考。

## 4. 核心接口与状态

建议文件：`include/gnuradio/uwb/uwb_fixed_tone_cancel_core.h`、`lib/uwb_fixed_tone_cancel_core.cc`。接口至少涵盖prepare(config)、reset(epoch)、提交训练数据、读取完整模型、按绝对样点处理SC16块。可合为一个streaming API，但必须返回准确consumed/produced，不应假设输入块恰等于周期或训练窗。

Config包括enable、sample_rate、tone_frequency_hz、period_s、training_s、crossfade_samples和缓存上限。Model含epoch、valid、complex coefficient、LUT、model generation。热路径不分配内存、不构造FFT plan、不逐样点sin/cos、不逐样点锁、不逐样点原子计数。

状态：CollectTraining→Estimate→Apply，周期重复。训练和模型不可共享裸可变buffer跨线程；若估计在现有frontend消费者线程进行，约50 µs小任务不必额外新增估计线程。

严格首版语义：每周期暂存起始0.5 ms原始数据，模型就绪后用新模型处理并按原顺序输出，包括该训练窗；后续实时流式处理。不等待收齐20 ms。源读取线程在此期间继续recv。

每次更新模型时，用同一绝对时间评价新旧单音，并做短交叉渐变（建议默认256样点，可设0用于数学参考比对），减少硬切换瞬态；渐变不丢样、不插样。复系数幅相不得用不同时间原点直接插值。

gap、时间戳跳变、采样率变化后清空训练并重新建立epoch；不跨不连续区间学习，不补零冒充连续。EOS训练不足时原样排出未处理尾部并记录partial_training_bypass。无可靠单音模型/数值无效时旁路，并计数；开关关闭必须保持原路径逐位一致。

样点坐标和硬件rx_time保持采集时间，不得把排队延迟写进时间戳或增加样点偏移。装饰器拆分/合并块时重新给出正确start_sample_abs/time_spec，gap必须在正确的输出边界出现。输入输出样点守恒，训练暂存算pending，不是丢失。

## 5. 有界内存与超载

训练raw约1.406 MiB，LUT1152 B，fold2304 B；不要分配58.98 MB的整20 ms波形。建议初始raw队列32块×65536复样点=8 MiB，约2.84 ms输入覆盖，仅作为可调首值，不能当作实时保证。还需计入训练暂存与队列元数据。输入块不够时流式累计，不能阻塞recv等模型。

队列满时UHD接收侧非阻塞drop完整块、累计丢弃样点并给下一输出明确gap；下游不得拼接成连续IQ。不得为减少overflow静默降低输入率。单独输出source samples、queued、consumed、pending、dropped、gap守恒计数，不能破坏现有窗口ledger。

## 7. 成本预算（独立内核实测，不是上线承诺）

本机9700X/CPU2、单核AVX2：0.5 ms幅相估计45.4 µs，LUT生成4.6 µs；20 ms原地消除2.42 ms、非原地3.22 ms；估计+建表+非原地整套实测3.96 ms。因缓存/执行顺序差异，各项中位数不能直接相加替代整套结果。

整套约一个核心20%计算预算作为起点；接入还要加队列、拷贝及下游竞争。0.5 ms训练+约50 µs计算+排队/积压清空，不能把启动延迟写成仅50 µs；也不能把20 ms整段累计CPU时间3.96 ms说成每包固定延迟。SC16连续读写逻辑流量约5.90 GB/s，UHD写入和下游访问另计。

## 8. 必做验证与交付

1. double数学参考：已知固定频率、不同幅相、非整周期训练长度（若接口支持）、任意分块/尾部、跨20 ms及288边界，逐点时间原点一致。饱和、舍入ties、模型超范围、无效配置。
2. streaming source：可控fake source，训练暂存/EOS、gap位置、源失败、start/stop、队列满、输入输出守恒；关闭逐位等于旧链。不要只验证新算法镜像。
3. 同一40 ms实采回放：用固定−232.96 MHz、每周期前0.5 ms估计；输出消除IQ并与独立固定频率Python参考对照。以前未知频率拟合结果只作旁列。计算单音残余随周期时间、自相关曲线、阈值扫描与到达时间；不能只报总功率降低。
4. 真实数据解调/雷达与关闭基线配对；报告code10配置、PSDU/FCS和CIR有无覆盖。不得因前导相关变好就宣布波形无损或弱目标保护通过。训练窗碰包鲁棒性本轮明确不要求。
5. 串行持benchmark锁，对关闭/开启做ABBA，同输入同库同机器：核心、source前处理、完整pipeline分开测；报告吞吐、每块CPU时间、首样点输出延迟、P50/P95/P99、积压、drop、总线程/core用量。用paced replay验证50个周期/秒，至少1 s；单独用非paced测吞吐上限，不混用。
6. 目标：当前机单通道737.28 MS/s paced replay至少持续1 s无新drop；达不到如实报告并定位，不以微基准推断通过。不自动实机采集，只有后续用户授权才上板。
7. 新build针对性QA，再运行受影响pipeline/core回归；按实际CTest数报告。产出开发报告、复现命令、测试代码SHA与实际加载库路径、诊断原始数据。保留历史数据，不把大IQ/build提交。
