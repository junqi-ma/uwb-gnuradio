# 解调与调度分层重构开发报告（2026-11-17）

方案：[解调与调度分层重构方案](解调与调度分层重构方案_2026-11-17.md)。
起点 `2a4e244`，分支 feature/sic-research。开始时工作区干净，已有代码已提交。
本轮仅软件/文件回放，不新增硬件证据。

## 交付与边界

- TX/RX 共用原语进入 uwb_hrp_codec.h，算法正文逐字搬移；21 个阶段/codec 函数
  的函数体已与起点逐字核对一致（记录在 verification.json）；RX detail 名称用 using
  保持源码兼容。TX 不再包含接收实现；SIC 重构的 CRC 调用也显式依赖 codec。
- 6713 行 uwb_demod_core.h 拆为职责明确的阶段头，原文件保留 11 行兼容聚合入口。
  完整包 API 声明在 uwb_demod_pipeline.h，编排在 uwb_core 的独立 TU（约 1180 行）。
  timing/FEC 仍各约 1200 行，边界清楚但不宣称所有复杂度已消除。
- SIC/GR/TWR/完整包实验封装和离线解码消费者使用轻量 API；单阶段 QA 显式包含
  相应阶段头，不再通过 TX 或完整包封装意外获得 RX 内部定义。
- begin_packet 集中清理 fused PHR 包内决策；模板缓存、workspace 容量和阶段自有
  reset 顺序保持原样。未强制改变 scratch 的字段布局。
- PacketExecutionPlan 集中整数网格准入与有效 profile；所有既有旋转/前缀/融合
  判定服从同一准入结果。finalize_demod_result 集中子计时发布及原坐标转换，
  每条退出路径仍调用一次，不修改 chip/局部诊断字段的历史语义。
- live PacketProcessor 只做单包 DSP，持有 worker 私有 resampler/scratch，
  不引用锁状态、队列或 Reporter；观察生成是独立纯转换，发布仍在 worker，应用
  仍在 RX owner。PacketRequest 集中携带 slot/generation 与坐标来源。
- 两套调度共用 resample_sc16_window，去掉三份重复 reset/process/flush 代码。
  动态捕获/锁定的共享任务池、固定周期的 SPSC 分发、及时控制反馈、有序结果提交
  均保持原策略，没有把有序日志回调接到实时锁定反馈路径。
- 安装所有新公共头；离线解码改为 CMake 目标并链接 uwb_core；诊断工具按模块
  插桩并编译独立命名的诊断入口，避免链接时误用未插桩实现。旧 dense 模式是兼容
  别名：当前窄 SFD 搜索本身已经逐 lag 扫描。

代码依赖与生命周期详见[架构说明](../架构_解调与窗口执行.md)。

## 回放一致性

基线原生 live 二进制和 libuwb_core.a 在修改前备份至 /tmp/uwb-refactor-base。
固定窗口基线 decoder 用 `git show 2a4e244:...` 的旧头与旧源码重新编译；
当前 decoder 来自 CMake uwb_dw3000_decode。二进制与输入 SHA-256 已归档。

用 compare_packets.py 对 +4/-12/-14 dB 各 200 包逐行比较 JSONL，忽略 demod_us，
其余状态、度量、CFO、FCS、PSDU hex 全部相同（600 行，0 差异）。
FCS 分别为 199/200、186/200、0/200；这是固定窗口 Full/on-demand 配置，
与 live 的融合/动态锁定档位不是同一配置，不混用 PRR 数字。
