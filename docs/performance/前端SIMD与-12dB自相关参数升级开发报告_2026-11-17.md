## 2. 按任务书实现的四项修改

### 修改 1：连续块 `step` 点累加核（`Acquisition::block_sum`）

`step` 从"每 `step` 点只抽算 1 对"改为"对连续 `step` 对样本全采样求和"，
数学上等价于 `step=1` 滑窗；`step` 只保留为环表粒度。表 `span/step = 3000`
项（`96 KB`，L2 常驻），外层 `sum += v - old` 仍是 `double`。

非跨界快路径（99.97% 调用）走 SIMD；环回绕（每个 2M 环 2 个块）走逐样点
masked 标量循环。

### 修改 2：主循环块尾安全边界

`while (acq.probe + Acquisition::lag < end)` →
`while (acq.probe + acq.step - 1 + Acquisition::lag < end)`，
保证 `[probe, probe+step-1+lag]` 全部落在有效 `end` 内。

### 修改 3：三角形峰顶触发与突发跌落保护

- `Acquisition` 新增 `peak_at`，`reset()` 清 `-1`。
- `fall_frac = 0.6`、`fall_after = 65536`（`16384` 不可用，任务书已说明）。
- 提交判定放在 `metric >= low_thr` 分支**之前**，因此无噪突发从 `1.0` 直接跌到
  `0.0`（QA 的 `cw_burst.sc16`）也能提交。
- 种子：`span > 6000` 时 `peak_at + lag/2`，`span <= 6000` 保留旧偏移。

### 修改 4：默认参数

`acq_span 64000 → 192000`、`acq_step 8 → 64`、`acq_low 0.0015 → 0.00015`、
`acq_peak 0.0028 → 0.00030`、`acq_persist` 不变；`--help` 文本同步；
参数校验与 QA 拒参逻辑未改。

## 3. 两处偏离任务书的地方（都是实测逼出来的）

### 3.1 累加核用整数 `vpmaddwd`，不是任务书写的 float

任务书 §2 修改 1 要求 `_mm256_cvtepi16_ps` 转 float + 4 条 FMA。实测这条路
**达不到 125 ms**，原因是 Alder Lake 上 `int16 -> float` 的加宽转换只能走唯一
的 shuffle 端口：

| 内核 | 0.5 s 回放耗时 | 说明 |
|---|---:|---|
| 仅 4×`vpmovsxwd` + 4×`vcvtdq2ps`（不乘） | `50 ms` | 转换本身就是地板 |
| 任务书 float 版（4 FMA/4 样点，单累加器组） | `92 ms` | 受 shuffle 端口 + FMA 端口双重限制 |
| float 版 + 两组独立累加器 | `92 ms` | FMA 依赖链不是瓶颈，端口才是 |
| **整数 `vpmaddwd` 版（本报告采用）** | **`66 ms`** | 内层循环零转换 |

`vpmaddwd` 本身就把每个复样点的 I/Q 两乘积相加，所以 `re/e1/e2/im` 各只需
一条乘加/4 样点；`im` 用「交换 a 的 I/Q + 取反 b 的 Q」得到
`ai·br - ar·bi`，只多 1 条 `vpshufb` + 1 条 `vpsignw`。

**溢出处理（任务书担心的两点都被消掉，而不是绕过）**：

- 输入先 `>>3`（13 位有效位，`|x| <= 4096`），int32 累加器每 64 样点冲入
  float，任意 `--acq-step` 下上界 `2.7e8 < 2^31`。
- `>>3` 之后 `|x| <= 4096`，`vpsignw` 取反**精确**，`int16 == -32768` 的取反
  溢出不可能发生。
- `>>3` 前用 `vpaddsw` 加 4 做**四舍五入**：直接算术右移是向 `-inf` 截断，
  在移位域留 `-0.5 LSB` 直流，192k 样点上相干累加会把噪底抬高 **10.5%**；
  改成饱和加 4 后 `+32767` 不会回绕成负数、`-32768` 仍精确，噪底偏差降到
  **0.37%**（见 §5.1）。
- 度量是 `|sum|^2 / (e1·e2)`，均匀缩放**精确抵消**；代价只有 8 LSB 量化步长，
  相对 542 LSB 包是 `-35.7 dB`，在 `-12 dB` 带内 SNR 下比它叠加进去的噪声低
  `55 dB`。

### 3.2 接收直写环形缓冲，取消整条流的 staging 拷贝

任务书 §1 认为 `frontend_us` 里"约 75~85 ms 是固定环形拷贝开销"。实测拷贝是
**45–70 ms**（`--tone off/on`），而任务书的 125 ms 目标隐含"扫描 ≤ 40–50 ms"。
整数内核已经压到 66 ms，两者相加仍然超。因此把
`read_samples(incoming) → copy_n(ring)` 改成**直写 ring**：

- 不跨界时 `read_samples` 直接写 `ring + (end & mask)`，稳态零拷贝
  （实测 `frontend_copy_us = 0.15–0.29 ms`，只剩每 32 块 1 次的回绕块）。
- 回绕块仍走 staging 缓冲 + 两次 `copy_n`。
- **gap 路径**：数据已经按 gap 前的原点写进 ring，随后 `memmove` 到新原点
  （放不下时退回 staging）。gap 罕见，不进稳态预算；`INVALID_GAP`、
  `valid_begin`、`acq.reset`、`note_time_discontinuity` 语义全部不变。
- 时序语义不变：写入仍在 `end += n` 之前完成，worker 仍只读已提交窗口。

## 4. 顺带修掉的两个缺陷

1. **标量尾与 SIMD 主路径不同标度**（会直接产生虚警）。`block_sum` 的
   `< 8` 样点尾部最初按原始 `int16` 累加，而 SIMD 路径按 `>>3`，两者差 64 倍；
   任何 `--acq-step` 不是 8 的倍数时，一个块会混用两种标度。环回绕回退循环
   有同样问题。现在三处（SIMD、尾部、回绕）共用同一 `>>3`+四舍五入标度，
   QA 新增 `--acq-step 64` 与 `--acq-step 3` 同种子断言。
2. **每块一次串行 `double` 除法**。0.5 s 回放有 5.76M 个块，除法约 19 ms。
   门限、峰值比较、回落判定全部改成与 `den = max(1, e1·e2)` 交叉相乘，
   只有在簇打开时才真正做除法（纯噪下为 0 次）。

## 6. 与任务书预期不一致、必须写清楚的地方

1. **`+10 / 0 dB` 的 `fcs=100/100` 无法达成，与本次改动无关**：
   `tools/rx/proto_low_snr_signal.py` 生成的是**纯前导**（256 SYNC 平铺，
   无 SFD/PHR/payload），后端无论多强都不可能通过 FCS。实测 `+10 dB`
   状态是 `PAYLOAD_FAILED`/`FCS_FAILED`，`0 dB` 是 `SFD_FAILED`，属正常。
   因此任务书 Step 3 的可判读指标只有前端捕获数，即 `acq_seeds`。
2. **`completed` 不是捕获数**。`completed` 是"EOF 前跑完的任务数"，受后端
   吞吐限制：`+10 dB` 每包走完整 payload 重试约 8 ms，而包周期 1 ms，队列
   必然积压。所以 `+10 dB` 的 `completed` 只有 60–67，但 `acq_seeds=100`。
   为此在 `COST_TOTAL` 新增 `acq_seeds`（前端产生的自相关种子数），把
   "捕获"与"解码"两个量分开。任务书 §3 Step 3 的 `completed >= 99` 在
   `-12/-14 dB` 成立（后端快速 `TIMING_FAILED`，实测 `99–100`）。
3. **任务书 §1 的"固定拷贝 75~85 ms"偏高**，实测 45–70 ms；这直接决定了
   §3.2 必须动输入路径才能达到 125 ms。
4. **`SCALAR` 构建不再是实时配置**。全速率扫描在标量下 `frontend_us`
   约 `462 ms / 0.5 s`（4.9× AVX2），`--replay` 非 paced 时
   `raw_drop_samples` 会到 `2.7e8`。SCALAR 只作为可编译/可验证回退，
   实时必须用 AVX2（x86-64 默认路径）。这一点在改动前不成立（旧的
   `64k/step=8` 标量只算 1/8 样点）。
