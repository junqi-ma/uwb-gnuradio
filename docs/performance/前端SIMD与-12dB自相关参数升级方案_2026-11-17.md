# 前端自相关 SIMD 化与 `-12 dB` 参数升级开发方案

**日期**：2026-11-17  
**目标文件**：[gr-uwb/apps/uwb_dw3000_live.cc](../../gr-uwb/apps/uwb_dw3000_live.cc)（可选同步微调 [tools/rx/qa_live_dw3000_console.py](../../tools/rx/qa_live_dw3000_console.py)）  
**范围**：仅升级流式前端捕获 `Acquisition` 及其默认参数，**不改后端解调器/锁定器**，为后续 `-12 dB` 进锁铺平前端输入。

---

## 1. 立项依据与性能指标（已实测）

在 `0.5 s`（`368,640,000` 样点）原生 `737.28 MS/s` 纯 AWGN 回放（`--workers 4 --taps eq16 --mode continuous --sync locked`）下实测现行标量 `double` 实现：

| 配置 | 有效积分对数 | `--tone off` `frontend_us` (单核占比) | `--tone on` `frontend_us` | `--tone on` `raw_drop_samples` |
|---|---:|---:|---:|---:|
| `-4 dB` 旧配置（`48k / step=50`） | `960` | `108.4 ms`（21.7%） | `121.4 ms`（24.3%） | `0` |
| 现行 `-10 dB` 默认（`64k / step=8`） | `8,000` | `262.9 ms`（52.6%） | `323.4 ms`（64.7%） | **`983,040`（`gaps=2`）** |
| 仅调参升 `-12 dB`（`192k / step=8`） | `24,000` | `317.1 ms`（63.4%） | `310.6 ms`（62.1%） | `0`（已无余量） |

**结论**：`frontend_us` 中约 `75~85 ms` 是固定环形拷贝开销，其余全消耗在 `Acquisition::scan` 的标量 `int16->double` 转换与大环形缓冲访存。不加 SIMD 直接压到 `-12 dB` 会让单核占用超 `60%` 并在 `--tone on` 下出现丢样。

**验收目标**：
1. `--tone on` 0.5 s 实时回放：`frontend_us <= 125 ms`（回到 `-4 dB` 水平）、`raw_drop_samples == 0`、`gaps == 0`、`false_alarms == 0`；
2. `-12.0 dB`（含 `+10 dB`、`0 dB`）捕获率 **`100%`**，且兼容现有 `CTest` 与 `SCALAR` 构建。

## 2. 具体修改设计（4 个步骤）

### 约束：严格遵循工程 `UWB_SIMD` 体系
- [gr-uwb/apps/CMakeLists.txt](../../gr-uwb/apps/CMakeLists.txt#L522) 已为 `uwb_dw3000_live` 绑定 `uwb_simd_apply(uwb_dw3000_live)`，**禁止在 `CMakeLists.txt` 中手工添加 `-march=native`**。
- 参照 [uwb_cir_fir_simd.h](../../gr-uwb/include/gnuradio/uwb/uwb_cir_fir_simd.h#L40-L45)，在 `uwb_dw3000_live.cc` 顶部使用 `#if defined(__AVX2__) && defined(__FMA__)` 引入 `<immintrin.h>`，并保留纯标量 fallback 以兼容 `-DUWB_SIMD=SCALAR`。

---

### 修改 1：连续块 `step` 点 SIMD 累加核 `reduce_block`

将原来的"每 `step` 点只抽算 `1` 对样本"改为"对连续 `step` 对样本做全采样求和"（数学上等价于 `step=1` 滑窗累加，但外层环形缓冲更新频率与除法/状态机降低 `step=64` 倍）：

```cpp
// 在 ring 上从 (probe, probe+lag) 起连续累加 step 对 complex<int16_t>：
//   re += ar*br + ai*bi
//   im += ai*br - ar*bi
//   e1 += ar*ar + ai*ai
//   e2 += br*br + bi*bi
```

**实现要点**：
1. **非跨界快速路径（99.99%+ 调用）**：
   设 `p0 = size_t(probe) & (history_size - 1)`、`q0 = size_t(probe + lag) & (history_size - 1)`。当 `p0 + step <= history_size && q0 + step <= history_size` 时，直接对连续内存 `&ring[p0]`、`&ring[q0]` 运算：
   - AVX2+FMA 路径：每次用 `_mm_loadu_si128` 读入 `4` 个 `complex<int16_t>`（8 个 `int16_t`），用 `_mm256_cvtepi16_ps` 转为 `float`（彻底避免 `int16 == -32768` 取反溢出及 `int32` 满量程乘法溢出）。
   - 用排列/奇偶交换（`_mm256_permute_ps(..., 0xB1)` + 符号掩码 `{-1,+1,...}`）一次求出 4 个复数共轭乘与能量并 `_mm256_fmadd_ps` 累加到 `acc_re, acc_im, acc_e1, acc_e2`；末尾不足 `4` 的余数用标量补齐（**保证 `--acq-step` 为任意正整数时行为均正确**）。
   - 块累加结束将 4 个通道水平归约后转为 `double` 写入 `Pair`。
2. **环形边界回退路径**：
   当 `p0 + step > history_size || q0 + step > history_size` 时（每个 2M 环仅 2 个块），直接走逐样点 `& (history_size - 1)` 的标量循环即可，无需复制或双倍展开 `ring`。
3. **外环保持 `double` 精度**：
   `pairs` 大小缩为 `span / step = 192000 / 64 = 3000`（`96 KB`，常驻 L2 缓存），外层 `sum += v - old` 维持 `double` 以消除大窗长滑动减法累计误差。

---

### 修改 2：主循环边界检查（防越界读取未写入样本）

在 `uwb_dw3000_live.cc` 约 `1452` 行，原边界条件：
```cpp
while (acq.probe + Acquisition::lag < end)
```
改为块尾安全边界：
```cpp
while (acq.probe + acq.step - 1 + Acquisition::lag < end)
```
确保单次块累加读取的 `[probe, probe + step - 1 + lag]` 区间全部已落入有效 `end` 范围内。

---

### 修改 3：三角形峰顶触发与突发跌落保护

原上升沿触发 `first + span / 2` 在 `192k` 滑窗下随 SNR（`+10 dB` 到 `-12 dB`）会漂移十余万样点；改为追踪 `192k` 三角形相关峰的顶点 `peak_at`：

1. `Acquisition` 新增状态字段 `int64_t peak_at = -1;`（在 `reset()` 时清为 `-1`），以及可配置的峰后回落参数：
   - `static constexpr double fall_frac = 0.6;`
   - `static constexpr int64_t fall_after = 65536;`（实测不可取 `16384`，`16k` 会在低 SNR 上升斜坡小平台提前触发并触发 `holdoff` 遮蔽真顶）。
2. 当 `metric >= low_thr`：
   - 若 `first < 0 || at - last > gap_max`，重置 `first = at; peak = 0; peak_at = at;`
   - 更新 `last = at;`；若 `metric > peak`，更新 `peak = metric; peak_at = at;`
3. **提交条件（含无噪突发跌落兼容）**：
   - 在 `first >= 0 && at - first >= min_persist && peak > peak_thr` 已满足时，只要出现以下任一信号即刻提交：
     - `metric <= fall_frac * peak`（已越过三角形顶点并明显回落；**注意**：即使该点突然跌破 `low_thr` —— 例如 `qa_live_dw3000_console.py` 的无噪 `cw_burst.sc16` 脉冲结束时 metric 从 `1.0` 直接跌到 `0.0` —— 也应优先触发提交，再重置簇状态）；
     - `at - peak_at >= fall_after`（峰后走满 `65,536` 样点，避免平顶宽突发一直等）。
   - **提交种子**：
     - 延迟自相关 `[start, start+span-lag)` 的相关性使得 `192k` 峰顶实际有 `1` 符号宽（`750` 原生样点）平台，`peak_at` 默认落在 `[start - 750, start]`。
     - 当 `span > 6000` 时设 `seed = std::max<int64_t>(0, peak_at + lag / 2)`（居中对齐符号起止）；当兼容旧小窗 `span <= 6000` 时维持 `seed = std::max<int64_t>(0, peak_at)`。
     - `holdoff = seed + holdoff_len;`、`first = -1; peak = 0; peak_at = -1;`。

### 修改 4：默认参数升级

更新 `Options` 与 `Acquisition` 默认参数（及对应 `--help` 打印文本）：

| 参数 | 现行值（`-10 dB` 档） | 升级值（稳过 `-12 dB`，兼顾 `-14 dB`） | 设定依据 |
|---|---:|---:|---|
| `acq_span` | `64000` | **`192000`** | 匹配 256-SYNC 原生前导长度，有效积分增至 `192,000` 对 |
| `acq_step` | `8` | **`64`** | 分块 SIMD 步长，`3,000` 环表常驻缓存，状态机降耗 8× |
| `acq_persist` | `12000` | **`12000`** | 保持不变（约 `16.3 µs`） |
| `acq_low` | `0.0015` | **`0.00015`** | 实测 `0.5 s` 纯噪极限 `~0.000052`，留 `~2.9×` 起簇保护 |
| `acq_peak` | `0.0028` | **`0.00030`** | `~5.7×` 高于纯噪最大值；同时低于 `-12 dB` 最弱包（`~0.0009`）`3×` 以上、且低于 `-14 dB` 最弱包（`~0.00037`） |

> 保留已有参数校验（`acq_step > 0`、`acq_span % acq_step == 0` 等）及 `qa_live_dw3000_console.py` 拒参逻辑不变。

## 3. 快速验证方案（执行耗时 < 20 秒）

### Step 1：编译与既有 CTest 回归（含 SIMD 与 SCALAR 编译校验）
1. 在现有构建目录增量编译并跑全量原生测试（确保 51 项全部通过，重点包含 `uwb_qa_dw3000_live_console`）：
   ```bash
   cmake --build gr-uwb/build-native --target uwb_dw3000_live -j
   ctest --test-dir gr-uwb/build-native --output-on-failure
   ```
2. 额外用 `-DUWB_SIMD=SCALAR` 在独立临时目录编译确认标量回退分支无语法/告警问题。

### Step 2：0.5 s 纯 AWGN 开销与零丢样验收（核心瓶颈测试）
使用 [proto_low_snr_signal.py](../../tools/rx/proto_low_snr_signal.py) 生成 `0.5 s` 纯噪声（用完删 `/tmp` 临时文件）：
```bash
python3 tools/rx/proto_low_snr_signal.py --noise --packets 500 --period-ms 1.0 \
  --out /tmp/uwb_fe_test/noise_0p5s.sc16 --format sc16

for tone in off on; do
  ./gr-uwb/build-native/apps/uwb_dw3000_live \
    --replay /tmp/uwb_fe_test/noise_0p5s.sc16 --seconds 0 --period-ms 1.0 \
    --mode continuous --sync locked --workers 4 --taps eq16 \
    --tone $tone --print summary
done
```
**验收门槛**：
- 两次均 `completed=0`（0 虚警）、`raw_drop_samples=0`、`gaps=0`；
- **`frontend_us <= 125,000`（`<= 25%` 单核，不高于 `-4 dB` 基线 `108/121 ms`）**。

### Step 3：`+10 dB`、`0 dB`、`-12 dB`（附测 `-14 dB`）捕获率验收
生成 `100` 包（`1 ms` 周期、`0.1 s`）合成测试流：
```bash
for snr in 10 0 -12 -14; do
  python3 tools/rx/proto_low_snr_signal.py --snr $snr --packets 100 --period-ms 1.0 \
    --out /tmp/uwb_fe_test/s${snr}.sc16 --format sc16
  ./gr-uwb/build-native/apps/uwb_dw3000_live \
    --replay /tmp/uwb_fe_test/s${snr}.sc16 --seconds 0 --period-ms 1.0 \
    --mode continuous --sync acquire --workers 4 --taps eq16 \
    --tone off --print summary
done
```
**验收门槛**（注：因本次未改后端解调器，`-12/-14 dB` 会正常上报 `status=TIMING_FAILED`，重点核查前端捕获送包数 `completed` 与零重叠）：
- `+10 dB`、`0 dB`、`fcs=100/100`、`raw_drop_samples=0`；
- **`-12.0 dB`**：`completed >= 99`（目标 `100/100`）、`OVERLAPPING_CANDIDATE == 0`、`INCOMPLETE_WINDOW == 0`（注：第 0 包起点在样本 `0`，受 `pre_guard=36864` 限制可能报 1 次 `INCOMPLETE_WINDOW`，即有效包 `1..99` 全部送进后端）；
- `-14.0 dB` 观察实测 `completed` 百分比作为能力边界记录；验证结束后清理 `/tmp/uwb_fe_test`。
