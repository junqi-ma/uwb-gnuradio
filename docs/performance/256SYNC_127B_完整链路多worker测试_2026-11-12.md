# 256 SYNC / 127 B PSDU：重采样与完整接收链路多 worker 测试

## 测试口径

按用户确认：完整 code-9 目标包和 code-10 干扰前导均为 **256 SYNC**。
目标 PSDU **127 字节，包含 2 字节 FCS，即 125 字节数据**；干扰仅 SYNC+SFD，
没有 PHR/payload。SFD 保持 4z2（8 符号）。单径、零 CFO、ISR20 dB、SNR20 dB。

沿用上一轮的独立原生信号生成、SC16、生产 65/48 重采样、前导 SIC、sensing CIR
和完整通信解码；16 组载荷/噪声/原点，四套 FIR、1/2/4/8 worker、三轮。
每轮生产 pipeline 预热128窗、测512窗；完整 DSP 每 worker 预热32次、共测512任务。
名义起点、CPU绑定、源流控及统计范围同上一轮报告。

原生完整窗口增至 **331331 点**，在737.28 MS/s下为 **449.40 µs**，含完整目标包
及上下文。它不是单独前导长，也不是纯 payload 空口时长。
生成器统一8193-tap Kaiser beta10做48/65下采样，本轮测试四套生产profile；
四套共享同一SC16字节池和ADC尺度，输入零削顶。输入池、尺度、PSDU、hash见fixture.json。

接收端 sensing CIR 和通信 CIR 配置为跳过前10个、使用余下 **246 SYNC**。
SIC 模型仍严格只用前 **8 SYNC** 估计，再外推相减整个256-SYNC前导；没有把
估计窗口改成256，也没有读干扰真值来拟合在线模型。

## 先补齐的256支持

原 Ipatov 准入条件只接受64 SYNC，且统一SIC内部通信解调仍使用默认64：

- `uwb_discrete_cir_estimator.cc`：Ipatov仅额外接受256（仍拒绝128等未验几何）；
  默认完整包容量按配置的SYNC数推导。
- `uwb_sic_unified.cc`：将配置的SYNC数传入内部通信解调；CIR长度按已配置前导
  推导。默认64的数值配置保持原值。
- pipeline前导模板按配置重复，benchmark几何不再强制覆盖回64。
- steady基准新增 `--target-sync-reps` / `--sic-sync-reps`，仅接受64或256；
  数据生成和完整DSP基准贯通相同几何参数。

检测/拟合/模板尺度/有限性等安全阈值没有放宽。新增QA验证256前导真实提交、
前8符号训练边界、末4个SYNC实际被消除，以及ROI外输出不变；128几何仍拒绝。
相关6项CTest全部通过（含默认64路径、离散CIR、重构和pipeline）。本轮未跑全量CTest。

本次补齐的是 **L1前导SIC的256配置**，不宣称L2整包SIC后端也已支持256。
目标完整包的通信解码/FCS恢复与L2整包干扰重构是两个不同范围。

## 功能验证

- 主矩阵96次运行；生产pipeline48次均640/640窗完成，0丢弃、0处理失败，全部
  有效SIC提交、sensing SFD检出（包括预热窗）。
- 完整DSP48次共24576个测量任务，全部SIC提交、CIR有效、FCS通过、127 B PSDU
  与期望字节逐点一致。预热也执行相同检查。
- 每个profile的12次生产pipeline运行，对比N1第一轮640个窗口的12个功能/
  坐标字段，**0差异**。这是结果字段一致性，没有对整段IQ做memcmp。
- 三个独立插桩诊断轮也均640/640有效提交及sensing检出。

本轮为有效处理负载计时，不是失败退出耗时。没有做多径、弱目标或CIR绝对幅度
保护矩阵，功能通过不等于此前0.1 dB CIR保护门槛关闭。

| 8 | 6.845 / 11.150 | 8.743 / 14.281 | 1.237 |

并行缩短的是多包完成间隔；单包延迟没有随worker数下降。
完整DSP平均服务时间从N1约5.980 ms增到N8约9.806 ms（+64%），所以扩展收益
只有4.84×。以任务服务跨度计算的worker有任务比例N4约99.8%、N8约99.1%，
没有明显领取任务饥饿；这不是硬件CPU利用率，也不能区分cache/内存/频率或
宿主调度等原因。

相较上一轮64/32的N8吞吐加速6.10×，本轮扩展效率下降。窗口/数据结构和工作量
明显变大，可能增加共享资源压力；没有硬件计数器证据时不把原因锁定为内存带宽。

N8每窗还有约565 µs的feeder流控等待，生产者在等消费进度；其read+拷贝约373 µs，
小于主要DSP服务预算。当前数据不支持认为RX已成为唯一瓶颈。
`rx_read_us`包含feeder等待，不能当作纯读取时间；这些部分耗时也不能直接相加
作为端到端延迟。全速回放排队受8N个in-flight上限影响，仍不代表paced延迟。

## 复现、文件与边界

```bash
cmake --build gr-uwb/build-sc16-r1r2 \
  --target experiment_preamble_recovery benchmark_chain_workers benchmark_sc16_pipeline_steady uwb_qa_uwb_sic_unified.cc -j2
python3 tools/sic/run_chain_workers.py \
  --out /tmp/uwb-chain-workers-256-127-new-run \
  --sync-reps 256 --sic-sync-reps 256 --psdu-bytes 127 \
  --measure 512 --warmup 128 --reps 3
```

每次输出使用新目录。锁、数据生成、独占CPU亲和性、统计和日志规则与上一轮一致。
原始数据：`docs/performance/data_chain_workers_256_127_20261112/`。
其中包含输入manifest、逐窗JSON/CSV、aggregate、跨worker字段比较、相关CTest日志、
生产支持修改patch、源码/实际库/二进制hash。运行基线为bf5a5be加本轮未提交修改。

256场景先通过16窗功能冒烟，再执行三轮512窗矩阵；相关6项CTest通过，
`git diff --check`通过。未跑全量回归；未上板、未做MATLAB、paced、P99目标、
多径/CFO/弱目标矩阵。没有更改默认64前导、默认滤波器或安全阈值。
