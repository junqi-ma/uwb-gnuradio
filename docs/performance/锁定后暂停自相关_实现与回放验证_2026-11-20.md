## 1. 改动摘要

新增 `--autocorr-when-locked scan|suspend|auto`（默认 `scan`）与
`--autocorr-resume-lookback N`。`suspend`（或 `auto` 且 `--interference off`）
在 `lock.scheduled()`（Verify/Locked/Holdover）期间跳过 `acq.scan`；失锁后
`acq.reset(max(0, valid_begin, end - lookback))` 再继续扫描。`suspend` 与
`--interference on` 组合在打开设备前报错退出（fail-closed）。

## 2. 门控语义（冻结接口）

```cpp
struct AutocorrGate {
    bool enabled=false, suspended=false;
    uint64_t suspend_events=0, resume_events=0;
    uint64_t suspended_samples=0, resume_backlog_samples=0;
    struct Action { bool scan=false, reset=false; int64_t reset_at=0; };
    Action update(bool scheduled, int64_t end, int64_t valid_begin,
                  int64_t lookback, size_t n);
};
```

- `!enabled`：始终 `{scan=true, reset=false}`，不触碰 `acq`。
- `enabled && scheduled`：首次进入 `++suspend_events`；`suspended_samples += n`；
  本块不扫描。
- `enabled && !scheduled && suspended`：`++resume_events`；
  `reset_at = max(0, valid_begin, end - max(0, lookback))`；
  `resume_backlog_samples += end - reset_at`；本块恢复扫描。
- `lookback` 默认 `acq_span + window = 192000 + 450000 = 642000` 原生样点
  （约 0.87 ms）；`0` 表示从当前 `end` 开始。`end` 为非负绝对样点号，
  `LLONG_MAX` 也不会下溢；`reset_at` 额外下限 0，避免把负 probe 传给
  `Acquisition::scan` 的 `size_t` 转换。
- RX gap 原有 `acq.reset(end)`、`valid_begin=end`、
  `lock.note_time_discontinuity()` 不变；gap 后门控在同一块自然恢复，
  `reset_at` 被 `valid_begin` 截断，不会跨 gap 回看。
- `submit_ready_acquire_window` 仍每块调用；失锁前留下的 `pending_seed`
  不会被新逻辑丢弃。

`--autocorr-when-locked` 的解析与 `Suspend+interference` 校验在创建
source/设备之前完成，错误返回码 2。`START` 行输出解析后的
`autocorr_when_locked=scan|suspend`；`LOCK_STATS` 末尾新增
`autocorr_suspend_events / autocorr_resume_events /
autocorr_suspended_samples / autocorr_resume_backlog_samples`，既有字段
顺序与含义不变。`-1` 仅作为 CLI 默认哨兵（等于 `acq_span+window`），help
与错误信息已明确；其余负值在 CLI 层拒绝。

## 4. `scan` 路径与基线一致性

夹具：`/tmp/opencode/uwb-live-1ms/dw3000_1ms_1s.sc16`（1 ms 周期，1.000 s，
SHA-256 `66b2a0d5…bfb4`）。基线二进制由改动前工作树单独构建于
`/tmp/opencode/baseline/gr-uwb/build-native-only`。

对照参数：`--period-ms 1 --tone off --workers 1 --print packets
--sync locked --interference off --fused on --cir full --taps eq16`。

**比较口径**：包按 `time_ms` 对齐。启动边界偶尔会多/少一个 acquire 窗口，
导致包 `id` 整体平移，因此 `id` 不是稳定键。判决字段为
`status/path/SFD/PHR/FCS/CRC/PSDU`；`start` 是检测原点，CFO/相关度量是
派生浮点值。

| 对照 | 包数 | 判决字段差异 | `start` 差异 | `FINAL` |
| --- | ---: | ---: | ---: | --- |
| 基线 vs 基线（第 1 组） | 998 / 998 | 0 | 0 | 相等 |
| 基线 vs 基线（第 2 组） | 998 / 999 | 0 | 1 个包 ±1 | 第二组多 1 个 acquire 包 |
| 基线 vs 新 `scan` | 999 / 999 | 0 | 20 个包 ±1 | 相等 |
| 新 `scan` vs 新 `scan` | 998 / 999 | 0 | 1 个包 ±1 | 第二组多 1 个 acquire 包 |

结论：

- 四组对照的**解码判决字段全部一致**（0 差异），包括 999/999 的
  status/FCS/PSDU。
- 998 vs 999 的差异是启动边界多一个 `path=acquire` 窗口；同样的差异在
  **同一基线二进制自对照**中出现，属于线程/启动时序噪声。
- `start` ±1 与派生 CFO/度量差异跟随该次运行的 `period_ppm`（基线一次
  运行出现 −0.8337 ppm，其余为 −0.7939 ppm），不是门控引入的判决变化。
- 新 `scan` 的四个门控计数均为 0，`START` 仅新增
  `autocorr_when_locked=scan`。

因此 `scan` 路径没有引入解码判决差异；严格逐字节一致不可达，原因是现有
live 反馈环本身不是逐位可复现的（同参数两次基线运行也会差 1 个包）。

## 5. ABBA 回放性能（`scan` vs `suspend`）

串行 ABBA，4 配对（8 次运行），每次 1.000 s 回放：

```sh
python3 tools/rx/autocorr_suspend_ab.py \
  --replay /tmp/opencode/uwb-live-1ms/dw3000_1ms_1s.sc16 \
  --period-ms 1 --workers 2 --queue 24 --rounds 4 \
  --out docs/performance/data_autocorr_suspend_20261120/abba.json
```

共同参数：`--sync locked --interference off --fused on --cir full --taps eq16`
（`--tone` 保持默认 on，符合 live 默认配置）。

| 轮 | 臂 | `frontend_scan_us` | `acq_seeds` | `fcs_ok` | `expected_slots` | gaps/drop |
| ---: | --- | ---: | ---: | ---: | ---: | --- |
| 1 | scan | 126,019.3 | 1002 | 997 | 993 | 0/0 |
| 2 | suspend | 1,643.4 | 6 | 996 | 993 | 0/0 |
| 3 | suspend | 2,237.8 | 8 | 997 | 992 | 0/0 |
| 4 | scan | 126,656.5 | 1002 | 997 | 993 | 0/0 |
| 5 | scan | 124,687.4 | 1002 | 996 | 993 | 0/0 |
| 6 | suspend | 1,783.0 | 6 | 996 | 993 | 0/0 |
| 7 | suspend | 1,842.9 | 6 | 996 | 993 | 0/0 |
| 8 | scan | 124,528.8 | 1002 | 996 | 993 | 0/0 |

配对结果（`suspend - scan`，4 对）：

| 指标 | scan 均值 | suspend 均值 | 配对中位数 | 变化 |
| --- | ---: | ---: | ---: | ---: |
| `frontend_scan_us` | 125,473.0 | 1,876.8 | −123,640.2 | **−98.5%** |
| `acq_seeds` | 1002 | 6.5 | −996 | −99.4% |
| `autocorr_suspend_events` | 0 | 1 | +1 | — |
| `autocorr_suspended_samples` | 0 | 732,725,248 | +732,954,624 | — |
| `fcs_failed` / `identity_rejects` / `lock_entries` | 2/2/1 | 2/2/1 | 0 | 每轮一致 |
| `dropped_queue` / `expired` | 0/0 | 0/0 | 0 | — |

8 次运行全部 `gaps=0`、`raw_drop_samples=0`、`source_errors=0`。
`scan_us_per_sample` 从 1.70e-4 降到约 3e-6 µs/样点。

**目标计数差异的逐包解释**：ABBA 中第 1 配对
`fcs_ok` scan=997 / suspend=996（`expected_slots` 都为 993），其余 3 对
相同。第 3 轮 suspend 的 `expected_slots=992`（比 scan 少 1 个启动槽）在
逐包专项中未复现，只按同一启动边界机制归因，未单独逐包证明。
为定位 `fcs_ok` ±1，另做了 4 组 `--print packets` 的 scan/suspend 配对
（993 个目标槽）：**每个目标槽的 status/PSDU 完全一致**；`fcs_ok` 的 ±1 差异只出现在
进锁前 `path=acquire` 的 5.577 ms 包（scan 4 次为 997/996/996/996，
suspend 为 996/997/997/997）。因此它不是 `suspend` 的目标解码退化，而是
启动时 acquire/进锁边界的一个额外候选观测；`fcs_failed`、身份拒绝和锁定
事件在各轮完全一致。

口径说明：`LOCK_STATS.fcs_ok` 统计所有通过身份校验的观测，包含
acquire/候选路径，不等于目标槽 PRR；目标槽成功应取 `path=target` 的
`PACKET` 行。`FINAL fcs` 也包含 acquire/候选窗口。`suspend` 下
`autocorr_ignored` 降为 0 是口径变化（锁定期不再产生 seed），不代表误报
消失。

## 6. 失锁恢复专项（合成目标停发）

夹具：`/tmp/opencode/uwb-live-1ms/dw3000_1ms_gap50ms.sc16`
（0.40 s 原采集 + 0.05 s 数字静默 + 0.45 s 起 0.35 s；1 ms 周期相位保持；
SHA-256 `242c459a…e2646`）。这是连续样本线上的“目标停发”，**不是设备
`RX_GAP`**。

最终 7 次运行（热页缓存，`--print packets`，2 worker）：

| 运行 | `expected_slots` | `fcs_ok` | 首个 target | `resume_events` | `resume_backlog_samples` |
| --- | ---: | ---: | ---: | ---: | ---: |
| `scan` ×2 | 749 | 747 | 4.577 ms | 0 | 0 |
| `suspend` 默认 lookback ×3 | 749 | 747 | 4.577 ms | 1 | 642,000 |
| `suspend` lookback=0 | 749 | 747 | 4.577 ms | 1 | 0 |
| `suspend` lookback=200000 | 749 | 747 | 4.577 ms | 1 | 200,000 |

所有 7 次运行的 `lock_entries=2`、`holdover_entries=1`、
`reacquire_entries=1`、`not_detected=8`；逐包按 `time_ms` 对齐后，
**相对 `scan` 的目标判决字段 0 差异**（无缺包/多包）。恢复段时间线完全
一致：

```text
449.742 ms  acquire 候选（TIMING_FAILED）
450.577 ms  acquire OK
451.577 ms  acquire OK
453.577 ms  起 target OK（新的 gen）
```

默认 lookback 与 `0` 只改变 `resume_backlog_samples`（642,000 / 0），
**重新锁定时刻相同**；`lookback=200000` 同样相同。默认值 642,000 样点
（约 0.87 ms）被 `valid_begin` 正常截断，没有跨停发段回看。

早期冷页缓存运行时曾出现首个 target 从 4.577 ms 变为 5.577 ms、
`expected_slots=748`、`fcs_ok=746`；该现象在 `lookback=0` 也出现过，
热缓存下 7 次运行均未复现，因此判定为**启动进锁边界的时序噪声**，不是
恢复回看造成的目标槽丢失。报告保留该记录以免掩盖运行间波动。

## 7. 已知限制与未验证项

1. **未上板**：没有 X410 live 的 `scan`/`suspend` 对照，没有真实
   `RX_GAP`、overflow、paced/8 worker、负载 P99 数据。
2. **短暂 Verify 抖动未验证**：若一次跟踪状态持续时间小于 lookback
   （默认约 0.87 ms），恢复时 `reset_at` 可能落在暂停前已扫描的 probe
   之前，从而重复扫描旧样本、可能重复提交一个 acquire 窗口并清空
   holdoff。正常 Locked→Holdover→Reacquire 至少为 holdover+reacquire
   （本夹具 11 个槽）远大于 lookback，未触发；本轮未构造更短的抖动夹具。
   在把默认改为 `auto` 前应先加重复 seed/提交计数并专门测试该边界。
3. 失锁恢复使用**合成静默**夹具，不是设备 gap，也不是真实目标停发；
   未测量恢复后首个 seed 的样点级延迟，也未单独记录恢复块的逐块
   `frontend_scan_us` 峰值（现有输出只有全程累计；增加逐块峰值超出本轮
   输出契约）。本轮以累计 `frontend_scan_us`、0 gap/0 丢样和 7 次一致性
   运行作为替代证据。
4. `--interference on` 行为按要求未改；只用 `scan` 一致性、`auto+on`
   解析与 0.25 s 冒烟证明未受影响，未做完整干扰监测回放/上板对照。
5. 未做 MATLAB 交叉验证：本任务只增加门控状态机，不改检测/解调算法，
   MATLAB `detectRepeatedPreamble` 等交叉验证不适用。
6. 未覆盖 `--mode timed`（本就不跑自相关；门控计数恒 0）、TWR、SIC。
7. 27 ppm / CFO/SFO、低 SNR、多径等场景不在本轮范围。

## 8. 结论与建议

- `scan` 默认路径：4 组逐包对照的**解码判决字段全部一致**；差异仅来自
  现有 live 反馈环的启动/浮点抖动（同二进制自对照同样出现）。
- `suspend` 在 1 ms 连续回放中把 `frontend_scan_us` 降低 **98.5%**
  （125.5 ms → 1.88 ms / 1 s），`acq_seeds` 1002→6.5；8 次运行
  0 gap、0 丢样，`fcs_failed`/身份拒绝/锁定事件每轮一致。
- 目标槽差异逐包定位到**启动 acquire 边界的一个额外观测**，不是目标
  解码退化；4 组 packet 级配对中 993 个目标槽判决完全相同。
- 合成停发 50 ms：默认 lookback 与 `0`/`200000` 的重新锁定时刻相同，
  7 次运行目标判决与 `scan` 一致。
- 建议：本轮保持默认 `scan`。在完成上板 `scan`/`suspend` 对照（含真实
  `RX_GAP`/overflow、`--interference on` 回归）并补测短暂 Verify 抖动后，
  再单独提交把默认改为 `auto`。当前证据支持“无干扰、长锁定段回放可
  暂停”，不足以把 `suspend` 描述为全场景已验证。
