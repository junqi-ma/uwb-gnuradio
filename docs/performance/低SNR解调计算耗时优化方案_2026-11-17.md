# 低 SNR 解调计算耗时优化可执行方案（含 Subagent 调度，2026-11-17）

> **前置背景**：在完成 Wave 1–3 低 SNR 捕获/Timing/CFO/SFD 优化及两步 Payload 软判决升级（精确 Max-Log `llr1` + 失败路径 CL-3 Trellis-Merge Chase & `RS(63,55)` 错误-擦除译码）后，`-12 dB` 完整帧（127 B / 6.81 Mb/s，1 ms 周期，4 worker）锁定态解调率已达 **`191/200`（有效包 `191/199 = 96.0%`，`dropped_queue = 0`）**。
>
> **当前痛点**：低 SNR 下单包计算耗时显著上升（`w1 locked` 下 `demod_mean` 从 `+4 dB` 的 `1014.5 µs` 升至 `-12 dB` 的 **`2881.3 µs`**；`w4 locked` 下 `compute_mean` 达 **`4372–4385 µs`**，已紧贴 1 ms 周期 × 4 worker 的 `4000 µs` 实时稳态红线；`acquire` 模式下更高达 `6543.7 µs` 并触发队列丢包）。
>
> **优化目标**：在不损失任何 SNR 档位解调率（PRR）与零虚警性质的前提下，消除 `stage_timing`、`stage_sfd`、`decode_payload_soft` 低 SNR 兜底路径中的**冗余探测与标量重复计算**，将 `-12 dB`：
> - `w1 locked`（`--workers 1 --queue 256`）的 `demod_mean` 从 `2881 µs` 压至 **`<= 1600 µs`**（降幅 `>= 44%`）；
> - `w4 locked`（`--workers 4 --queue 24`）的 `compute_mean` 从 `4372 µs` 压至 **`<= 3300 µs`**，稳居 `4000 µs` 实时线以下；
> - `-10 / -12 dB acquire` 的 `compute_mean` 降低 `>= 1500 µs`，大幅减少离线全速回放时的 `DROPPED_QUEUE`。

3. **`stage_sfd` 离散网格兜底用标量重复算了 8 遍符号相关，且前置空跑 8 个窄窗**：

## 2. 具体优化技术规格（4 项任务）

### Task 1：`fold_acquire` 有效窗裁剪 + `try_fold_acquire` 内部去重与 8-lag 向量化
**文件**：`gr-uwb/include/gnuradio/uwb/uwb_demod_core.h`

1. **`fold_acquire`（约 L258–354）窗口直接夹紧到 `centre ± P/2`**：
   - `fold_acquire` 只在 `[lo_lag, hi_lag]`（即 `[centre - P/2, centre + P/2]`）内取 argmax，外部折叠与相关纯属无效计算（外层 `try_fold_acquire` 的前导沿消歧使用的是原始 `rx` 缓冲与外层 `radius`，不依赖 `folded` 的窗宽）。
   - 将 `w0`、`w1` 改为：
     ```cpp
     const int64_t half_period = P / 2;
     int64_t w0 = std::max<int64_t>(0, std::max<int64_t>(w0_in, centre - half_period));
     int64_t w1 = std::min<int64_t>(std::min<int64_t>(w1_in, centre + half_period),
                                    static_cast<int64_t>(n) - Li);
     ```
   - 保持后续 `room`、`k_eff`、`w1 = std::min(w1, n - Li - (k_eff - 1) * P)` 逻辑不变；此时 `lo_lag` 为 `0`、`hi_lag` 为 `span`。
   - **数学等价性**：对于所有原本落在 `[centre - P/2, centre + P/2]` 内的有效 lag，折叠向量 `folded`、滑窗功率 `pw`、相关值 `acc` 与原实现**逐位一致**；在 `AcquireLegacy`（`radius = 8192`）下折叠样本数减至 1/8.5，相关次数从 `16,385` 减至 `1,017`（**减少 93.8%**）。

2. **`try_fold_acquire` 前导沿消歧去重与 `window_power` 替换（约 L893–940）**：
   - 将 `ss_metric` 内部标量循环 `for (size_t k = 0; k < L; ++k) pw += std::norm(...)` 替换为 `const float pw = window_power(rx + pos, L);`。
   - 对 `j ∈ [-max_j, +max_j]`（共 `2 * max_j + 1` 个候选点），在第一个循环算完 `ss_metric(fold.start + j * P)` 后存入小数组/向量 `cand_metrics[j + max_j]`，第二个循环直接查表比较 `here >= edge_thr`，消除完整第二遍 `ss_metric` 调用（省去一半单符号相关）。

3. **`fold_anchor_fit` 17-lag 精修改用 `real_template_dot_8lag`（约 L415–435）**：
   - 当前对 `lag = 0 .. 2*refine`（`refine = 8`，共 17 个 lag）逐点调用 `real_template_dot_single`。
   - 当 `use_real` 为真时，改用与 `fold_acquire` 相同的 `8-lag` 批处理循环：
     ```cpp
     int64_t lag = 0;
     if (use_real) {
         for (; lag + 7 <= 2 * refine; lag += 8) {
             std::complex<float> acc8[8];
             rxopt::real_template_dot_8lag(sup.data() + lag, taps_dup, L, acc8);
             for (int m = 0; m < 8; ++m) {
                 const int64_t cur = lag + m;
                 const float met = std::norm(acc8[m]) / (pw * Et + 1e-12f);
                 if (met > bm) {
                     bm = met;
                     bl = cur;
                     bacc = acc8[m];
                 }
                 if (cur < 2 * refine)
                     pw += std::norm(sup[cur + Li]) - std::norm(sup[cur]);
             }
         }
     }
     for (; lag <= 2 * refine; ++lag) {
         // 原单点尾处理
     }
     ```

### Task 3：`stage_sfd` 离散整数符号网格 80 符号 SIMD 预计算 + 低 SNR 窄窗早停
**文件**：`gr-uwb/include/gnuradio/uwb/uwb_demod_core.h`（约 L2280–2380）

1. **低 SNR 下跳过必败的 `k = ±1..±4` 偏移窄窗（约 L2280–2288）**：
   - `bool sfd_passed = scan_window(expected, kSfdNarrowHalf, 0);` 执行后，`best` 保存了 `k=0` 窄窗（`expected ± 64`）的最大度量。
   - 若 `!sfd_passed && timing.detected_peaks == profile.preamble_repetitions && timing.metric < thr && best < 0.015f`（即低 SNR 下 `k=0` 窄窗连 `scan_window` 最低门槛 `0.02f` 的 75% 都不到），跳过 `k = 1..kSfdSymbolOffsets` 的 8 个窄窗（省掉 `8 × 129 = 1,032` 个 lag 的 SFD 折叠相关），直接进入下方离散网格兜底。

2. **离散网格兜底改用单符号 SIMD 预计算 + 8 符号线性组合（约 L2307–2375）**：
   - 格点坐标为 `pos_k = expected + k * period`（`k ∈ [-kGridHalf, +kGridHalf]`，`kGridHalf = 36`，共 73 个格点）。
   - 当 `period == static_cast<int64_t>(sym)`（标准 `1016` 周期；若 `period != sym` 则回退原 `sfd_metric_at` 即可）时：
     - 格点 `k` 的 SFD 窗口覆盖符号 `k, k+1, ..., k + len - 1`（`4z2` 下 `len = 8`）。
     - 只需对符号下标 `m ∈ [-kGridHalf, +kGridHalf + static_cast<int64_t>(len) - 1]`（共 `2 * 36 + 8 = 80` 个符号位置），预计算每个符号 `spos = expected + m * static_cast<int64_t>(sym)` 的：
       - 单符号功率：`sym_pwr[m] = window_power(rx + spos, sym)`；
       - 单符号相关：`sym_corr[m] = use_real_sfd_fast ? rxopt::real_template_dot_single(rx + spos, taps_dup, sym) : detail::timing_conjugate_dot(rx + spos, template_wf.data(), sym)`；
       - （越界的 `spos` 记 `sym_valid[m] = false`）。
     - 随后对每个格点 `k ∈ [-36, +36]`，若其连续 `len` 个符号均有效，直接用 **8 次复数加减与 8 次浮点加法**合成整段 SFD 相关与功率：
       ```cpp
       float pwr = 0.0f;
       std::complex<float> acc_unscaled(0.0f, 0.0f);
       for (size_t s = 0; s < len; ++s) {
           const size_t idx = static_cast<size_t>(k + kGridHalf) + s;
           pwr += sym_pwr[idx];
           acc_unscaled += static_cast<float>(sfd_sequence[s]) * sym_corr[idx];
       }
       const std::complex<float> acc = acc_unscaled * sfd_scale;
       const float metric = std::norm(acc) / (pwr + 1e-12f);
       ```
     - 找到最优格点 `gpos` 后，对其周围微调偏移（当跳过了 `k=1..4` 窄窗时精修 `d ∈ [-4, +4]`，否则精修 `d ∈ [-1, +1]`，跳过 `d == 0`）评估 `sfd_metric_at(gpos + d)`。
     - 同时优化 `sfd_metric_at(pos)` 自身：用 `window_power(rx + pos, sfd_len)` 求功率，且当 `use_real_sfd_fast` 为真时，分 `len` 个符号调 `real_template_dot_single` 按 `sfd_sequence[s]` 加权求和（替代标量 8128 点 `sfd_dot`）。
   - **复杂度对比**：从 `75 × 8128 = 609,600` 次**标量**复数乘加，降为 `80 × 1016 = 81,280` 次 **AVX2/AVX-512 SIMD** 实模板内积（计算量减至 **1/7.5** 且全程 SIMD，预计将离散网格耗时从 `~350 µs` 压至 **`< 25 µs`**）。

### Task 4：`decode_payload_soft` 与 `rescue_payload_soft` 合并首遍 Viterbi 并优先跑 RS 擦除
**文件**：`gr-uwb/include/gnuradio/uwb/uwb_demod_core.h`（约 L3900–4160）

1. **消除重复的全长软 Viterbi**：
   - 在 `decode_payload_soft` 中，直接调用 `vitdec_cl3_soft_trace(llr0j.data(), llr1j.data(), total, tr)`（代替先调 `vitdec_cl3_soft` 再在 `rescue_payload_soft` 内重调 `vitdec_cl3_soft_trace`）。
   - 从 `tr.bits` 切片 `rs_cw(tr.bits.begin() + 19, tr.bits.begin() + (total - 2))`，调用 `finish_rs_crc_payload(rs_cw, psdu_bits, out, sub)`；若返回 `true && out.fcs_pass`，直接返回 `true`。
   - 否则将已算好的 `const Cl3TrellisTrace& tr` 传给 `rescue_payload_soft(llr0j.data(), llr1j.data(), total, psdu_bits, tr, rescued, sub)`，省去整整一遍 1229 步 Viterbi 前向回溯。

2. **失败 RS 块先试 3 次 `rs_decode_block_erasures`（`v = 2, 4, 6`），未过 CRC 再试局部 Trellis 翻转**：
   - 在 `rescue_payload_soft` 中：
     - **第一阶段（零 Viterbi 开销）**：对每个 `rs_decode_block` 失败的块 `b`，先根据该块 63 个 RS 符号的最小 `|LLR|` 选出最弱的 6 个符号，依次尝试 `v = 2, 4, 6` 的 `rs_decode_block_erasures`（最多 3 次 RS 擦除译码，耗时仅几微秒）。
     - 若第一阶段后所有块 `b` 的 `bc[b].cands` 均非空，立即执行一次组合打包与 `crc16_802154` 校验：若 `fcs_pass` 为真，**直接填好 `out` 返回 `true`**，完全跳过后续 `6 + 15 = 21` 次 `local_cl3_trellis_flip`！
     - **第二阶段（按需 Trellis Chase）**：仅当第一阶段后仍有块的 `cands` 为空，或第一阶段候选组合未通过 CRC 时，才对这些块运行 `weak` 合并点排序、6 次单翻转与 15 次双翻转 `local_cl3_trellis_flip`（且一旦任一翻转通过 `rs_decode_block` 产出了新候选，最后再统一跑组合 CRC 校验）。
