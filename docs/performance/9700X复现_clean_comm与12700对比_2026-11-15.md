# 9700X 复现 clean comm 测试及 12700 对比（2026-11-15）

## 结论

按用户给定命令复现后，9700X 的 clean comm 计算耗时低于 12700 归档记录。+50 kHz、1/2/4 worker 下单包均值约 2.206 / 2.275 / 2.554 ms，完成间隔约 2.207 / 1.140 / 0.640 ms。全部 18 轮 × 512 = 9216 任务 FCS 与 PSDU 逐字节通过、零回退。此前实时脚本的 7–8 ms 不能作为这套负载的 CPU 性能对比依据。

## 复现配置

先以 `git pull --ff-only` 拉取至 `a8f0016`；本机没有旧的 `build-sc16-r1r2`，以 Release、DOXYGEN OFF 新建独立构建目录。没有改生产代码或测试源代码，未覆盖 12700 历史数据。

```sh
cmake -S gr-uwb -B gr-uwb/build-sc16-r1r2 -DCMAKE_BUILD_TYPE=Release -DENABLE_DOXYGEN=OFF
env -u LD_LIBRARY_PATH cmake --build gr-uwb/build-sc16-r1r2 --target experiment_preamble_recovery benchmark_chain_workers -j16
python3 tools/sic/run_clean_comm_workers.py --out /tmp/uwb-clean-comm-9700x-20261115-r1 --measure 512 --warmup 128 --reps 3 --workers 1 2 4 --cfo-hz 50000 0
```

clean code9 / 256 SYNC / 127 B PSDU 含 FCS / 4z2，16 组 PSDU/起点、331331 原生样点、737.28→998.4 MS/s、quality_minorder、融合 PHR/payload、Fast SFD/CFO 与按需 soft-chip。无干扰、噪声、SIC、sensing。三轮 worker 与 CFO 顺序按原脚本交替；同一个基准锁串行执行。每 worker 预热128任务、每次测量512任务。

沿用原脚本 CPU4/6/8/10 和协调CPU0。本机 worker 分别位于不同物理 core4/6/0/2；协调线程CPU0和worker CPU8是SMT兄弟。12700归档为20逻辑CPU虚拟机拓扑，两机物理映射不同，未人为改绑核以维持命令一致。

计时仍是 `resample_us = reset + process_sc16 + flush`，总任务包含重采样和完整通信解码，排除 RX、队列、提交。没有启用 FixedToneCancelSc16Source，不把连续消除或其折算估计加进本次实测。

## 一致性、归档与比较边界

- 两机 `fixture.json` 完全相同，包括16组源IQ hash、两组SC16 mixture hash、PSDU、ADC尺度、窗口几何。9216任务全部FCS/PSDU通过，三类回退计数全部为0；逐文件 CFO 误差和 SFD 坐标保存在 `comparison.json`。
- Python 驱动与生成器 C++ 源码 hash 相同。但历史 provenance 中 `benchmark_chain_workers.cc` 为 `081d9de0…`，当前提交为 `ad4f7b09…`；用户确认没有在测后修改。当前无法解释该归档校验不一致，不能声称所有基准源码字节完全一致。排查普通CRLF/BOM/末尾换行不能复现历史hash。
- 此外两机环境不同：9700X 为16逻辑CPU本机环境，12700历史记录为20逻辑CPU虚拟机拓扑；本机 VOLK 3.3，历史为2.5，GNU Radio及编译环境也不同。结论是本次机器/软件环境对归档结果的复现比较，不是隔离全部因素的CPU架构测试。
- 本次按当前已提交源码构建成功，基准的全部功能检查通过。未重跑全量CTest，未上板，未测单音消除、paced、PER、8 worker或连续流吞吐验收。
