# X410 接收信噪比与链路余量测量（2026-11-16）

测量对象是 DW3000 → X410 的实际空口链路，当前设置：**发送端衰减 10 dB、距离
1.5 m**。数据来自 2026-11-15 晚采集的三份 1 秒 SC16（5 ms / 2 ms / 1 ms 周期），
测量方法与解调器无关，全部从原始样点统计得出。

原始输出在 `docs/performance/data_rx_snr_20261116/`，测量工具是
`tools/rx/measure_rx_snr.py`。

---

## 1. 结论摘要

1. **带内 SNR = +13.7 dB**（信号功率 / 热噪声功率，都在 ±250 MHz 信道 5 带宽内）。
   5 ms、2 ms、1 ms 三次采集分别是 **+13.62 / +13.70 / +13.71 dB**，完全一致 ——
   **把周期从 5 ms 缩到 1 ms 没有损失任何链路预算**。
2. **热噪声底 = −47.5 dBFS**（rms 139 LSB，全 737.28 MHz），比 16 bit 量化底高
   48 dB。ADC 峰值 −17.5 dBFS、**0 个样点削顶**，还有 ~17 dB 余量。**再加接收增益
   不会提高 SNR**（噪声和信号同比例上升），当前增益是合适的。
3. **−232.96 MHz 的 CW 单音比整个热噪声底还高 12–13 dB**，功率和信号本身同量级
   （rms 576–640 LSB vs 信号 541 LSB）。不消单音，带内 SNR 掉到 **−1 dB**。
4. **单音消除不是可选优化**：同一份 1 ms 回放，`--tone on` 是 **99.5% FCS**，
   `--tone off` 掉到 **33%**。机制不只是 SNR —— 单音在采集器的 `lag=750` 处
   **恰好整周期相干**（−91/288 × 750 = −237 个周期），归一化延迟自相关被它持续
   触发，候选数从 989 涨到 **1239**（被 0.8 ms holdoff 限速，等于一直在触发），
   工作队列被打满（`dropped_queue=490`），真包大量被丢。
5. **链路余量约 +10 dB**：等效再衰减 10 dB 时 FCS 仍是 99.5%，14 dB 掉到 93.2%，
   **18 dB 时采集彻底失效**（`candidates=0`，一个包都没锁上）。瓶颈是**采集门限**，
   不是解码器 —— 解码器在 0 dB 带内 SNR 下还能过 93%。

## 3. 测量方法

不使用解调器的任何指标（`tmetric`、`cirmetric` 都是归一化相关，不能直接换算
SNR）。全部从 SC16 原始样点统计：

1. **定位包**：按周期把 1 秒数据切成 5 µs 块，对 200 个周期做块功率平均，得到
   占空比曲线。高功率段是包，低功率段是包间噪声。包在部分采集里跨周期边界，
   所以噪声窗按**环绕**取最长连续低功率段。
2. **热噪声底**：对噪声窗做 Welch PSD（16k 点），取**中位数**。用中位数而不是
   均值，是为了排除单音和 WiFi 突发。
3. **信号**：包区 PSD − 噪声区 PSD，在 ±250 MHz 内积分。单音在时域先按
   `exp(-j2π·(-91/288)·n)` 拟合后减掉，积分时再挖掉 ±3 MHz，避免拟合残差污染。
4. **带内 SNR** = 信号功率 /（热噪声 PSD × 带宽）。

三个口径必须分开看，混用会得出互相矛盾的结论：

| 口径 | 含义 | 本次数值 |
| :--- | :--- | ---: |
| **带内 SNR（±250 MHz）** | 信号功率 / 同带宽热噪声。**这是链路预算该用的数** | **+13.7 dB** |
| 全带宽 SNR（737.28 MHz） | 信号功率 / 整个 Nyquist 带内的全部噪声 | −0.8…−1.6 dB |
| 不消单音 | 信号 /（热噪声 + 单音） | −0.7…−1.5 dB |

全带宽口径偏低有两个原因，都不代表链路差：接收带宽（737 MHz）比信号带宽
（约 500 MHz）宽，多出来的噪声白算；而且单音落在带内。

## 4. 结果

### 4.1 带内 SNR

| 项 | 5 ms | 2 ms | 1 ms |
| :--- | ---: | ---: | ---: |
| 包长 | 440.0 µs | 445.0 µs | 445.0 µs |
| 信号（±250 MHz） | 54.7 dB / rms 541 | 54.7 dB / rms 542 | 54.7 dB / rms 544 |
| 热噪声（±250 MHz） | 41.0 dB | 41.0 dB | 41.0 dB |
| **带内 SNR** | **+13.62 dB** | **+13.70 dB** | **+13.71 dB** |
| 热噪声（737.28 MHz） | −47.4 dBFS / rms 139.5 | −47.5 / 138.3 | −47.5 / 138.8 |
| CW 单音 @ −232.96 MHz | rms 576 | rms 600 | rms 640 |
| 单音 vs 热噪声（737 MHz） | +12.3 dB | +12.7 dB | +13.3 dB |
| 带内 SNR（不消单音） | −0.71 dB | −1.03 dB | −1.54 dB |
| 全带宽 SNR | −0.80 dB | −1.11 dB | −1.61 dB |
| 256× SYNC 相干积累后（+24.1 dB） | +37.7 dB | +37.8 dB | +37.8 dB |

三次采集的信号功率（rms 541 / 542 / 544 LSB）和热噪声（rms 139.5 / 138.3 / 138.8）
几乎完全相同，说明**周期缩短没有改变链路**，只是改变了占空比和主机负载。

### 4.2 噪声底与 ADC 余量

| 项 | 值 |
| :--- | :--- |
| 热噪声 PSD | −45.8 dB re 1 LSB²/Hz |
| 热噪声（737.28 MHz） | rms 139 LSB = **−47.5 dBFS** |
| 16 bit 量化底 | ≈ −96 dBFS |
| 热噪声高于量化底 | **48 dB** |
| 采集峰值 | −17.8 dBFS（5 ms）/ −17.3 dBFS（1 ms） |
| 削顶样点 | **0 / 442,368,000**（5 ms）、**0 / 88,473,600**（1 ms） |

两个结论：

- **没有削顶风险**，峰值离满量程还有 ~17 dB。
- **加增益不会改善 SNR**。热噪声比量化底高 48 dB，说明限制来自射频前端/环境噪声，
  不是 ADC 位数。把增益从 60 提到 70，信号和噪声一起涨 10 dB，SNR 不变。

### 4.3 单音干扰

`−232.96 MHz`（= `−91/288 × fs`）有一个稳定 CW 单音，三次采集 rms 576 / 600 / 640 LSB，
比整个 737 MHz 带宽内的热噪声功率高 **12–13 dB**，和信号本身（541 LSB）同量级。

这就是 `FixedToneCancelSc16Source` 针对的那个单音。它不是"可选优化"，见 §5。

噪声区里还有几处宽带凸起（−178 MHz 约 9 MHz 宽、−100/−93/−88 MHz 一簇、
−58.88 MHz、+94.72 MHz），各占热噪声功率的 10–20%，看起来像 **WiFi 6E 突发**
（6.39–6.59 GHz 正在 6E 频段内）。它们对 SNR 的影响 <0.2 dB，但如果以后做远距离
或弱信号测试，这些会是先撞到的东西。

## 5. 单音消除的价值

同一份 `rx_1ms_1s.sc16`，1 ms、W=4、`--sync locked`、`--raw-blocks 512`，两轮：

| 轮次 | `--tone` | 检出包 | FCS | `candidates` | `cand_target` | `cand_unknown` | `dropped_queue` | `out_of_grid` |
| :--- | :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | **on** | 1016 | **1011/1016（99.5%）** | 989 | 973 | 16 | 0 | 0 |
| 1 | off | 1680 | 559/1680（33.3%） | **1239** | 70 | **1169** | **490** | 121 |
| 2 | **on** | 1016 | **1014/1016（99.8%）** | 988 | 972 | 16 | 0 | 0 |
| 2 | off | 1670 | 536/1670（32.1%） | **1239** | 70 | **1169** | **501** | 126 |

原始输出：`data_rx_snr_20261116/tone_on_off.txt`。

**失败机制不是"SNR 不够导致解不出来"，而是采集器被打爆**：

1. 单音在 `lag=750` 处整周期相干（`−91/288 × 750 = −237`，正好整数周期），
   归一化延迟自相关对它的响应接近 1，于是**采集器一直在触发**。
2. 采集有 589,824 样点（0.8 ms）的 holdoff，所以触发率被限在 ~1250/s ——
   实测 `candidates=1239`，正好是这个上限。真包只有 ~1000 个/s。
3. 多出来的候选进入工作队列，队列被打满：`dropped_queue=490`（期望 500 个时隙，
   丢了 490 个）。真包的窗口被假候选挤掉。
4. 结果：检出 1680 个（多 65%），但只有 70 个被识别成目标，FCS 掉到 33%。

**所以单音消除同时解决两个问题**：把带内 SNR 从 −1 dB 拉回 +13.7 dB，以及
让采集器不再被一个"完美的周期信号"持续触发。

## 6. 链路余量

### 6.1 方法

额外路损只衰减信号、不改变接收机噪声。所以往采集里叠加

```
P_add = P_thermal × (10^(X/10) − 1)
```

的高斯白噪声，就**精确等价于 X dB 额外路损**。`P_thermal = 139²`（实测热噪声，
每复样点功率）。单音和 WiFi 保持原样（它们是外部干扰，不随路损变化），接收机
照常消单音。

夹具：`rx_1ms_1s.sc16` 前 200 ms（200 个 1 ms 周期）。注入量已校验：+18 dB 档
实测噪声增量 1,198,509，预测 1,199,834（差 0.1%）。

### 6.2 结果

| 额外路损 | 带内 SNR | 检出 | FCS | `candidates` | 锁定状态 |
| ---: | ---: | ---: | ---: | ---: | :--- |
| 0 dB | +13.7 dB | 205 | 204/205（99.5%） | 189 | locked |
| 3 dB | +8.9 dB | 202 | 201/202（99.5%） | 189 | locked |
| 6 dB | +6.7 dB | 200 | 199/200（99.5%） | 189 | locked |
| **10 dB** | **+3.3 dB** | 201 | 200/201（**99.5%**） | 189 | locked |
| 14 dB | −0.5 dB | 190 | 177/190（93.2%） | **1** | locked |
| **18 dB** | **−4.4 dB** | **0** | — | **0** | **acquire** |
| 22 dB | −8.3 dB | 0 | — | 0 | acquire |

原始输出：`data_rx_snr_20261116/margin_sweep.txt`。

### 6.3 瓶颈是采集门限，不是解码器

`+18 dB` 时 `candidates=0`、`expected_slots=0`、`final_state=acquire` —— 采集
**一个候选都没提交**，所以根本没有进入解码。门限在 `uwb_dw3000_live.cc` 的
`Acquisition::scan`：

```cpp
if (metric >= .15) {                       // 起窗
    ...
    if (at-first >= 36864 && peak > .5) {  // 跨度 >= 50 us 且峰值 > 0.5 才提交
```

离线复算这个归一化自相关峰值（每档 4 个包取最大，按 live 路径先消单音）：

| 额外路损 | 0 dB | 3 dB | 6 dB | 10 dB | 14 dB | 18 dB | 22 dB |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 峰值 metric | 0.894 | 0.852 | 0.801 | 0.666 | **0.363** | **0.221** | 0.184 |
| `peak > 0.5` | 过 | 过 | 过 | 过 | 不过 | 不过 | 不过 |

`+14 dB` 那一档之所以还能工作，是因为 190 个包里**恰好有一个**过了 0.5
（`candidates=1`），锁上之后由调度器接管，不再依赖采集。**这是运气，不是余量。**

所以：

- **可用余量 ≈ +10 dB**（FCS 无损失）
- **+14 dB 是临界**（93%，且锁定靠单个包的偶然通过）
- **+18 dB 彻底失效**（采集门限）

如果按自由空间、6.5 GHz、路损 ∝ d² 粗算，+10 dB 余量约等于**距离再拉远 3.16 倍**
（1.5 m → 约 4.7 m），或**再衰减 10 dB**。这个换算是估算，没有实测支撑。

## 7. 与周期无关

三次采集的信号功率、热噪声、带内 SNR 全部一致（§4.1）。周期从 5 ms 缩到 1 ms
改变的是：

- 占空比：8.8% → 22.2% → 44.5%
- 主机负载：1 ms 下 4 worker 每核 60%（见
  [`X410_2ms周期收包解调报告_2026-11-15.md`](X410_2ms周期收包解调报告_2026-11-15.md) §9）
- 原始环需求：1 ms 必须 `--raw-blocks 512`（32 MiB）

**链路预算不变。** 所以周期继续缩短不需要重新评估 SNR，只需要重新评估主机算力。

## 8. 必须保留的限制

1. **没有功率计标定**。全部是相对量（dBFS、dB）。要 dBm 或绝对 EIRP 必须另做标定。
2. **只有 1.5 m / 10 dB 衰减这一个点**。没有距离扫描、没有衰减扫描，所以
   "10 dB 余量"是噪声注入等效出来的，不是真的把板子挪远了测的。真实环境里
   多径、天线方向图、遮挡都会让实际余量低于这个数。
3. **噪声注入模型假设噪声是白的**。实测噪声里确实有 WiFi 6E 突发和单音，
   注入只加白噪声。对"额外路损"这个场景是对的（路损不加噪声），但如果要评估
   抗干扰能力，必须另外注入真实干扰。
4. **余量实验只在 1 ms 上做**。SNR 与周期无关（§7），所以结论应当可迁移，
   但采集门限的行为没有在 5 ms / 2 ms 上复验。
5. **`+14 dB` 的 93% 不可复现为"能工作"**。它依赖 190 个包里恰好一个通过采集门限；
   换一份采集、换一个相位，可能直接 0 包。
6. **采集门限是固定绝对值**（`metric >= 0.15`、`peak > 0.5`）。这意味着灵敏度
   不随噪声自适应。要提升弱信号能力，应该改这里，而不是改解调器。
7. **未验证**：多径 / AWGN / ISR 的受控组合、CFO 扫频、SFO、MATLAB 交叉验证、
   长时间 soak 下的噪声底漂移。

```sh
cd /home/oi/Desktop/uwb-gnuradio

# 1) 带内 SNR（三份采集，各约 1-2 分钟）

  --input testdata/x410_fixed_tone_live_20261115/rx_1ms_1s.sc16 --period-ms 1

  --input testdata/x410_fixed_tone_live_20261115/rx_2ms_1s_v3.sc16 --period-ms 2

    --tone $t --summary 1000 --print summary
```
