# 256 SYNC / 127 B：单 worker sensing 与 comm 独立任务耗时拆解

## 范围和计时方法

同一个完整code9目标包、code10前导干扰，两路均256 SYNC，4z2；目标127 B PSDU
含2 B FCS（125 B数据），干扰没有PHR/payload。单径、零CFO、ISR20、SNR20。
原生输入331331点，737.28→998.4 MS/s，16个载荷/噪声/原点组成相同字节池。

本轮将两种任务独立执行，而不是在一次任务中串行运行两个消费者：

- sensing：SC16重采样 → Ipatov preamble-only SIC → sensing SFD/起点/CIR。
- comm：SC16重采样 → 相同preamble-only SIC → 完整目标包解调/PSDU/FCS。

comm指对code9目标包的完整通信解调任务，不是去解码只有前导的code10干扰。
两个任务使用同一输入与公开模板；在线模块不接收clean/干扰真值。
SIC模型仍仅在前8个SYNC上估计，外推消除256-SYNC+SFD前导；接收端CIR配置246次。

每profile、每任务运行三轮，每轮预热32次、测512窗，共1536个观测。CPU4单worker，
协调线程CPU0，独占benchmark锁。没有RX、硬件等待、队列或commit；预分配与模板
生成在冷路径。表中均值使用三轮全部逐窗观测等权汇总，P50/P95也直接从整体时间
计算，是描述统计；不相加各阶段P50。

另设sensing_detail诊断模式，将生产radar_cir_one的成功路径按同样的生产原语
拆开计时：search_sfd、refine_sync_origin、estimate_radar_cir。每轮预热前16个
输入逐例对照原生产入口，检查状态、SFD/起点/峰/幅度/有效重复数及完整raw/norm
tap向量完全一致。默认quality的诊断轮总均值4.667 ms，普通入口4.675 ms，差
-0.18%；四profile的该差异为-2.11…+3.89%，包含环境/代码上下文变化，不解释
成精确插桩开销。

|---|---:|---:|

| preamble-only SIC | 1.729 | 1.726 |
| sensing接收阶段 | 1.237 | 未执行 |
| 完整comm解调/FCS | 未执行 | 1.214 |
| **任务整体均值** | **4.675** | **4.627** |
| 整体P50 | 4.555 | 4.543 |
| 整体P95 | 5.535 | 5.438 |

公共前端（重采样+SIC）各占约74%，下游消费者约26%。同一窗口联合执行两个
消费者时，公共前端只计算一次；两个独立任务总耗时相加约9.30 ms会重复计算
前端，不能当作共享前端联合链路的总耗时。上一轮联合链路约5.98 ms具有不同
执行上下文，不把跨轮相减当作某一消费者的直接计时。

## 公共前端：重采样

默认quality的sensing_detail诊断中，重采样均值1714.02 µs，细分为：

| 操作 | 均值µs |
|---|---:|
| reset | 0.22 |
| process_sc16（转换、调度、多相FIR融合） | 1712.72 |
| flush及收尾长度检查 | 1.07 |

转换已经融合到process_sc16，不能把“没有独立convert_us”解释成没有转换指令。
整包重采样是真正的主要计算成本；reset/flush相对很小。

## 公共前端：preamble-only SIC

默认quality，两种独立任务的SIC均值分摊，单位µs：

| SIC阶段 | sensing任务 | comm任务 |
|---|---:|---:|
| 前8 SYNC的检测/CFO/CIR/拟合检查 | 198.49 | 202.40 |
| 干扰前导接收与SFD确认（止于SFD） | 460.16 | 456.50 |
| 信道作用后的干扰波形重构 | 267.16 | 271.92 |
| ROI相减及区域外输出拷贝 | 213.94 | 208.09 |
| 其余SIC包装/校验/统计等未细分范围 | 589.55 | 586.66 |
| **SIC整体** | **1729.30** | **1725.58** |

前导接收是为了确认**干扰**的256-SYNC与SFD，不解码其PHR/payload；comm任务
最后的1.214 ms是另一轮对**目标包**的完整解调，两个调用不能混为一谈。

以sensing任务的SIC为例，下面各表都是父计时的子项，不能重复相加到总耗时。

估计198.49 µs：

| 子项 | 均值µs |
|---|---:|
| 粗/细检测 | 13.63 |
| CFO估计 | 1.72 |
| Ipatov相关CIR | 45.41 |
| LS求解 | 0（此路径不使用LS） |
| 训练拟合检查 | 33.59 |
| 估计阶段其余校验、局部能量等 | 104.14 |

干扰前导接收460.16 µs：同步检测/跟踪398.32、CFO阶段18.23、SFD阶段41.55、
其余约2.06。SFD阶段还含tail重跟踪/CFO复估，沿用原有字段语义。

重构267.16 µs：单位模板尺度检查0.10、稀疏卷积120.98、相位准备/旋转3.65，
其余142.43。后者包含重构缓冲清零、边界/包装等范围，不能全部当成乘加内核。
前缀脉冲事件在prepare阶段缓存，热路径没有逐包重新生成完整前缀。

SIC未细分的约590 µs是真实测得的父子计时余项，不能冒称已全部归因。源代码
明确包含：稀疏apply入口的整窗输入有限性扫描、事务/模型/事件校验，以及相减后
用于suppression统计的ROI能量扫描；本轮没有分别给这些函数增加独立计时。
估计阶段另有可见输入有限性检查，因此数据安全扫描也不是“前8符号数学估计”
的一部分。此结果支持继续定位这些整窗工作，不支持直接宣布这590 µs都能删除。

## sensing接收阶段

默认quality、sensing_detail诊断均值1228.61 µs；普通入口为1236.89 µs：

| 子阶段 | 均值µs | 诊断父阶段占比 |
|---|---:|---:|
| SFD搜索与相关 | 695.71 | 56.6% |
| SYNC起点细化/有效性门控 | 13.40 | 1.1% |
| CIR相干平均、相关和归一化 | 518.52 | 42.2% |
| 返回值包装等余项 | 0.99 | 0.1% |

当前sensing阶段并非只有CIR乘加；约一半以上花在SFD搜索。CIR使用116个tap
（pre16/post100）、246次重复，与comm内部的38-tap CIR/软chip处理不是同一项工作。
本轮没有启用跳过检测的predicted-timing旁路。

## comm接收阶段

默认quality，对清理后的完整目标包解调，均值1214.39 µs：

| 子阶段 | 均值µs | comm父阶段占比 |
|---|---:|---:|
| 初始SYNC检测/跟踪 | 423.57 | 34.9% |
| 初始CFO估计/补偿 | 16.68 | 1.4% |
| SFD搜索、tail重跟踪及CFO复估 | 231.92 | 19.1% |
| CIR及软chip生成 | 154.63 | 12.7% |
| NS-SFD定位 | 11.02 | 0.9% |
| PHR解码/长度 | 25.04 | 2.1% |
| payload解调/纠错/FCS | 346.87 | 28.6% |
| 回退路径 | 0 |
| 其余包装 | 4.65 | 0.4% |

CIR/软chip154.63 µs内，CIR估计87.08、软chip FIR28.66、后处理37.17、余项1.71。

PHR/payload融合快路径、fast SFD/CFO、按需soft-chip均启用；三个统计回退计数
在全部测量任务中均为0，当前数据不是靠失败回退得到的。

## 验证和复现

- 4 profiles × 3种运行（普通sensing、分段sensing、comm）× 3轮，共36次运行、
  18432个测量任务。所有SIC均提交；两个sensing版本CIR有效；comm全部FCS通过
  且127 B PSDU正确。任务未执行的消费者标记不被误算为失败。
- 12次分段sensing运行预热时共192例与生产入口逐点比较，全部一致。
- 独立检查每组均值父子分摊闭合、整体时间闭合及全部回退计数为0。
- 仅在统一SIC里透传已有重构子计时（原来为0未接线），不增加重构内的时钟读数，
  不改变算法或安全检查。相关SIC unified QA通过，未重跑全量CTest。

```bash
cmake --build gr-uwb/build-sc16-r1r2 --target benchmark_chain_workers -j2
python3 tools/sic/run_chain_workers.py \
  --out /tmp/uwb-single-worker-task-detail-new-run \
  --sync-reps 256 --sic-sync-reps 256 --psdu-bytes 127 \
  --single-worker-detail --measure 512 --warmup 128 --reps 3
```

独立任务实际预热32次，以C++基准参数为准；`--warmup 128`是驱动中生产pipeline
模式的配置，本轮没有运行生产pipeline。输出目录必须不存在。
数据：`docs/performance/data_single_worker_task_detail_256_127_20261112/`，含逐任务
CSV、分轮统计、汇总、模板/输入hash、实际库/二进制/源码hash、QA日志。
无硬件、paced、P99、MATLAB或新质量门槛通过结论。
