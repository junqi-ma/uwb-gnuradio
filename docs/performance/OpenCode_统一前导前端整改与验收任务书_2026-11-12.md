# OpenCode：统一前导前端整改与验收

## 1. 任务定位

本任务补充 `OpenCode_Sensing与Comm统一前端和CIR_开发方案_2026-11-12.md`，
修正当前实现中的缺陷，完成原任务验收。无需重新设计一套前导检测器。

当前实验位置：`.worktrees/sensing-shared-cir`，分支
`feature/sensing-shared-cir`，从 `068d21e` 创建，已有未提交开发代码。
继续使用该 worktree 和 `gr-uwb/build-sensing-shared-cir`。开始前记录实际
HEAD、diff、未跟踪源码和实际加载库；先保存可回溯的开发快照，不能 reset、
clean、覆盖现有工作或把未跟踪的新头文件/QA 遗漏在快照之外。
若本文指向的缺陷已经修正，核对实现及测试后记录关闭，不重复修改。

历史正确性与性能 control 为 `bd311cd`。当前候选已共享
`acquire_preamble()`：sensing 用 CirOnly，preamble-only SIC 用 SyncSfdOnly，
comm 用 FullPacket。要求共享的是实现；不同码、不同包的检测/CFO结果不能混用。
本轮不额外实现 sensing/comm 跨调用结果缓存，不改变 SIC 前8符号训练、重构算法、
重采样系数，不新增 GNU Radio block，不安装、上板、推送或移动历史 tag。

## 2. 优先修复正确性

### R1：worker 独占 scratch，禁止消息线程重分配

当前 `uwb_radar_cir_estimator_block.cc::handle_rx()` 中对 `d_scratch_` 调用
`reserve_radar_cir_core(n, ...)`，而 `worker_loop()` 同时使用该对象。
输入长度变大时可能重分配 worker 正在使用的缓冲。

- 删除消息线程对 worker scratch 的 reserve/resize/prepare 等修改。
- 有公开最大窗口时，在启动 worker 前按最大容量预留；原生 pipeline 保留现有
  每 worker 初始化时预留的方式。
- 动态窗口必须由 worker 在处理任务前独占扩容，单列容量增长次数和开销。
  未知上限时不能宣称整个热路径永不分配，也不要靠锁住整段 DSP 修复所有权。
- 增加消息线程持续投递、worker 在运行、窗口长度交替增大的针对性回归；
  检查输出和生命周期。条件允许用 TSAN 补查，未运行则明确记录。

### R2：共享 CIR 缓存使用自己的身份与容量判断

当前 `stage_cir_softchips()` 先更新 `scratch.cir_template.key`，再用它判断
`sync_cir_code` 是否需要重建；切码后该条件可能已被前一步清除。

- 根据共享核自身 `ready`、实际模板 fingerprint、code identity，以及
  avg/raw/norm 各缓冲所需长度/容量决定是否 prepare。
- 不依赖另一个已经更新过的缓存 key，不只比较 tap 总数。
- 保持原 comm 浮点顺序、归一化与 CMF 输出合同。
- 测试同一个 scratch 顺序处理 9→10→11→12→9，覆盖38/116 tap、tap数不变的
  切码、扩容/缩小窗口、失败后恢复。每步与全新 scratch 对照。

### R3：定时 sensing 的 CFO 策略明确且实际补偿

- 正常检测模式：估计目标码 CFO，走共享前端，使用最终 CFO 输入 CIR。
- `use_predicted_timing=true` 且已知目标 CFO：直接补偿，但使用与检测模式相同的
  去旋转内核、覆盖校验、距离轴与相位合同。
- 定时模式且目标 CFO 未知：调用共享前端估计；检测失败则失败关闭。
  不能仅增加 `cfo_epoch=0` 标签便继续按零 CFO 输出成功 CIR。
- 若已有弱回波调用无法独立估计，使用显式提供的校准 CFO，或明确返回不可估计；
  不偷偷改变门限/检测支持来保证成功。CFO=0也必须是显式已知或实际估计结果。
- 区分目标 CFO 与被消除干扰 CFO。在线入口禁止读取仿真注入真值。
- 配置开关与辅助平均入口必须使用一致策略，禁止元数据说“未补偿”但实际已补偿，
  或相反；补偿关闭仅可作为显式诊断，不作为默认成功路径。

### R4：所有 CIR 消费者都检查最终 CFO 覆盖

- 根据实际使用的周期 P、TX轴原点、pre/post、skip/count 计算覆盖；不能先按
  名义 P 补偿，后按另一个 P 读取却没有补齐。保留 raw→final 的一次补偿语义。
- `publish_alongside_average()` 的 skip/count 可能不同于主 CIR：重新计算其读取
  并集，并补齐最终 CFO 覆盖或明确失败，不能直接复用指针便假定覆盖充分。
- 检测失败、覆盖不足、非有限值、零合法重复后清空有效长度和结果，不能读取上窗。
- 保留116 tap、TX时间距离轴和 raw 复幅度；明确窗口绝对原点、局部旋转参考与
  跨窗相位关系，不把局部 sample 0 误称全局绝对 sample 0。
- 对正常/定时/额外平均入口测试 ±50 kHz、bootstrap≠final、不同skip/count、
  分数周期和边界；首中末 SYNC 对相同估计 CFO 的独立 double 参考。

## 3. 对齐已有快速前端

在 sensing 创建前端 profile 时启用并贯通现有实现：

```cpp
p.rx_fast_sfd = true;
p.rx_fast_cfo_rotation = true;
p.rx_seed_refine_tail = true;
```

- 这三个选项分别复用现有 fast SFD、分块向量旋转和尾部窄搜/安全回退，
  不重新实现算法；保留已有不支持条件下的合法回退并统计次数。
- sensing 到 CIR 结束；不为它生成 PHR/payload soft-chip。不要照抄 comm 的
  payload/PHR融合开关来“加速”CirOnly。
- 搜索 seed、ROI、margin、阈值、前导支持条件仍按公开配置显式传入并核对输出。
  ROI 的最终候选范围不能靠注释代替校验；不能通过放宽门控获得性能或成功率。
- 仅对齐适用的计算实现，不强行把 sensing 的116 tap、发送时间轴、门限改成
  comm 的38 tap和接收时间轴。comm/SIC 既有默认配置不顺手全局修改。
- 快/慢核不要求所有 IQ 位级相等；以独立数值门槛、门控稳定性、PSDU/FCS和
  感知指标验收，阈值附近发生差异须给出输入和原因。

诊断依据：一次干净工作网格、256SYNC/127B、116tap/246累加、固定单核的局部
ABBA中，旧 sensing 约1.260–1.285 ms，新实现默认约1.228–1.235 ms，开启上述
三项约0.626–0.646 ms。这只是定位配置遗漏的证据，不是生产整链路性能结论，
也不能代替正式矩阵或作为必须复现的绝对时间指标。

## 4. 修正计时与构建集成

- `RadarCirResult::cir_us` 必须实际测量共享 CIR 调用，不能始终为0。
- coverage规划是 frontend SFD父计时的子项，单列但不可再次加入 frontend总计。
  统一命名规划/去旋转时间，避免定时分支与检测分支的同名字段含义不同。
- sensing 外层墙钟为总计；前端父阶段、CIR及其余开销互斥分解。微秒截断误差
  允许有明确边界；不能把重复计时造成的负“other”用 max(0,...) 掩盖。
- pipeline、benchmark、JSON/CSV和聚合脚本同步更新新字段/列数；确认导出和
  统计实际使用它们。沿用生产入口，禁止恢复旧手写radar诊断路径。
- 将新增 `qa_uwb_sync_cir_core.cc`、`qa_uwb_preamble_frontend.cc` 及整改QA
  接入 CMake/CTest；公共新头文件加入安装清单，验证公开头文件可独立包含。
- 核对实际编译/链接/加载路径。全量 CTest 若失败，逐项对基线复现，区分继承
  失败与新增回归；不得用“80项已跑”替代新增QA实际已注册/已通过的证据。

## 5. 执行与验收顺序

按 R1/R2→R3/R4→快速配置→计时/构建→功能/质量→性能推进，阶段完成后保存
可回溯快照。原任务书第7–9节仍有效，以下给出优先验收入口。

1. 数学核：codes9–12、38/116tap、64/256SYNC、边界/容量/非有限/切码，
   相同估计CFO下独立float64参考相对L2≤2e-5，raw/norm标度及峰位置正确。
2. 前端与适配：目标CFO=0/±50k，bootstrap≠final，定时已知/未知CFO，
   检测失败、缺halo、额外平均覆盖、物理时延/相位、worker缓冲所有权。
3. comm/SIC：黄金、PSDU/FCS、损坏包失败/回退；SIC-only不运行目标 CIR/PHR/
   payload，8-SYNC训练和尾部实际消除不退化。
4. 端到端：沿用原任务书64/32、256/127，work/native，两目标码方向、
   单径/分数多径、ISR0/10/20与独立目标/干扰CFO组合。先每格16例；报告有效
   样本、检测、提交、完整PSDU/FCS。PSDU长度含2字节FCS。
5. 感知：固定距离轴、主瓣排除区域，报告raw峰位/幅度、复数L2、PSLR/ISLR、
   主瓣宽度和强弱目标保护；旧SIC的既有幅度偏差另列，不宣称此次已修复。
6. 正确性通过后正式性能：独占 `/tmp/uwb-sic-benchmark.lock`，串行执行，
   N1下quality Kaiser/realtime等波纹、64/32和256/127、sensing/comm分别测量，
   每臂预热≥32、512有效观测、5组ABBA、3session。control和candidate输入hash、
   亲和性、优化开关及有效负载一致，必要时另列单开关诊断。
7. 门槛保持：116tap CIR比旧核快≥20%，sensing接收整体快≥10%；comm和
   SIC-only不得稳定退化>5%。不达标如实报告并定位，不能关闭CFO补偿以达标。
8. N1通过后补N4/N8生产pipeline和含comm完整DSP，验证功能、状态账本、
   丢弃/失败和吞吐/服务延迟；不将离线容量称为paced或硬件实时验证。
