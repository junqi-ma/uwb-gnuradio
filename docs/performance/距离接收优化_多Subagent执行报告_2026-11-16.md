## 3. Wave 1 结果

### 3.1 Agent-A：建议 1 不成立（保留诊断与开关）

**先测量后改动**。新增只读诊断字段（`cfo_init_hz` / `cfo_refit_hz` / `cfo_init_pk` /
`cfo_refit_pk` / `cfo_refit_span` / `cfo_rot2_us` / `cfo_drift_rad` / `cfo_act`），实测：

| 量 | 实测 |
|---|---|
| 初始拟合 peaks（`stage_cfo`） | 231–232（256 SYNC − 24 启动排除） |
| tail 重拟合 peaks | 40 |
| 第二次旋转跨度 | 279,467 样点 |
| 仅第二次旋转耗时 | 200–227 µs（= `sfd_cforef` 的 99.9%） |
| Δf = refit − initial | 均值 17–21 Hz，**p90 318–348 Hz，max 875 Hz** |
| Δf 在跨度上的相位漂移 | 均值 0.33–0.35 rad，**p90 0.70，max 1.50 rad** |

两条硬结论：

1. **第二次 CFO 拟合不是冗余**。只有约 19% 的包落在 0.10 rad 预算内；初始拟合的 232 个峰里
   有被回溯/弱符号污染的，斜率会偏，tail 重拟合是真实修正。
2. **「跳过第二次整块去旋转」在端到端上不成立**。去旋转是「把下游要读的样点物化到
   `scratch.derotated`」，跳过它只是把同样的工作搬到第一次旋转：实测 `st_cfo` 22 → 240 µs、
   `st_sfd` 249 → 34 µs、`cforef` 214 → 0.1 µs，`demod` 无变化。

**唯一真实冗余**：第二次旋转用 `initial_chip_budget()`（40 个 PHR-head 符号 + 1.05），
其末端越过 payload 起点 34,781 样点。已改为 `required_derotated_hi()`（下游真正读到的最高样点）。
但主控 A/B 实测：`cforef` −27 µs 的同时 `st_payload` **+28 µs** —— 省下的区间正好是
payload 段现在必须覆盖的区间，**净收益 ≈ 0**。这是本轮最重要的负面结论：
**去旋转只能变快，不能变少**（见 §3.4 与 §5.1）。

保留价值：CFO 双拟合诊断（本轮所有分析都依赖它）、`--cfo-refit legacy|auto|skip` 三个
可回退开关、以及「区间收紧」本身（把重复旋转从 34,781 样点降到约 101 样点，虽然总时长不变，
但消除了同一区间被同一 CFO 旋转两遍的结构性冗余）。

### 3.2 Agent-B：锁定态 `pre_guard`（达成）

`pre_guard` 是给 `acquire` 阶段自相关种子留的裕量（种子是自相关平台起点，可能比真实包起点早
约 36864 样点）；进入 `locked` 后起点由周期预测器给出（残差 −2…+5 样点），
只需覆盖 `locked_roi` + 重采样群时延。

- 新增 `TargetLockCore::set_pre_guard()`（唯一允许运行期改的几何字段，越界/未声明预算
  fail-closed 返回 false，调用方当致命错误处理）；`--locked-pre-guard` 默认 **8192**。
- 按锁状态生效：`LOCKED → 8192`，`ACQUIRE/VERIFY/HOLDOVER/REACQUIRE → 36864`。
- 所有切窗点（目标窗、自相关候选窗、timed 盲网格）统一用当次生效的 `cur_pre_guard`，
  `PACKET` 行新增 `guard=` 便于逐窗核对。
- 分配仍按最大几何（`window=450000`），运行期只允许缩小。

实测：窗口 374,217 → **345,545 样点（−7.66%）**；`resample_us` 730.9 → **673.3（−7.6%）**；
`compute` 1726.8 → 1650.7（−4.4%）；PRR 无退化。5.2 m 的 1947 个目标窗
`pred − win == guard` **1947/1947 成立**。

### 3.3 Agent-B：建议 7 被否定（5.2 m 的 `NOWIN=50` 不是捕获问题）

`NOWIN=50` 的构成：

| 来源 | slot | 数量 |
|---|---|---|
| **文件前导静默（文件里没有包）** | 0–44 | **45** |
| 锁定入口流水线延迟 | 48–51 | 4 |
| 尾部不足一窗 | ~1999 | 1 |

三条独立证据证明前 45.656 ms 无包：① 生产 `acquire` 路径（131072 搜索裕量 + 128 符号回溯）
单独跑 5.2 m，首个 PACKET 仍是 `time_ms=45.656 start=33662125`；② 采集目录自带的另一版
二进制日志首个 PACKET 也是 `time_ms=45.656`；③ 原始文件 lag=750 稀疏自相关平台统计，
前 45 个 slot 的 `frac(metric>=0.15)` 仅 0–0.209（散点），有包区域最高 0.752。

**因此跨周期非相干累加在 5.2 m 上救不回任何 `NOWIN`（无包可累加）**，未实现。
`d2p5m` 的 `NOWIN=5` 同理是捕获结构（36864 样点平台 + 0.8 ms holdoff + 3 观测 VERIFY），
不是门限。

### 3.4 Agent-C：payload 剖析（改变优化方向）

`st_payload` 拆分（13,960 个 CRC-OK 包均值，子项之和与父阶段偏差 0.68 µs，逐包断言子项 ≤ 父项）：

| 桶 | µs | 占比 |
|---|---:|---:|
| `pay_soft`（fused CMF 四候选相关 + PN） | 119.9 | 47.3% |
| `pay_viterbi` | 6.2 | 2.5% |
| `pay_rs` | 10.3 | 4.1% |
| `pay_crc` | 0.5 | 0.2% |
| `pay_other`（其中 **payload 区间去旋转 113.6**） | 116.5 | 46.0% |
| 合计 | 253.3 | 100% |

**结论：Viterbi + RS + CRC 合计只有 6.8%（约 17 µs），不是热点。**
payload 的热点是 fused CMF 相关（120 µs）与 payload 区 CFO 去旋转（114 µs）。
加上 SFD 段的 `cforef`，**CFO 去旋转合计约 320 µs/包，占 `compute` 约 20%**，
是重采样之外最大的单项 —— 这直接决定了 Wave 2 的投入方向（Agent-F）。

## 4. Wave 2 结果

### 4.1 Agent-D：锁定态网格跟踪 + 尾部重探（最大单项收益）

`LockedBounded` 原来对 256 个 SYNC **逐个**做 ±8 半径、17 个 lag × 1016 tap 的相关。
改为：

1. 探测阶段不变（±256 ROI，`locked_inner_symbols` 个内侧 SYNC）；
2. **16 个稀疏锚点**（从 `first_hit_k` 到最后一个 SYNC）用原 `local_best(±8, 0.08)` 真实搜索，
   最小二乘 bootstrap 网格；仅当名义网格会让末锚点偏 > 4 样点（未 trim 时钟）才做第二遍锚点（半径 16）；
3. 每个 SYNC 在预测位置做**一次 8-lag 相关取 argmax**（8-lag 核有独立累加器，比单 lag 核便宜，
   且 argmax 让峰值位置/CFO 相位与 legacy 一致）；
4. `measured_period` / `preamble_start` 最终由**全部 refined 峰位置**最小二乘得到
   （与 legacy 256 点拟合同一估计器），锚点只做 bootstrap 与回退；
5. **fail-closed**：锚点 < 4、斜率退化、周期偏离名义 > 0.5%、有效 SYNC < 4、
   单点 metric 的 p90 < 0.5×锚点中位数 → 全部回退 legacy 逐符号路径（`grid_fb`）。

实测：`st_timing` **274.9 → 149.4 µs（−45.7%）**，`grid_anch=16`、`grid_valid=256`、
**`grid_fb=0`**（正常包零回退）。

**对任务书的一处有意偏离（已记录）**：任务书要求 `measured_period` 必须来自锚点拟合。
实测 16 锚点拟合的标准误是 256 点拟合的 4 倍，在 2.5 m 造成 1 包/2000 的 payload 翻转；
改为「锚点 bootstrap + 全 refined 峰拟合」后消失。refined 位置是真实 argmax 而非量化网格，
所以 `integer_chip_grid()` / `spc_ppm` / `grid_reject` 语义不变
（QA 用 50 ppm 压缩时钟验证仍被拒绝）。

**建议 6（5.2 m 的 20 个 `TIMING_FAILED`）**：诊断显示 20/20 都是 `bounded_fail=1`、
`first_5_max=0.029..0.053`（低于 0.08），而 `med_tail_32_255` 达 0.14–0.20 ——
前几个符号被突发干扰压低、尾部干净。实现为**失败路径**的稀疏尾部重探
（m=8,16,…,248，先 ±32 再全 ROI，门限用跟踪门限 0.08，命中需 ≥2 个相邻网格符号确认）。

实测：5.2 m `TIMING_FAILED` **21 → 4**，PRR **96.27% → 97.00%**。
逐包证据：`tail_hit=1` 共 17 包被挽救（`tail_k` = 53/77/253 等，`tail_best` 0.17–0.19），
其中 16 包解码 OK、1 包后续 `CFO_FAILED`（`sync=3`，峰太少无法拟合）。
剩余 4 包：3 包 `tail_best=0.000`（64 次探测无一过 0.08，整段前导没有可用尾部），
1 包 `tail_best=0.113` 但无 2 个邻居确认（按设计判为 ROI 虚警）。
副作用：5.2 m 的 `PAYLOAD_FAILED` 3→10，因为被挽救的包从 `TIMING_FAILED` 推进到 payload
阶段后才失败；**总失败数 45 → 18**。

**建议 6 的突发消隐（任务 C）未采纳**：A/B 已消除 17/21，剩余 4 包是窗口本身不可解。

### 4.2 Agent-F：CFO 去旋转内核单遍化（达成）

`derotate_range_block` 原本每 1024 样点块做**两遍**：先 `src × table`，再乘块锚点相位
`exp(-j·w·b0)`。改为把块锚点折进表项**在寄存器里**，数据只读写一遍
（表仍保持 4 链 + 每 16 步从 double 精确重锚，块锚点仍是精确 double sin/cos）。

**对任务书假设的修正（重要）**：任务书假设「40 B/样点、第二遍打 DRAM」。
实测第二遍读的 `dst` 是刚写过的 8 KiB 块，命中 L1，**真实流式流量只有 16 B/样点**，
两遍一样。所以收益不来自省带宽，而来自**砍掉一次全宽复乘 + 一次 load/store**
（每 4 复样点 18 → 13 条 uop）。试过 5 种实现，完全融合 AVX2（`permute 0xB1` + `addsub`）最优；
逐块递推建表最差（2.3 ns/样点，rel L2 1.8e-7 超合同），已否决。

隔离微基准（500k 样点，11 次中位数）：**0.250–0.267 → 0.190–0.211 ns/样点（−19…−28%）**。

误差合同（500k 样点，新旧直接比较，已固化为 QA）：

| CFO | max abs | 相对 L2 |
|---|---|---|
| 0 | 0（逐位相同） | 0 |
| 0.5/2/5/20/−20 kHz | 2.39e-7 … 2.67e-7 | 5.74e-8 … 5.81e-8 |
| ±200 kHz | 2.39e-7 / 2.43e-7 | 6.44e-8 / 6.45e-8 |

→ max abs ≤ 2.67e-7（门槛 1e-6）、相对 L2 ≤ 6.5e-8（门槛 1e-7），
且对独立 double 参考**未劣化**（QA 逐 CFO 断言 `new ≤ old + 1e-7`）。

流水线实测（ABBA 配对均值）：`sfd_cforef` **209.9 → 179.3（−14.6%）**、
`pay_derot` **130.0 → 112.9（−13.1%）**、`demod` **958.8 → 892.4（−6.9%）**、
`compute` **1636.0 → 1568.2（−4.1%）**。旋转总成本 360.7 → 311.4 µs（−13.7%）。

## 5. 被实测否定的规划项（保留数据）

### 5.1 建议 1：去掉/合并 SFD 二次 CFO 与全帧去旋转 —— **不成立**

预期 −150…−240 µs，实测净 **0 µs**。三个原因，每个都有独立测量支撑：

1. **第二次拟合不是冗余**：Δf p90 318–348 Hz，在 279,467 样点跨度上漂移 p90 0.70 rad、
   max 1.50 rad；只有 19% 的包落在 0.10 rad 预算内。
2. **跳过第二次旋转只是迁移工作**：`st_cfo` 22 → 240 µs、`st_sfd` 249 → 34 µs，
   总旋转样点只降 1.8%，`demod` 不变。
3. **收紧旋转区间也被抵消**：`cforef` −27 µs 的同时 `st_payload` +28 µs，
   因为 payload 段必须从 `min(sec_hi, base0)` 开始覆盖。

**根因**：去旋转是把下游要读的样点**物化**到 `scratch.derotated`，下游（final SFD、CIR、
soft-chip FIR、fused CMF）全部从这个缓冲区读。要真正省掉这约 320 µs，只有一条路：
**把相位斜坡折进 fused CMF / soft-chip 内核**（按 chip 递推，误差 < 0.002 rad/chip）。
那会改变数值（不再与现路径逐位一致），需要先立误差合同；本轮未做。

### 5.2 建议 7：周期累加捕获 —— **在 5.2 m 上无对象**

见 §3.3。`NOWIN=50` 中 45 个是文件前导静默（文件里没有包），4 个是锁定入口流水线延迟，
1 个是文件尾。跨周期累加救不回任何一个；放宽固定门限则会重演「单音触发捕获」的老问题
（`--tone off` 时 `candidates` 989→1239、`dropped_queue=490/500`）。

### 5.3 建议 5：锁定态 SFD 定点验证 —— **主动取消**

`st_sfd` 的 87% 是 `sfd_cforef`（去旋转），SFD 搜索本身（`sfd_boot` + `sfd_final`）
只有约 35 µs。收窄搜索窗最多省十几微秒，价值不足以占用一个 worktree。
该 worktree 改投 Agent-F，收益高一个数量级。

### 5.4 建议 8：统一 CFAR 门限 —— **未启动**

建议 5 未做，其前置条件（收窄搜索空间）不存在；且本轮已证明 5.2 m 的失败不是门限问题，
统一门限的收益无法在本轮数据上证明。

## 7. 已知问题与未验证项

### 7.1 已复现的偶发（与本轮改动无关）

- `uwb_qa_uwb_fixed_tone_cancel_source` 在 `loadavg > 3` 时会因环形缓冲溢出
  （`dropped_samples=5120`）失败；主 worktree 基线同样 10 次里失败 1 次。
  单跑与复跑均通过，属既有 paced 时序敏感项。
- **整段失锁**：在并行编译负载下，5.2 m 与 2.5 m 偶发 `reacquire_entries=1`、
  8–9 个连续 `TIMING_FAILED`。Agent-F 观察到 6 次运行中 2 次（**基线与新二进制都出现**）；
  主控在 2.5 m 上观察到 3 次中 2 次（当时另有 agent 在跑）。
  **空载复测：2.5 m 基线 10/10、新二进制 10/10 全部 OK=1995、TIM=0、无失锁**，
  故判定为负载诱发的既有偶发，不是本轮回归。**但这条必须在报告里保留**：
  它说明该夹具在负载下不可用于 PRR 验收。

### 7.2 未验证

- **上板 / UHD 实机**、`recv` 溢出、paced 到达、8 worker、负载下 P99。
- 多径 / AWGN / ISR、CFO 扫频、SFO、MATLAB 交叉验证。
- `--locked-pre-guard` 只验证了 8192（下限 1596 未扫）。
- `--locked-roi 64/128`、`locked_grid_anchor_count` 扫描。
- `--cfo-refit auto|skip` 在 27 ppm 未 trim 时钟下的行为（该场景 `grid_reject` 会关掉融合路径）。
- `--locked-timing legacy` 保留为回退开关，但未在 7 距离上做完整对照。
- 去旋转内核的 `UWB_SIMD=SCALAR` 构建整块走标量尾巴，未做性能测试。
- 数值差异虽小但非零（≤2.67e-7）：14k 包回放显示解码计数一致，
  但这不等于证明该量级扰动永不翻转任何判决。

## 8. 后续建议（按实测收益/风险排序）

| 优先级 | 项目 | 依据 | 预估 |
|---|---|---|---|
| **P0** | 把 CFO 相位斜坡折进 fused CMF / soft-chip 内核（按 chip 递推） | §5.1：去旋转约 280 µs 只能这样消除 | −150…−200 µs/包，需先立误差合同 |

| **P3** | 远端（>5 m）链路余量 | 5.2 m 剩余 4 个 TIM 是窗口本身不可解 | 属捕获/前端，不在解调侧 |
