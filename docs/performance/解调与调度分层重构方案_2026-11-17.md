# 解调与调度分层重构方案（2026-11-17）

起点：`2a4e244`，工作区干净，当前代码已提交。用户授权规划并执行重构。
仅软件、文件回放；不改变 PHY 门限、运算顺序、锁定策略或设备行为。

## 交付范围

1. 抽出 TX/RX 共用 codec（CRC、GF、SECDED、spreading），保持原算法及 RX detail
   兼容别名；TX 不再包含解调实现。现有 golden/编码/解码 QA 验证。
2. 将大型解调头按 grid、scratch、timing、CFO、SFD、soft-chip、payload/PHR
   分层。保留 uwb_demod_core.h 作为兼容聚合入口；公共完整包 API 单独声明，
   demodulate_one 编排移入 uwb_core 的独立 TU。只调用完整包 API 的生产消费者
   使用轻量入口。补齐所有安装依赖，并验证独立安装消费者。
3. 明确 worker 缓存、包内状态、工作区的生命周期；保留既有 scratch 字段兼容，
   集中包初始化与执行路径准入，避免重排算法或扩大清理范围。
4. 抽出 live 的单包处理器：重采样、解调、auto CIR 重试与 native 坐标观察生成。
   处理器不访问锁定状态、Reporter 或任务队列。worker 只接任务、调用处理器、
   发布反馈和输出。公共重采样窗口处理供 live 和 pipeline 共用。
5. 明确两套调度的不同策略，保留共享任务池与各 worker SPSC、完成反馈与顺序输出
   的现有语义；共用基础计算与生命周期合同，不强行用固定周期 scheduler 替代
   动态目标 scheduler。不实现未经验证的新统一队列拓扑。

## 验收合同

- 旧入口、stage API、分数网格和融合失败回退可用；timed 无 replay 继续 fail-closed。
- 编码字节、解码状态、PSDU/FCS、坐标与诊断计数不变；时间字段只用于性能比较。
- worker 私有 scratch/resampler，不增加包间共享可变 DSP 状态。
- RX 主线程仍是锁状态 owner；观察完成后立即入队，不等待结果顺序提交。
- pipeline 仍按 window_id 提交，worker 完成前不释放窗口，停止后排空已接纳任务。
- native 全套 CTest；AVX2/SCALAR 受影响 QA；旧新二进制文件回放对照；
  安装到临时目录并编译轻量 API/codec 消费者；记录未完成的硬件/性能验证。

## 实施顺序与回退

先 codec + 模块拆分，再运行时处理器和公共窗口计算，每阶段构建并运行相关 QA。
提交保持阶段可审查。源码级拆分不宣称自动提速；性能需 ABBA 实测。
旧 native 二进制保存在 /tmp/uwb-refactor-base，仅用于本次对照，不作为永久复现依赖。

## 后续独立工作

共享队列与 SPSC 谁更适合整条链路，需要专门负载实验；长期结果保留、乱序缓冲上限、
回调隔离也需要单独定义产品策略。本次保留现有行为，不将其混入保持数值结果的拆分。
