# OpenUWB 全仓库架构重构验收报告（2026-11-20）

本报告是 `docs/OpenCode执行方案_openUWB全仓库架构重构_2026-11-20.md` 的 Phase 4
交付物：记录 Phase 0 → Phase 3 的最终验证结果、ABBA 性能对比、兼容层清除清单和
后续入口。原始 ABBA 数据见同目录
[`data_openuwb_refactor_20261120/abba.json`](data_openuwb_refactor_20261120/abba.json)。

## 1. 结论

- **功能**：三预设 CTest 全绿；控制台 `stdout` 协议未变；安装消费者同时通过
  `find_package(OpenUWB)` 与旧 `find_package(uwb)`。实时回放的完成包数与 FCS
  成功数在 A/B 两侧**逐轮完全相同**（1006 / 981）。
- **性能**：微基准、稳态管线和实时回放均未发现超过噪声水平的退化。最大绝对
  中位数差为 −2.92%（见 §4.1，方向为更快），且逐轮取值区间与基线重叠；早期
  2-cycle 一轮的 K3 `+5.20%` 在 3-cycle 复测中变为 `−2.92%`，确认是噪声而非回归。
- **兼容层**：保留 109 处 `TODO(openuwb-compat-removal)`（§4.5），全部为显式、
  可机械清除的转发头 / 别名 / 回退路径，不包含隐式行为分叉。

## 3. ABBA 方法与复现

复现工具：[`tools/perf/abba_refactor_acceptance.py`](../../tools/perf/abba_refactor_acceptance.py)。

```sh
# 基线（Phase 0 0A）独立只读 worktree
git worktree add --detach /tmp/opencode/uwb-baseline d036564
cmake -S /tmp/opencode/uwb-baseline/gr-uwb -B /tmp/opencode/uwb-baseline/build-native \
  -DCMAKE_BUILD_TYPE=Release -DUWB_SIMD=AVX2 -DENABLE_UHD_BACKEND=AUTO -DUWB_BUILD_EXPERIMENTS=ON
cmake --build /tmp/opencode/uwb-baseline/build-native -j5 --target \
  bench_demod_sic_kernels benchmark_sc16_pipeline_steady uwb_dw3000_live
# 内核微基准的 AVX-512 对照另建 build-avx512

# 当前树
cmake --preset native-avx2 && cmake --build --preset native-avx2 -j
cmake --preset native-avx512 && cmake --build --preset native-avx512 -j

env -u LD_LIBRARY_PATH python3 tools/perf/abba_refactor_acceptance.py \
  --baseline /tmp/opencode/uwb-baseline --out /tmp/opencode/abba-phase4 --cycles 3
```

约束与口径：

- 每个用例按 **A B B A** 重复 3 轮（每侧 6 次），严格串行；脚本同一时刻只运行
  一个子进程，不与编译、测试或其他 Subagent 并行。
- 单线程用例用 `taskset -c 0`；稳态管线与双 worker 回放用 `taskset -c 0,1`，
  两臂相同。首轮曾把回放也固定在单核，2 个 worker 与 feeder 争抢导致两轮
  `raw_drop_samples` 达 5.8–6.3 亿样点；该配置只测机器调度，已废弃并改用
  `0,1` 复测，最终数据全部 `raw_drop_samples=0`。
- 统计量：每臂取中位数；差异 = (当前中位数 − 基线中位数) / 基线中位数。
- 所有运行清除 `LD_LIBRARY_PATH`，`UWB_TESTDATA_DIR` 指向当前仓库 `testdata/`。

### 4.2 稳态管线（`native-avx2`, `benchmark_sc16_pipeline_steady`）

固定 `--native-rate 737280000 --work-rate 998400000 --warmup-windows 20
--measure-windows 300 --dsp-workers 1 --pool-size 16 --flow-in-flight 24`，
每轮实际测量 263 个窗口（两臂一致）。

| 指标 | A (µs) | B (µs) | Δ |
| :--- | ---: | ---: | ---: |
| `e2e_us_mean` | 51.057 | 51.093 | +0.07% |
| `e2e_us_p95` | 51.757 | 51.702 | −0.11% |
| `steady_window_us` | 51.528 | 51.566 | +0.07% |

### 4.3 实时接收回放（`native-avx2`）

基线 `uwb_dw3000_live --replay … --summary 1000 --workers 2`，当前
`openuwb_rx` 同参数；每轮 1 s、7.37 亿样点。

| 指标 | A | B | Δ |
| :--- | ---: | ---: | ---: |
| `completed` | 1006 | 1006 | 0.00% |
| `fcs_ok` | 981 | 981 | 0.00% |
| `raw_samples` | 737 280 000 | 737 280 000 | 0 |
| `raw_drop_samples` | 0 | 0 | — |
| `demod_mean` (µs) | 646.80 | 645.95 | −0.13% |
| `resample_mean` (µs) | 551.05 | 567.15 | +2.92% |
| `compute_mean` (µs) | 1211.85 | 1233.45 | +1.78% |
| `compute_p95` (µs) | 1395.25 | 1555.05 | +11.45% |

判读：

- **功能逐轮完全一致**：6 次 A 与 6 次 B 都是 `completed=1006`、`fcs_ok=981`，
  输入丢弃与 gap 均为 0。这是本阶段最强的等价证据。
- `demod_mean` 差 −0.13%，与 §4.2 的 `sic_us_mean`/解码路径一致。
- `resample_mean`/`compute_mean` 的中位数差 +2.9%/+1.8%，但单轮离散达 ±10%
  （基线 537–618 µs、当前 545–704 µs），中位数差小于单轮极差，不能判为回归；
  同一重采样代码在 §4.2 的更紧测量中是 +0.36%。
- `compute_p95` 来自最后一个 `SUMMARY_PARTIAL` 批次（仅 6 个包），不是全局
  p95，统计上不可用于跨版本比较；保留原值仅作记录。

## 5. 限制与未验证

- **距离回放基线未执行**：`tools/rx/run_distance_replay.py` 的默认夹具目录
  `/media/oi/Data/uwb/clean_distance/2026-11-16` 在本机不存在，`testdata/` 也没有
  7 距离捕获，因此没有 Phase 0 的逐包回放基线可比。工具本身已支持无 `--binary`
  自动发现，本次只如实记录夹具缺失。
- 实时回放的单包耗时受宿主调度影响，单轮离散 ±10%；结论以功能计数和稳态基准
  为准，不把 <3% 的回放差异解释为代码变化。
- 本轮没有重跑 MATLAB 逐样点/逐包交叉验证，也没有上板；SIC 按计划未接入
  `openuwb_rx`。
- ABBA 数据采集期间，机器上除本工具外没有并行编译或测试；但桌面环境仍可能
  抢占 CPU，故采用 ABBA 交替与中位数，并单独标记输入掉样的运行。

## 6. 合并与后续

分支满足合并主分支的机械条件：三预设全绿、控制台/安装契约通过、功能计数一致、
无可解释的性能退化、工作树只含本阶段预期改动。

后续建议按独立分支推进，不在本分支继续扩大范围：

1. **仓库改名 `openUWB`**（2026-11-20 已完成）：GitHub 仓库为
   `junqi-ma/openUWB`，本地 `origin` 已更新，`main` 指向本次验收提交；旧
   `main` 顶点保存在 `archive/main-before-openUWB`。文档中没有绝对仓库链接，
   因此无需额外改写；CMake 包名本来就是 `OpenUWB`。
2. **SIC 接入**：基于 `openuwb::runtime` 的 `PacketProcessor` 与 `openuwb::sic`
   在 `openuwb_rx` 中增加可选 SIC 阶段；必须先补逐包等价与 fail-open 回归，
   再讨论默认开启。
3. **`openuwb_tx` / 4z / 4ab**：按 `apps/openuwb_tx/README.md` 的边界实现 TX；
   4z/4ab 从 `include/openuwb/phy/hrp/common/standard_rev.h` 出发，带自己的
   profile 数据与测试，不允许空壳分支。
4. **兼容层清除**：按 §4.5 的类别逐项删除，每类单独提交并跑三预设；删除前
   先确认没有下游项目仍使用 `find_package(uwb)` 或 `<gnuradio/uwb/...>`。
