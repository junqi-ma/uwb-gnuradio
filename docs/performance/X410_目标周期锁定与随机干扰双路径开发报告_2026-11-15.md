## 3. 设计要点

### 3.1 目标锁状态机

`ACQUIRE → VERIFY → LOCKED → HOLDOVER → REACQUIRE`，只有调度（RX）线程修改状态。

- **ACQUIRE**：无计划。宽范围同步 + 自相关候选 + 目标码模板确认。
- **VERIFY**：第一个身份有效目标包锚定 slot 网格；`verify_observations`（默认 3）
  个独立有效包后进 LOCKED。slot 索引由观测间隔推断，**允许漏包**（间隔 2 个 slot
  仍是同一网格），不会把 10 ms 误认成新周期。
- **LOCKED**：按学习到的 `(t0, period)` 预测每个期望时隙，
  `n_pred(k) = round(t0_exact + k * period_samples_exact)`，**每个 k 独立取整**，
  绝不累加取整后的整数周期。
- **HOLDOVER**：一次目标失败保持相位/周期预测；失败或 unknown 观测不更新锁；
  按连续失败次数线性扩宽前后保护区（上限可配）。
- **REACQUIRE**：连续失败达阈值、残差连续超限、或 RX 非预期 gap 时，generation
  自增、清空网格、回到 ACQUIRE。全局重捕获只在这里发生，不在 worker 内。

反馈：worker 通过 `push_observation()` 写入有界队列（默认 64，满则计数丢弃），
调度线程 `drain_observations()` 统一应用。乱序完成按 generation + slot 处理；
重复 slot、旧 generation、超网格 slot 都被显式计数并忽略，**worker 完成顺序不会被
当作空口顺序**。

### 3.2 窗口几何

`TargetWindowGeometry{pre_guard, capture, post_guard}`，包起点固定在 `pre_guard`
位置，`capture` 由 PHY 推导（256 SYNC + 4z2 + PHR + 127 B 最大 PSDU + 脉冲/重采样
halo），**不依赖本包尚未解出的 PHR**。live 入口实测
`capture=329161` native 样点（≈446 µs），`pre_guard=36864`，`post_guard=8192`，
`window_capacity=374217`，与规划 §4 的 ~331331 点估计一致。

### 3.3 `LockedBounded` 同步策略

`stage_timing()` 新增显式分支：

- 只允许在 `seed ± locked_roi_samples`（默认 256）内做首次 SYNC 匹配；
- 依次探测 `seed + m*symbol`（`m = 0..locked_inner_symbols`，默认 4），找到后按已知
  符号网格换算回包起点——这是有限探测集，**不是扫描**；
- **不**执行 stride 粗扫、**不**执行整 SYNC 网格探测、默认**不**执行逐符号回溯；
- ROI 失败直接返回跟踪失败，由锁状态机决定扩窗或重捕获；
- 仍保留 256 个 SYNC 的逐符号跟踪，因为 CFO/CIR 需要有效峰值。

诊断字段 `bounded_attempts / bounded_success / bounded_failures /
bounded_legacy_scans / bounded_inner_used / bounded_roi_samples /
backtrack_symbols` 随 `DemodResult` 输出。`bounded_legacy_scans` 在
`LockedBounded` 下**必须为 0**，QA 与实采都验证了这一点。

### 3.4 随机干扰路径

自相关仍负责发现候选，但**分类推迟到提交时刻**：目标窗在包起点后约 0.46 ms 才
提交，而自相关在包起点后约 8 µs 就触发，检测时刻还没有该 slot 的计划记录。

- 候选落在已提交的目标 slot 预测位置内 → `TargetAssociated`，不再切第二个窗；
- 关联结论由该 slot 的解调结果确认：成功 → `dedup_confirmed`；失败 →
  `INTERFERENCE_AMBIGUOUS` 事件（可能是重叠干扰），**不静默丢弃**；
- 确认是不同 code 的候选即使落在目标窗内也判为 `Interference`；
- 远离网格的候选保持 `Unknown`，按需提交干扰窗，其解调结果再决定身份。

因此**没有**简单屏蔽整个目标时间区间。

### 3.5 设备定时 `timed_burst`

`TimedRxPlanCore` 提供：硬件对齐外扩（起点向下、长度向上取整到 SPC 倍数）、
有界前瞻、命令提前量、多 chunk 装配、以及 8 种互斥终端状态
（`complete / partial / timeout / late_command / overflow / device_time_jump /
planned_gap / unexpected_gap / cancelled`）。已下发给设备的窗口不可回写；预测更新
只改未提交窗口。计划空档记 `planned_gap`（不是错误）；窗内缺样记
`unexpected_gap` 并使检测统计/目标锁失效。

`merge_physical_rx_intervals()` 实现 §8 的单音训练窗与目标窗物理区间合并：重叠区间
只采一次，按逻辑切片分别引用，单音网格按绝对时间独立取整（不累加）。

### 5.6 与仿真夹具的差距及其归因

同一波形配置（256 SYNC / 127 B / 4z2）下，仿真夹具
（`tools/sic/run_clean_comm_workers.py` 的 `clean_comm`，code 9，1 worker）与 X410
实采的单包解调耗时相差约 1.7 倍。逐阶段对照（均值，成功包）：

| 阶段 | 仿真夹具 µs | X410 实采 µs | 差 |
|---|---|---|---|
| timing | 427.4 | 384.4 | −43 |
| CFO | 15.9 | 35.1 | +19 |
| SFD | 200.4 | 489.0 | **+289** |
| **CIR + soft-chip** | **115.2** | **901.8** | **+787** |
| NS-SFD | 10.0 | 6.9 | −3 |
| PHR | 19.0 | 5.0 | −14 |
| payload | 290.9 | 49.0 | −242 |
| other | 4.2 | 0.0 | −4 |
| **合计** | **1086.4** | **1871.2** | **+785（1.72×）** |

#### 根因：采样时钟偏差使融合 CMF 的整数 chip 网格不成立

融合 CMF（`rx_fused_payload_cmf` / `rx_fused_phr_cmf`）用固定的
`kSamplesPerChip = 2` 整数网格直接对 CFO 补偿后的 IQ 做四候选相关，因此要求

```
| samples_per_chip - 2 | <= 1e-9      （即 <= 0.0005 ppm）
```

实采实测：

| | `samples_per_chip` | 相对 2.0 |
|---|---|---|
| X410 实采 | **1.9999465** | **−26.7 ppm** |
| 仿真夹具 | 2.0（精确） | 0 |

实采偏差是门限的 **5.3 万倍**，融合路径被直接拒绝。

这不是把门限调松就能解决的算术洁癖，而是物理约束：

- PSDU 127 B → 1208 个 BPM 符号 × 64 chip × 2 样点 = **154,624 样点**
- −26.7 ppm 在该区间累积 **4.1 样点 ≈ 2.1 chip** 的漂移
- 若要求漂移 < 1 样点，允许的偏差上限是 `1 / 154,624 = 6.5 ppm`

也就是说，固定整数 chip 网格最多容忍约 6.5 ppm，而真实 X410 时钟是 −26.7 ppm。
**融合路径在真实硬件上不可能成立，除非先做 SFO 补偿或逐符号重锚定。**

仿真夹具不出现这个问题，因为它是用 `resample_poly(x, 48, 65)` 从标称 998.4 MS/s
精确有理重采样出来的，chip 网格恰好是 2.0。

这个 −26.7 ppm 与 §5.3 独立测得的包周期 −27.25 ppm 是同一个时钟偏差的两个侧面
（一个从包间隔测，一个从 chip 周期测），互相印证。

#### 第二个独立阻塞：`--cir auto` 选到 `Bypass`

融合路径的配置门限还要求 `cir_soft_chip_mode != Bypass && != Rake`。live 入口的
`--cir auto` 映射为 `Bypass`，所以即使时钟完美，融合路径也会被配置门限先拒。

四次对照（1 s 实采，4 worker，`--sync locked`）：

| `--fused` | `--cir` | demod µs | `st_cir` µs | `st_fallback` µs | 回退次数 | FCS |
|---|---|---|---|---|---|---|
| off | auto（Bypass） | 1800.0 | 827.4 | 0 | 0 | 198/200 |
| on | full | 17203.7 | 72.2 | 16248.8 | 1 | 198/200 |
| off | full | 17053.5 | 15898.9 | 0 | 0 | 198/200 |
| on | bypass | 1870.2 | 51.9 | 1077.2 | 1 | 198/200 |

读法：

- `--fused on --cir full`：配置门限过了，`st_cir` 只有 72 µs（融合路径确实把 FIR
  缩到 SYNC/SFD/PHR 前缀），但运行时 `spc` 检查失败 → 回退整条流 16.2 ms。
- `--fused off --cir full`：没有融合，`full` 模式对 228,422 个 chip 跑 38 抽头匹配
  滤波 → `st_cir` 15.9 ms，**完全不可用**。
- `--fused on --cir bypass`：配置门限先拒（Bypass），回退 1.08 ms。

所以"打开融合就能变快"是错的：**必须先解决时钟偏差，否则只是把一次失败的尝试
换个地方付钱。**

#### 顺带修掉的一处纯浪费

`rx_softchip_on_demand`（按 PHR 长度扩展软比特前缀）在 `fused=off` 时**每个包都
失败**再回退，等于白跑一遍。`--ondemand` 改为默认跟随 `--fused`（即 `fused=off`
时关闭）后，3 次配对：

| 配置 | demod 均值 µs（3 次） | 回退次数 | FCS |
|---|---|---|---|
| `--ondemand on`（旧默认） | 1938.6 / 1984.8 / 2017.2（均 1980.2） | 1/包 | 199、199、198 |
| `--ondemand off`（新默认） | 1856.3 / 1822.6 / 1827.4（均 1835.4） | 0 | 199、199、199 |

**−7.3%，三次同向，FCS 持平。** 这是"少做一次注定失败的尝试"，不是算法改变。

#### 结论与下一步

X410 实采比仿真夹具慢，**不是噪声/多径/CFO 的问题，而是采样时钟偏差**：融合 CMF
的固定整数 chip 网格在 −26.7 ppm 下会累积约 2 个 chip 的漂移。

**受控实验（同一波形、同一噪声种子，只改时钟）**：用 `modulate_one` 生成一个
code10/256 SYNC/4z2/127 B 包，48/65 精确重采样到 native，40 个包按 5 ms 排布，
噪声种子相同；第二份用 FFT 重采样把整段压短 −27 ppm。

| 指标 | 0 ppm | −27 ppm | 差 |
|---|---|---|---|
| `spc_ppm` | 0.000 | −27.639 | — |
| demod µs | 1225.9 | 1580.4 | **+354.5（+29%）** |
| resample µs | 1744.3 | 1740.7 | −3.6（噪声） |
| timing µs | 382.7 | 370.9 | −11.7 |
| CFO µs | 44.9 | 64.4 | +19.5 |
| SFD µs | 338.7 | 393.8 | +55.1 |
| **CIR + soft-chip µs** | **399.3** | **688.5** | **+289.2（占 82%）** |
| NS-SFD / PHR / payload µs | 7.9 / 4.2 / 42.9 | 7.8 / 4.5 / 45.3 | +2.6 |
| 检出 SYNC 数 | 256 | 256 | 0 |
| CFO 拟合峰数 | 40 | 40 | 0 |
| FCS | 39/40 | 39/40 | 0 |

**除 CIR/soft-chip 外没有实质差别。** 机制是代码分支切换：
`samples_per_chip != 2` 使 `fractional_grid=true`，软比特 FIR 从 AVX2 整数网格
内核切到**标量分数插值**路径——每个 chip 做两次 38 抽头点积（`dot_at(p0)` 与
`dot_at(p0+1)`）再线性插值，即 2 倍点积且不向量化。

实采与 −27 ppm 夹具的残差只有 +61.5 µs（+3.9%），来自真实噪声/多径/CFO。

**把时钟修好后融合路径确实可用（同一夹具实测）**：

| 夹具 | `--fused` | demod µs | `st_cir` µs | 回退 | FCS |
|---|---|---|---|---|---|
| 0 ppm | off | 1225.9 | 399.3 | 0 | 39/40 |
| 0 ppm | **on** | **980.5** | **95.2** | **0** | 39/40 |
| −27 ppm | off | 1580.4 | 688.5 | 0 | 39/40 |
| −27 ppm | on | 16493.0 | 38.9 | 15754.2 | 39/40 |

**0 ppm 下融合路径把 demod 从 1225.9 压到 980.5 µs（−20%），`st_cir` 从 399 压到
95 µs，零回退。** −27 ppm 下同一开关反而触发 15.8 ms 的整条流回退。

因此两条路都成立：

1. **把 DW3000 的晶振 trim 回 ±1 ppm 以内** —— 融合路径立刻可用，实采预期
   1637 → 约 1000 µs；
2. 或在接收端做逐符号重锚定 / 分数延迟模板 / SFO 预补偿，让融合路径容忍 SFO。

两条都属于解调核心改动，本轮未做。本轮只把**门限的真实含义、实际偏差值、
"调松门限也没用"的定量依据，以及"时钟修好后能拿回多少"的实测证据**记录下来。

#### X410 侧能不能微调晶振

直接查询本机 X410（`uhd::usrp::multi_usrp`，只读）：

```
mboard        : x410
clock sources : mboard internal external nsync gpsdo
master clock rate range: 737280000.000000 .. 737280000.000000 (step 0.000000)
rx rate requested : 737280000.000000
rx rate actual    : 737280000.000000     error +0.0000 ppm, coerced: no
```

- **没有任意 ppm 微调旋钮**：主时钟率是一个单点值（737.28 MHz），由 FPGA 镜像
  决定，`set_master_clock_rate()` 无法移动它。
- `get_rx_rate()` 返回的是**配置值**（主时钟率 / 抽取比），不是测量值。所以
  "0 ppm error" 只说明分频比设置精确，**不能证明晶振准确**。
- 想让 X410 真正准，只能用 `external` 10 MHz 参考、`gpsdo` 或 `nsync`。
- 而且这次的偏差在 DW3000 发送端，trim X410 是修错的那一头。

#### 重采样与单音消除：实机 vs 仿真

这两段是**数据无关**的固定系数运算，所以"实机数据 vs 仿真数据"本身不改变成本。
实测（同一 374,217 样点目标窗，4 worker）：

| 配置 | resample µs | ns/样点 | cancel ms/s |
|---|---|---|---|
| 夹具 0 ppm，`--tone off` | 1744.3 | 4.661 | 0 |
| 夹具 −27 ppm，`--tone off` | 1740.7 | 4.652 | 0 |
| 夹具 0 ppm，`--tone on` | 1825.0 | 4.877 | 82.1 |
| 夹具 −27 ppm，`--tone on` | 1874.2 | 5.008 | 82.0 |
| X410 实采，`--tone on` | 1844.0 | 4.928 | 90.9 |
| `clean_comm` 仿真基准（330,185 样点） | 1677.2 | 5.079 | 不适用 |

**重采样：没有数据依赖。** 同一夹具 0 ppm 与 −27 ppm 相差 0.2%（4.661 vs 4.652
ns/样点）；实采 4.928 相对夹具 `tone off` 的 +5.7%，用同一夹具把 decorator 打开
即可复现（4.877），所以那 5.7% 是**内存竞争**而不是数据内容。实采与夹具
`tone on` 只差 1.0%。

**单音消除：也没有数据依赖，但实机路径比孤立内核慢 2.2–2.4 倍。**

| 测量位置 | ms/s |
|---|---|
| 孤立内核基准（65,536 样点块，无竞争） | **38.1** |
| live 夹具（全流程） | 82.1 |
| live X410 实采（全流程） | 90.9 |

`--tone on` 时 `bypassed_samples=0`、`cancelled_samples` 等于全部样点，说明两边都在
做真正的相减，不是走了旁路。差距来自**内存带宽**：单音消除是纯 load+subs+store，
与环形缓冲拷贝（≈5.9 GB/s）、重采样（≈7.9 GB/s）抢同一条内存通道，合计约
19.6 GB/s。孤立基准独占内存时 38 ms/s，进流水线后 82–91 ms/s。

实采比夹具再高 10.7%，因为实采的 demod 更重（CIR 688 vs 399 µs），worker 占用更多
内存带宽。

**结论**：这两段没有"实机 vs 仿真"的算法差异；差别只来自**是否挂着 decorator**
与**同时有多少 DSP 在抢内存**。`clean_comm` 仿真基准不含单音消除这一步，所以它
与实采之间没有可比的单音数字，只能与孤立内核基准对照。

#### 整数 chip 网格门限：从 1e-9 改为物理推导的漂移预算

融合 CMF 与 AVX2 软比特内核都按整数 `kSamplesPerChip` 网格索引样点，所以真正要问的
不是"samples_per_chip 是否精确等于 2"，而是"整帧累积的网格漂移是否在相关容差内"。

原门限 `|spc − 2| ≤ 1e-9`（0.0005 ppm）比 256 峰周期拟合的**估计器噪声**（实测
1.5–2.2 ppm 逐包 stdev）低约三个数量级，**真实数据永远无法满足**。

新门限按漂移预算推导：

```
最长帧 127 B → BPRF payload 154,624 样点
允许漂移 1.0 样点  ⇒  1.0 / 154,624 = 6.5 ppm
```

代码里是 `kIntegerGridCeilingPpm = 1 / kMaxFramePayloadSamples`（硬上限）与
`kIntegerGridMaxClockPpm`（默认准入值），并新增
`integer_chip_grid()` / `integer_chip_grid_at()` 两个判定函数（各带一个显式容差重载），
替换了 `uwb_demod_core.h` 里全部 5 处 `1e-9`：
`fractional_grid` 判定（软比特内核选择）、两处 `prepare_fused_*_pn` 守卫、
两处 `fused_supported` 守卫。容差本身来自 `Qm35825Profile::fused_gate_ppm`
（`--fused-gate-ppm`），默认等于物理上限。QA 新增
`integer_chip_grid_tolerance_matches_the_drift_budget`，钉住两端：
0.66 / 1.24 / 1.4 ppm 接受、1.6 ppm 与 27 ppm 拒绝、显式容差重载生效、
边界等于文档中的漂移预算、退化输入 fail-closed。

#### 门限默认值：物理上限 6.468 ppm，不是更紧的 1.5 ppm

门限现在可通过 `Qm35825Profile::fused_gate_ppm` 与 `--fused-gate-ppm` 逐次运行调整，
硬上限是 `kIntegerGridCeilingPpm = 1 / 154624 = 6.468 ppm`（1 样点漂移）。

曾试过更紧的 **1.5 ppm（0.23 样点漂移）**，结果**明显更差**，原因是一条被忽略的
耦合链：

```
门限拒包 → fractional_grid = true → 软比特内核从 AVX2 整数网格切到标量分数插值
        → 228,416 chip × 38 抽头 = 15.3 ms/包（而非 110 µs）
```

trim6b 采集（4 worker，2 次）：

| 门限 | 走融合路径 | demod µs | 被拒包的 `st_cir` | FCS |
|---|---|---|---|---|
| 1.5 ppm | 84% | 3549 / 3693 | **15,263** | 203/204 |
| **6.468 ppm（默认）** | **100%** | **1103 / 1128** | — | 203/204 |

**1.5 ppm 比 6.468 ppm 慢 3.2 倍。** 根本原因是 256 峰周期拟合的量化步长约 2 ppm
（实测 stdev 1.5–2.2 ppm），紧门限拒掉的不是坏时钟，而是**估计噪声**；而被拒的包
不是"稍微慢一点"，是掉进 15 ms 的标量分数内核。

所以默认取物理上限。要收紧门限，前提是先有一个比周期拟合更准的时钟估计
（例如用 CFO/载频，实测 ±0.14 ppm，比周期拟合准一个数量级以上）。

#### 顺带修掉：门限拒包与 on-demand 前缀的耦合缺陷

原实现里"是否生成 on-demand 短前缀"由 `--ondemand`（默认跟随 `--fused`）决定，
而"是否允许融合"由门限决定，两者独立。于是门限拒包时前缀仍然被截短（只到 NS-SFD），
PHR 拿不到软比特 → FCS 失败 → 触发整条流重试。

实测后果：1.5 ppm 门限下 16% 的包走这条路径，**16.2 ms/包**（`st_fallback` 15.4 ms），
比常规全前缀（2.6 ms）还差 6 倍。

修法：在 Stage 1 之后**每包只判定一次** `integer_grid_ok`（用 `timing.measured_period`），
并让它同时控制三件耦合的事——第二次 CFO 旋转范围、on-demand 前缀、融合 PHR/payload。
被拒的包直接走完整前缀（2.6 ms），不再触发 16 ms 重试。

## 6. 必须保留的限制

1. **定时路径未上板**。连续模式已在 X410 实机验证（§5.9：10 s，0 丢样点，
   99.3–99.7% 解码，锁稳定）。UHD 定时命令路径（`STREAM_MODE_NUM_SAMPS_AND_DONE`、`stream_now=false`、
   `time_spec`、`num_samps`）本轮**没有实现到 `UhdDeviceSc16Source`**，
   `--mode timed` 无 `--replay` 时 fail-closed 返回 2。因此 §7 的
   "设备定时命令"仍只有计划层与 fake source 证据，没有 X410 证据。
2. **单音消除在 timed 模式下关闭**。现有单音模块按连续流、20 ms 周期、开头 0.5 ms
   训练设计；定时流的训练窗可能落在包上，会把包自身减掉。设备定时单音调度
   （`merge_physical_rx_intervals`）已实现并有 QA，但**未接入 live source**。
   live 入口在 timed 模式显式打印
   `TONE_CANCEL disabled reason=timed_burst_training_unscheduled`。
3. **均值没有显著加速**。见 §5.1。不要引用"锁定后 demod 快 52%"——那是尾部。
4. **`LockedBounded` 有约 0.5% 的包代价**。残差超出 ±256 ROI 的包会被显式判为
   `TIMING_FAILED`，由锁状态机扩窗或重捕获，不会静默降级为宽扫描。
5. **`--locked-roi` 的 64/128 未验证**。规划要求按残差分布决定，本轮只跑了 256。
6. **`max_slot_gap` 与 `reacquire_miss_count` 耦合**：允许的 slot 间隔取二者较大值，
   避免"允许漏包"与"连续失败重捕获"互相矛盾。实际阈值仍需按丢包/时钟漂移标定。
7. **同码同周期同 SFD 的两台设备无法区分**。没有地址/帧身份时，锁不会因为
   "相关最强"而切换目标；这类观测会被 `out_of_grid` 或 `identity_rejects` 挡住，
   但不会给出正确的归属。
8. **未接 SIC**。干扰路径本轮只到事件、时窗与诊断，且**只在连续模式启用**
   （`timed_burst` 的空档不具备自相关可观测性）。把干扰窗提交给现有 SIC 仍是
   独立显式选项，未启用。
9. **未验证**：UHD 上板、RX 溢出、paced 到达、8 worker、P99、MATLAB 交叉验证、
   多径/AWGN/ISR、CFO 扫频与 SFO、timed 模式的实际占空比与设备对齐误差。

## 7. 复现命令

```bash
# 构建
cd gr-uwb/build-cfo-tail-fix && cmake . && cmake --build . -j8

# 全量 QA
env -u LD_LIBRARY_PATH ctest -j1

# 连续模式 A/B（1 s 实采，4 worker）。默认已是 --fused on --cir full。
env -u LD_LIBRARY_PATH ./apps/uwb_dw3000_live \
  --replay ../testdata/x410_fixed_tone_live_20261115/rx_ch3_rx1_1s_trim6b.sc16 \
  --workers 4 --sync acquire --summary 1000
env -u LD_LIBRARY_PATH ./apps/uwb_dw3000_live \
  --replay ../testdata/x410_fixed_tone_live_20261115/rx_ch3_rx1_1s_trim6b.sc16 \
  --workers 4 --sync locked  --summary 1000

# 旧默认对照（融合关闭、CIR 自动）
env -u LD_LIBRARY_PATH ./apps/uwb_dw3000_live \
  --replay ../testdata/x410_fixed_tone_live_20261115/rx_ch3_rx1_1s_trim6b.sc16 \
  --workers 4 --sync locked --fused off --cir auto --summary 1000

# 设备定时 burst（paced fake device）
env -u LD_LIBRARY_PATH ./apps/uwb_dw3000_live \
  --replay ../testdata/x410_fixed_tone_live_20261115/rx_ch3_rx1_1s.sc16 \
  --mode timed --workers 4 --sync locked --timed-t0-ms 3.2646 \
  --timed-lookahead 4 --summary 1000
```

`--timed-t0-ms` 是 `timed_burst` 的初始时隙锚点：定时模式没有盲捕获能力，网格未
对齐时永远看不到目标。该值应由操作员按已知发射时刻给出，或由一次连续模式捕获
测得（本夹具为 3.2646 ms）。
