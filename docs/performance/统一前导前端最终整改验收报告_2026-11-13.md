## 2. 额外已修（超出三点，按“保留已有工作”处理）

**256-SYNC CFO 拟合读取占位相位**：`acquire_preamble()` 的 SFD 锚定全网格中
`peak_corr[0, tail_first)` 是零占位，`fit_cfo` 把 `arg(0)=0` 当相位测量。256 SYNC
下 232 个拟合峰里 216 个是占位。改为**先切出实测尾段再拟合**（64 SYNC 因
`global_skip == tail_first == 24` 逐位不变）。

- 实测：256 SYNC +50 kHz 由 **3908 Hz → 49995 Hz**，`peak_abs` 0.0127 → 0.463，
  FCS/PSDU 恢复通过；新增 `qa_uwb_cfo_fit_coverage.cc`（3 例，0/±50 kHz 精确到
  <1 Hz，`peaks_used == 40`）。
- 连带解除一个 TWR 限制：`qa_uwb_twr_phy_matrix.cc` 原先**把该缺陷写成期望**
  （>64 SYNC 在 20 kHz 下必须失败、白名单只有 {16,64}）。现所有长度 CFO 精确，
  白名单变为 PHR 可描述性决定的 **{16, 64, 1024}**。两处断言已改为更强的不变式
  （stock 与“跳过合成峰”workaround 逐项一致）。

## 3. 配对性能（单 worker，256SYNC/127B，116 tap，同输入）

`tools/sic/benchmark_sensing_paired.cc` 同一源码分别对 `921c38f` 与候选编译，
A/B/B/A 交错，3 组 × 每 slot 32 = **每臂 192 次**，预热 32，单 session，
独占 `/tmp/uwb-sic-benchmark.lock`，`taskset -c 2`。

| 臂 | n | mean | P50 | P95 |
|---|---|---|---|---|
| 整改前 `921c38f` | 192 | 1234.34 µs | 1195.86 | 1466.03 |
| 整改后 | 192 | **630.68 µs** | **579.10** | **779.24** |

**ratio 0.5109（mean）/ 0.4843（P50）/ 0.5315（P95），提速 1.96×（−48.9%）**。
每臂 192/192 次 `peak_tap=18`、`tap_count=116` 与参考一致，两臂输出等价。

comm 健全性（非验收）：`demodulate_one` 64/32 由 1077.66 → 1055.91 µs
（ratio 0.980），`stage_cir_us` 769.65 → 773.27 µs（+0.47%），无异常。

## 5. 测试状态

候选 build 串行全量：**85 项，81 通过，3 失败，1 跳过**（120 s）。
3 项失败为既有失败，已在 `bd311cd` 干净 worktree 复现：
`uwb_qa_uwb_pdu_rational_resampler_65_32_workers.cc`、
`uwb_qa_uwb_fullpacket_cfo_diag.cc`、`uwb_qa_uwb_preamble_sic_core.cc`。

本轮为使 R04 后的 QA 确定性而修正的**测试前提**（非放宽断言）：
`qa_uwb_radar_cir_estimator_block` 的队列/生命周期用例改为预建 PMT 负载并等待
投递完成（R04 让 worker 快 4×，原“生产者必然跑赢消费者”的前提失效）；
`qa_uwb_preamble_frontend` 的 epoch 用例改为给前 24 个 SYNC 加额外频偏，构造真实的
bootstrap ≠ final，而不再依赖已被修复的零占位相位。
