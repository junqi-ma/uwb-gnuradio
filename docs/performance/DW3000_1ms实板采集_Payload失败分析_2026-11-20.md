# DW3000 1 ms 实板采集 1 s：成功率与 Payload 失败分析（2026-11-20）

本报告分析 DW3000 以 1 ms 周期连续发送时，X410 采集 1 s 原始 SC16 后的离线
解调结果，重点定位 3 个 `PAYLOAD_FAILED` 包。证据为实板采集 + 文件回放，
**不是仿真，也未做 MATLAB 逐样点交叉验证或 TWR**。

- 代码基线：`5ce858a`（`feature/sic-research`）
- 采集工具：`uwb_uhd_sc16_capture`，本地新增 `--uhd-antenna` 选项（未提交）
- 数据与日志：
  [data_dw3000_1ms_payload_20261120](data_dw3000_1ms_payload_20261120/README.md)

---

## 1. 结论摘要

| 口径 | 成功 / 总数 | 成功率 |
| --- | ---: | ---: |
| 目标 slot（`path=target`） | **986 / 992** | **99.40%** |
| 全部提交窗口（含采集候选） | 1002 / 1047 | 95.70% |

目标包失败 6 个：`SFD_FAILED` 3 个、`PAYLOAD_FAILED` 3 个。3 个 payload
失败不是 FCS 边界问题，也不是数据丢失，而是：

> acquire 阶段的 SYNC 周期最小二乘拟合出现约 7–9 ppm 的离群偏置，超过
> 6.468 ppm 的整数网格门限；解调因此关闭 on-demand/fused 路径，改用带这个
> 偏置 `samples_per_chip` 的 legacy 分数网格。payload 后段累积漂移约
> 1.1–1.4 个样点，Viterbi 后 RS 译码失败，没有产生任何 PSDU 字节。

同一 legacy 解码器在周期估计正确时（`--sync locked`）可以解出这 3 个包；
`--taps eq32`、`--taps quality` 或 `--timing-sparse off` 也能让周期估计回到
0 ppm 并全部解出。因此问题在 **timing/周期估计**，不在 payload 解码器本身。

## 3. 离线分析方法

```sh
uwb_dw3000_live --replay dw3000_1ms_1s.sc16 \
  --period-ms 1 --workers 1 --seconds 2 \
  --print packets --summary 100
```

- paced 回放，处理时长与文件 1 s 对齐。
- 默认配置：`--sync acquire --cir full --fused on --ondemand on --taps eq16
  --timing-sparse on --tone on`。
- 单 worker；日志中 `raw_drop_samples=0`、`source_errors=0`、`gaps=0`、
  `dropped_queue=0`，因此本报告的成功率不含 live 前端的队列/丢样影响。
- 统计以 `PACKET` 行为准：成功 = `status=OK && fcs=1 && crc=1`。
  `path=target` 表示锁定后的周期目标窗口，`path=acquire` 表示采集阶段的
  候选窗口，两者分开统计。

（`LOCK_STATS` 中的 `fcs_ok=990` 是进锁身份观测计数，含候选/重复观测，
与逐包 `PACKET` 计数口径不同；本报告不使用它作为 PRR 分子。）

## 4. 成功率与失败分布

### 4.1 目标 slot

- 目标 slot 范围 5–996，共 992 个，**无缺槽、无重复**。
- 成功 986，失败 6：

| 失败状态 | 数量 | 说明 |
| --- | ---: | --- |
| `SFD_FAILED` | 3 | slot 128 / 784 / 980，SFD metric=0，未进入 PHR |
| `PAYLOAD_FAILED` | 3 | slot 253 / 401 / 468，SFD/PHR 正常，payload RS 失败 |

payload 失败占目标包的 0.30%，占全部目标失败的 50%。

### 4.2 全部提交窗口

1047 个提交窗口中成功 1002（95.70%），失败 45：

| 状态 | 数量 | 占失败 | 主要来源 |
| --- | ---: | ---: | --- |
| `TIMING_FAILED` | 28 | 62.2% | 全部为 acquire 候选（`sync=0`），非目标包 |
| `SFD_FAILED` | 12 | 26.7% | 9 个 acquire 候选 + 3 个目标包 |
| `PAYLOAD_FAILED` | 3 | 6.7% | 全部为目标包 |
| `INCOMPLETE_WINDOW` | 2 | 4.4% | 采集首尾边界 |

acquire 阶段的 55 个候选窗口中 16 个成功、39 个失败；这些失败不应计入
1 ms 链路的 PRR。

## 5. 3 个 payload 失败逐包定位

三者共同点：`sfd=1`、`phr=1`、`len=127`，但 `psdu=` 为空，说明
`rs_decode_stream` 失败，而不是 RS 成功后的 FCS 不匹配
（`finish_rs_crc_payload` 在 RS 失败时不会产生 `bytes`）。

| slot | time_ms | CFO kHz | tmetric | sfdmetric | cirmetric | spc_ppm | 漂移(样点) | 路径 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 253 | 255.577 | 5.687 | 0.2411 | 0.3244 | 0.5943 | -9.587 | 1.35 | legacy |
| 401 | 403.577 | 4.706 | 0.2973 | 0.2942 | 0.6032 | -7.704 | 1.06 | legacy |
| 468 | 470.577 | 5.816 | 0.3310 | 0.3235 | 0.5799 | -9.037 | 1.27 | legacy |

三者均为：

```text
grid_reject=1  st_fused=0  pay_legacy_calls=1  pay_fused_calls=0
```

即整数网格准入被拒，没有运行 fused PHR/payload CMF，走 legacy 全流软 chip 路径。

同一份数据中还有 3 个目标包也被网格拒绝，但解码成功：

| slot | 状态 | spc_ppm | 漂移(样点) |
| ---: | --- | ---: | ---: |
| 9 | OK | -15.911 | 2.33 |
| 85 | OK | -10.626 | 1.51 |
| 295 | OK | -6.601 | 0.89 |

说明偏置超过 1 个样点不是“必然失败”：legacy 解码在边界上具有概率性，
最终是否失败还取决于该包的 SNR/ISI 余量。3 个失败是“周期偏置 + 边际信道”
的共同结果，但偏置是把它们推过解码边界的可控因素。

> 漂移按 `spc_ppm × 154,624 samples` 估算。154,624 是代码中 127 B BPRF
> payload 的最大跨度（`kMaxFramePayloadSamples`）；6.468 ppm 对应 1 个样点。

## 6. 根因分析

### 6.1 周期估计偏置

- `samples_per_chip` 由 `stage_timing` 的 `measured_period / 508` 得到。
- `measured_period` 是 SYNC 峰位置对重复索引的普通最小二乘斜率
  （`uwb_demod_timing.h`，peak positions 为整数样点）。
- 本段数据的真实时钟由锁定统计给出：`period_ppm = -0.834`。
- 3 个失败包的 `spc_ppm` 为 -9.587 / -7.704 / -9.037，相对真实值偏
  -8.75 / -6.87 / -8.20 ppm。
- 在 127 B payload 上分别对应 1.35 / 1.06 / 1.27 个样点的累积网格漂移，
  超过“1 个样点”的网格物理余量。
- 多数包（702/992）`spc_ppm=0.000`，峰位严格落在 1016 样点栅格上；
  少数包因峰位抖动使斜率成为离群值。

### 6.2 门限与回退链

`plan_packet_execution()`（`uwb_demod_execution.h`）用
`integer_chip_grid(spc_hat, fused_gate_ppm)` 判断整数网格：

- 门限默认 `kIntegerGridCeilingPpm = 1 / 154624 × 1e6 = 6.468 ppm`
  （`uwb_demod_grid.h`）。
- 超门限时关闭 `rx_softchip_on_demand`、`rx_fused_payload_cmf`、
  `rx_fused_phr_cmf`、`rx_fused_sfo_track`，走
  `run_primary_full_stream_decode()`。
- legacy 软 chip 路径直接把 `period / 508` 当分数网格
  （`uwb_demod_softchips.h`）；它没有 fused 路径的整数 2 spc 网格 +
  8-bin 分数相位 CIR 库 + joint-ML 解码兜底。
- 因此同一个偏置在 fused 路径会被“吸附”到整数网格，在 legacy 路径则
  直接变成采样网格漂移。

### 6.3 隔离实验

同一抓包，只改一个条件：

| 配置 | 3 个焦点包 | spc_ppm | 路径 | 目标包成功 |
| --- | --- | --- | --- | ---: |
| 基线 `eq16 + sparse + acquire` | 全部失败 | -9.6 / -7.7 / -9.0 | legacy | 986/992 |
| `--taps eq32` | 全部 OK | 0 / 0 / 0 | fused | 988/992 |
| `--taps quality` | 全部 OK | 0 / 0 / 0 | fused | 989/992 |
| `--timing-sparse off` | 全部 OK | 0 / 0 / -5.7 | fused | 991/993 |
| `--sync locked` | 全部 OK | -4.1 / -5.3 / -1.5 | fused | 991/991 |
| `--cfo-refit auto` | 全部失败 | 同基线 | legacy | 986/992 |
| `--cfo-refit skip` | 全部失败 | 同基线 | legacy | 982/991 |
| `--ondemand off` | 全部失败 | 同基线 | legacy | 985/991 |
| `--fused off --sync acquire`（4 worker） | 全部失败 | 同基线 | legacy | 986/992 |
| `--fused off --sync locked`（4 worker） | 全部 OK | 0 / 0 / -0.65 | legacy | 990/990 |
| `--taps eq32 --fused off --sync acquire`（4 worker） | 全部 OK | 0 / 0 / 0 | legacy | 990/994 |

带 `--fused off` 的行使用 4 worker / `--queue 256`，仅用于隔离 legacy 解码器；
1 worker 的 legacy 全流在 1 ms 周期下会队列溢出（`var-fusedoff` 中 471 个
`DROPPED_QUEUE`），不能用于成功率对比。其余行均为单 worker。

关键行：

1. `--fused off --sync acquire` 仍复现 3 个失败，且 spc 值与基线完全相同；
   此时 `grid_reject=0`（因为 fused/on-demand 关闭后不做该准入），
   说明失败跟随的是 **acquire 周期估计**，不是 fused 回退动作。
2. `--fused off --sync locked` 用同一个 legacy 解码器，周期估计回到约 0，
   990/990 全部成功。
3. `--taps eq32 --fused off --sync acquire` 也全部成功，说明 legacy 解码器
   本身没有问题；改变重采样滤波器质量即可消除周期拟合离群。

因此因果链是：

```text
eq16 重采样 + 稀疏 timing 模板
  → 个别包 SYNC 峰位 ±1 样点抖动
  → measured_period 最小二乘斜率偏 7–9 ppm
  → 超过 6.468 ppm 网格门限
  → legacy 分数网格使用偏置 spc
  → payload 后段网格漂移 1.1–1.4 样点
  → 软 chip/去扩频 ISI 增大，Viterbi 后 RS 失败
  → PAYLOAD_FAILED（无 PSDU 字节）
```

### 6.4 为什么不是 FCS/CRC 或解码器缺陷

- 3 个包 `sfd=1`、`phr=1`、`len=127` 正确；失败只在 payload。
- `psdu` 为空：`rs_decode_stream` 未成功，未进入 CRC 比较。
- 同一个 legacy 解码器在 `--sync locked`（spc≈0）下全部成功。
- `--cfo-refit auto` 与基线结果完全一致，说明 CFO 二次重估不是本组失败的原因；
  `--cfo-refit skip` 反而新增 3 个 payload 失败，说明 CFO 重估对 payload
  有独立贡献，但不是这 3 个包的主因。

## 7. 建议

### 7.1 运行配置

1. 1 ms 连续接收优先 `--sync locked`：本抓包 991/991，无 payload 失败，
   且锁定后稳态耗时最低。
2. 若必须保持 acquire，可用 `--taps eq32`（或 `quality`）或
   `--timing-sparse off`；两者本次都能消除这 3 个失败。
3. 不建议把 `--fused-gate-ppm` 抬到 6.468 以上：该值是“127 B frame 漂移
   1 个样点”的物理上限，真实 27 ppm 时钟会被错误接纳；应修估计量而不是放宽门限。

### 7.2 代码改进（按优先级）

1. **稳健周期拟合**：在 `uwb_demod_timing.h` 的峰位拟合中加入
   残差门限和 outlier 剔除（或用 Theil–Sen / 中位斜率）。残差超限时
   回退到锁定网格周期、上一次可信周期或 `period` hint。
2. **失败重试**：当 `grid_reject` 且 legacy FCS 失败时，增加一次
   “整数网格重试”（把 spc 吸附到最近的整数），而不是用同一偏置参数
   重复全流解码。重试应有明确上限，避免低 SNR 下耗时翻倍。
3. **周期先验**：连续模式下已有 `period_samples=737279` 和
   `period_ppm≈-0.8` 的长期估计，可把它作为单包周期拟合的强先验，
   仅在残差显著改善时接受单包估计。
4. **CFO 推导 SFO（已实现，默认开启）**：在同源晶振硬件上，由 Stage-2
   `fit_cfo` 与 `carrier_freq_hz`（live `--freq`）直接按
   `1016 / (1 + cfo_hz / carrier_freq_hz)` 推导 `measured_period`
   （`Qm35825Profile::rx_sfo_from_cfo = true`，`uwb_dw3000_live --sfo-from-cfo on|off`）。

## 8. 局限与未验证事项

- 仅 1 次 1 s 采集、1 种 payload（127 B）、1 个 worker；payload 失败样本只有 3 个，
  统计置信度有限。
- 真实 `samples_per_chip` 由解调器报告值和锁定 `period_ppm` 反推，
  没有对每条 SYNC 峰位做离线逐点重拟合；漂移数值是机理估算。
- 未做 MATLAB 逐样点/逐包交叉验证，未做 TWR，未验证上板实时链路的
  长期稳定性。
- 文件回放无 live 前端丢样和队列影响，所以本报告 99.40% 不能直接等同于
  live 运行 PRR；此前同一设备 15 s live 运行的目标包 PRR 约 97.8–97.9%，
  差异主要来自前端/调度，不是本报告的 payload 失败。
- 采集使用了本地未提交的 `--uhd-antenna` 选项；代码基线为 `5ce858a`。
