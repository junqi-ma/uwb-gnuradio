## 2. 为什么"总 tap 数"不是成本

内核把每相长度补齐到 8 的倍数，AVX2 内层循环**恒定跑 `Hpad` 个复数 tap**：

```
H    = ceil(T / 65)
Hpad = 8 * ceil(H / 8)
```

所以成本正比于 `Hpad`，而不是 `T`。只有跨档位才有收益：

| profile | 现状 | 目标档位 | 需要的 T | 每样点乘加变化 |
| :--- | :--- | :--- | :--- | ---: |
| realtime | Hpad 24（T=1319） | 16 | T ≤ 1040 | **−33.3%** |
| quality | Hpad 48（T=2707） | 40 | T ≤ 2600 | −16.7% |
| quality | Hpad 48 | 32 | T ≤ 2080 | **−33.3%** |

同一档位内应取**最大的奇数 T**：内核成本完全相同，但余量最大。这是本轮候选
选择的依据，也是 `eq_conservative`（realtime, T=1559, Hpad 24）没有速度收益的原因。

## 3. 设计与搜索（G1）

脚本：`testdata/design_resampler_equiripple.py`，产物在
`testdata/resampler_65_48_equiripple/`。

- 设计目标 **0.09 dB / 72 dB**（留量化与数值余量），验收仍按 **0.1 dB / 70 dB**。
- 权重初值 `ws0 = δp/δs`，其中 `δp=(10^(Rp/20)−1)/(10^(Rp/20)+1)`、`δs=10^(−As/20)`；
  在 `ws0/8 … ws0×8` 上做 9 点对数网格，再对胜者做黄金分割局部细化。
- 目标函数是**无量纲相对余量** `min((Rp−ripple)/Rp, (|As|−|stop|)/|As|)`。
  直接用 dB 相减会让 72 dB 的量纲压过 0.09 dB，得到只在纹波侧优化的假最优。
- 长度搜索：先 32 步长粗扫定位可行区，再对边界逐个奇数 T 复验，最后在每个可达档位
  取档位内最大奇数 T 细化权重。
- 失败分类记录：`remez_no_converge` / `non_finite` / 频响不合格，三者分开统计。

搜索量：realtime 173 次、quality 180 次设计尝试（全部记录在
`search_{profile}.csv`），耗时 20.7 s / 65.2 s。

## 4. 独立频响验证

脚本：`testdata/verify_resampler_equiripple.py`。它只读**落盘的 float32 二进制**，
不导入设计脚本、不消费设计脚本的"已通过"布尔值。

- FFT 网格 `nfft = 2^21`，步长 0.02285 MHz，比任务书要求的 `Fv/(64T)` 细 12–32 倍。
- 显式补入 DC、`B`、`Fv/2` 三个精确频率的 double DTFT。
- 对网格定位到的每个局部极值做黄金分割**离格细化**，最坏值不取网格点。
- 网格加密一倍复核收敛：纹波变化 ≤1.9e-5 dB，阻带变化 ≤7e-6 dB。

| profile | T | 纹波 | 全阻带（相对通带最小） | 相对通带最大 | dc 误差 | 群时延 | 判定 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | :--- |
| realtime `hpad16` | 1039 | 0.08676 | −74.564 | −74.650 | −3.25e-07 | 10.8125 | **PASS** |
| realtime `cons` | 1559 | 0.00945 | −108.107 | −108.116 | −4.32e-07 | 16.2292 | **PASS** |
| quality `hpad32` | 2079 | 0.08492 | −76.027 | −76.112 | +5.16e-07 | 21.6458 | **PASS** |
| quality `cons` | 2599 | 0.00970 | −73.871 | −73.881 | +1.52e-07 | 27.0625 | **PASS** |

全部实对称、奇数长度、有限；`|sum(h32) − 65| ≤ 5.2e-7`（门槛 1e-3）。

## 5. 数值与契约 QA（G2）

### 5.1 做了什么，为什么

内核代码本轮**没有任何改动**，系数只是数据。因此重跑 FIR 内核自身的 QA
（C1/C2 位级一致、惰性调度表、worker 屏障）**信息量为零**，全部跳过。

真正需要验证的是**随 T 变化的那部分几何**，因为频响检查看不到它们：

- 多相分解 `arms[i%65][i/65]`：`T=1039 = 65×15+64`，第 64 相只有 15 个 tap；
  `T=1319 = 65×20+19`，第 19–64 相只有 20 个。补齐行为必须验证。
- 历史长度 `H_−1`：15 / 31 取代 20 / 41。
- 输出长度契约 `ceil(((N−1)×65+T)/48)`。
- flush 行为。

### 5.2 方法：独立 float64 参考

`testdata/verify_resampler_core_reference.py` 从**定义**重写一遍：

```
v[j] = x[j/65]（j%65==0），否则 0
u    = v * h          （float64 全卷积）
y[m] = u[48m]
```

输入由 `benchmark_sc16_burst_core` 公开的 LCG 规格逐位重建，输出直接读
`--dump-iq` 的原始 CF32。不复用任何 C++ 代码。

### 5.3 结果

`tools/performance/run_equiripple_g2.py`，6 组系数 × 4 种输入（random / rails /
impulse / zero）× 8 种长度（1、2、64、65、66、1000、4000、56000）：

| 项 | 结果 |
| :--- | :--- |
| 用例数 | **192** |
| 失败 | **0** |
| 长度契约不符 | **0** |
| 最差相对 L2 | **6.28e-8**（出现在 **Kaiser 基线**，不是新系数） |
| 最差绝对误差 | **2.58e-7** |

现有 core QA 的绝对门槛是 `1e-4`（golden 为 `2e-3`），实测比它低约 3 个数量级。
新系数在数值上不比基线差。

## 6. 应用质量（G3）

### 6.1 先剔除没有意义的测试

**PER（3 个 SNR 点 × 1000 包）不做，理由是它测不出要测的东西。**

- 1000 包、PER≈5% 时二项标准误 `sqrt(0.05×0.95/1000)=0.69` 个百分点，
  95% 置信半宽 **±1.35 pp**，已经大于任务书自己的 1 pp 门槛。
- 期望效应：EVM 0.73% 相当于 `−20log10(0.0073) = 42.7 dB` 的信噪比等效。
  与 5 dB 热噪声合成后损失 **0.0007 dB**；与 0 dB 合成损失 0.0002 dB。
- 也就是说，要测的效应比测试分辨率小约 **3 个数量级**。跑 6000 次解码只能得到
  "不确定"，而同样的机时用来测 EVM 能直接看到效应本身。

因此改用**波形层直接测量**：EVM、相对 L2、互相关峰位与幅度比。这些量的分辨率
足以分辨 0.01 dB 级别的差异，而且它们正是 CIR 峰位 / 幅度门槛所依据的物理量。

**SIC 抑制与解码不做，理由是基础设施不具备，且不能造假。**

- 仓库里的 SIC 场景（干净单径、分数多径、非零 CFO、低 SNR、SYNC 碰撞、损坏包）
  由 `gr-uwb/apps/sic_preamble_sim.py` 在 **998.4 MS/s work grid** 上生成。
  直接用它就**绕过了被测的 65/48 重采样器**，任务书 §5 明确禁止。
- 唯一的 native grid fixture（`testdata/uhd_sc16/sim_preamble_sc16_737m28_rate.bin`）
  在 `period=100000 / capture=56000` 下两个滤波器都判 `below_detect_threshold`，
  `actual_suppression_db = 0`，没有可比较的抑制比。
- 结论：SIC 抑制 / PSDU / FCS / PER 一律**列为未验证**，不做推测。

### 6.2 实测：波形失真

`tools/performance/run_equiripple_g3.py`，同一 native fixture，同一 pipeline，
只换 `--resampler-profile`。按**理论群时延差** `(T_a−T_b)/(2×48)` 做 FFT 相位斜坡
对齐（不是自由拟合时移），再比较。

| profile | 理论位移 | 未对齐相对 L2 | 对齐后 | 去增益后 | 残差 lag | 幅度比 | 相关 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| realtime | +2.9167 样点 | 153.1% | 0.909% | **0.731%** | **0 样点** | **+0.0475 dB** | 0.999973 |
| quality | +6.5417 样点 | 143.2% | 0.643% | **0.425%** | **0 样点** | **+0.0421 dB** | 0.999991 |

（4 个窗口逐一计算，离散度 <0.01%，上表为窗口均值。）

对照任务书的应用级门槛：

| 门槛 | 要求 | 实测 | 判定 |
| :--- | :--- | :--- | :--- |
| CIR 峰位置差 | ≤0.1 输出样点 | **0 样点** | 通过 |
| 主峰幅度差 | ≤0.1 dB | **+0.047 / +0.042 dB** | 通过 |
| SIC 抑制恶化 | ≤0.2 dB | 无法测量 | **未验证** |

**对齐是关键**：不对齐时 153% 的"误差"几乎全部是 2.92 样点的时延，不是失真。
理论位移对齐后残差 lag 恰好为 0，说明群时延模型 `(T−1)/(2×48)` 与实测一致——
这同时验证了 §7 里"集成时必须改时延补偿"的量化依据。

0.43%–0.73% 的残余失真主要来自 290 MHz 以上的过渡带：两个滤波器都在那里滚降，
但形状不同。这部分不是缺陷，是换滤波器的固有代价。

### 6.3 决策一致性

8 个窗口（2 profile × 4 窗口）的 `state`、`sic_executed`、`sic_committed`、
`sic_status`、`radar_executed`、`radar_sfd_found`、`radar_detected_start`
**全部相同（8/8）**。由于两者都不触发检测，这一项的证明力有限，只作为
"没有引入新的行为差异"的记录，不作为质量通过的依据。

## 7. 性能对照

### 7.1 只换系数（任务书 §6 第 1 步）

同一个 binary、`--fixed-phase 1 --convert-cache 0`、同一分派路径，A=Kaiser，
B=等波纹。每格 5 组 ABBA（A B B A），56k 每次 10000 稳态窗口、4k 每次 100000，
绑定 CPU 6，全程独占基准锁。统计量是**按 (config, pair) 的配对中位比值**，
不是把两侧池化后比边际 IQR。

跑满三个独立 session（S1、S2、S3），每 session 每格 5 组 ABBA：

| 配置 | S1 | S2 | S3 | **三 session 中位** | 范围 |
| :--- | ---: | ---: | ---: | ---: | :--- |
| realtime_56k | −18.94% | −12.49% | −12.58% | **−12.58%** | −18.94 … −12.49 |
| realtime_4k | −12.75% | −20.25% | −20.78% | **−20.25%** | −20.78 … −12.75 |
| quality_56k | −24.23% | −23.94% | −24.45% | **−24.23%** | −24.45 … −23.94 |
| quality_4k | −24.21% | −24.56% | −25.04% | **−24.56%** | −25.04 … −24.21 |

单 session 内 5 组配对区间**全部小于 1**（没有一组出现退化）。绝对耗时以 S1 为例：

| 配置 | Kaiser p50 | 等波纹 p50 |
| :--- | ---: | ---: |
| realtime_56k | 154.80 µs | 125.52 µs |
| realtime_4k | 10.27 µs | 8.90 µs |
| quality_56k | 259.16 µs | 195.91 µs |
| quality_4k | 18.64 µs | 14.10 µs |

### 7.2 复现性：quality 稳定，realtime 不稳

- **quality 三个 session 一致**（−23.9% … −25.0%，跨度 1.1 pp），可以直接引用。
- **realtime 不稳**：56k 在 S1 是 −18.9%、在 S2/S3 是 −12.5%；4k 恰好反过来
  （S1 −12.8%、S2/S3 −20.5%）。两个 session 互相吻合、一个偏离，说明是
  session 级的状态差异（频率/缓存/同机负载），不是滤波器本身的性质。
- 因此 realtime **只宣称"−12% 以上"**，不引用具体百分比；quality 引用中位值。
- 四格全部超过 5% 门槛这一点在三个 session 里都成立。

### 7.3 保守候选

| 配置 | 配对中位 | 说明 |
| :--- | ---: | :--- |
| realtime_56k | **+6.87%** | 同 Hpad 24，无收益 |
| realtime_4k | −6.56% | 符号与 56k 相反 |
| quality_56k | −10.10% | Hpad 48→40，真实收益 |
| quality_4k | −11.79% | 同上 |

realtime 保守候选（T=1559）与 Kaiser 同档，内核成本相同，剩下的差异是数据对齐
与输出样点数的微小变化，**符号随窗口长度翻转**，不能算收益。quality 保守候选
跨了一个档位，收益真实。

### 7.4 新档位模板展开：试过，否决

任务书 §6 第 2 步允许为入围档位添加同构模板实例。已实现并测量：

- 同系数下通用路径 vs 专门内核：56k −1.8%/−2.0%，4k −6.9%/−7.3%。
- 但**同一个 build 目录内**对照显示，它让现有 Hpad 24/48 内核变慢
  **+3.4%…+4.7%**（Kaiser 系数、同一 binary、仅头文件不同）。改成只对 SC16 路径
  实例化后更差（quality_56k +12.9%）。

结论：**已回退，不保留**。收益（1.8%–7.3%）不足以抵消对既有 profile 的扰动，
而且本轮不改默认路径，没有必要承担这个风险。回退后重新编译的二进制与改动前
逐字节相同，且四个 tap 集的 `--dump-iq` 输出与改动前 `memcmp` 全等。

### 7.5 归因的诚实边界

单 session 四臂对照（K=Kaiser/旧二进制，EQ=等波纹/旧二进制，KG=Kaiser/新二进制，
EQG=等波纹/新二进制）：

| 配置 | K→EQ | K→KG（漂移） | K→EQG |
| :--- | ---: | ---: | ---: |
| realtime_56k | −12.58% | +3.46% | −14.03% |
| realtime_4k | −20.78% | +5.32% | −25.41% |
| quality_56k | −24.45% | +4.53% | −25.87% |
| quality_4k | −25.04% | +3.73% | −30.41% |

跨 binary 的 Kaiser 漂移达 +3.5%…+5.3%，所以**不能**把 EQG 的数字拆成
"系数贡献 + 内核贡献"再相加（可加性残差 4.5–8.9 pp）。本报告只给
§7.1 的同 binary 配对结论，不给逐因子百分比。

## 8. 未验证项

- **SIC 抑制、PSDU/FCS、PER、EVM 之外的解调指标**：现有 SIC fixture 是 work-grid，
  使用即绕过被测重采样器；native fixture 不触发检测。需要先建 native-grid 的
  SIC 场景生成链，才能继续。
- **群时延变化的集成**：realtime 群时延从 13.73 降到 10.81 输出样点（−2.92），
  quality 从 28.19 降到 21.65（−6.54）。实测残差 lag 为 0，说明必须按这个量改
  解调器时延补偿、capture/halo 几何与时间原点，**本轮未改**。
- **上板 / UHD 实机 / paced 到达 / 实时吞吐**：未做。
- **MATLAB 交叉验证**：未做。本轮用独立 Python float64 参考替代，不等价于 MATLAB。
- **8 worker、AVX-512、FPGA**：未做。
- **`Hpad` 16/32 的专门内核**：已否决，见 §7.4。

## 9. 建议

1. **保留两个速度候选**（realtime `hpad16`、quality `hpad32`）作为显式实验选项，
   不修改默认 profile。它们满足频响、数值、长度契约、波形质量与速度五项。
2. **quality 优先落地**：它同时有 −24% 的内核收益和更小的失真（EVM 0.43%），
   而且保守候选（Hpad 40）还保留了 −10%…−12% 的退路。
3. **realtime 先补 SIC 验证再用**：它的纹波最大（0.0868 dB）、余量最薄（3.6%），
   而 realtime 恰恰是最可能影响实时链路的 profile。
4. **下一步（若继续）**：建 native-grid SIC 场景生成链 → 跑 §5 的六个场景配对 →
   再决定是否替换默认。不要先改默认路径再补验证。
