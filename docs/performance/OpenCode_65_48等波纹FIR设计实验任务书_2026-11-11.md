# OpenCode：65/48 等波纹 FIR 设计实验任务书

日期：2026-11-11。规划时源码 HEAD：`170c551d1802d861227f4e24144073dca64df747`。

## 1. 目标与范围

为 SC16 737.28 MS/s → 998.4 MS/s 的 65/48 多相重采样设计等波纹线性相位 FIR，验证能否在既定频响和 UWB 接收质量约束下，降低实际计算成本。交付可复现设计脚本、候选系数、独立验证、同环境性能对照与推荐结论。

本轮是显式实验，不覆盖旧系数，不修改默认 profile，不更改采样率、带宽或阻带门槛；不上板、不安装、不推送、不扩展到 65/32。不做多级、Farrow、FFT 重采样，不夹带 RX 流水线重构。设计不成功也是有效结论，禁止为交付收益而放宽门槛。

当前 Kaiser 脚本只是从估算阶数向上搜索，不是全局最小阶证明。Remez 也是给定长度和权重下的数值设计；报告应称“已搜索范围内最短合格候选”，不能声称已达所有 FIR 算法的理论下限。

## 2. 冻结基线与频响规格

先记录实际 HEAD、工作区差异、编译参数、加载库、系数 SHA256、NumPy/SciPy 版本、CPU/虚拟化环境。不得覆盖已有未提交文件。

基线文件：`testdata/design_resampler_minorder.py`、`testdata/resampler_65_48/design_minorder.json` 和 `taps_{realtime,quality}_minorder.txt`。注意 `.txt` 实际是 float32 二进制；以运行加载的二进制为准，CSV 不能代替。

| 项目 | realtime | quality |
|---|---:|---:|
| 通带边缘 B | 290 MHz | 330 MHz |
| 阻带起点 Fin−B | 447.28 MHz | 407.28 MHz |
| 基线总 tap 数 T | 1319 | 2707 |
| 最长分相长度 ceil(T/65) | 21 | 42 |
| 当前 AVX2 补齐长度 Hpad | 24 | 48 |
| 历史设计记录通带纹波 | 约 0.00529 dB | 约 0.00497 dB |

统一设计采样率 Fv = 65×737.28 MHz = 47.9232 GHz；设计实对称、奇数长度 Type-I FIR，归一化后 DC 增益为 65。

加载后 float32 系数必须满足：

- 通带 `[0,B]`：`20log10(max|H|/min|H|) ≤ 0.1 dB`。
- 全阻带 `[Fin−B,Fv/2]`：`20log10(max_stop|H|/min_pass|H|) ≤ −70 dB`。采用通带最小值作参考，比旧脚本以最大值作参考略严格，报告同时给出两种口径，不静默混用。
- 用 float64 累加已量化系数：`abs(sum(h32)−65) < 1e−3`；全部有限、实对称。
- 不对过渡带增加平坦度要求，但必须展示过渡带峰值与时域振铃。

旧脚本只检查阻带起点至 500 MHz；先用本轮全阻带验证器重验旧系数并如实报告。旧系数失败不等于候选可降低门槛，也不能把两套验证范围直接比较。

## 3. 设计与搜索

新增 `testdata/design_resampler_equiripple.py`，产物置于新的 `testdata/resampler_65_48_equiripple/`。支持命令行指定 profile、长度范围、权重范围、设计余量与输出目录，保存成功和失败记录。

使用 `scipy.signal.remez`，归一化频率避免单位混淆：

```python
h = remez(T, [0, B/Fv, (Fin-B)/Fv, 0.5], [1, 0],
          weight=[1, ws], fs=1.0, maxiter=100, grid_density=32)
h = h * (65.0 / h.sum())
h32 = h.astype('<f4')
```

该代码只是设计入口，返回成功不构成合格。DC 归一化、float32 量化之后必须重验全部规格，不得只验 double 设计结果。

搜索方法：

1. 主搜索建议以 0.09 dB / 72 dB 作为设计目标，留出量化和数值余量；正式验收仍按 0.1 dB / 70 dB。若余量导致无收益，可另列贴规格边界候选，不修改验收线。
2. 权重初值可取 `ws = delta_p/delta_s`，其中 `delta_p=(10**(Rp/20)-1)/(10**(Rp/20)+1)`、`delta_s=10**(-As/20)`；在该值两侧做对数网格搜索，再局部细化。归一化和相对阻带定义会影响结果，公式仅用于初值。
3. 先粗扫长度定位可行区域，再对边界逐个奇数长度复验，记录不收敛、非有限和频响不合格的区别。不得把单次 Remez 不收敛解释为数学不可行；边界失败用更高 grid_density/maxiter 重试并保留日志。
4. 每个 profile 保留最多三类候选：搜索范围内最短合格、最快 SIMD 档位候选、保守纹波候选（例如 ≤0.01 dB）。去掉重复项。先做廉价频响筛选，少量入围者才跑完整 UWB 与性能。
5. 不能只按总 T 排序。报告 `T`、每相长度、`Hpad=8*ceil(ceil(T/65)/8)`、65 相系数和的范围、实际内核名称及系数内存。

优先观察的档位：realtime 从 Hpad=24 降到 16，要求奇数 T≤1039；quality 从 48 降到 40，要求 T≤2599，进一步到 32 要求 T≤2079。它们是探索目标，不是可实现承诺。若长度缩短但仍在同一 Hpad 档位，当前内核未必明显提速。

Remez 文档：https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.remez.html 。锁定本机实际版本，不为本任务擅自升级环境。

### 3.1 CPU/FMA 结构优先的选型要求（用户补充）

优化目标为“满足频响与应用质量约束时，当前 CPU 上的实测执行耗时最小”。总 tap 数最短仅作为诊断候选；正式推荐按实际内核成本选取。滤波器设计与分相布局、新长度模板实例共同评估，但各自收益仍按第 6 节拆分。

1. **先选 SIMD 档位，再在档位内选滤波器。** 对 Hpad=16/24/32/40/48 中相关档位搜索；一个档位内多几个 tap 通常不增加现有固定长度点积循环次数，因此同时寻找该档位内具有更好纹波、阻带余量和应用效果的候选。长度导致的边界/flush 开销仍实测。不要为把总 T 凑成 65 或 8 的倍数而牺牲奇数对称结构；向量对齐由各相零填充承担。
2. **沿用适合现有 SC16 数据的连续分相布局。** 候选先使用已有反序、实系数对应 I/Q 复制与预缩放的布局，使数据和系数加载连续，避免运行时逐 tap 索引、gather、掩码和系数广播。若提出新布局，需单列转换/打包、内存容量及实际收益，不同时改动多个因素。
3. **保留多输出独立累加链。** 先沿用现有四输出、每输出两条累加链的 FMA 内核，为入围 Hpad 做编译期展开；检查生成汇编中的循环、加载、转换、shuffle 与栈溢出。不要只数 FMA 指令或追求完全展开，代码大小与寄存器压力也必须检查。本轮不顺带搜索更多输出并行度或改变求和次序。
4. **对称性不直接折算成乘法减半。** 原型 FIR 对称不代表每个多相支路各自对称；跨相复用还依赖输入索引和输出时刻。当前实验不引入折叠 FIR、强制稀疏或系数量化为二次幂；这些结构需要另行证明并测量，不能从原型系数外观推断收益。
5. **用简明成本表筛选，再用计时决策。** 每个入围候选列出 Hpad、每四输出的向量 FMA/加载/SC16 转换数量、系数存储字节、实际内核分派、汇编有无 spill，以及 ns/输出样点。无硬件计数器时明确未知项，不把计算量下降比例当成耗时下降比例。

同一 Hpad 的候选若速度无法区分，优先选择应用质量与频响余量更好的候选，再考虑群时延与长度。realtime 与 quality 可以落在不同档位，也可以只有一个 profile 获益。最终结论限定到实测 CPU、编译器与内核配置，不声称对所有 CPU 最优。

## 4. 独立频响与重采样验证

新增独立验证脚本，读取落盘后二进制，不复用设计程序的“已通过”布尔值。

- 用 FFT/freqz 对 `[0,Fv/2]` 密集扫描，频率步长初值不大于 `Fv/(64*T)`；显式补入 DC、B、阻带起点和 Nyquist。定位全部候选局部极值，用 double 直接 DTFT 和局部极值搜索复核；加密一倍检查最坏值收敛，接近门槛者继续加密。报告最坏值、频率和数值收敛结果；不把有限网格称为解析证明。
- 分别报告 double 设计与 float32 加载结果，记录量化前后余量；输出全频段、通带、阻带边缘频响图及冲激响应图。
- 用同一候选 h32 的独立 double `upfirdn`/公式参考核检验 C++，覆盖冲激、全零、DC、复数单音、固定种子随机 IQ、SC16 极值与短输入、随机分块及 flush。覆盖全部 65 个可达输出相位；有意选取非整周期块长。
- 基线与新滤波器的输出不要求逐位相等。对同一新系数，验证串流/整块、SC16 融合/分步、不同 DSP worker 路径的既有一致性契约；不可通过改变系数而顺带放宽实现 QA。与 double 参考的误差门槛优先继承既有 core QA，并在运行前记录具体数值。
- 测试正负通带中心/边缘、过渡带、输入 Nyquist 附近单音及镜像/混叠落点。稳态部分与 startup/flush 分开；避免用非相干 FFT 泄漏误判 70 dB 阻带，使用相干采样或精确频率投影。

## 5. 延迟、长度与 UWB 质量：必须单独过关

换 T 会改变群时延及 flush 长度，不能沿用旧元数据或裁剪掩盖差异：

- 群时延为 `(T−1)/(2*Fv)` 秒，即 `(T−1)/(2*48)` 个输出样点，通常含分数样点。
- 输出长度遵循现有契约 `ceil(((N−1)*65+T)/48)`，另查空输入契约。逐项检查 pipeline 输出长度、capture/halo、时间原点、窗口元数据及解调器的时延补偿。
- 离线波形比较按已知理论群时延校准共同有效支持区；不得通过对每个窗口自由拟合增益、时移、CFO 来隐藏失真。完整生产输出及边界仍需单独验证。

以固定输入、种子和原有接收配置进行 Kaiser/等波纹配对：至少覆盖既有可复现的干净单径、分数多径、非零 CFO、低 SNR/接近解码门限、SYNC 碰撞、损坏包旁路场景。运行前列明实际 fixture/run 路径、输入网格和样本量；不能用绕过 native 重采样的 work-grid fixture 冒充该验证。

应用级验收建议在执行前写入 manifest：

- 确定性正常与损坏包语料：PSDU/FCS/status、提交/旁路决策无新增错误；预期时延元数据变化单列解释。
- 既有 CIR/弱目标保护的绝对门槛必须全部保留；附加相对基线守门：配对 CIR 峰位置差≤0.1 输出样点、主峰幅度差≤0.1 dB、真实 SIC 抑制恶化≤0.2 dB。若现有指标分辨率或定义无法表达这些门槛，先固定可执行的指标定义并说明，不在看到结果后选更宽门槛。
- 固定相同噪声实现做至少三个门限附近 SNR 点，每点至少 1000 包；报告配对错误计数和差值的 95% 置信区间。建议 PER 增量上界≤1 个百分点；样本不足以判定则标为不确定，不宣布通过。
- 报告共同支持区的 EVM/相对 L2、CIR 旁瓣、弱目标和边缘振铃；这些诊断不能代替解码与 SIC 指标。未接通原生输入验证链时明确列为未完成，不准宣布可替换默认。

0.1 dB 通带规格允许比当前 Kaiser 更大波纹，因此“频响通过”不等于“对 CIR/SIC 无影响”。若最短候选质量退化，尝试保守纹波候选；不得改接收阈值来补偿。

## 6. 性能对照：区分系数收益与内核收益

现有 C1 内核仅对 Hpad=24/48 做编译期展开，其他长度回退通用路径。因此分两步：

1. **只换系数**：同一个 binary、同一 fixed-phase 设置、C2 关闭，Kaiser 与候选均走实际分派。先报告这一版真实收益。
2. **可选新档位展开**：只有频响与基本 QA 通过且通用路径有明显限制时，才为入围档位添加同构模板实例；不改变 FMA/reduction 次序，不改其他算法。新增独立提交，验证同系数通用/专门内核的一致性。重测新 binary 的 Kaiser 控制组，不能跨 binary 把全部收益归给滤波器。

使用现有 `benchmark_sc16_burst_core` 的 `--taps` 接口。独立 build，例如 `gr-uwb/build-sc16-equiripple`；不覆盖历史 build。每轮性能独占 `/tmp/uwb-sic-benchmark.lock`，设计搜索/QA 与性能测试不得同时运行。

正式矩阵：realtime/quality × 4000/56000 输入点；core 单 worker；pipeline dsp_workers=1/2/4、resampler_workers=1。先筛 core，仅质量通过的推荐候选进入完整矩阵。

- 每格至少 5 组 ABBA、每次至少 10000 个稳态窗口，预热不计入；固定输入、CPU affinity、电源/线程配置。记录运行顺序及异常，不事后挑最快轮次。
- A=Kaiser，B=候选。按 ABBA 组汇总配对耗时比及区间，再给跨组中位数；不能只把两侧全部运行池化取中位数，用 IQR 分离冒充配对统计。
- 报告 core P50/P95/P99、ns/输入样点、pipeline 墙钟/完成窗、有效输入 MS/s，以及 admitted/completed/dropped/cancelled。算法群时延、执行耗时、队列延迟和冷启动分列。
- 更短 FIR 会自然减少 flush 输出量，分别报告完整 burst 开销与共同稳态输出区单位成本，避免把少输出样点当成全额内核加速。
- 准入建议：56k core 中位耗时至少下降 5%，配对区间支持下降；4k 与尾延迟无明确超过 5% 的退化。pipeline 收益单独判定，测量不确定则记不确定。任一 profile 可独立成功，不强求同时替换。
- 端到端测试前核对独立复核意见中的大间隔 RX 取消、启动错误传播与计时归因问题是否已修复；未修复则不把受影响 pipeline 结果作为验收证据。core 实验可先完成，不要求本任务顺带修改 RX。

不把 read_samples 中包含的流控等待当成磁盘/内存硬下限；不据文件回放宣布连续 737.28 MS/s 硬件实时通过。

## 7. 执行顺序与交付

按 G0→G4 串行过门，失败停止依赖阶段并保留有效证据：

| 阶段 | 交付 | 进入下一阶段条件 |
|---|---|---|
| G0 基线复核 | 系数哈希、全阻带复验、测试/计时配置 manifest | 基线口径与候选规格明确 |
| G1 设计搜索 | 脚本、搜索 CSV、float32 候选、频响图 | 独立频响通过 |
| G2 接入与数值 QA | 同系数参考对照、分块/尾部/相位/元数据检查 | 实现正确，无越界或时间轴错误 |
| G3 应用质量 | 解码/CIR/SIC 配对结果及未验证项 | 质量门槛通过或明确候选淘汰 |
| G4 性能与决策 | ABBA 原始记录、配对汇总、推荐候选 | 频响、质量、速度三项分别判定 |

可以在 G2 后做小规模 core 预筛减少 G3 工作量，但正式速度结论在质量验证后给出。若使用多个 agent，可分为设计、独立验证、性能/接入三个文件所有权；性能仅一个执行者，主 agent 冻结规格并汇总，设计者不能自行签发独立验收。

新增报告 `docs/performance/65_48等波纹FIR实验报告_2026-11-11.md`，包括每个 profile 的 T/Hpad、纹波、全阻带、量化余量、群时延、应用效果、core/pipeline 配对耗时及是否推荐。所有数据绑定 code-tested SHA 与系数 SHA256。新系数与小型元数据可入库，大 IQ/build/大日志不入库；历史数据不覆盖。

最终允许三类结论：①质量与速度均通过，推荐后续显式集成；②滤波器合格但 SIMD/系统收益不足，保留实验；③频响或应用质量失败，保持 Kaiser。即使结论①，也不在本轮自动修改默认路径。
