## 1. 落点与不变量

实际链路（未改）：`UhdDeviceSc16Source::read_samples → rx_producer_loop 按时间表
拼窗 → 窗口池 → dsp_consumer_loop → sic/radar`。

新增落点（任务书 §2）：

```
UHD/replay 持续 recv
  → [装饰器] 专用原始读取线程 → 有界原始 SC16 块环（默认 32×65536 = 8 MiB）
  → [装饰器] read_samples()：训练/估计/外推状态机 + 融合 copy_cancel 写进调用方 storage
  → 现有窗口拼装 / 窗口池 / 原 DSP
```

- **在截窗之前**：窗间训练数据仍在流里，模型不依赖包到达；包检测/重采样/SIC/CIR 全部受益。
- `start_stream()` 仍只在所有 DSP worker Ready 屏障之后调用（`rx_producer_loop`）。
  装饰器 `open()` 只分配内存 + `prepare()`，不启动 UHD 采样、不启动读取线程。
- 装饰器逐层传递 EOF / 停止 / 致命错误 / `is_gap` / 时间戳：
  - 新增 `ISc16StreamSource::request_stop()`（默认空实现，`stop()` 调用）解决
    "RX 线程阻塞在自己的条件变量里，`stop()` 等 `wait()` 会卡住"。
  - 新增 `ISc16StreamSource::fatal_error()`；`rx_producer_loop` 每次读后检查，
    包装源的失败**不会被伪装成短读或 EOF**，而是 `set_source_error()` → 运行失败退出码非 0。
  - `start_stream()` 等待（有界 10 s）读取线程的 result，设备/文件启动失败仍同步返回。
- 两层 read 计数分开：`tone.source_read_calls`（装饰器→真实源/硬件 recv）与
  `read_calls`/`RxDiagnostics.read_calls`（窗口拼装者→装饰器）。

## 2. 数学实现（与任务书 §3 对齐）

`c = (1/Nt) Σ x[epoch+n]·e^{-jωn}`，`î[epoch+n] = c·e^{jωn}`，
`out = saturate_int16(in − round_nearest_even(î))`。

- **周期由配置推导并校验**：`find_exact_period()` 在 `P ≤ 4096` 内要求
  `f0·P/fs` 为整数（相对容差 1e-9）。默认 737.28 MS/s、−232.96 MHz 得到
  `P=288, cycles=−91, ω=−2π·91/288`。**没有短周期的组合显式报 unsupported**，
  不近似成 288 点表（QA：100 MHz/737.28 MHz 的 625/4608 被拒绝）。
- **训练采用 int32 折叠 + double 投影**：`S[r] = Σ_{n≡r} x[epoch+n]`，
  `c = (1/Nt)Σ_r S[r]e^{-jωr}`。因 `e^{-jω·288}=1`，这对**任意 Nt**
  （含非整周期）与全窗单频投影代数等价，非 FFT、非频率估计。
  `Nt/288 ≤ 65535` 才允许（int32 不溢出），否则初始化报错。
- **显式真实时间原点**：训练起点即 LUT 相位原点，索引严格
  `(t − epoch) mod 288`；跨 read 分块/尾部/20 ms 边界均按绝对样点推进
  （QA 覆盖 chunk 1/7/288/289/4096、起点 0/±20 ms/多周期）。
- **单位复数基底只初始化一次**：每次更新只做"复系数旋转/缩放 + 量化"，
  不重复 sin/cos。实测建表 6.65–6.92 µs。
- **量化固定 nearest-even、与 fenv 无关**（QA 在 4 种 rounding mode 下逐项比对；
  含 ±0.5/±1.5/±2.5/±3.5 ties 表）。
- **模型超范围显式拒绝**：单音分量不能表示成 int16 时 `finish_training()` 返回
  `InvalidModel` 且**不改动已有 LUT**（QA：1 样点饱和训练窗触发；上一 LUT 逐字节保留）。
  绝不先夹断单音。
- **交叉渐变**：模型切换时用同一绝对时间评价新旧单音，线性 `a_j=(j+1)/C`，
  C=256（=0 为数学参考硬切换）。表在更新时一次算好，热路径只查表；不丢样、不插样。
  渐变表量化失败也不会夹断（回退硬切换）。
- **热路径**：一次 load → 16 路 `_mm256_subs_epi16` → store / 8 复样点；
  无分配、无 sin/cos、无锁、无逐样点原子计数。
- **AVX2 运行时分派**（`__builtin_cpu_supports`），函数用
  `__attribute__((target("avx2")))` 单独编译，**没有给整个库无条件开 AVX2**；
  scalar 与 AVX2 输出逐位相等（QA 65536 样点全等）。
- **存储布局**：块用 `std::complex<int16_t>`，核心吃 `int16_t*`；
  依赖标准保证的 `complex<T>` ≙ `T[2]` 交错布局（代码内注明）。

## 3. 缓冲所有权（任务书 §2.1）

- 生产路径是"raw 队列 → 现有 storage"，因此用 **`copy_cancel(raw, storage, count, phase)`**
  一次"加载→饱和减→写入"完成搬运与消除：**没有先 memcpy 再原地减**，
  也没有额外 clean 缓冲。
- `cancel_in_place` 只作为核心 API 与 benchmark 的第二条可比路径存在，
  生产 pipeline **不同时使用**两种互斥策略。
- 原始块**从不被原地改写**，训练折叠在原始样点上完成（估计后才回放该训练窗），
  所以同一段 raw 不会消除两次、也不会把已 clean 数据标成 raw。
- 重叠调度窗只从已 clean 的 storage 再复制，不再消除。

## 4. 状态机、gap 与守恒

`CollectTraining → Estimate → Apply`，每 Np=14745600 样点（20 ms，按样点数不用 wall clock）重复。

- **严格首版语义**：每到周期起点暂存/等待该周期起始 Nt=368640 样点（0.5 ms），
  用新模型处理并**按原顺序输出该训练窗**（不丢这笔延迟，不提前输出旧模型结果）。
  训练期间读取线程继续 recv。实测首样点输出延迟 0.69 ms（8 MiB 队列）。
- **不等待整 20 ms**：后续连续流式输出，只在训练窗时阻塞约 0.5 ms。
- **gap / 时间戳跳变**：绝对样点轴跳变或源报 `is_gap` → 在**正确输出边界**给出
  `meta.is_gap` + 真实丢失样点数；同时丢弃模型、清空训练、**在 gap 后的首个样点
  重建 epoch**（不跨不连续区间学习、不补零）。QA 验证 `start_sample_abs=4064`、
  `gap_samples=64`（源报的与索引跳变只取一次，不重复计数）。
- **EOS 训练不足**：`partial_training_bypass`，尾部**原样输出**（QA 逐字节比对）。
- **无可靠模型**：`model_rejects` 计数并旁路该周期。
- **队列满**：接收侧非阻塞**整块丢弃**，累计丢弃样点并在下一个成功块上打 gap；
  不为减少溢出降低输入率。
- **守恒**：`source_samples == queued + dropped`，`queued == consumed + pending`
  （训练暂存计入 pending，不算丢失）。runner 把该守恒纳入 `runtime_ok`。
- **关闭模式**：不创建装饰器、不建线程、不复制一次；两条关闭运行 IQ dump 逐字节相同。

- 交叉渐变：渐变表 vs 独立参考逐项相等、渐变结束点正确切回周期表、

### 6.5 QA 反复运行暴露并修掉的竞态

初次串行全量回归 83 项全绿后，把新增 QA 单独反复跑 6 次复现出 3 次失败：
4 周期用例偶发 `training_windows=5 / model_rejects=1 / bypassed=97`，
pipeline 用例偶发窗口 0 未被消除（原始样点）。

- **根因**：训练状态机判断"训练窗被 gap 打断"时，`contiguous_end` 与
  `published_end` 取自**两次不同的 head/tail 观测**。读取线程在这两次观测之间
  正常发布了更多连续数据，于是"还没收到更多数据"被误判成不连续：
  模型被作废、epoch 被前移、该周期样点旁路（97 样点正好是一次 read 块大小）。
- **修复**：改为单一快照的 `RunSpan{contiguous_end, published_end}`
  （同一次 tail/head 观测内算完），只有 `contiguous_end < published_end` 才算真不连续。
- **复测**：新增 QA 连续 12 次、四测组合连续 8 次、全量串行 83 项再次全绿。
  这是本轮唯一在 QA 反复运行中暴露的算法级缺陷，已修入同一提交。

## 7. 性能

| 16384 样点融合消除 | 1.01–1.05 µs |

每 65536 样点的融合消除吞吐 = 155 GB/s 逻辑流量（L2 常驻）；按 737.28 MS/s 折算
**单核 6.6–6.9%**（`cancel_cpu` 在真实 pipeline 里实测 66–69 ms/s）。

与旧原型对比：估算 45.4→65 µs、建表 4.58→6.7 µs（本轮实现多了 block 首尾处理、
渐变表和显式范围检查；未做进一步微优化）。**不把"融合更省一遍访存"直接等同于
端到端实时提速**：整 20 ms 冷缓存情形仍受内存带宽支配（14–25 GB/s），
与两遍的差异主要来自少一遍 59 MB 写回/读。

### 7.3 缺陷定位：paced replay 的启动突发（已修）

第一次测到 "1 s paced 仍有 0.08–0.5% 丢块"，定位到两个独立原因：

1. **`ReplaySc16Source` 的 paced 时间基准取自 `open()`**，而 pipeline 在 worker-ready
   屏障之前就 `open()`。屏障期间（≥ ms 级）源"欠账"，`start_stream()` 后全速突发
   补数据，把 8 MiB 环瞬间打满。已改为 `start_stream()` 重置时间基准
   （unpaced 路径逐位不变）。修复后同样的 1 s paced 用例从 "0.08–0.5% 丢" 变为 **0 丢**，
   首样点延迟从 3.48 ms 变为 0.69 ms。
2. **把整个进程 `taskset -c 2` 绑成单核**时，读取线程 + RX 线程 + DSP 线程 + 主线程
   抢一个核，RX 消费者会被调度挤开 >2.8 ms，默认 8 MiB 环必丢：
   实测 queue=32 → 58–347 万样点丢弃，queue=64（5.7 ms）仍丢，
   queue=128（11.4 ms）不稳定，queue=256（22.8 ms）0 丢。
   **这是"整进程单核"的人为条件**，不是单通道正常条件：修正 §7.3-1 后不绑核时
   默认 32 块在 3 次 stage-only 与 4 次 pipeline 的 1 s paced 运行中**全部 0 丢块**。
   同一绑核命令重复运行也会在 "0 丢" 与 "0.8% 丢" 之间跳，
   因此**不把绑单核当作可承诺的运行条件**。若必须把整条链压到一个核，请把
   `--tone-cancel-queue-blocks` 提到 256，并预期 p99 变差。

## 8. 明确未验证 / 限制

- **未上板**，未重新采集；未验证真实 UHD `recv` 溢出、paced 到达、8 Worker、AVX-512。
- **未做 MATLAB 交叉验证**；未做 PSDU/FCS/PER；未做 CIR/弱目标保护对照（§7.4）。
- **频率必须是已知固定值**：配置的接收基带频率，不是 RF 中心频率。更换采样率/
  频率后必须重新给配置；没有短周期的组合会显式失败（不会静默沿用 288 点表）。
  通用 NCO 后端**未实现**（任务书不要求）。
- 训练窗碰包时模型会被包污染（本轮明确不做鲁棒性）；若某周期无可靠模型则旁路并计数。
- 已 clean 的 storage 只在原复制处再复制；**同一原始流只消除一次**，
  但若将来有人把装饰器接到"已经不是原始样点"的源上，语义需要重新评估。
- 前处理线程与 RX 线程共享一个核时会退化（§7.3）；建议给读取线程留出独立核。
- 低阈值（≤0.05）下自相关候选组数上升，属旁瓣分裂，未做检测器阈值联合调优。

## 10. 结论口径

- "消除正确"：核心数学有独立 double 参考与逐字节输出比对；40 ms 实采与独立
  numpy 固定频率参考**逐字节一致**。这是本轮最强的证据。
- "没有破坏原链路"：关闭路径两条运行 IQ 逐字节相同；全量 83 项 CTest 0 失败；
  开启后窗口服务时间 +0.9/+3.9%、0 新增窗口丢弃。
- "实时"：仅指本机单通道 737.28 MS/s **paced 回放** 1 s 0 丢块（不绑核）；
  前处理约 7% 单核，非 paced 上限被文件 I/O 限制。**不宣称上板实时通过。**
- 检测指标改善（自相关中位数 0.640→0.004、模板相关 8/8 保留）**不等于**波形无损、
  FCS 通过或弱目标保护通过。
