# 低 SNR 候选捕获：自相关 vs 折叠互相关的可行性实验（2026-11-17）

> 目的：回答"能不能用折叠 + 互相关替代延迟自相关做候选捕获，并在 −16 / −20 dB
> 带内 SNR 下锁定包时间"。
> 全部结论来自 **Python/numpy 原型**，未改任何 C++、未上板、未跑 CTest。
> 任务背景见 [低SNR进锁阶段优化与快速验证方案_2026-11-17.md](低SNR进锁阶段优化与快速验证方案_2026-11-17.md)，
> 前序测量见 [AWGN_SNR仿真与阈值分析_2026-11-17.md](AWGN_SNR仿真与阈值分析_2026-11-17.md)。

**一句话结论**：折叠 + 互相关在 −16 dB 有 42 倍余量、在 −20 dB 有 23 倍余量，
但它**只能测相位（mod 1016），测不出符号序号**，所以它是自相关的精定级而不是替代品；
两段式（自相关粗筛 + 折叠确认/精定）成本只比纯自相关高约 7%。

---

## 1. 实验口径

### 1.1 信号夹具

统一生成器：`tools/rx/proto_low_snr_signal.py`（numpy/scipy，无 C++ 构建）。

- **工作网格**（本报告主口径）：998.4 MS/s，SYNC 周期恰好 **1016** 样点，
  256 SYNC 前导 = 260,096 样点；直接由生产 SYNC 模板平铺，不做 48/65 重采样。
- **原生网格**（仅作历史对照）：737.28 MS/s，周期 750.2769 样点（分数）。
- 包按 1 ms 周期排布，包 RMS 标定 542 LSB；`make_stream_work()` 加白噪。
- **SNR 定义**：±250 MHz 带内 SNR。工作网格全带 998.4 MHz，故全带噪声功率是带内的
  `998.4/500 = 1.997` 倍。
- 夹具是**理想 AWGN、单径、无 CFO/SFO/多径/干扰**。真实 48/65 输出被限带到
  ±368.64 MHz，带内噪声占比更低，实际工作网格 metric 约再高 **2.6 dB**（对本方案有利）。

### 1.2 两个度量

**自相关（现行）**：

```
metric[at] = |Σ_{k<span} x[at+k]·x*[at+k+lag]|² / (Σ|x[at+k]|² · Σ|x[at+k+lag]|²)
```

低 SNR 下 `metric ≈ (S/(S+N))²`，**随 SNR 平方滚降**；噪底 `≈ 1/span`。

**折叠 + 互相关（候选方案）**：

```
folded[i] = Σ_{m=0}^{K-1} x[at + i + 1016·m],  i ∈ [0,1016)
metric    = max_φ |Σ_i folded[i]·t*[(i+φ) mod 1016]|² / Σ_i |folded[i]|²
```

`t` 为 L2 归一化的 SYNC 模板（1016 样点），φ 遍历全部 1016 个循环 lag。
低 SNR 下 `metric ≈ K·S/(S+N)`（上界 1），噪底 `≈ 1/1016`，**与 K 和 SNR 无关**——
这是它与自相关最本质的差别。

## 2. 实验 A：工作网格自相关粗筛

脚本 `tools/rx/proto_acq_triangle.py`，数据 `data_low_snr_lock_20261117/acq_triangle.json`。
配置：`lag=1016, span=260096, step=64, low=9e-5, peak=1.8e-4, persist=12000`，
三角形峰顶触发，每档 100 包。

### 2.1 检测与精度

| 带内 SNR | 检出(±36864) | **落在 ±508** | \|err\| min/med/p95/max | 虚警 |
|---:|---:|---:|---|---:|
| +10 dB | 100/100 | **43** | 0 / 512 / 1024 / 1024 | 0 |
| 0 dB | 100/100 | **47** | 0 / 512 / 1024 / 1024 | 0 |
| −10 dB | 100/100 | **34** | 0 / 640 / 1600 / 2304 | 0 |
| −14 dB | 98/100 | **20** | 0 / 1216 / 6365 / 33472 | 2 |
| −16 dB | 22/100 | **3** | 128 / 2400 / 11578 / 13440 | 2 |
| −18 dB | 0/100 | 0 | — | 0 |

**关键发现（结构性，不是 SNR 问题）**：延迟自相关的相干区间是
`[start, start+span−lag)`，**任何**落在 `[start−lag, start]` 的窗口起点都完整包含该区间，
所以 metric 的顶部在**恰好一个符号（1016 样点）**上是平的，argmax 在平台上均匀分布。
实测有符号误差恒落在 `[−1024, 0]`，因此**即使 +10 dB 也只有 43% 落在 ±508**。

把 seed 改成平台中心（`peak_at+508`）后：+10 dB → 92/100，0 dB → 92/100，
−10 dB → 56，−14 dB → 29，−16 dB → 2。

### 2.2 余量（对纯噪，0.5 s = 4.992 亿样点、780 万次 metric 评估）

纯噪 metric：mean `3.78e-6`、p99 `1.72e-5`、**max `5.559e-5`**。
计划门限 `peak=1.8e-4` 只有噪底最大值的 **3.24 倍**，`low=9e-5` 只有 **1.62 倍**。

| SNR | 信号 metric 中位 / 最弱 | 余量（中位 / 最弱） |
|---:|---|---|
| +10 | 6.92e-1 / 6.90e-1 | 12440× / 12419× |
| 0 | 1.10e-1 / 1.09e-1 | 1987× / 1961× |
| −10 | 2.26e-3 / 2.03e-3 | 40.6× / 36.5× |
| −14 | 3.86e-4 / 2.84e-4 | 6.94× / 5.11× |
| −16 | 1.59e-4 / 9.46e-5 | **2.86× / 1.70×** |
| −18 | 6.83e-5 / 2.79e-5 | **1.23× / 0.50×** |

按 `(S/(S+N))²` 的 2 dB/1 dB 规律，3 倍余量在 **−15.8 dB（中位包）/ −15.2 dB（最弱包）**
就已经耗尽。把门限压到 `peak=8e-5`（1.4× 噪底）能恢复 −16 dB 的检出，但代价是
**每 100 包 40 次虚警**（预滤配置 `low=2e-5/peak=4e-5` 实测：−16 dB 60/100 检出、40 虚警）。

### 2.3 算力

现行实现（标量 double）实测：原生 64k/8 配置（0.125 pair/样点）**300 ms CPU / 0.5 s 数据
= 60% 单核**（前序报告）。全速率 1 pair/样点 = 8 倍 → **约 480% 单核**；工作网格再乘
1.35（998.4/737.28）→ **约 650% 单核**。**计划书里 192k/64 的全速率自相关在当前实现下
不可实时**，必须先把它改成 int16 SIMD 内核（理论 0.62 指令/样点，约 8% 单核）。

## 3. 实验 B：折叠 K + 循环互相关

脚本 `tools/rx/proto_fold_timing.py`，数据 `data_low_snr_lock_20261117/fold_timing.json`。
每档 100 包，折叠起点取真实起点（验证度量本身），残差用全 1016 lag 搜索。

### 3.1 检测能力

| SNR | 单符号 metric 中位 | ±256+PAR 通过 | K=64 中位 [min,max] | K=256 中位 | 残差 | 余量 K64/K256 |
|---:|---:|---:|---|---:|---:|---:|
| −6 | 0.141 | 100/100 | 0.890 | 0.970 | 0 | 38.5 / 40.0 dB |
| −10 | 0.070 | 5/100 | 0.763 | 0.928 | 0 | 37.2 / 39.6 dB |
| −14 | 0.036 | 0/100 | 0.560 | 0.836 | 0 | 34.5 / 38.7 dB |
| **−16** | **0.026** | **0/100** | **0.445 [0.413, 0.488]** | **0.762** | **0** | **32.5 / 37.9 dB** |
| −20 | 0.015 | 0/100 | 0.243 [0.209, 0.290] | 0.561 | 0 | 27.3 / 35.3 dB |
| −24 | 0.012 | 0/100 | 0.113 [0.087, 0.154] | 0.335 | 0 | 20.6 / 30.8 dB |

- 生产单符号门限 0.25 在这套夹具里对应约 **−1.5 dB**，与"−14 dB 下 timing_ok=0/50"吻合。
- **−16 dB：K=64 与 K=256 都是 100/100、残差 0**，只是余量 42× vs 71×。
- 3 包锁定概率 `P(≥3/8)` 在 −16 dB 下 **K=64 与 K=256 都是 1.000**；
  −20 dB 时 K=64 掉到 0.448（因为 0.25 门限），K=256 仍 1.000。

### 3.2 门限：−20 dB 的"下降"是门限造成的

| SNR | K | 最弱包 metric | 噪底比 | 通过@0.25 | **通过@0.05** |
|---:|---:|---:|---:|---:|---:|
| −16 | 64 | 0.413 | 38.6× | 100/100 | **100/100** |
| −16 | 256 | 0.743 | 66.4× | 100/100 | **100/100** |
| **−20** | **64** | **0.209** | **19.6×** | **30/100** | **100/100** |
| −20 | 256 | 0.525 | 46.9× | 100/100 | **100/100** |
| **−24** | **64** | **0.087** | **8.2×** | **0/100** | **100/100** |
| −24 | 256 | 0.291 | 26.0× | 100/100 | **100/100** |

纯噪折叠 metric（200 个折叠位置 × 1016 lag = 203,200 次试验）：中位 0.0071、
p95 0.0092、**max 0.0107（K=64）/ 0.0112（K=256）**，**与 K 和 SNR 无关**。

因此折叠级门限应按噪底定：**0.05 = 4.7× 噪底最大值**，同时比 −16 dB 最弱包低 8 倍。
用 0.05 后 **K=64 的检出下限约 −26 dB**（−24 dB 最弱 0.087 = 8.2× 噪底）。
0.25 是单符号门限，**不应沿用到折叠级**。

### 3.3 K 的选择

−16 dB 下 K 扫描：

| K | 16 | 32 | 64 | 128 | 256 |
|---|---:|---:|---:|---:|---:|
| metric 中位 | 0.168 | 0.288 | 0.445 | 0.616 | 0.762 |
| @0.25 通过 | 0% | 100% | 100% | 100% | 100% |
| 4.25 kHz CFO 相干损失 | −0.07 dB | −0.28 dB | **−1.12 dB** | −4.93 dB | **−20.45 dB** |

CFO 扫描（−16 dB，metric 中位）：

| CFO | 0 | 350 Hz | 1 kHz | 4.25 kHz |
|---|---:|---:|---:|---:|
| K=64 | 0.448 | 0.448 | 0.444 | **0.387（100%）** |
| K=256 | 0.761 | 0.758 | 0.721 | **0.028（0%）** |

**K=64 是应选深度**：−16 dB 有 42× 余量，对实机 trim 后 4.25 kHz 残余 CFO 只掉 1.1 dB；
K=256 在 260 µs 内累计 6.96 rad 直接塌掉，且要吃满整段 260,096 样点前导，没有余量做
lag 搜索或候选迟到。K=32 是 −16 dB 能过 0.25 的最小深度（0.288），成本更低。

### 3.4 粗筛精度要求：±508 样点

−16 dB，折叠起点故意加粗筛误差：

| 粗筛误差 | 0 | 250 | 500 | **508** | 600 | 1016 | 2032 | 4064 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 总误差（K=64） | 0 | 0 | 0 | **0** | +1016 | +1016 | +2032 | +4064 |
| metric | 0.444 | 0.447 | 0.449 | 0.448 | 0.448 | 0.448 | 0.447 | 0.448 |

**折叠只能确认"这里有周期前导"，无法发现整符号滑移**：偏差超过半符号时 metric 不降、
估计整体滑一个 1016。所以粗筛必须给到 **±508（±0.51 µs，半个符号）**。

### 3.5 成本

| 配置 | 折叠复加 | 互相关复运算 | 每候选复运算 | @1 候选/ms |
|---|---:|---:|---:|---:|
| K=64 + FFT | 65,024 | 152,400 | 217,424 | **0.87 GFLOP/s ≈ 3.5% 单核** |
| K=64 + 直接点积 | 65,024 | 1,032,256 | 1,097,280 | 4.39 GFLOP/s ≈ 18% |
| K=256 + FFT | 260,096 | 152,400 | 412,496 | 1.65 GFLOP/s ≈ 6.6% |

（按单核 25 GFLOP/s 折算。）折叠每候选只读 65k 样点 ≈ 260 KB，1 候选/ms 时
内存带宽 0.26 GB/s。

## 4. 为什么折叠不能替代自相关

### 4.1 折叠是周期匹配，对整符号平移不敏感

在 `at` 折叠与在 `at+1016` 折叠结果**完全相同**（循环移位一位）。所以折叠测的是
"相位 mod 1016"，不是"包在哪"。前导有 256 个符号，`start`、`start+1016`、
`start+2032`… 折叠只要跨度还在前导内，metric 全是 0.44（−16 dB）。

平台边缘还是**软**的：折叠跨度每移出一个符号，metric 只掉 `(63/64)² ≈ 3%`，
要移出 64 个符号才掉到 0。所以从边缘形状最多定到几千样点，定不到 ±508。

对比自相关：平台**恰好一个符号宽**、边缘是**硬台阶**（移出即掉到噪底）。
这是自相关唯一的、不可替代的价值——给出"绝对位置，误差 ≤ 1 符号"。

### 4.2 折遍一个 5 ms 窗口的代价

| 项目 | 数值 |
|---|---:|
| 5 ms 窗口（998.4 MS/s） | 4,992,000 样点 |
| 需要的折叠位置（每符号一次） | 4,913 |
| 每位置（折叠 + FFT 互相关） | 217,424 复运算 |
| 每窗口合计 | **1.07e9 复运算** |
| 每秒（200 窗口） | **2.1e11 复运算/s ≈ 24–50 核** |
| 折算每输入样点 | ≈ 856 real flop/sample |
| 对比自相关 | 10–12 ops/sample |

**折叠全窗口搜索比自相关贵约 60–80 倍。** 原因是自相关本质上是"2 抽头匹配滤波"
（只用 `x[n]` 与 `x[n+1016]` 的相关性），是能找到的最便宜的周期性检测器；
折叠是"1016 抽头匹配滤波 + K 符号相干积分"，每位置贵约 1000 倍，只因为只需在候选处
做一次才显得便宜。

### 4.3 想砍掉自相关的替代品

替代品必须能提供**绝对位置**：

- 能量/包络边缘：−16 dB 下信号只占 1.7% 能量，单符号信噪比不够，长窗精度差；
- SFD 相关：非周期、8 符号，−16 dB 下约 140× 余量，但要在全窗口搜 SFD，
  FFT 成本约 4e11 复运算/s，同样不可行。

两条都不比自相关便宜。

## 5. 结论与建议架构

1. **折叠 + 互相关在 −16 dB 是"富余"而不是"勉强"**：K=64 最弱包 0.413、噪底 0.0107，
   余量 38.6×，残差 0；3 包锁定概率 1.000。
2. **门限必须按噪底重定**：折叠级用 **0.05**（4.7× 噪底），不要沿用单符号的 0.25。
   改门限后 K=64 覆盖到约 **−26 dB**，−20 dB 是 100/100 而不是 30/100。
3. **K=64 是默认**：−16 dB 42× 余量，4.25 kHz CFO 只掉 1.1 dB，只需 25% 前导做前视，
   成本 0.87 GFLOP/s。K=256 只在"CFO 已收敛到 1 kHz 内且要探 −24 dB 以下"时作第二轮。
4. **两段式是正解**：自相关粗筛（绝对位置 ≤ ±1016）+ 折叠确认/精定（相位 ±1 样点）。
   成本取决于粗筛实现：
   - 沿用现行 64k/8 原生配置（实测 0.60 核）+ 折叠（0.035 核）= **0.635 核，+6%**；
   - 改成全速率 192k/64 工作网格并重写成 int16 SIMD（约 0.08 核）+ 折叠 = 0.115 核，
     折叠占 +44%；
   - 全速率 192k/64 但保留当前标量 double 实现 = 约 6.5 核，**不可实时**。
   所以"折叠几乎免费"只在粗筛维持当前成本档位时成立。
5. **粗筛本身需要两处改造**：
   - seed 取**平台中心**（`peak_at + 508`）而不是平台起点：+10/0 dB 的 ±508 命中率
     从 43/47% 提到 92/92%；
   - 门限按噪底重定：`peak` 从 1.8e-4（3.24× 噪底）降到约 **2× 噪底（1.1e-4 量级）**，
     `low` 相应下调，并**接受虚警**——由折叠级用 0.05 门限否掉。注意 −16 dB 最弱包
     metric 是 9.46e-5，只比噪底最大值高 1.7 倍，**不存在"既 100% 检出又零虚警"的
     粗筛门限**，这正是必须靠折叠确认的原因。
6. **符号序号仍需非周期线索**：折叠只解决相位。−16 dB 下最可行的是 SFD 相关
   （8 符号，约 140× 余量），或粗筛平台边缘（≥0 dB 可用，低 SNR 退化）。

## 6. 未验证与限制

- 全部为**合成 AWGN、单径、无 CFO/SFO（CFO 仅单独扫描）、无多径、无干扰**。
  未验证：多径、窄带干扰、48/65 重采样后的真实带限与群时延、实机时钟漂移、
  收发两端 SFO 累积。
- 夹具噪声在全带白，比真实 48/65 输出**悲观约 2.6 dB**（metric）。
- 折叠的"粗筛 ±508"假设粗筛误差与折叠窗口相互独立；真实链路里粗筛误差与 SNR 相关，
  需要在闭环里复测。
- 折叠级成本按 1 候选/ms 计；低门限粗筛的虚警率会抬高候选数，实际成本需按实测候选率折算。
- 未做 C++ 实现、未跑 CTest、未上板；`stage_timing` / `stage_sfd` / `stage_cir` 未改动。
- 自相关全速率（1 pair/样点）的 8% 单核估计是**指令数推算**，不是实测；
  当前标量 double 实现实测为 480–650% 单核，必须重写内核才能实时。

## 7. 待定问题（供后续讨论）

1. **粗筛去留**：保留延迟自相关（便宜、给绝对位置 ≤ ±1016，但 −16 dB 只有 1.7× 余量、
   且全速率需要 int16 SIMD 重写），还是换别的绝对位置线索（能量边缘 / SFD 相关都不便宜）。
2. **符号序号消歧**：用 SFD 相关（−16 dB 约 140× 余量，但需在 ±1016 窗口内搜），
   还是用粗筛平台边缘（≥0 dB 可用、低 SNR 退化）。这条决定了整条链路能不能在 −16 dB 闭环。
3. **折叠放在哪一级**：重采样之后（周期精确 1016，但需全速率 48/65 重采样，约 +2.5 核）
   还是之前（需分数周期插值折叠，成本在候选级但实现复杂）。这条对总算力影响最大。
4. **粗筛门限与虚警预算**：低门限换检出必然带来虚警，需要定"每包允许多少候选"
   （折叠级每候选 0.87 MFLOP，虚警率直接乘成本）。
5. **K 是否自适应**：默认 K=64；若能在折叠前用粗 CFO 补偿把 CFO 压到 1 kHz 内，
   可切 K=256 换取 −24 dB 以下的能力。
