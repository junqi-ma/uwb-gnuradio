# X410 原生实时路径：单 worker / 多 worker 耗时（2026-11-15）

当前默认 2 worker 合理：每包计算约 7.9 ms，两个 worker 处理相邻包可跟上 5 ms 到达间隔；单 worker 会排队并丢包。增加到 4 或 8 worker 没有明显减少单包计算时间。

## 配置与方法

AMD Ryzen 7 9700X，Release `-O3 -march=native`，不绑核。X410 通道 3 / RX1、737.28 MS/s、6489.6 MHz、gain 60。code10 / 256 SYNC / 4z2 / 127 B / STS off。保留固定单音消除、自相关盲捕获、默认 `--cir auto`，不改数学与默认 worker 数。每包窗口 450000 native 样点（610.35 µs），重采样至约 609k work 样点；不是此前性能报告的 4000/56000 点窗口。

独占 `/tmp/uwb-sic-benchmark.lock`，按 1→2→4→4→2→1 顺序串行，每次上板 3 秒。另用同一份 1 秒实采原始 IQ，按原采样率做相同顺序的回放对照。全部 run/失败均保留。每次前 20 个候选排除于计时分位数之外，成功/失败计数保留全部候选。分位数按线性插值。

`compute_us` 是 worker 开始处理到解调及可选重试结束的墙钟时间，不含打印；`cpu_us` 使用线程 CPU 时钟。`queue_us` 从窗口复制前到 worker 开始，包含一次截窗复制、唤醒及排队。`latency_ms = queue_us/1000 + compute_us/1000`。均不含等待空口整窗形成、UHD/RX 前端积压。成功要求 FCS 和独立 CRC 同时通过。

## 上板结果

下表为两次运行合并；计算阶段含已处理的失败包和重试，队列丢弃没有计算耗时，排除在耗时样本外。单位 ms。

| worker | 计时样本 | 重采样均值 | 首次解调均值 | 总计算均值 / P50 / P95 / P99 | 排队 P50 / P95 | 就绪到完成 P50 / P95 |
|---|---:|---:|---:|---|---|---|
| 1 | 815 | 2.200 | 5.139 | 7.349 / 7.297 / 8.039 / 8.568 | 166.962 / 172.444 | 174.358 / 179.887 |
| 2 | 1159 | 2.325 | 5.534 | 7.878 / 7.724 / 8.902 / 9.736 | 0.127 / 0.227 | 7.868 / 9.127 |
| 4 | 1036 | 2.326 | 5.645 | 7.979 / 7.616 / 9.293 / 16.913 | 0.124 / 0.220 | 7.761 / 9.437 |
| 8 | 1157 | 2.385 | 5.822 | 8.271 / 7.691 / 10.969 / 18.930 | 0.125 / 0.255 | 7.838 / 11.099 |

1 worker 两次共 1197 候选：854 成功、342 `DROPPED_QUEUE`、1 payload 失败；2 worker 为 1198/1199（1 payload 失败）；4 worker 为 1075/1078（2 invalid gap、1 payload 失败）。所有 raw ring 丢样为 0。一次 4 worker run 出现 5 次 UHD 源错误/间断，收到的数据仅约 2.4 秒，因此候选较少；另一轮 4 worker 为 598/598、0 源错误。不能把候选成功率当作发射端 PER。

单 worker 平均每包约 7.35 ms，容量约 136 包/s，低于当前约 200 包/s；2 worker 平均约 7.88 ms，但相邻包可重叠处理。并行发生在包之间，不会把单包计算时间除以 worker 数。

2 worker 的线程 CPU 均值为 7.87 ms，接近墙钟 7.88 ms，说明该段主要在运算。一次 Full CIR 重试额外 22.85 ms，整包最大计算 30.18 ms；极端失败/重试不能用普通包均值代替。

## 前端开销（连续流）

前端三个分项按每接收 1 秒连续信号归一化。这里是代码段墙钟累计，并非整个进程 CPU 利用率。自相关/环形存储分项包含截窗复制及提交，不含 tone；tone 两项来自现有 source 统计，不含内部锁、等待等全部杂项。

| worker | 单音参数估计 ms/s | 单音消除 ms/s | 自相关 / 环形存储 / 截窗 ms/s |
|---|---:|---:|---:|
| 1 | 3.86 | 84.58 | 166.95 |
| 2 | 3.96 | 95.95 | 196.39 |
| 4 | 4.01 | 101.99 | 198.29 |
| 8 | 4.33 | 103.68 | 208.21 |

以 2 worker 为例，连续前端上述三个分项合计约 296 ms/秒信号。若按 200 包/s 摊销，约 1.48 ms/包，但这不是可直接加到某个包上的串行延迟；前端独立于 DSP worker 运行。`reader_us` 含 UHD 阻塞等待，不能当作纯计算开销。未测量完整进程/内核/网卡驱动 CPU，未宣称端到端硬实时。

所有回放源错误/间断/raw 丢样为 0。2/4 worker 均每轮重试 1 包并恢复成功；1 worker 第二轮可能直接因队列满丢弃该包。短文件尾部停止接收后仍清空队列，因此 1 worker 成功比例好于持续上板场景，不能据此认定持续吞吐足够。

## 8 worker 补充测试

沿用同一二进制、PHY、捕获窗口、计时定义和 warmup 规则；另外运行 8→8，两次上板各 3 秒。原 1/2/4 结果未覆盖，8 worker 是随后补测，不是与此前配置交错配对的显著性实验。

- 上板分别 596/598、598/600，合计 **1194/1198** FCS+CRC 成功；失败为 2 payload、1 CFO、1 停止时窗口不足。4 次 Full CIR 重试。两轮 raw 丢样、源错误、gap、队列丢弃均为 0。
- 排除各轮前 20 个候选后计时 1157 包；计算均值 **8.271 ms**、P50 **7.691 ms**、P95 **10.969 ms**、P99 **18.930 ms**。就绪到完成 P95 **11.099 ms**，最大 **32.583 ms**；普通成功且不重试的计算均值 **8.210 ms**。
- 同文件 paced 回放两轮均 200/200，合计 **400/400**，每轮 1 次 Full CIR 重试，0 队列丢弃/源错误/gap；计算均值 **7.927 ms**、P95 **9.175 ms**。
- 当前固定输入约 200 包/s，8 worker 未观察到单包延迟收益，默认继续保留 2 worker。未进行饱和输入测试，不能将此结论推广为“8 worker 最大吞吐没有提升”，也不能把短时分位数差异都归因于 worker 数。

原始记录在 `live_8/`、`replay_8/`，配置与同二进制校验见 `metadata_8.json`。本次只扩展基准脚本的 `--workers` 参数，不改生产解码代码；两组实际运行也验证了新增参数与日志解析。复现：
