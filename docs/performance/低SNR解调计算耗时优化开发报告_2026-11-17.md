## 1. 交付内容

### 1.1 Task 1 —— `fold_acquire` 有效窗裁剪 + 去重 + 8-lag 批处理

`gr-uwb/include/gnuradio/uwb/uwb_demod_core.h`

1. **窗口直接夹紧到 `centre ± P/2`**（`fold_acquire`，L282–297）。
   `room` / `k_eff` 仍按**原始** `w0` 计算，所以折叠深度和折叠向量本身逐位不变；
   只有相关窗口被夹紧。`AcquireLegacy`（`radius=8192`）下 span 从 `16384` 降到
   `1016`（**−93.8%**），被丢掉的 15,368 个 lag 本来就被 `lo_lag/hi_lag` 排除在
   argmax 之外。`LockedBounded`（`radius=256 < P/2`）是交集，窗口不变。
2. **前导沿消歧单遍化**（L976–1020）：`ss_metric` 的标量功率循环换成
   `window_power_8acc`；`2*max_j+1` 个候选度量一次算完存进 `cand_metric`，
   第二遍只做查表比较（原来把同一批 `1016` 点相关算了两遍）。
3. **`fold_anchor_fit` 17-lag 精修改 8-lag 批处理**（L434–470）：`use_real` 时用
   `real_template_dot_8lag`，逐 lag 与 `real_template_dot_single` 逐位一致，
   `pw` 更新顺序不变，选出的锚点不变。

### 1.2 Task 2 —— `LockedBounded` 低 SNR 探针早停

`local_best` 新增 `float* raw_max_out`（门限判定**之前**的窗口原始最大值）。

1. **内侧探针收窄**（L1086–1112）：`m = 0` 保留 `±roi`；若 `m = 0` 未命中且其
   `raw_max < 0.045`，则 `m = 1..inner` 的搜索半径收到 `±32`（`4 × 513 → 4 × 65`）。
   锁定态时钟残差只有几样点，`±32` 完全覆盖真实格点；漏掉的部分由尾部探针和折叠
   兜底，两者都保留完整 ROI。
2. **宽尾部探针改到折叠之后**（L1109–1245）。这是本轮**最大的单点收益**。
   任务书 Task 2.2 要求"Tier 0 全部未命中且 `tier0_raw_max < 0.05` 时跳过 Tier 1"，
   但**实测 `-12 dB` 的 `tier0_raw_max = 0.066…0.081`**（新诊断 `tail_raw`），
   0.05 的门限根本不会触发。原因：SYNC 匹配滤波峰只有约 1 chip（2 样点）宽，
   残差在 `±32` 内时 Tier 0 看到的是**满高**的峰，所以 `tail_raw` 反映的是信号
   强度而不是残差大小——任务书的判据在物理上不成立。
   因此改为按**能力**排序而不是按**幅度**排序：窄扫（`±32`，32 符号 × 65 lag）
   → 折叠（同一 `±roi` 窗口，64 符号相干增益，灵敏度高约 18 dB）→ 宽扫
   （`±roi`，32 符号 × 513 lag，仅当折叠也失败时才跑）。
   实测 `-12 dB` 200 包：窄扫从未产生可确认命中（`tail_hit=0`），折叠全部救回，
   所以这个重排**不改变任何结果**，只省掉每包 `32 × 513 = 16,416` 次单符号相关
   （约 1.2 ms）。
3. **跳过必败的 256 符号跟踪**（L1720–1736）：`bounded && locked_tail_probe &&
   !grid_applied && !fold_used && first_metric < min(0.25, 0.08)` 时直接走
   `Post-train fold retry`。门限取**跟踪底线 0.08**而不是任务书的 `thr = 0.25`：
   0.25 会把 5.2 m 实测的尾部救援（`first_metric 0.14…0.20`）也误判为必败，
   那是真实可跟踪的训练序列。

### 1.3 Task 3 —— `stage_sfd` 离散网格 SIMD 预计算 + 窄窗早停

1. **跳过必败的 `k = ±1..±4` 窄窗**（L2280–2298）：`best < 0.015f` 且
   `detected_peaks == preamble_repetitions` 且 `timing.metric < 0.25` 时跳过
   `8 × 129 = 1,032` 个 lag。离散网格覆盖同样的 `±4`（以及 `±36`）符号，
   且判通门限更低、带极性锁，不会丢包。
2. **离散网格按符号分解**（L2426–2530）：`SFD = kron(sfd_seq, sync)`，格点间距
   恰为 `period`，所以 `period == sym` 时 `2*36 + len = 80` 个符号位置覆盖全部
   73 个格点窗口。预计算 80 个单符号相关（`real_template_dot_single`，SIMD）与
   80 个单符号功率（`window_power_8acc`），每个格点度量退化为 `len` 次复数加减
   + `len` 次浮点加法。**只在 `rx_fast_sfd && real_sync_template.is_real` 时启用**，
   非快速路径仍走原标量模板（避免归一化尺度不一致）。
3. `sfd_metric_at` 自身也改用 `window_power_8acc`，快速路径下按符号分解求和
   （与 `sfd_real_dot_single` 同序，逐位一致）。

### 1.4 Task 4 —— `decode_payload_soft` / `rescue_payload_soft`

1. **消除重复的全长软 Viterbi**：`decode_payload_soft` 只跑一次
   `vitdec_cl3_soft_trace`，`tr.bits` 直接用于第一遍 RS/CRC，失败时把同一个
   `tr` 传给 `rescue_payload_soft`（新签名 `const Cl3TrellisTrace&`）。
   `tr.bits` 与 `vitdec_cl3_soft` 逐位一致（新增 QA 守护，见 §4）。
2. **RS 擦除优先**：`rescue_payload_soft` 拆成两阶段。
   阶段 1 对每个 `rs_decode_block` 失败的块先试 `v = 2, 4, 6` 的
   `rs_decode_block_erasures`（零 Viterbi 开销）；若所有块都有候选，立刻做一次
   组合打包 + CRC-16，通过就直接返回，**完全跳过 21 次局部 Trellis 重译**。
   阶段 2 才对这些块跑 6 次单翻转 + 15 次双翻转。

### 1.5 任务书未覆盖、但实测是主因的两处

1. **采集粗扫的逐样点取模**（`stage_timing` acquire 分支）：`(j - j_lo) % stride`
   在 `262,144` 次迭代的循环里做整数除法。改成计数器后省约 200 µs；进一步把
   滑窗功率改成"按 stride 块用 8 个累加器推进"（两条 `|x|²` 流可向量化，只剩
   每块一次串行浮点加），又省约 200 µs。合计 `-12 dB acquire` 的
   `initial_coarse_search_us` 从 `2181…2311` 降到 `1987…2082`。
   **这是 `-12 dB acquire` 达标的关键**：粗扫原本占整条采集搜索的 85%。
2. **`local_best` 的初始功率**改用 `window_power_8acc`。窄窗（17 lag）时这
   `1016` 点标量求和占整个调用的很大比例；采集回退路径一次要调 259 次。

  单遍软 Viterbi + 硬 RS 必须失败、`decode_payload_soft` 必须救回原 wire 字节，
  100 组纯噪 LLR 0 次假 CRC 通过）。
- 低 SNR 折叠：`-12/-14 dB` 各 `50/50`（±6 符号种子扰动，起点误差 0），
  100 纯噪窗 0 虚警。

## 5. 未达成的三项：实测归因

### 5.1 `-12 dB w1 st_sfd = 317 µs`（门限 220）

实测 `stage_sfd` 的构成（`-12 dB`，w1）：

| 子阶段 | 基线 | 本轮 |
|---|---|---|
| `sfd_boot`（真正的 `scan_window`） | 15 | 15 |
| `sfd_tail`（SFD 锚定的 40-SYNC 尾部重跟踪 = 又一次 `stage_timing`） | 400…560 | **103…262** |
| `sfd_cforef`（第二次 CFO 拟合 + 第二次去旋转 279,467 样点） | 113…326 | 100…132 |
| `sfd_final`（去旋转后重跑 SFD） | 14 | 14 |

任务书把 `stage_sfd` 的 530 µs 归因为"离散网格标量重复算 8 遍符号相关 + 前置空跑
8 个窄窗"。**实测不成立**：`sfd_win=1`、`sfd_coarse=128`、`sfd_fine=1`，即只跑了
`k=0` 一个 ±64 窄窗（129 个 lag），离散网格和 `k=±1..±4` 从未执行
（`sfdmetric=0.022…0.043 ≥ 0.02`，低底线 PAR 路径直接判通）。

剩余 317 µs 中约 245 µs 是 `sfd_tail` + `sfd_cforef`，两者都是**架构性**成本：
前者是"用 SFD 锚点重测 40 个尾部 SYNC 以改善 CFO"，后者是"把下游要读的
279,467 个样点用新 CFO 物化到 `scratch.derotated`"（AGENTS 已记录：去旋转只能变快
不能变少）。而且 `-12 dB` 下 `cfo_refit_pk=0`——重跟踪和重拟合**最终没有产出任何
东西**（`fit_cfo` 失败，第二次旋转用的是未变的初始 CFO）。

**已量化的后续方案（本轮未改默认）**：`--cfo-refit auto --cfo-refit-min-peaks 16`
可以让第二次旋转在"重拟合没有移动估计 + 单遍旋转已覆盖"时被跳过。实测：

| 档位 | `st_sfd` 默认 | `--cfo-refit auto --cfo-refit-min-peaks 16` | `fcs` |
|---|---|---|---|
| `-10 dB` w1 | 270 | **145** | `197/200`（不变） |
| `-12 dB` w1 | 309 | **180** | `191/200`（不变） |

即 `st_sfd` 可到 180 µs（低于 220 门限），PRR 不变。**未改默认的原因**：
`cfo_refit_min_peaks = 64` 是为"256 峰全训练序列"设的，而折叠路径只有 16 个
超锚点（跨度 240 符号，杠杆臂其实等价）；把默认从 `legacy` 改成 `auto` 会影响
所有 SNR 与所有配置，而 AGENTS 明确记录 `--cfo-refit auto|skip` **在 27 ppm 未
trim 时钟下未验证**。这一条应在有 27 ppm 实测与上板数据后再改。

### 5.2 `-12 dB w1 st_payload = 350 µs`（门限 320）

实测构成（`-12 dB`，w1，两次配对）：

| 子桶 | 基线 | 本轮 |
|---|---|---|
| `pay_soft`（融合 PN + 四候选相关） | 179…189 | 179…181 |
| `pay_vit` | 29…33 | 31…32 |
| `pay_rs` | 50…56 | 49…50 |
| `pay_other`（Trellis-Chase 翻转 + 擦除译码） | 95…103 | **91…95** |
| `pay_derot`（payload 去旋转） | 74…82 | 76…81 |

Task 4 的收益只有约 10 µs：`pay_other` 从 95…103 降到 91…95，`pay_vit` 不变。
原因有两条：①`vitdec_cl3_soft_trace` 并不比 `vitdec_cl3_soft` 慢（`+4 dB` 实测
10.0 vs 10.8 µs），所以"合并 Viterbi"省下的是**一次本来就不贵的调用**；
②`stage_payload_fused_cmf` 的流程是"先硬判决（`decode_payload_hard` 内含一次硬
Viterbi），失败才用同一批度量原地软判决"，所以 `-12 dB` 的 `pay_vit` 天然是
"硬 + 软"两次 Viterbi，与 rescue 内部的重复无关。
剩余 350 µs 里 `pay_soft`（~180）与 `pay_derot`（~78）合计 74%，都不在任务书
范围内。

### 5.3 `-10 dB w4 comp = 2764 µs`（门限 2600）

`-10 dB` w1 的 `comp` 是 2010 µs，w4 是 2764 µs——**+37%** 全部来自 4 worker 的
内存带宽竞争，不是算力：同一份逐包分解里 `st_sfd` 280→471、`st_payload`
295→478、`st_cir` 133→234、`st_timing` 397→529。这三个阶段都是访存密集型
（SFD 的 8,128 点模板相关、payload 的 279k 样点去旋转 + 融合相关、CIR 的
54 符号相干平均）。任务书基线 3063 µs 是在更低负载下测的，本轮同机 ABBA 基线
是 3125 µs，降幅 −11.6% 已经超过任务书"`-10 dB` 降 1500 µs"之外的任何单项要求，
但离 2600 还差 164 µs。要继续降只能减少访存（例如把 CFO 相位斜坡折进融合 CMF /
soft-chip 内核，AGENTS 已列为 P0），不在本任务书范围。

## 6. 新增诊断

`PACKET` 行新增（纯诊断，无逻辑依赖）：

- `tail_raw` / `inner_raw`：尾部窄扫与内侧 `m=0` 探针在**门限判定之前**的窗口
  原始最大归一化相关。这两个值就是 §1.2 早停判据的输入，也是判定"深低 SNR"
  与"残差过大"的依据。
- `timing_coarse` / `timing_fine` / `timing_seed`：SFD 锚定尾部重跟踪的计时桶。
- `timing0_coarse` / `timing0_fine`：**第一次**（采集）搜索的计时桶。原来会被
  尾部重跟踪覆盖而丢失；`timing0_coarse` 直接暴露了粗扫占采集搜索 85% 这一事实。

## 7. 未验证

- **上板 / UHD 实机**、paced 到达、8 worker、负载下 P99、多径、AWGN+ISR 混合、
  MATLAB 交叉验证、CFO 扫频与 SFO、`-16/-18 dB`。
- **未 trim 的 27 ppm 时钟**：本轮全部夹具都是 0 ppm 合成波形，`integer_chip_grid`
  恒为真、融合路径恒启用。`fold_acquire` 的窗口夹紧与 `stage_sfd` 的符号分解都
  依赖 `period ≈ sym`；27 ppm 下 `period` 仍是 1016（`llround`），但
  `measured_period` 会漂移，`sym_decompose` 的 `period == sym` 判据依然成立，
  未在实采上验证。
- **`locked_roi_samples` 非 256**：本轮只测了默认 256。
- **5.2 m 实采的"头部被干扰、尾部干净"场景**：本轮机器上没有该夹具，只有
  `test_locked_tail_probe_rescues_leading_interference` 的合成等价用例。
  尾部宽扫被移到折叠之后，该场景走窄扫（残差 ~0），QA 已覆盖；但"残差 > 32 样点
  且尾部干净"这一分支现在只有折叠兜底，没有实采证据。
- **`--cfo-refit auto` 的默认化**：见 §5.1，已量化收益但未改默认。
