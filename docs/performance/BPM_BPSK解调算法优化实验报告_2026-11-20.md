## 3. 实现要点

### 3.1 联合双正交 ML（Agent A，`uwb_demod_fec.h`）

- 分支度量 `μ_t(g0,g1) = -(1-2g1)·m_{g0}[t]`，复用 4-state 8-edge 显式展开、
  严格 `<` tie-break 与 `Cl3BackBuffer`（N≤2048 栈上 8 KB）。
- `vitdec_cl3_biorth[_trace]`、`local_cl3_trellis_flip_biorth`、
  `rescue_payload_biorth`（Phase 1 RS erasures + Phase 2 局部翻转）。
- `terminated=true` 强制终态 0；`clip_biorth_metrics` 用固定 1024 点采样中位数
  做 4× 软限幅（O(N)、零堆分配）。
- `decode_payload_biorth_soft` 与 `decode_phr_biorth_soft` 端到端入口。

### 3.2 Known-Hop + DD-PLL（Agent B，`uwb_rx_fused_cmf.h`）

- `hop = (pn[8s] < 0)`；每符号只算 `win0 + hop*16` 与 `+64` 两个窗口。
- `dot2_shared_fixed52`：13 组 ×4 complex、0 标量尾，模板每组只 load 一次，
  两个候选各 2 路 `fmaddsub`。
- `dot2_fused_fixed52`（§9.1 复核引入）：两个 44-tap 半模板常驻 L1D
  （16×44 complex = 5.6 KB），合并模板的每一组在 MAC 循环里**用寄存器拼出来**
  再喂给两个候选窗口，不再写/读 `scratch.fused_tpl`。分组顺序、偶/奇两条
  `fmaddsub` 链与 `fused_mac_group` 运算次序完全不变，因此输出与
  `build_fused_symbol_template` + `dot2_shared_fixed52` **逐位相同**
  （QA `known_hop_inline_template_merge_is_bit_exact`，7 种窗口偏移 ×
  8×8 模板组合 × 4 符号组合 × 每组合 2 个候选）。
  注意这里刻意**不**退化成“两个半模板各做一次 44 点点积再相加”：那样 9 个
  重叠分组会被累加两次（26 → 44 组 MAC），实测反而更慢。
- `correlate_payload_known_hop_fused_cfo`：整数快路径复用 4-chip LUT；
  SFO 路径按 `samples_per_chip_actual + 8-bin CIR bank` 取整/分数相位。
- DD-PLL：符号级二阶 PI 环路、幅度 EMA 门限、频偏限幅、复数增量旋转。

### 3.3 PHR 精校 + 分数 CIR 库（Agent C，`uwb_rx_phase_sfo.h`）

- `refine_phase_cfo_from_phr`：21 符号相干度门限、lag-1 频偏、中心符号平均相位
  外推到 payload 起点；返回 `rot_init * exp(-j·θ)`（与生产
  `signed = pol·Re(rot·complex_value)` 同口径）。
- `build_fractional_cir_bank`：bin 0 逐位等于原 taps；bin b>0 为 +b/8 样点
  Catmull-Rom 插值，并按原 L2 范数归一化。
- `decompose_sfo_position`：最近 1/8 子样点分解，负数 floor 正确。

### 3.4 Wave 2 集成

- `Qm35825Profile` 新增 6 个默认 `false` 的开关：
  `rx_bpm_known_hop / rx_bpm_joint_ml / rx_bpm_terminated_viterbi /
  rx_bpm_ddpll / rx_phr_phase_refine / rx_fused_sfo_track`。
- 解码顺序（保持旧路径兜底）：
  1. 联合双正交 ML（若开启）——同一批 metrics，只多一次 Viterbi；
  2. 失败则 `decode_payload_hard`（无融合 PHR metrics 时的唯一入口，也是第一回退）；
  3. 再失败则旧拆分 LLR 软判决；
  4. 再失败则**同一 IQ 上的上一轮 4 候选融合路径**；
  5. 最后才是 `run_full_stream_fallback`。
  因此新算法不可能丢掉旧融合路径能解的包；`timed` fail-closed 未改。
- ML 提前（§9.2 复核）：`decode_payload_biorth_soft` 第一次先跑**非 trace**
  的 `vitdec_cl3_biorth`（省掉每包 ~24 KB 的 `diff`/`alt` 暂存），只有 FCS
  失败、需要 rescue 时才重建 `Cl3TrellisTrace`。两者逐位一致
  （QA `test_w1_joint_ml_non_trace_matches_trace`，N=1…2049、全零 tie、
  部分 tie、terminated 两态）。因此高 SNR 下一个包只付一次 Viterbi
  （`pay_vit` 8.6 → 8.4 µs），低 SNR 下省掉一整轮注定失败的硬判。
- PHR 阶段新增 Known-Hop 2 候选、双正交 PHR 与 PHR 导频精校；精校结果统一
  旋转到 payload 相位后再送联合 Viterbi。
- **SFO 关键修复**：27 ppm 时 PHR 窗口按标称 2 样点网格计算会累计
  `phr_start·(spc−2) ≈ 7` 样点漂移，导致 PHR 解出错误长度（113 而非 127）并
  触发全流回退。现在把 PHR 整数窗起点按该漂移四舍五入补偿，残差 < 0.5 样点；
  payload 使用精确 8-bin bank。修复后 `sfo27ppm` 原生融合、零全流回退。
- 整数网格上 `rx_fused_sfo_track` 自动关闭，不引入任何额外开销。

### 3.5 两个 opt-in 开关（默认不参与推荐配置）

- **DD-PLL**：实现与 QA 完整，但在 1208 符号核内实测 +40 µs
  （内核微基准 off 50–83 µs → on 91–97 µs），6 组夹具与 −13 dB 扫点均未带来
  额外解码率；保持 `UWB_BPM_DDPLL=1` 可选。
- **PHR 导频精校**：门限 `prod ≥ 0.997`（相邻乘积相干度）+ 相干度 0.65。
  在 −12 dB 下 lag-1 斜率外推噪声较大，若强制启用会使 `control` 出现 1 帧
  回退（ABBA 中 `st_fallback` 均值 ~65 µs/包）；因此 level 3/4 仅保留门控版本，
  推荐配置用 `UWB_BPM_PHR_REFINE=0`。高 SNR 下精校仍可用（golden 与 QA 验证）。

## 6. 与目标的差距分析

1. **`pay_soft` 未达 42–55 µs（实测 control 86 µs）**
   - 2 候选把 IQ 读取量精确减半（1.96 MB → 0.98 MB），dot 核本身 1.93×；
   - 但整核只有约 1.2×：每符号 52 点模板构建（416 B 写 + 704 B 读）与
     CFO ramp 未变。§9.1 已把模板合成搬进寄存器（内核微基准中
     build+dot 由 33.3 µs 降到 29.2 µs，≈12%），但**在整机流水线里测不出来**：
     同一二进制加 `UWB_BPM_LEGACY_TPL=1/0` 的 A/B 中 `pay_corr` 中位数
     69–76 µs 两边相同（§9.3）。
   - 原因是这一层的瓶颈已经不是 ALU：同一内核在隔离微基准里只要 28–34 µs，
     在 `uwb_dw3000_live` 里稳定是 70–78 µs，差值随主机负载变化（`taskset -c 5`
     与 `taskset -c 5,6,7,8` 分别为 74 与 79 µs），即采样读取/共享主机内存
     子系统而非模板运算在决定 `pay_soft`。
   - 参考上界：同一二进制里上一轮的 4 候选核（`UWB_BPM_LEVEL=0`）`pay_corr`
     也只有 57–69 µs，所以“把 control 压到 45–55 µs”需要先把整个
     payload 读带宽问题解决，而不是继续削减模板或 MAC 次数。
2. **`st_payload` 未达 70–95 µs**：低 SNR 已到 131 µs（−13%），但 control
   仍有 109 µs。主要成本从“读样本”转为“样本 + 译码”；`pay_vit` 在低 SNR 已
   从 28 µs 降到 15 µs，`st_fallback` 由 191 µs 归零。
3. **`st_cir` 未整体进入 100–130 µs**：整数网格上仍是上一轮水平（137–149 µs）。
   本轮 CIR 相关改动（Tail 合并/x4）已在上一轮合入，本轮未继续优化。
4. **sfo27ppm 的 `st_total` 极值仍偏大**：复核后 A,B,B,A ×3 的 12 次 run 里
   B 全部落在 1.64–1.90 ms（`st_fallback` 中位数 0 µs），不再出现上一轮
   2.44 ms 中位数 + 3.05 ms 极值的“约 1/41 帧走全流”。但 SFD 段仍有
   `st_sfd` 65 µs vs 基线 411 µs 之外的个别慢帧，属边缘情况，未单独修。
5. **DD-PLL / PHR 精校未带来解码率增益**：在 6 组夹具与 −13 dB 扫点上，
   M1 = M2 = M3；两者保留为 opt-in，避免用 40 µs/包的成本换 0 增益。

## 8. 未验证边界与风险

- **未上板**：全部为软件 / 文件回放；没有 UHD 实时流、队列丢弃、真实 CFO/SFO/
  多径与硬件时钟证据。
- **未做 9700X AVX-512 运行时**：本机 i7-12700 无 AVX-512，只做编译检查。
- **未做 MATLAB 逐样点交叉验证**：双正交 ML、Known-Hop、PHR 精校与 SFO 库均为
  代数等价/统计验证。
- **实采 Gate 0 覆盖不足**：只有 golden 帧可完整解码；`capture_out/packet_0.iq`
  的 payload 不过 FCS。`hop`/尾比特规则的历史硬件普适性未证实。
- **PHR 精校的估计器**：lag-1 斜率在 11k 样点外推下对噪声敏感；当前用
  `prod≥0.997` 门控。若要在低 SNR 真正获益，建议改为解缠相位最小二乘/更短外推。
- **DD-PLL 成本**：+40 µs/包，当前未纳入推荐配置；真实硬件残余 CFO 较大时可再评估。
- **sfo27ppm 极值慢帧**：复核后已无全流回退，但仍有个别 SFD 边缘慢帧，未单独修复。
- **共享主机抖动**：`st_timing/st_total` 的 run 间波动可达 ±20%；ABBA 中位数与
  极值同时给出，绝对 µs 不应与其他机器/日期直接比较。
- **payload 读带宽**：§9.3 证明 `pay_soft` 在本机主要由采样读取/内存子系统决定
  （同一内核隔离 28–34 µs、整机 70–78 µs），模板与 MAC 已不是瓶颈；继续做
  算术层优化不会改变端到端数字。
- **`st_payload` 仍 +7 µs（control）**：2 候选的读窗口是两段 416 B（中间 96 B
  空隙），4 候选是 1 段 1056 B 连续流；在整机内存受限时前者对预取不友好。
  若要把 control 拉回基线，需要改成“固定起点 + 连续读 132 样点、按 hop 选
  子偏移”的核，属下一轮工作，本轮未做。

## 9. 复核轮（`f4aa84e`）

上一版报告提交后，针对 `pay_soft` 的两条评审意见做了实现与实测：
① 去掉每符号 52 点模板的合成与搬运；② 去掉“先硬判失败再走联合 ML”的双次尝试。
两条都已实现，但**结论与预期不同**，这里把证据一并留下。

### 9.1 半模板在寄存器内合并（`dot2_fused_fixed52`）

- 做法：不再把 `lut_lo/lut_hi` 合并写入 `scratch.fused_tpl[52]`，而是在 MAC
  循环里按组拼出合并模板并直接喂给两个候选窗口（细节见 §3.2 第三条）。
- 同进程微基准（1208 符号，AVX2，21 次/组取中位、共 5 组再取中位）：

  | 写法 | MAC 组/符号 | 中位耗时 |
  | --- | ---: | ---: |
  | 落地模板（`fused_tpl`）+ `dot2_shared_fixed52` | 26 | 33.3 µs |
  | 朴素拆分：两个 44 点各点一次再相加 | 44 | 31.0 µs |
  | **寄存器合并 `dot2_fused_fixed52`** | 26 | **29.2 µs** |

  即寄存器合并比落地模板快约 12%、比朴素拆分快约 6%；朴素拆分虽然省了模板
  搬运，却把 9 个重叠分组累加两次，因此并不是最优写法。
- 整机：`UWB_BPM_LEVEL=4 UWB_BPM_PHR_REFINE=0`，同一二进制加
  `UWB_BPM_LEGACY_TPL=1`（落地模板）`/0`（寄存器合并）交替 5 轮，`pay_corr`
  中位数 69/71 µs 对 69/76/65/74/70 µs，**无可分辨差异**；与 §6 第 1 条的
  带宽解释一致。该临时开关在提交前已删除。

### 9.2 联合 ML 提前 + 非 trace 快路径

- 解码顺序改为“ML → 硬判 → 软判 → 4 候选 → 全流回退”（§3.4）。
- 只改顺序时 `pay_vit` 从 8.3 µs 涨到 13.8 µs：`vitdec_cl3_biorth_trace` 每次
  调用都新分配 ~24 KB 的 `diff/alt` 暂存并填 `INF`，干净包为此多付 5.5 µs。
- 改为“第一次先跑非 trace 的 `vitdec_cl3_biorth`，只在 FCS 失败、需要 rescue
  时重建 trace”后，`pay_vit` 回到 8.4 µs（与硬判 8.6 µs 持平），
  并在 −13 dB 上省掉一整轮注定失败的硬判：`pay_vit` 13.0 → 9.4 µs、
  `pay_rs` 5.2 → 3.0 µs（40 帧均值）。
- 逐位一致性由 QA `test_w1_joint_ml_non_trace_matches_trace` 保证。

### 9.3 复核结论

| 项 | 结论 |
| --- | --- |
| ① 模板合成开销 | 实现并保留（逐位等价、少 13 次 store + 13 次 load/符号）；整机收益在噪声内 |
| ② ML 提前 | 实现并保留；配上非 trace 快路径后高 SNR 零代价，低 SNR 省一轮硬判 |
| 解码率 | 6×40 与 −11…−16 dB 扫点与复核前**逐项一致**，错误 FCS 仍为 0 |
| 回归 | 全量 CTest 58/58；AVX-512 三目标编译通过 |
| 未达标 | `pay_soft` / `st_payload` 仍未进入目标区间，瓶颈是采样读带宽（§6、§8） |
