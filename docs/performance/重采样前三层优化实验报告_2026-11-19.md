# 重采样前三层优化（RS-1 ~ RS-5）实施与实验报告

> **日期**：2026-11-19
> **基线**：`feature/sic-research` @ `b654733`（工作树另含 Timing/SFD/CIR 方案的未提交改动，二者文件无重叠）
> **范围**：仅第一~三层（`RS-1`~`RS-5`）。**未做**第四层（Live 窗口裁剪/两段式重采样、`eq12`/`eq8` 新档位）。
> **结论一句话**：`RS-1/2/3` 与既有内核保持逐位一致；`RS-1` 整窗零拷贝在 450k 长窗上带来 5.5%~10.0% 的 `total` 改善，56k 窗在噪声内；`RS-5` 转置内核（AVX2）在 realtime 上约持平、quality 上明显偏慢，**默认关闭、仅显式 `--kernel transposed` 启用**；本机无 AVX-512，AVX-512 路径只做了编译与“运行时跳过”验证。

## 2. 正确性 / 契约验证

### 2.1 `RS-1` 与流式路径逐位一致

`qa_uwb_resampler_burst_opt.cc::test_process_window_zero_copy_bit_identity`：

- 长度 `N = 0, 1, 7, 47, 48, 49, 65, 128, 1024, 4096, 56000`；
- 5 组真实 taps：`65/48 realtime/quality`、`65/32 realtime/quality`、`48/65 TX`；
- `fixed_phase` 关/开（即默认调度与 C1 两条宏块路径）；
- 断言 `process_window_sc16()` 与 `reset + process_sc16 + flush` **逐样本 real/imag 相等且整体 `memcmp == 0`**，并校验 `produced/consumed/flush_complete/input_items/output_items`；
- 同一组用例再经 `resample_sc16_window()` 复测一次。

结果：`*** No errors detected`（AVX2 与 SCALAR 构建均通过）。

### 2.2 `RS-2/RS-3/RS-4`（AVX-512）逐位一致

`qa_uwb_resampler_avx512.cc` 原有 AVX2 vs AVX-512 `memcmp` 门禁全部保留，并新增：

- `test_avx512_window_entry_bit_identity`：经 `process_window_sc16()` 比较 AVX2 vs AVX-512，覆盖 4 组 taps × `fixed_phase` 0/1 × 长度 `1..56000`。

本机（i7-12700）**没有 AVX-512**，该用例按既有 `avx512_ready()` 逻辑打印 SKIP 并通过；AVX-512 构建完成了完整编译（`UWB_SIMD=AVX512`），但**没有运行证据**。

### 2.3 `RS-5` 独立 float64 参考

`qa_uwb_resampler_transposed.cc` 内置独立 double `upfirdn` 参考：

`y[m] = Σ_k taps[(m·M mod L) + L·k] · x[floor(m·M/L) − k]`，`x` 在 `[0,N)` 外为 0。

覆盖：

- `65/48` 四组 taps：`eq16 H=16`、`realtime H=21`、`eq32 H=32`、`quality H=42`（H 均不是 8 的倍数，验证无 padding FMA 浪费）；
- `65/32`：`realtime H=17`、`quality H=42`；
- 长度 `0,1,7,47,48,49,65,128,1024,4096,56000`，以及生产级 `450000`；
- LCG / rails / impulse、非对齐输入指针、显式 `scalar` 与 `avx2`；AVX-512 仅在支持时追加；
- `set_kernel("transposed")` 与独立类输出 `memcmp == 0`。

门限：长度完全一致，最大绝对误差 `< 1e-5`。AVX2 与 SCALAR 构建均通过。

### 2.4 既有契约

- `qa_uwb_resampler_burst_opt.cc` 全部通过（含 C1 全相位、MT、FC32、48/65、短窗/小 grant）。
- `qa_uwb_refactor_contracts.cc` 通过（`resample_sc16_window` 的 history/scale/tail 语义未变）。
- `baseline` 与新版在 `--window-mode 0` 下的 FNV-1a 输出校验和完全一致（见 §4）。

## 4. ABBA 实测（RS-1 / RS-5）

### 4.1 方法

- CPU：12th Gen Intel Core i7-12700（8P+4E，20 线程；本机无 AVX-512）；测试锁 `taskset -c 5`。
- 构建：Release，AVX2，UHD OFF；基线二进制在 `b654733` 独立 worktree 构建，路径不同、库不同。
- 串行、同环境、ABBA 交替三轮；每轮 `--reps 100 --warmup 20`；`total` = 每窗 `reset+process+flush` 的均值。
- 输入：LCG（`seed=0x1234567`），taps 取 `testdata/resampler_65_48/`，长度 56,000 与 450,000。
- 由于系统存在调度抖动（run 内 mean 与 P50 差异可达 15%），表中同时给出 **mean** 与 **三次 run 的 P50 中位数**；百分比按 mean 计算，仅作趋势判断。

Taps FNV-1a 64：

| 文件 | FNV |
|---|---|
| `65/48/taps_realtime_minorder.txt` | `0x8c4024a677744a49` |
| `65/48/taps_quality_minorder.txt` | `0x4133bb40c3d2dcb4` |

四个方案的输出校验和（`--length 56000/450000` 各自一致）：

- Baseline / `--window-mode 0` / `--window-mode 1`：三者完全相同（逐位一致的直接证据）；
- `--kernel transposed`：不同（预期；转置内核改变累加顺序，由 §2.3 的 `1e-5` 参考门禁负责）。

### 4.2 结果

#### realtime_minorder（H=21, H_pad=24）

| N | 方案 | total mean (us) | P50 中位 (us) | vs baseline |
|---|---|---:|---:|---:|
| 56k | Baseline | 180.8 | 162.5 | — |
| 56k | `window-mode 0` | 176.4 | 161.2 | -2.4% |
| 56k | `window-mode 1`（RS-1） | 181.5 | 173.9 | +0.4% |
| 56k | transposed（RS-5） | 201.2 | 180.3 | +11.3% |
| 450k | Baseline | 1700.8 | 1497.9 | — |
| 450k | `window-mode 0` | 1559.2 | 1468.8 | -8.3% |
| 450k | `window-mode 1`（RS-1） | 1607.8 | 1499.7 | -5.5% |
| 450k | transposed（RS-5） | 1671.5 | 1556.1 | -1.7% |

#### quality_minorder（H=42, H_pad=48）

| N | 方案 | total mean (us) | P50 中位 (us) | vs baseline |
|---|---|---:|---:|---:|
| 56k | Baseline | 295.7 | 272.2 | — |
| 56k | `window-mode 0` | 294.0 | 271.4 | -0.6% |
| 56k | `window-mode 1`（RS-1） | 303.5 | 254.5 | +2.6% |
| 56k | transposed（RS-5） | 351.3 | 333.6 | +18.8% |
| 450k | Baseline | 2546.6 | 2379.2 | — |

| 450k | transposed（RS-5） | 3079.9 | 2794.7 | +20.9% |

### 4.3 解读

1. **RS-1 有效且与长度强相关**：56k 窗只省 224 KiB 拷贝，收益落在噪声内（P50 甚至 -6.5%）；450k 窗省约 1.8 MiB 拷贝，quality 稳定 -10.0%、realtime -5.5%。
2. **RS-2/RS-3** 只在 AVX-512 上生效，本机无法量化；但批处理减少了每宏块跨 TU 调用，且对齐表不改变数值，属于“零风险保留”。
3. **RS-4（AVX-512）** 采用运行时 `vpermi2ps` 重建四个窗口，去掉每 4 输出 6 条 `jne`；归约树与 FMA 顺序不变。因无 AVX-512 机器，只有编译门禁。
4. **RS-4（AVX2）两种实现均未保留**：先试“指针预选 + 重复加载”，再试“8 路复用掩码编译期特化”，在 56k/450k × realtime/quality 上一致出现 7%~23% 回退（代码膨胀 + 额外加载），因此 AVX2 保持 `b654733` 原始实现并在头文件注释中记录该实测结论。
5. **RS-5 裁决**：AVX2 转置内核在 realtime 上接近持平（56k 慢、450k 略快），quality 上稳定慢 18~21%（H=42 时 tile 构建与标量广播成本超过省下的 padding FMA）。因此：
   - **默认仍是宏块路径**（`set_kernel("default")`，`transposed_enabled() == false`）；
   - 转置内核作为显式 A/B 开关交付（`--kernel transposed[ _avx2|_avx512|_scalar]` + `--window-mode 1`），既有 QA 与 1e-4/1e-5 门限不变；
   - AVX-512 8 宏块版本（每块 4 KiB、8 相位散射写回）预期优于 AVX2 4 宏块版本，但**必须**在支持 AVX-512 的机器上重跑 §4 的 ABBA 后才能改默认。

## 5. 复现命令

```bash
# 构建
cmake -S gr-uwb -B gr-uwb/build-resamp-avx2 -DCMAKE_BUILD_TYPE=Release \
  -DUWB_SIMD=AVX2 -DENABLE_UHD_BACKEND=OFF
cmake --build gr-uwb/build-resamp-avx2 -j

# 必跑 QA
env -u LD_LIBRARY_PATH ./gr-uwb/build-resamp-avx2/lib/uwb_qa_uwb_resampler_burst_opt.cc
env -u LD_LIBRARY_PATH ./gr-uwb/build-resamp-avx2/lib/uwb_qa_uwb_resampler_avx512.cc
env -u LD_LIBRARY_PATH ./gr-uwb/build-resamp-avx2/lib/uwb_qa_uwb_resampler_transposed.cc

# 单窗 A/B（同一二进制内的三条路径）
B=gr-uwb/build-resamp-avx2/apps/benchmark_sc16_burst_core
T=testdata/resampler_65_48/taps_quality_minorder.txt
taskset -c 5 env -u LD_LIBRARY_PATH $B --taps $T --length 450000 --reps 100 --warmup 20 --window-mode 0 --json /tmp/w0.json
taskset -c 5 env -u LD_LIBRARY_PATH $B --taps $T --length 450000 --reps 100 --warmup 20 --window-mode 1 --json /tmp/w1.json
taskset -c 5 env -u LD_LIBRARY_PATH $B --taps $T --length 450000 --reps 100 --warmup 20 --window-mode 1 --kernel transposed --json /tmp/trans.json
```

跨基线对照：在 `b654733` 独立 worktree 用相同 CMake 参数构建 `benchmark_sc16_burst_core`，串行执行同样的 `--taps/--length/--reps`（旧二进制无 `--window-mode`，等价于 0）。
