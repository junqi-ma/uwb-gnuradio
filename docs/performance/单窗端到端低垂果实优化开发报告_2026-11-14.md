## 2. 三个整改点

### Track A：SIC bypass 零拷贝、`i_hat=nullptr`、流水线冗余缓冲（`fcb1f1a` + `f9f8e06`）

- `SicUnifiedConfig` 新增 `bool copy_input_on_bypass = true`（默认保持历史语义）。
  五个顶层 L0 出口统一走 `bypass_outputs()`：`invalid_buffers_or_scratch`、
  `config_or_template_mismatch`、估计失败、PreambleOnly `sfd_detect_failed`、
  strict-FullPacket abort，外加 `reconstruct_and_subtract_unified()` 的
  `fail_closed()`。
- 该字段**故意不进** `compute_unified_config_hash()`：它不改变任何缓存内容，
  进哈希会让"用默认值 prepare 的 scratch"在 false 下误报
  `config_or_template_mismatch`（QA 已验证）。
- 流水线 worker：置 `copy_input_on_bypass=false`、`i_hat=nullptr`，删除
  `sic_ihat` 的声明/`assign`/`resize`；`cf32_native` 只在无专用重采样核的分支
  预分配（专用 65/48、65/32 路径不再做 8×native_capacity 的死清零）。
- 模板摘要记忆化：`cache_matches()` 对 `(sync ptr/len, preamble ptr/len,
  impulse_sync ptr/len, epoch, digest)` 做 memo，8 KB SYNC 内容摘要只在元组或
  epoch 变化时重算；`force_full_hash` 与 `invalidate_template_identity()` 作为
  逃生口。**残留风险已写入头文件**：同指针 + 同长度 + 原地改内容不可检测。

### Track B：窗外自相关归因修正 + `energy_prefix` 惰性/AVX2（`5a16898`）

- 归因规则（代码注释逐字保留）：lag-`sps` 自相关命中在 `seg_start` 表示
  "`seg_start` 附近存在周期内容"，证据区间是
  `[seg_start - sps, seg_start + box_segs*seg_len + 2*sps)`，目标自身前导位于
  `[t_lo, t_hi)`。**只有证据区间完全落在归因带 `[t_lo - sps, t_hi + sps)` 之外**
  才算窗外干扰；`outside_ivs`/`inside_ivs` 的构造（搜索区域）完全未改。
- `energy_prefix` 改为**惰性**（预检判定不拒绝之后才建），预检自身用
  `sum_sq_range` 直接算自己那几段能量；前缀与段能量都用
  `__attribute__((target("avx2")))` + `__builtin_cpu_supports("avx2")` 分派
  （该 TU 无全局 `-mavx2`，所以 `__AVX2__` 为假，标量核保留为回退）。
  前缀仍在 **double** 累加：4 个 float 平方 → 2×`__m256d` → 组内 double 前缀 →
  每组一次 double 加法。
- AVX2 vs 独立标量 double 参考：552128 点最大相对误差 **2.5351e-08**（门槛 1e-7）。
- **必须如实记录的边界**：该快速剔除只在调用方设置 `target_preamble_lo/hi`
  **且** `autocorr_search_inside_target == false` 时才会触发。**Fixed 调度流水线
  从不设置该带**（`slot->use_dynamic_slot == false`），因此本修正
  **不会让生产流水线的 clean 窗走快速剔除**——它是归因正确性修正。
  实测印证：clean 窗 `sic_status` 两臂都是 `below_detect_threshold`（各 480/720 窗）。
- 完全在带内的干扰包（整个周期区都在 `[t_lo, t_hi)`）新旧规则都无法用自相关区分；
  旧规则落到 `below_detect_threshold`，新规则直接拒绝，**最终结果相同**（带内本来
  就不在搜索范围内），QA 已断言这一点。

### Track C：`RealSyncTemplate` 缓存、`local_best` 能量向量化、零 CFO 旁路（`2427edd`）

- `RealSyncTemplate::key`（此前是死字段）改为**内容键**：对原始模板字节 + 长度做
  FNV-1a，按 8 字节消费。归一化模板与能量缓存在 `DemodScratch`
  （`sync_template_norm`/`sync_template_energy`），**不再覆盖 `work`**。
  `build_real_sync_template()` 仍会 `reset()`（key=0），所以 `stage_sfd` 用原始
  模板重建时会自动失效。全部状态在每 worker 的 scratch 内，无静态量、无锁。
- `local_best` 的初始窗能量改用 `rxopt::window_energy()` → AVX2 8 lane FMA
  （运行时 `has_avx2_fma()` 分派，标量回退保留）。逐候选 O(1) 更新未动。
- `derotate_cfo_range()` 在 `w == 0.0` 时跳过建表与两趟 VOLK，直接 memcpy：
  `exp(-j·0·i) ≡ (1,0)`，逐位相同（QA 对两种核都验证过）。
- **否决并如实记录**：CFO 表缓存（`build_cfo_table` 只建 64 个 double 锚点，
  实测 3.33 µs，不是 1024 次 sin/cos ≈ 15 µs，且两趟旋转用不同 `w`，无可复用）；
  冗余重复去旋转（已确认不存在）。
- 峰值位置逐位不变（64 窗全部 `9984 + k·1016 + 1015`）；`local_best` 度量最差相对
  偏差 8.34e-7；256-SYNC sensing CIR 的 `peak_tap`/`peak_abs`/116 个 tap 的
  float 位模式 **`cmp` 逐字节相同**。

## 3. 测量合同

- **配对协议**：每格 A B B A 交替，`--groups` 组；每臂 = 2 × groups 次运行。
  N=1 用 4 组（每臂 8 次），N=8 用 3 组（每臂 6 次）。
- **预热/测量窗**：N=1 预热 12、测量 48；N=8 预热 24、测量 96。
- **CPU 绑定**：N=1 用 `taskset -c 2,4`（两个非 SMT 同胞核）。
  同一二进制 A/B/B/A 的配对中位比 **1.011 [0.986..1.039]**，绝对 e2e 也从
  780 降到 630 µs；单核绑定（`-c 2`）噪声 ±10 %，故不采用。
- **N=8 不绑定**：`taskset -c 2,4,...,16` 反而更慢（treatment B256_clean
  三次 867/775/749 µs vs 不绑定 684/667/526 µs）——8 核绑定把 feeder/commit
  线程挤在同一批核上。因此 N=8 正式数据用不绑定的
  `data_low_hanging_20261114/n8_unpinned/`，绑定对照单列于此。
- 每次运行由二进制自身持有 `/tmp/uwb-sic-benchmark.lock`；`ready_ok=false`、
  `ledger_invariants_ok=false` 或测量窗数不足的运行一律被驱动脚本拒绝
  （本轮 0 次拒绝）。
- 报告口径：**配对中位比**（组内 treatment 均值 / control 均值，再取组间中位）
  是主指标；`ratio` 列（全臂均值比）作为对照一并保留在 `summary.json`。

## 5. 未做 / 未验证

- **未上板**：无 USRP、无 paced 到达、无 UHD `recv` 溢出交互、无 AVX-512、无 MATLAB
  交叉验证。本文所有数字是文件回放的吞吐上限，不是实时调度下的出包间隔。
- **N=8 的绝对吞吐受 VM 拓扑限制**：20 逻辑 CPU 的 WSL2 虚拟机，不保证宿主物理核
  映射或频率；N=8 只报相对比，不宣称达到某个绝对窗率。
- **Track B 的快速剔除在生产流水线不生效**（Fixed 调度不设目标带）。要让它在
  `AutoAcquire` 动态槽路径上生效需要单独评估"带内共址干扰"的漏检风险，本轮未做。
- **未测**：PSLR/ISLR 全量、非零 CFO 的感知质量、跨窗相位专项、弱目标保护矩阵、
  三 session 性能矩阵、6912 例功能矩阵。
- **未改**：`uwb_discrete_cir_reconstruct.cc` 的三处 reconstruction 级 fail-closed
  `y → out` 拷贝仍不认 `copy_input_on_bypass`（签名来自禁改的
  `uwb_discrete_cir_sic.h`）；它们只在重建级失败时执行，且 `committed==false`，
  对 clean 热路径无影响。
- **`compute_unified_template_hash` 仍只按指针识别 preamble**（改动前既有行为），
  本轮未加强。
- 候选不标记为全面验收通过，不自动合并主分支，未推送、未安装到系统、未移动 tag。
