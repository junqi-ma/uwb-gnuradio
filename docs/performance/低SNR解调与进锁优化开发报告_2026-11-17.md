## 2. 各模块实现要点

### 2.1 Live 进锁开关（`uwb_dw3000_live.cc`）

- `--lock-fcs on|off`（默认 `on`）→ `TargetLockConfig::require_fcs`。`off` 时只要 `timing_ok && sfd_ok`
  且网格残差合规即可驱动 `ACQUIRE → VERIFY → LOCKED`，由 `TargetLockCore` 用残差区分目标与干扰。
- `--stop-after-sfd on|off`（默认 `off`）→ `Qm35825Profile::rx_stop_after_sfd`（同时作用于 acquire 与 locked 配置）。
- 非法值（`invalid`/`true`/`1`/`ON`/空）严格返回退出码 2，与 `--tone`/`--fused` 不同（后两者"非 off 即 on"）。
- 两处联动修复：
  1. `--cir auto` 的 15 ms `Full` 重试加前置 `!p.rx_stop_after_sfd`；
  2. `INTERFERENCE ... reason=identity_mismatch` 与 `++interference_events` 仅在
     `lock_fcs == "on" && stop_after_sfd != "on"` 时记录。
- 默认值复现旧行为；唯一输出差异是 `START` 行新增 `lock_fcs=` / `stop_after_sfd=` 两个字段。

### 2.2 Timing（`stage_timing`）

1. **PAR 兜底**：`!bounded` 分支的 `narrow` 与 `legacy_seed_radius` 两个局部 `local_best` 开启
   `allow_par_fallback`（`count ∈ [64,1024]`、`PAR ≥ 20`、底线 `0.06`）。宽 `coarse_scan` 与全网格探测
   保持绝对门限，避免纯噪虚警。
2. **弱训练二次跟踪**：第一遍按旧门限跟踪；若训练长度 `< max(4, min_valid_peaks)`，再按 `0.06` 底线
   重跑一遍。高 SNR 第一遍即完成，零额外开销。**（主控新增：Subagent 原实现只在 `first_metric < 0.25`
   时降门限，而 −8 dB 下窄窗最大值可能偶然越过 0.25，导致跟踪仍被截断。）**
3. **`K=64` 周期折叠**：仅当所有单符号路径失败时触发。
   - 窗口：`bounded` 取 `seed ± roi`；`!bounded` 取 `seed ± min(margin, 8192)`。
   - `folded[m] = Σ_{k<K_eff} rx[w0+m+k·1016]`，滑窗归一化相关，门限 **`0.05`**（实测 −14 dB 折叠度量
     最小 0.532，纯噪 200 位置最大 0.0107）。
   - 缓冲不足时退化 `K_eff = min(64, 可用符号数)`，要求 `≥ 16`。
4. **绝对符号消歧（主控新增，任务书未包含）**：前导是 256 个逐字节相同的 SYNC，折叠度量严格以
   `1016` 为周期，**折叠本身无法给出绝对符号号**。实测前端种子在 −14 dB 下误差达 −6.5…+4.4 个符号。
   因此在折叠给出的网格相位上，沿候选网格从早到晚扫描，取**第一个**单符号度量越过
   `max(0.003, 0.2·max_metric)` 的格点——真起点之前是噪声（≈0.001），之后是 SYNC（≈0.038）。
5. **16×16 超级锚点拟合**：每 16 个 SYNC 相干累加为超级符号（+12 dB），在预期位置 ±8 样点精寻峰，
   最小二乘拟合 `measured_period` 与 `preamble_start_sample`。
6. **`detected_peaks` 语义**：折叠路径填 `preamble_repetitions`（256）而非 16 个锚点数。
   因为 `stage_cir_softchips` 从 `detected_peaks` 推导相干平均次数，填 16 会让 CIR 只平均 8 个 SYNC
   而不是 54 个（约 −8 dB CIR SNR）。锚点位置仍写入 `peak_samples/peak_metrics/peak_corr`。

### 2.3 CFO（`fit_cfo` + Tail Retrack）

- **稀疏锚点解缠绕**：相邻对门限先按 `dt ≤ 1.5·1016` 累积；若为空，退化到 `dt ≤ 20·1016`，斜率用
  `arg(adj_sum)/mean_dt`。密集训练（256 峰）走原路径，算术逐位不变。
  20 符号跨度内 `|CFO| < fs/(2·20·1016) = 24.6 kHz` 无 ±π 模糊。
- **Tail Retrack 门限**：`radar_verification_threshold` 由写死的 `0.20f` 改为
  `min(profile.radar_verification_threshold, 0.08f)`。尾部起点已由 `bootstrap_sfd` 钉在 ±8 样点，
  绝对门限在这里只是拒绝真实低 SNR SYNC（−3.5 dB 实测 23/100 `CFO_FAILED`）。

### 2.4 SFD（`stage_sfd`）

- 主路径（`k ∈ [0,±4]`、`kSfdNarrowHalf = 64`、`0.02` 低底线、`0.08` 高底线）**逐位不变**。
- 仅当主路径 `!sfd_passed` 时进入离散整数符号网格兜底：
  - `k ∈ [-36, +36]` 的整数符号格点先按 `δ=0` 评估，只对最优格点做 `±1` 样点精修（75 次而非 219 次）；
  - 判通条件：`peak ≥ 0.008`、离散网格 `PAR ≥ 1.5`、8 符号相干极性全匹配。
  - 8 符号极性校验抽成共用 lambda，原 `0.02..0.08` 低底线路径与网格兜底共用，无代码复制。

### 2.5 PHR / Payload 软判决

- `rxfusion::decide_bpm_soft`：硬判决与 `decide_bpm` 逐位相同，LLR 与 `bprf_demod_soft` 同约定
  （`llr0 = |half0|−|half1|`、`llr1 = 选中半支有符号度量`，正值倾向 bit 0）。
- `decode_phr_decisions` / `decode_phr_decisions_soft` 共用 `phr_secded_parse`（SECDED + 尾能量护栏 +
  长度/速率解析）。`stage_phr` 与 `stage_phr_fused_cmf` 改用软 Viterbi；融合 PHR 缓存 21 组 `llr0/llr1`，
  `reset_decisions()` 同步失效。
- `decode_payload_hard` / `decode_payload_soft` 共用 `finish_rs_crc_payload`（RS(63,55) + LSB-first 打包 +
  CRC-16 + FCS）。`stage_payload_fused_cmf` 先跑硬判决；失败或 `!fcs_pass` 时用**同一批四支路度量**
  原地跑软 Viterbi；只有软判决也失败才退回外层 ~15 ms 全流重算。

## 3. 与任务书的偏离（均为实测逼出）

1. **折叠不能给出绝对符号号**。任务书 §3 Subagent 2 假设"折叠区落在窗口内即可定出精确 `first_start`"，
   但前导是 256 个相同 SYNC，折叠度量严格以 1016 为周期。实测前端种子在 −14 dB 下误差 −6.5…+4.4 符号。
   主控增加"前导沿扫描"消歧（§2.2 第 4 条），QA 用 ±6 符号扰动种子验证。
2. **`detected_peaks` 填 256 而非 16**。任务书要求填锚点数；这会让 CIR 相干平均从 54 个 SYNC 掉到 8 个。
3. **SFD 的 PAR 门限取 1.5 而非 5.5**。离散网格的背景格点落在 SYNC 上，而 `4z2` 序列（和为 −4）与纯 SYNC
   的相关只有 1/4 功率，实测真峰只有背景的约 2 倍。5.5 会拒掉 −14 dB 的真峰。虚警由 `0.008` 底线
   （纯噪 200 窗最大 0.00053，15 倍余量）与 8 符号极性锁（单候选 2⁻⁸）承担，实测 200 窗 0 虚警。
4. **SFD QA 落在 `qa_uwb_demod_core.cc` 而非 `qa_uwb_radar_sfd_core.cc`**。`stage_sfd` 的既有 QA 在
   前者；后者测的是 `radar::refine_sync_origin`，不是同一个函数。
5. **CFO 尾部超级锚点兜底未实现**。−12/−14 dB 下 Tail Retrack 仍会失败（`cfo_refit_pk=0`），但初始
   16 锚点拟合已把 CFO 估到 ±10 Hz（本夹具 CFO=0），`res.cfo.ok` 为真，链路正常。
   任务书要求的"尾部仍不足 4 峰时构造超级锚点"因此没有触发场景，未加。
6. **任务书"−14 dB CFO 误差 < 50 Hz"目标未单独验证**。本夹具 CFO=0，实测初始拟合残差 ±10 Hz；
   带 ±2 kHz 注入的 CFO 精度只做了 16 锚点合成单测（0.1% 相对误差），未做完整帧注入。

## 5. 未验证 / 已知限制

- **未上板、未接 UHD**：全部为文件回放。paced 到达、8 worker、负载下 P99、真实溢出均未验证。
- **未做多径 / 混合 AWGN+ISR / 干扰场景**：本文所有 SNR 均为纯 AWGN。
- **未做 MATLAB 交叉验证**。
- **未做 CFO 扫频与 SFO**：完整帧只在 CFO=0 下跑过；CFO 精度只做了合成单测。
- **`-12/-14 dB` 的 `identity_rejects` 不对称**（68 vs 2）：−12 dB 落在单符号门限（0.06）与折叠门限之间，
  部分包的 SFD/残差被判不合规。不影响 `lock_entries=1 / reacquire=0 / LOCKED`，但 −12 dB 的
  `fcs_ok=130` 低于 −14 dB 的 197，机制未进一步归因。
- **`--sync locked` 在 −10 dB 反而低于 acquire**（165 vs 179）：LockedBounded 的 ±256 ROI 在低 SNR 下
  的重跟成功率低于宽搜。未调参。
- **SCALAR 不是实时配置**：前端 `frontend_us` 在 SCALAR 下约 462 ms / 0.5 s（AVX2 约 98 ms），
  实时必须 AVX2。
- **折叠路径成本**：失败时约 1–3 ms/包（折叠 + 全窗相关 + 16 锚点）。高 SNR 与能走通单符号的包零开销。

## 6. 复现

```bash
# 构建（本机 AVX2）
cmake -S gr-uwb -B gr-uwb/build-native -DCMAKE_BUILD_TYPE=Release \
  -DUWB_SIMD=AUTO -DUWB_BUILD_GNURADIO=OFF -DENABLE_UHD_BACKEND=OFF -DUWB_BUILD_EXPERIMENTS=OFF
cmake --build gr-uwb/build-native -j
ctest --test-dir gr-uwb/build-native --output-on-failure

# 进锁闭环
./gr-uwb/build-native/apps/uwb_dw3000_live \
  --replay /tmp/low_snr_eval/fm14.sc16 --seconds 0 --period-ms 1.0 \
  --mode continuous --sync locked --workers 4 \
  --cir full --fused on --taps eq16 --tone off \
  --lock-fcs off --stop-after-sfd on
```

（`gen_full_frame.cc`、`build_stream.py`、`matrix.py`），属一次性评测工具，未入库。
