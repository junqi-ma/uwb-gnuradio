## 1. 总体编排与防冲突策略

由于解调核心集中在单头文件 `gr-uwb/include/gnuradio/uwb/uwb_demod_core.h`，而前端调度/窗口/捕获集中在 `gr-uwb/apps/uwb_dw3000_live.cc`，为避免多个 Subagent 并行改同一文件产生大面积合并冲突，采用 **"独立 Git Worktree 隔离 + 按文件/函数边界分波次并行 + 主控统一集成验收"** 模式：

- **公共约束（所有 Subagent 必须遵守）**：
  1. 严格遵守仓库根目录 `AGENTS.md`：保留分数网格与融合回退路径、`Full -> Bypass`（`grid_reject`）降级保护、AVX-512/AVX2 逐位一致、`timed` 无 `--replay` 时 fail-closed，不改动 `gr-uwb/build-avx512-smtcheck`。
  2. 构建命令统一为：
     ```bash
     cmake -S gr-uwb -B gr-uwb/build -DCMAKE_BUILD_TYPE=Release \
       -DUWB_SIMD=AVX512 -DUWB_BUILD_GNURADIO=OFF \
       -DENABLE_UHD_BACKEND=OFF -DUWB_BUILD_EXPERIMENTS=ON
     cmake --build gr-uwb/build -j
     ctest --test-dir gr-uwb/build --output-on-failure
     ```
  3. 每个 Subagent 必须在自己的 worktree（`git worktree add .worktrees/<agent-name> -b exp/<agent-name> 717b351`）中独立编译、跑通全量 CTest（53 项可运行测试全过，`uwb_qa_native_install_consumer` 按设计跳过），并跑 7 距离离线回放对照后才允许提交。
  4. **7 距离回放统一基准**：数据集 `/media/oi/Data/uwb/clean_distance/2026-11-16/d{0p8,1p6,2p5,3p5,3p8,4p2,5p2}m_period1ms/rx_2s_r01.sc16`，必须记录各距离 PRR、失败分类（NOWIN / TIM / CFO / SFD / PAY）及 `demod_mean` / `OK-only` / `p95` / `compute_mean`（与 `717b351` 基线对比）。

## 2. 波次划分与 Subagent 任务分配

### Wave 1：零文件冲突的三路并行（可同时启动 3 个 Subagent + 1 个只读剖析 Subagent）

| Subagent | 分支 / Worktree | 独占修改文件/函数边界 | 对应优化项 | 预期收益 |
|---|---|---|---|---|
| **Agent-A：SFD 去旋转优化** | `exp/opt-sfd-cforef` | `uwb_demod_core.h` 中的 `stage_sfd`（`sfd_cforef`）、`stage_cir_softchips`、`stage_payload_fused_cmf` | **建议 1**：去掉/合并 SFD 二次 CFO 拟合与全帧去旋转（改为 CMF/soft-chip 内逐 chip 相位递推或低 ppm 跳过） | `demod` −150 ~ −240 µs/包 |
| **Agent-B：锁定态窗口与单音调度** | `exp/opt-live-window` | `gr-uwb/apps/uwb_dw3000_live.cc` 中的 `pre_guard` 计算（~L1001）、`Acquisition::scan`（~L677）及单音消除调用边界 | **建议 3**（锁定态缩短 `pre_guard`）+ **建议 7**（`5.2 m` 周期累加捕获降 `NOWIN=50`，可选含 `2.5 m` `NOWIN=6` 排查） | `resample` 约 −65 µs/包；`5.2 m` 首次锁定时间与 `NOWIN` 大幅下降 |
| **Agent-C：Payload 子阶段打点（只读/轻改）** | `exp/prof-payload` | `uwb_demod_core.h` 中的 `DemodResult` / `stage_payload_*` 计时字段（仅加微秒打点） | **补充观察**：拆分 `st_payload`（~248 µs）内部 soft-bit 映射、Viterbi、RS 解码耗时占比 | 为后续 Payload 优化提供实测热点，无算法风险 |

> **Wave 1 集成顺序**：`Agent-C`（纯计时打点）→ `Agent-A` → `Agent-B`，由主控（Integrator）按序 merge 到集成分支，每合入一个立即跑 `ctest` + 7 距离对比。

### Wave 2：基于 Wave 1 集成基线的两路并行

> 前提：Wave 1 已合入集成分支（记为 `base-w1`），`stage_sfd` 内的 `sfd_cforef` 边界已稳定。

| Subagent | 分支 / Worktree | 独占修改文件/函数边界 | 对应优化项 | 预期收益 |
|---|---|---|---|---|
| **Agent-D：锁定态网格跟踪、CIR 合并与突发消隐** | `exp/opt-locked-grid-cir` | `uwb_demod_core.h` 中的 `stage_timing`（仅 `LockedBounded` 分支）及 `demodulate_one` 中 `timing -> cfo -> cir` 衔接 | **建议 2 + 建议 6**：8–16 稀疏锚点校验网格 + 256 符号单点相关一次完成相位提取与 CIR 累加 + 能量异常符号突发消隐 | `timing + CIR` −240 µs/包；挽救 `5.2 m` 突发干扰导致的 `TIMING_FAILED`（+0.6~1.0% PRR） |
| **Agent-E：锁定态 SFD 定点验证与门限收敛** | `exp/opt-sfd-locked-gate` | `uwb_demod_core.h` 中的 `stage_sfd` 搜索窗口与判决逻辑（仅 `LockedBounded` 模式） | **建议 5 + 建议 8（局部）**：锁定态 SFD 从 `sfd_coarse=128` 收缩为 1–3 个预测位置定点验证，并简化多层启发式门限 | 搜索空间缩小 ~40×，大幅降低虚警与规则复杂度 |

> **Wave 2 注意事项**：`Agent-D` 与 `Agent-E` 均修改 `uwb_demod_core.h`，但严格隔离在不同函数（`stage_timing`/`stage_cir` vs `stage_sfd`），严禁互相修改对方函数及共享结构体签名；主控合并时按 `Agent-D` → `Agent-E` 顺序合入。

## 3. 各 Subagent 标准交付 Prompt 模板（可直接分发给 OpenCode）

每个 Subagent 启动时，主控只需替换 `<...>` 部分即可下发：

```text
你是 <Agent-X>，负责在独立 worktree `.worktrees/<agent-name>`（分支 `exp/<agent-name>`，基线 `<base-commit>`）中完成以下单一职责优化：

【修改范围（严禁越界）】
- 只允许修改：<列出允许修改的文件与函数>
- 禁止修改其他阶段逻辑，禁止改动 `gr-uwb/build-avx512-smtcheck`。
- 必须遵守根目录 `AGENTS.md` 中关于分数网格回退、Full->Bypass 降级、AVX-512/AVX2 逐位一致、timed fail-closed 的所有约束。

【任务目标】
<对应建议的具体技术要求与不变量>

【验收步骤（必须全部执行并在汇报中附真实输出）】
1. 在 `.worktrees/<agent-name>/gr-uwb/build` 完成 Release + AVX512 编译并运行 `ctest --test-dir gr-uwb/build --output-on-failure`，确认 53/53 可运行测试全过。

3. 输出与基线（`717b351`）的对比表：各距离 PRR、NOWIN/TIM/CFO/SFD/PAY、`demod_mean`（含 OK-only）、`p95`、`compute_mean`。
4. 若 PRR 无退化且单测全过，在 `exp/<agent-name>` 提交干净的 commit（不含构建产物和临时日志）；若某项实验不成立或收益为负，保留完整数据并明确汇报原因。
```

## 4. 主控（Integrator）验收与合并检查清单

1. **合并前检查**：确认 Subagent 的 `git diff --stat` 仅包含约定文件，无无关格式改动。
2. **逐一合入与回归**：每次只合入一个 Subagent 分支，重新编译并运行 `ctest`（53/53），防止叠加引入隐性交互 bug。
3. **端到端总验收**：Wave 1 + Wave 2 全部合入后，跑一次完整的 7 距离 2 s 回放与 AVX2/AVX512 一致性检查，核对 `compute_mean` 是否从约 `1715 µs` 降至目标区间（约 `1250–1300 µs`），以及 `5.2 m` PRR（`TIMING_FAILED` / `NOWIN`）的改善幅度，并更新性能报告。
