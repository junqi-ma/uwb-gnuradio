## 3. 测量合同（摘要）

完整定义见 `docs/performance/接口冻结_UHD_SC16第二轮优化_2026-11-11.md` §5。

| 指标 | 定义 | 是否可跨变体比较 |
| :--- | :--- | :--- |
| `cold_total` | `start()` → `wait()` 返回（含初始化与 drain） | 与历史 100/1000 窗口口径一致 |
| `startup_ready` | `start()` → 全部 Worker Ready | 仅 A2/A1 有意义 |
| `warm_service` | 测量区间内逐窗 `resample_us`/`convert_us`/`sic_us`/`sensing_us`/`e2e_us` | 是 |
| `steady_throughput` | 测量区间 `[最早 rx_push_time, 最晚 commit_time]` 内 Completed 窗口数 / 区间 | 是 |
| `drain_tail` | `wait()` 返回 − 最晚 `commit_time` | 是 |
| RX 计数 | `read_calls/samples_read/bytes/slot_copy/compact_move/...` | 仅诊断跑，不参与正式裁决 |

测量区间选择：`--warmup-windows W` 跳过前 W 个 Completed 窗口，
`--measure-windows M` 取接下来的 M 个（0 = 剩余全部）。区间内不跳过任何窗口，
因此丢弃与慢窗不会被过滤掉。

**输入受限的显式化**：稳态驱动使用有限池（16 槽/Worker）与窗口级 in-flight 流控
（`--flow-in-flight`），流控只存在于基准 feeder，不进入生产 RX。每次运行都报告
`feeder_flow_waits` / `feeder_flow_wait_us` / `dropped`，因此"输入受限"不会被
伪装成"容量结论"。

**正式计时与诊断计时分开**：正式矩阵默认 `--diag-rx/--diag-commit` 关闭；
诊断跑单独执行并单独标注，不混入收益裁决。

## 5. 结果

### 5.1 测量合同验证

在正式采集前先验证计时合同本身（用 control 与 A1 二进制均可复现）：

| 检查 | 结果 |
| :--- | :--- |
| 账本守恒（所有正式运行） | 100% PASS，`offered == admitted + dropped + gap_before + cancelled` 且 `admitted == completed + failed + gap_after` |
| 零丢弃 | 有限池 16 + feeder in-flight 流控下，56k/4k × N∈{1,2,4} 全部 `dropped=0` |
| 窗口区间不跳窗 | 测量区间是 Completed 窗口的连续切片，`measure_windows_actual` 与请求值一致 |
| 稳态区间边界 | 首/末测量窗的 `commit_time`，跨度为 `n-1` 个完成间隔；另报 `steady_lookahead_ms` 与 `drain_tail_ms` |
| 就绪屏障 | `startup_ready_ms` 与 `wait_ready()` 返回值一致；失败运行返回非零退出码且不伪造 Completed |
| 功能字段 | `compare_pipeline_windows.py` 对 control/A1 的 11 字段逐窗 PASS；注入单字段/单样点改动会被判 FAIL |
| 诊断一致性 | `bytes_read == samples_read*4`、`slot_copy_bytes == published*capacity*4`、`commit_calls == results_emitted == results().size()` |

一份 56k/N=1/100 窗的 RX 诊断基线（control+A2，Phase B 之前）如下，用于给 Phase B
定标；它同时暴露了旧 RX 的真实构成：

```
read_calls=22 samples=1232000 bytes=4928000  published=22 dropped=0
stream_buf_resize_count=22 zero_init_bytes=4928000 compact_move_bytes=0 max_buffered_samples=56000
read_us=1634.3 assemble_us=0.4 slot_copy_us=267.4 dispatch_us=6.2 ledger_wait_us=2.0
```

即每窗 224 KB 读入、224 KB 值初始化（随后立刻被覆盖）、224 KB 拷入 slot；
`erase()` 在该几何下移动 0 字节。`read_us` 约 74 µs/窗是 RX 的硬下限。

变体 `control`（HEAD + 插桩 + A2）对比 `A1`，9 组 ABBA（每组 4 次运行 →
每变体 18 次有效运行，全部零丢弃），历史冷启动口径（56k 100 窗 / 4k 400 窗）：

| 配置 | startup_ready 中位数 | 变化 | 判定 | cold_total 变化 | drain_tail 变化 |
| :--- | ---: | ---: | --- | ---: | ---: |
| 56k-rt-N1 | 7.173 → 5.738 ms | **−20.0%** | 超出噪声 | **−7.3%** | −14.5% |
| 56k-q-N1 | 7.308 → 5.701 ms | **−22.0%** | 超出噪声 | **−7.7%** | −15.8% |
| 56k-rt-N4 | 14.013 → 12.839 ms | −8.4% | 噪声内 | **−12.6%** | −31.9% |
| 56k-q-N4 | 16.242 → 13.503 ms | −16.9% | 噪声内 | −5.3% | −49.0% |
| 4k-rt-N1 | 1.859 → 0.402 ms | **−78.4%** | 超出噪声 | **−18.7%** | −46.3% |
| 4k-rt-N4 | 2.383 → 0.664 ms | **−72.1%** | 超出噪声 | **−42.6%** | −75.6% |

> 测量工具修正：最初两轮 A1 冷启动采集（`data_sc16_round2/A1`、`A1b`）在 4k 路径
> 使用了 `--pool-size 128` 而窗口数是 400，RX 无流控地跑在 Worker 前面，
> 造成 131/400 `DroppedAdmission`。这些运行的 startup 数值仍有效，但 cold/steady
> 被丢弃窗口污染。工具已改为"冷启动池 ≥ 窗口数 + 16"，本节只引用零丢弃的
> `A1c` 数据；前两轮保留以示修正过程，不作为结论。

暖态服务时间用 2000 窗稳态区间复测（5 组 ABBA，每变体 10 次有效运行），
避免 100 窗冷启动口径的噪声：

| 配置 | steady us/窗 | 变化 | resample 均值 | 变化 | resample P95 | 变化 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| 56k-rt-N1 | 250.99 → 250.51 | −0.2% | 195.83 → 193.70 | −1.1% | 268.98 → 262.57 | −2.4% |
| 56k-q-N1 | 364.10 → 356.49 | −2.1% | 304.94 → 301.02 | −1.3% | 426.73 → 407.23 | −4.6% |
| 56k-rt-N4 | 77.19 → 75.05 | −2.8% | 212.51 → 211.92 | −0.3% | 334.78 → 338.42 | +1.1% |

**A1 裁决：保留。** 冷启动显著改善（N=1 约 −20%，4k 路径约 −78%），暖态服务时间
在 ±3% 内无系统性退化，全部正确性通过。逐窗位级一致性由
`qa_uwb_resampler_burst_opt.cc`（最终 14 例，含 A1 阶段 9 例的惰性分配/往返/
短输入/极小 max_out/分块一致覆盖）与 `control`/`A1` 的 11 字段比对共同覆盖。

补充测量（不由 A1 引起，但解释 N=4 的 startup 绝对值）：56k + `--consumer sic`
的 N=4 启动时间约 12–14 ms，其中 4 个 Worker 各自的 SIC 模板（64×1016 CF32）与
scratch 准备占主导；A1 的 5 MiB 表只占约 1.5 ms/实例。4k + `--consumer sensing`
没有 SIC 准备，因此 A1 的收益比例高达 76–78%。这是下一轮可优化的启动项。

| 4k-q-N1 | 27.784 → 27.241 | −2.0% | 噪声内 |

| 56k-rt-N4 | 76.80 → 76.78 | −0.0% | 噪声内 |
| 56k-q-N1 | 361.29 → 363.85 | +0.7% | 噪声内 |
| 56k-q-N2 | 190.70 → 190.42 | −0.1% | 噪声内 |
| 56k-q-N4 | 118.14 → 116.71 | −1.2% | 噪声内 |

**B1 裁决：未通过 5% 性能门槛（吞吐收益在噪声内），但因资源与正确性要求保留。**
它把每窗 224 KB 的"先清零再覆盖"降到每 run 一次 448 KB，把每窗一次 `resize`
降到整个 run 一次，并消除了 `discard < 32768` 时旧实现从不收缩导致的缓冲随运行
时长增长（任务书 §6 明确要求"内存规模不随已运行窗口数增长"）。这些是被直接
测量的、真实消除的工作，只是**没有转化为端到端吞吐**：

| `--diag-rx`，56k/N=1，2100 窗（3 次重复） | A1（旧 RX） | B1（新 RX） |
| :--- | ---: | ---: |
| `stream_buf_resize_count` | 2100 | **1** |
| `stream_buf_zero_init_bytes` | 470,400,000（224,000/窗） | **448,000（213/窗）** |
| `compact_move_bytes` | 0 | 0 |
| `max_buffered_samples` | 56,000 | 56,000 |
| `read_us`（2100 窗） | 523,356 / 544,643 / 523,501 | 514,316 / 515,002 / 547,020 |
| `slot_copy_us` | 23,165 / 21,100 / 18,617 | 16,905 / 16,377 / 17,628 |

原因：`read_us`（每窗约 250 µs，即 224 KB @ ~0.9 GB/s）才是 RX 的硬下限，
被消除的清零与 `resize` 只占 RX 总量的约 4%，而端到端节奏由 `max(RX, DSP)+提交`
决定，RX 在全部 12 个配置里都不是唯一瓶颈。因此这里不宣称吞吐收益，只声明
"用测量证明消除了无用工作 + 满足内存有界要求 + 无稳定退化（唯一越界格为
+1.8%，绝对量 0.13 µs）"。

## 6. 未验证项与保留限制

1. **未上板**。全部数字来自文件回放（`/tmp/opencode/bench/steady_*.bin`，页缓存
   热）。UHD 实机多核、`recv` 溢出交互、驱动缓冲、paced 到达均未验证。
   UHD 源的 `STREAM_MODE_START_CONTINUOUS` 已从 `open()` 移到 `start_stream()`
   （就绪屏障之后），但该改动**只在无 UHD 的构建上编译过**，未在设备上运行。
2. **提交路径未重构**。`commit_result()` 仍在 `commit_mutex_` 内做分配、保序重排
   和回调；RX 的丢弃窗口与 Worker 结果共用该锁。实测（56k rt N=4、2000 窗、
   `--diag-commit`）：`commit_calls=2200`，`max_out_of_order_span=31`，
   `lock_wait` 合计 6,395 µs（2.9 µs/次）、`reorder` 2,362 µs（1.1 µs/次）、
   `callback` 7,665 µs（3.5 µs/次，其中包含基准驱动的 feeder 唤醒）。
   以 79 µs/窗计，提交路径约占 10%，且 RX 确实会在该锁上等待，因此
   **本轮不宣称整体 RX 已无阻塞**。
3. **RX 读取仍是最小下限**：56k 窗口每窗 224 KB 的 `::read` 约 250 µs
   （~0.9 GB/s，WSL2 页缓存）。本轮只移除了清零/`resize`，没有改读策略
   （更大读块、`preadv`、`O_DIRECT`、多 RX 线程、slot 直读都未做）。
4. **`dsp_workers=8` 未测**（任务书只要求 1/2/4；历史上 8 已出现回落）。
5. **AVX-512 / FPGA / MATLAB / native 交叉验证未做**。本机为 AVX2。
6. **虚拟化与频率**：WSL2 虚拟机，`scaling_governor` 不可读，未记录实际频率；
   物理核到逻辑核的映射依据 `lscpu`（P-core 独立核 2/4/6/8），未用硬件计数器。
   绑核结果由 `worker_ready_info().affinity_applied` 逐 Worker 记录，实测全部
   `applied=true`，但虚拟机无法证明物理核独占。
7. **C2 只做了筛选，没有做完整 12 格矩阵**；结论"不保留"基于 2 个流水线格 +
   4 个核心格的一致证据，不是全矩阵。
8. **B1 未通过 5% 性能门槛**。它的收益是资源/正确性（消除 99.9% 的冗余清零、
   缓冲不随运行时长增长），端到端吞吐改善在噪声内。若评审要求"无收益即回退"，
   B1 是唯一需要重新裁决的改动；其数据在 §5.3，回退只需还原
   `uwb_uhd_sc16_pipeline.cc` 的 RX 循环。
9. **`bit-exact` 的边界**：C1/C2 的位级一致是相对于当前默认 SC16 内核（同一
   FMA 顺序）证明的；它不证明该内核与 MATLAB `upfirdn` 参考在数值上一致
   （那是既有 `qa_uwb_rational_resampler_*` 的职责，本轮未改）。
10. **测量区间定义**：吞吐用首/末测量窗 `commit_time` 之间的完成间隔
    （`n-1` 个间隔），与"首窗 push → 末窗 commit"的跨度不同；后者会把 RX
    look-ahead 算进测量区间，报告同时给出 `steady_lookahead_ms` 以便复核。

## 8. 结论

- **A1 保留**：启动开销 −20%…−78%，暖态无退化。
- **B1 保留（非性能理由）**：消除 99.9% 的 RX 冗余清零与逐窗 `resize`，内存
  有界；吞吐收益在噪声内，如实记为"未通过 5% 门槛"。
- **C1 保留并成为默认**：端到端 −8.3%/−7.8%/−8.4%（56k rt N=1/2/4）、
  −3.3%/−6.2%/−6.4%（56k q）、−8.0%（4k rt N=1）；resample 均值全网改善，
  P95/P99 无退化格。
- **C2 不保留**：符号随 profile 翻转。
- 最终矩阵 12 格中 8 格吞吐改善 ≥3.3%，其中 6 格 ≥5% 且超出噪声；其余 4 格
  （4k N≥2 与 4k q N=1/N=2）在噪声内，无任何格出现 >5% 的稳定退化。
- 逐窗功能字段与重采样 IQ 均已直接比对通过；全量 CTest 78/79 通过、1 按设计跳过。
