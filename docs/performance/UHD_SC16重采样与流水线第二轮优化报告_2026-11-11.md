## 3. 测量合同（摘要）

完整定义见 `docs/performance/接口冻结_UHD_SC16第二轮优化_2026-11-11.md` §5。

| 指标 | 定义 | 是否可跨变体比较 |
| :--- | :--- | :--- |
| `cold_total` | `start()` → `wait()` 返回（含初始化与 drain） | 与历史 100/1000 窗口口径一致 |
| `startup_ready` | `start()` → 全部 Worker Ready | 仅 A2/A1 有意义 |
| `warm_service` | 测量区间内逐窗 `resample_us`/`convert_us`/`sic_us`/`sensing_us`/`e2e_us` | 是 |
| `steady_throughput` | 测量区间 `[最早 rx_push_time, 最晚 commit_time]` 内 Completed 窗口数 / 区间 | 是 |
| `drain_tail` | `wait()` 返回 − 最晚 `commit_time` | 是 |
| RX 计数 | `read_calls/samples_read/bytes/slot_copy/compact_move/...` | 仅诊断跑，不参与正式裁决 |

测量区间选择：`--warmup-windows W` 跳过前 W 个 Completed 窗口，
`--measure-windows M` 取接下来的 M 个（0 = 剩余全部）。区间内不跳过任何窗口，
因此丢弃与慢窗不会被过滤掉。

**输入受限的显式化**：稳态驱动使用有限池（16 槽/Worker）与窗口级 in-flight 流控
（`--flow-in-flight`），流控只存在于基准 feeder，不进入生产 RX。每次运行都报告
`feeder_flow_waits` / `feeder_flow_wait_us` / `dropped`，因此"输入受限"不会被
伪装成"容量结论"。

**正式计时与诊断计时分开**：正式矩阵默认 `--diag-rx/--diag-commit` 关闭；
诊断跑单独执行并单独标注，不混入收益裁决。
