### 3.2 PCH 与 `UwbSimd.cmake` 的兼容性（实测）

GCC 对 PCH 的 `-m` 标志一致性要求经独立实验确认：

| PCH 编译标志 | 消费 TU 标志 | 结果 |
| :--- | :--- | :--- |
| 无 `-mavx2` | `-mavx2 -mfma` | **可用**，每条 TU 打印 `-Winvalid-pch` 提示 |
| `-mavx2 -mfma` | 无 | 不兼容（PCH 被拒绝） |

因此拆分 plain / simd 两个 PCH 是必要的：SIMD 目标改绑 simd PCH 后完全匹配；
若个别目标仍走 plain PCH，只是退回"不使用 PCH"，不会产生错误。
本机全量构建出现 50 条 `-Winvalid-pch` 提示，均为该预期路径，**不是新增缺陷**。
未修改 `UwbSimd.cmake`，未引入 `-march=native`。

1. **模板策略**：`RationalResamplerLmCore` / `TransposedResampler` 在头文件写
   `extern template`（4 个别名：65/48、65/32、48/65、32/65），在 `.cc` 内做类模板

   `SyncMatchedFilter::for_each_lag`、`vitdec_cl3_truncated`（仅内部使用，沉入 `.cc`
   匿名命名空间）。
3. **`append_ieee_fcs` 契约**：`tests/unit/twr/qa_uwb_twr_frame.cc` 以源码扫描计数

4. **热路径边界**：AVX2/AVX-512 intrinsic 内核、单样点转换、短 getter 全部保持

5. **依赖方向**：`openuwb_dsp` 的 `target_link_libraries` 未变（仅 `openuwb_support`），
   `detector_core.h` / `uwb_detector_core.cc` 只含 `support/` 与 `dsp/matched_filter.h`，

## 7. 既有 flake 归因：`uwb_qa_uwb_fixed_tone_cancel_source.cc`

该测试断言 `run.tone.dropped_samples == 0`，与方案文档点名的"高并发偶发 flake 目标"一致。
做三组对照（同一断言，同一行为）：

| 树 | 独立运行 | 通过率 |
| :--- | :--- | ---: |
| `91f0b23`（零重构基线，Unix Makefiles，无 PCH） | 10 次 | 9 / 10 |
| `70de99f`（Ninja+PCH，未拆头） | 12 次 | 10 / 12 |
| HEAD（拆头后） | 12 次交错 + 15 次其他批次 | 11 / 12（另两批 8/10、3/5） |

失败信息在三棵树上完全相同（`qa_uwb_fixed_tone_cancel_source.cc(660)`，
`dropped_samples != 0`）。结合**交错对照**（A 11/12 vs B 10/12），
判定为 `lib/radio` 固定单音消除源对宿主调度敏感的**既有 flake**，
与本次重构无关；重构 diff 中**不含任何 `radio/` 或 `tone_cancel` 文件**。

处置：不修改测试、不改容差；在 `dev-avx2` 日常闭环中用 `-L rx_sic` 规避，
全量验收以"重复运行 + 单体复跑"记录。**未写成已修复。**

## 8. 验收中发现并修复的既有缺陷（独立提交 `3de1e71`）

`uwb_qa_native_install_consumer` 在本机首次真正执行时失败：

- **现象**：`find_package(uwb CONFIG REQUIRED)` 报
  "the installed openuwb::uwb_native was built with UHD, but …nor pkg-config module 'uhd' was found"，
  而本次构建 `UHD backends: 0`（**根本没有 UHD**）。
- **根因**：主包 `OpenUWBConfig.cmake` 在无 UHD 构建下把 UhdDep include 替换为注释；
  旧包模板 `cmake/Modules/uwbConfig.cmake.in` 却**无条件** include
  `OpenUWBConfigUhdDep.cmake`，而后者无条件要求找到 UHD。
- **复现**：在 `91f0b23` 上执行同一安装+消费者流程，`consumer_rc=1`，同样报错。
  该路径此前长期被"无前缀 → SKIP"掩盖。
- **修复**：旧包改用与主包同款 `@OPENUWB_CONFIG_UHD_DEP@` 替换，
  无 UHD 构建不引入 UHD 依赖闭合，UHD 构建行为不变。
- **验证**：修复后 `uwb_qa_native_install_consumer` **1/1 通过**（7.47 s）。

这是本次验收**唯一**的代码修复，且与 Ninja/拆头重构无关，单独提交以便追溯。
