# UHD SC16 Burst 级多核并行流水线开发方案（2026-11-11）

## 0. 背景与结论

`docs/sic/UHD_SC16_65_48重采样优化性能评估报告_2026-11-10.md:44-90` 已实测：
单 Burst 内部切分多核（`--resampler-workers N`）在 56,000 点窗口上双核
**228.84 µs** 反而慢于单核 **171.58 µs**。根因三条，均在代码中可复现：

1. `run_mt_sc16` 必须先串行把每个输出点的相位/窗口偏移写进
   `sched_arm_buf_` / `sched_win_buf_`，再让 worker 跑**单路**
   `filter_window_sc16`，完全退化掉 `fir_avx2_sc16_4x` 的 4 路寄存器复用。
2. `pool_parallel_for` 每包一次 `mutex` + `notify_all` + `wait` 屏障，
   futex 唤醒固定税 ~20–35 µs。
3. 只并行了重采样，下游 SIC / 解调仍在单线程串行。

因此本轮改为 **Burst 级多核分发（Per-Burst Run-to-Completion）**：
UHD 读出的一段窗口整体交给某一个 DSP 核，该核独立完成
`SC16 重采样 → SIC → 雷达/通信解调` 全流程。核间零同步、零共享写、
单核满血跑 `run_macroblock_sc16` + `fir_avx2_sc16_4x`。

**不实现连续流重采样**。当前每个窗口自带 pre/post guard 且进入重采样前
调用 `reset()`，窗口之间无滤波器历史依赖，因此可安全分发到任意核。

## 1. 架构契约（Phase 0 已冻结）

`gr-uwb/include/gnuradio/uwb/uwb_uhd_sc16_pipeline.h` 已冻结如下增量：

```cpp
struct WindowResult {
    uint64_t window_id = 0;
    int worker_id = 0;   // 处理该 Burst 的 DSP Worker 索引 [0, dsp_workers)
    ...
};

struct PipelineConfig {
    ...
    int dsp_workers = 1;                  // Burst 级并行 DSP 线程数
    std::vector<int> cpu_cores_dsp;       // 显式绑核列表（非空时覆盖 cpu_core_dsp）
};

class UhdSc16Pipeline {
private:
    void rx_producer_loop();
    void dsp_consumer_loop(int worker_id);
    int  effective_dsp_workers() const;
    void commit_result(int worker_id, const WindowResult& res);
    void flush_pending_results();

    std::vector<std::unique_ptr<Sc16WindowRingPool>> pools_;  // 每 Worker 一个 SPSC 池
    std::thread rx_thread_;
    std::vector<std::thread> dsp_threads_;
    std::mutex ledger_mutex_;    // 保护多线程账本变更
    std::mutex commit_mutex_;    // 保护 reorder buffer + results_ + 回调
    std::vector<std::unique_ptr<WindowResult>> pending_results_;
    uint64_t next_commit_id_ = 0;
};
```

### 1.1 不可违反的约束

| 编号 | 约束 | 理由 |
| :--- | :--- | :--- |
| C1 | `pools_` 长度为 `effective_dsp_workers()`；`pools_[w]` 只由 `rx_thread_` 生产、只由 `dsp_threads_[w]` 消费 | 保持 `Sc16WindowRingPool` 严格 1P/1C 无锁语义，禁止改成 MPMC |
| C2 | `dsp_workers <= 1` 时行为必须与改动前**逐位一致**（含时序字段语义） | 向后兼容，历史基线不被覆盖 |
| C3 | 每个 Worker 的重采样器必须 `set_num_workers(1)` | 禁止在 Worker 内再嵌套线程池，保证走 `run_macroblock_sc16` |
| C4 | 每个 Worker 持有私有 `RationalResampler*Core`、`SicUnifiedScratch`、`RadarCirCoreScratch`、`cf32_work`/`sic_out`/`sic_ihat` 缓冲 | 零共享写，零伪共享 |
| C5 | `results_` 与 `result_cb_` 必须严格按 `window_id` 递增顺序输出 | 对外契约不变，QA 可逐窗对比 |
| C6 | 账本守恒律 `offered == admitted + dropped + invalid_gap_before + cancelled` 与 `admitted == completed + failed + invalid_gap_after` 在任意 `dsp_workers` 下 100% 成立 | 硬性验收 |
| C7 | RX 派发绝不阻塞、绝不上溯背压到 UHD 驱动 | 避免 USRP `O` overflow |
| C8 | `stop()` / `wait()` 在多核下必须无死锁、有限时间内退出 | 现有 `test_pipeline_stop_and_cancel` 门槛 ≤ 2000 ms |

### 1.2 派发策略（RX 生产者）

对第 `k` 个窗口，优先尝试 `pools_[k % N]`；若该池瞬时满载，顺序探测
`pools_[(k + 1) % N] … pools_[(k + N - 1) % N]`；**全部满载**才计入
`ledger_.dropped_admission`。因为 `rx_thread_` 是唯一生产者，逐池仍是
1P/1C，无需任何 CAS。

> 说明：这是「轮询优先 + 顺延」而非严格轮询。目的是在某个 Worker 偶发
> 长尾（例如 SIC 未提交）时不丢包，同时保持长期负载均衡。

### 1.3 保序提交（Reorder Buffer）

Worker 完成顺序天然乱序。`commit_result()` 将结果放入
`pending_results_[window_id]`，随后从 `next_commit_id_` 起连续 flush：
命中则 `results_.push_back` + 调用 `result_cb_`，并 `next_commit_id_++`。
丢弃窗口（`DroppedAdmission`）由 RX 线程同样走 `commit_result()`，
因此乱序与丢包混合场景仍然保序。

`wait()` 在所有线程 join 之后调用 `flush_pending_results()`，处理因
`max_windows` 提前结束或 `stop()` 产生的尾部空洞（按 `window_id` 升序
强制 flush，不丢结果）。

### 1.4 绑核规则

- `cpu_cores_dsp` 非空：必须恰好 `dsp_workers` 个元素，第 `w` 个 Worker
  绑到 `cpu_cores_dsp[w]`。数量不匹配时 `initialize()` 返回 false 并打印
  明确错误（fail-closed，不静默降级）。
- 否则若 `cpu_core_dsp >= 0`：第 `w` 个 Worker 绑到 `cpu_core_dsp + w`。
- 否则不绑核。

## 3. 验收门槛

1. 全量 CTest 通过（含新增 3 项多核 QA）。
2. `dsp_workers ∈ {1,2,4}` 下，`4,000` 与 `56,000` 点窗口的
   `WindowResult` 逐窗一致：`window_id`、`state`、`sic_committed`、
   `actual_suppression_db`、`radar_peak_metric`、`radar_detected_start`
   差异为 **0.00e+00**。
3. 账本守恒律 100% 成立，满载零非预期丢弃。
4. 吞吐：`fullspeed` 压测下 `Wall Time / Completed Windows` 随 `N`
   接近线性下降；单包 `resample_us` 保持单核极限（4000 点 ≈ 11.8 µs，
   56000 点 ≈ 171.6 µs，`realtime_minorder`）。
5. 基准必须独占 `/tmp/uwb-sic-benchmark.lock`。
6. 本机 `env -u LD_LIBRARY_PATH` + `ldd` 确认加载 `build-sc16-pipeline/lib`。
7. 未上板；UHD 实机多核与 paced 到达不宣称通过。
