## 2. 每个用例防御什么

### 2.1 `test_pipeline_ready_barrier_slow_init`

- Worker 1 的 `cfg.test_worker_init_hook` 睡 30 ms，其余 1 ms；4 个 Worker。
- `wait_ready(2000)` 必须返回 **true**，耗时 ≥ 20 ms（证明慢初始化真的延迟了就绪）
  且 ≤ 2000 ms；`ready_ok()==true`、`failed()==false`、`init_error()` 为空、
  `worker_ready_info()` 长度为 4 且每个 `state==Ready`。
- 源侧闸门在 `read_samples()` 内阻塞 RX 线程，因此 `wait_ready()` 返回瞬间读取
  `ledger.admitted_windows` **不可能**被 RX 抢跑：断言 `admitted==0`、`offered==0`、
  `completed==0`。这就是"所有 Worker 就绪前不得准入任何窗口"的可判定形式。
- 闸门打开并 `wait()` 之后断言：`start_stream()` 恰好调用 1 次、调用时 4 个 Worker
  的初始化钩子全部完成、`read_samples()` 从未早于全部钩子完成（源侧记录）。
- 收尾：账本守恒、`offered==6`、`admitted+dropped==6`、`completed==admitted`、
  `results().size()==admitted+dropped`、`native_start_abs` 为
  `max(0, k*capacity - pre_guard)`（首窗负 guard 裁剪）。

**不冻结**：admitted 与 dropped 的拆分（池容量/调度相关）。

### 2.2 `test_pipeline_init_failure_propagation`

- Worker 0 睡 10 ms 后 Ready，Worker 1 抛 `std::runtime_error("qa injected ...")`。
  这是"部分就绪后失败"，比"一开始就失败"更难。
- `wait_ready(2000)` 必须返回 false 且 ≤ 2000 ms；`failed()==true`、
  `ready_ok()==false`、`init_error()` 非空且含 `injected`；
  `worker_ready_info()[1].state==Failed`、`error` 非空。
- `offered==0`、`admitted==0`、`completed==0`、`dropped==0`、`cancelled==0`，
  `results()` 为空，`start_stream()` 从未调用，源位置仍为 0。
- `stop()+wait()` 在 2000 ms 内返回，收尾后 `completed` 仍为 0，且**没有**任何
  `state==Completed` 的伪造结果。

**防的是**：把初始化异常变成 `std::terminate`、永久等 ready，或失败后用空的
`Completed` 结果凑账。

### 2.3 `test_pipeline_stop_during_ready_wait`

- 钩子统一睡 200 ms；`start()` 后立刻 `stop()`。
- `wait_ready(5000)` 必须返回 false，且从 `stop()` 到返回 ≤ 1500 ms（不是等钩子
  睡完）；`wait()` 从 `stop()` 起 ≤ 2000 ms；账本守恒、`completed==0`、
  `start_stream()` 未调用。

### 2.4 `test_pipeline_eof_shorter_than_one_window`

- 源只有 `capacity/4` 个样点。断言 `offered==0` 或"全部 offered 都被 cancel"，
  `completed==0`、`admitted==0`、`dropped==0`、无 `Completed` 结果、账本守恒、
  源被读到 EOF。

### 2.5 `test_pipeline_normal_drain`

- 4 Worker、12 窗、无 guard（`start(k)==k*capacity` 精确）、池容量 = 窗数（无丢弃）。
- `offered==admitted==completed==12`，`dropped/cancelled/invalid_gap/failed` 全 0；
  `results()` 12 条，`window_id` 严格升序且等于下标，全部 `Completed`，
  `native_start_abs==k*capacity`、`native_sample_count==capacity`，
  每个结果的时间戳单调（`rx_push_time <= worker_start <= worker_end <= commit_time`）。
- 诊断路径（`enable_rx_diagnostics`/`enable_commit_diagnostics`）：
  `read_calls>0`、`samples_read>=12*capacity`、`bytes_read==samples_read*4`、
  `windows_published==12`、`windows_dropped==0`、
  `slot_copy_bytes==12*capacity*4`、`commit_calls==results_emitted==12`。
- `reset_diagnostics()` 在 `wait()` 之后调用：计数归零，但 `results()` 与
  `ledger` 功能状态不变（证明它"只清计数、不改功能"）。

**不冻结**：`worker_id` 的分配与各 Worker 的窗口数。

### 2.6 `test_pipeline_small_pool_overload`

- 2 槽池 / 4 Worker / 200 窗。**只**断言：账本两条守恒律逐项展开、
  `results().size()==admitted+dropped+invalid_gap_before`、`window_id` 严格升序、
  每个 id 最多出现一次、总墙钟 ≤ 30 s（无死锁）。
- **明确不**断言 `admitted==8` 或任何调度相关计数（任务书 A3 明令禁止重新冻结）。

### 2.7 `test_pipeline_unique_terminal_state`

- 2 槽池 / 4 Worker / 80 窗：`results()` 中不得有重复 `window_id`；按状态分类计数
  必须与 `ledger` 的 `completed_windows`、`dropped_admission`、`processing_failed`、
  `invalid_gap_before+after` 一致；`results()` 条数等于
  `admitted+dropped+invalid_gap_before`。

### 2.8 `test_pipeline_rx_window_boundaries`（Phase B 契约）

7 个几何：相邻（period==capacity、无 guard）、重叠（period 1200 < capacity 2800）、
间隔大于一窗（period 5000 > capacity 2200）、对抗性短读 `{37,1,4096,7}`、
单窗多次读（64/次）、EOF 落在窗内（4 个完整窗 + 1 次 cancel）、首窗负 guard 裁剪
（`t0=50, pre_guard=200`）。

每个几何跑两次完全相同的绝对样点数据：

1. **A**：`PredictiveSc16Source`（可指定任意读块，含 1 样点读）；
2. **B**：`ReplaySc16Source` 读同一份数据（每窗一次大读）。

断言：

- 两次运行的 `results().size()` 都等于由几何推导出的完整窗数；
- 每窗 `window_id==k`、`state==Completed`、`native_start_abs==max(0, k*period-pre_guard)`、
  `native_sample_count==capacity`（**逐窗精确整数比较**，不是只比条数）；
- `sic_executed`/`radar_executed` 为 true（`ConsumerMode::Both`）；
- **11 个功能字段逐窗位级相等**（`qa_check_same_window`）。这些字段由 slot 样点
  算出，所以任何 stale/错位/缺失样点都会改变其中至少一个；
- 内容签名非退化检查：radar 走 `use_predicted_timing` 的 1 次 SYNC 路径，
  `radar_peak_metric` 必须至少在一个窗非零（否则“相等”可能只是两边都恒为 0，
  测试直接失败而不是静默弱化）。

**已知限制（重要）**：冻结接口没有把 `Sc16WindowSlot::sc16_samples` 暴露给调用方，
QA 无法直接逐字节比较 slot。上面的内容校验是"精确几何 + 源侧绝对范围 + 由样点
派生的 11 字段位级相等"，**不等价于** slot 字节比对。最终数字的直接样点检查必须
用 runner 的 `win_<id>_<tag>.cf32` dump 加
`tools/performance/compare_pipeline_windows.py --iq-dir`（见 §4）。

只使用本轮候选构建目录：

```bash
cd /home/junqima/workspace/uwb-gnuradio/gr-uwb/build-sc16-burst-opt

    --log_level=message --run_test=qa_uwb_uhd_sc16_pipeline/test_pipeline_rx_window_boundaries
```

`env -u LD_LIBRARY_PATH` 不是可选项：本机默认 `LD_LIBRARY_PATH` 可能命中
`/usr/local` 下的旧库，导致测的不是本 build。需要复核时可加
`ldd ./lib/uwb_qa_uwb_uhd_sc16_pipeline.cc | grep gnuradio`。

比较工具：

```bash
cd /home/junqima/workspace/uwb-gnuradio

# 自检（不读外部文件）
python3 tools/performance/compare_pipeline_windows.py --self-test

# 两份 dump 逐窗比较（默认只比 11 个功能字段；worker_id/计时不设门槛）
python3 tools/performance/compare_pipeline_windows.py A.json B.json

# 直接样点（IQ）检查：--iq-dir 第一次给 A、第二次给 B
python3 tools/performance/compare_pipeline_windows.py A.json B.json \
    --iq-dir runs/control --iq-dir runs/candidate
```

退出码：`0` 全部通过；`1` 有差异/字段不可用/账本不守恒；`2` 用法或文件错误。

`--iq-dir` 中的文件命名为 `win_<id>_<tag>.cf32`（complex64，小端，real/imag
各 float32）。`<tag>` 自动发现；一个窗口匹配到多个 tag 时工具**报错**而不是猜。
只给一次 `--iq-dir` 时，B 侧回退到 `B.json` 所在目录。默认 `--iq-tol 0.0`
= **逐字节精确**；给非零容差时，结果标注为 "tolerated"，绝不写成 "byte-identical"。
非 `Completed` 的窗口（丢弃/取消/失败）没有 DSP 输出，IQ 比较会跳过并列出原因。

## 4. 本轮"测量有效"（measurement validity）的含义

1. **诊断计时与正式计时分开跑。** `enable_rx_diagnostics` /
   `enable_commit_diagnostics` 打开的运行只用于归因（读、拼装、slot copy、派发、
   提交锁等待/重排/回调）。正式计时必须两个开关都关。两套数字不得混在同一张表，
   也不得用诊断跑的数字当作正式收益。
2. **有限池 + 持续输入。** 稳态基准必须用有限 `pool_capacity`，并同时报告
   `offered / admitted / completed / dropped / cancelled` 和队列状态。
   "把池扩到整轮"或"零丢弃靠改生产 RX"都不算有效测量；若基准 feeder 做了节拍/
   批次流控，必须显式报告（输入受限不能当容量结论）。
3. **不挑快窗。** `--warmup-windows W` / `--measure-windows M` 的区间必须打印，
   实际样本数不足 M 时如实报告实际数，不能只保留跑得快的窗口。尾部 drain 单列。
4. **11 字段相等 ≠ IQ 相等。** 逐窗功能字段相等只说明 DSP 功能一致；重采样 IQ
   是否逐位一致必须直接比对样点。任何"没有 IQ 差异"的结论都必须来自
   `--iq-dir` 的实测输出（默认逐字节），不能由 11 字段推得。
5. **丢弃要有账。** 每个 dump 都必须满足
   `offered == admitted + dropped + invalid_gap_before + cancelled` 与
   `admitted == completed + failed + invalid_gap_after`；
   且 `len(windows) == admitted + dropped + invalid_gap_before`
   （`Cancelled` 按契约不出现在 `results()`，只在账本里）。
   A/B 两侧的 drop 数不同必须解释，不能当作噪声略过。
6. **调度差异不是功能差异。** `worker_id`、各阶段计时、过载时的准入集合允许不同；
   只有 `--strict-worker-id` 时才比较 `worker_id`，且该模式不得用于性能对照。
7. **身份绑定。** 每个正式数字要能追到：commit/diff、编译器与 `CMAKE_BUILD_TYPE`、
   `-O3 -march=native`、`ldd` 实际加载库、CPU/虚拟化拓扑、输入与 taps 的
   checksum、机器负载。基线/候选串行 ABBA、≥5 组配对、独占
   `/tmp/uwb-sic-benchmark.lock`。

- [ ] 诊断跑与正式跑是否分开；正式跑的两个诊断开关是否为 false。
- [ ] 稳态测量窗数是否 ≥ 10000（不足时是否声明"不确定"并只做一次延长复测）；
      P50/P95/P99 与样本数是否同时给出。
- [ ] 是否出现 >5% 的稳定退化（服务时间/吞吐/P95/P99），尤其 warm 路径。
- [ ] 结论是否越界：UHD 实机、`recv` 溢出交互、paced 到达、8 Worker、连续 1 GS/s、
      MATLAB 验证，本轮均**未**验证，不得写成通过。
- [ ] 是否有把"零丢弃"当默认路径的改动（生产 RX 不得加流控/背压）。

## 6. 冻结接口不足之处（需要主 agent 知悉）

1. **slot 原始样点不可见。** `UhdSc16Pipeline` 不向调用方暴露
   `Sc16WindowSlot::sc16_samples`（`pools_` 是私有成员），也没有 QA 专用
   bypass consumer。因此 A3-h 要求的"整段 slot 样点逐点比对"无法在 QA 内直接完成，
   现以"精确几何 + 源侧绝对范围 + 11 字段位级相等（含非零 radar CIR 指标）"替代，
   并在 §2.8 明确标注其边界。若需要真正的 slot 字节级回归，冻结接口需增加
   QA-only 访问器或 IQ dump 钩子（属 B/主 agent 的文件）。
2. **IQ dump 生产端尚未落地。** 编写本文件时，`benchmark_sc16_pipeline_steady.cc`
   与 `uwb_uhd_sc16_pipeline_runner.cc` 都还没有写 `win_<id>_<tag>.cf32`。
   `compare_pipeline_windows.py --iq-dir` 在缺文件时会**失败**（fail-closed），
   不会静默通过；在驱动补上 dump 之前，"IQ 已逐位一致"无法被证明。
3. **Phase B 尚未落地。** 编写本文件时 RX 仍是 HEAD 的 `stream_buf.resize()/erase()`
   实现（源码注释也标注 "Phase B replaces this"）。A3-h 当前验证的是
   "HEAD RX 循环 + 新就绪屏障"；B 的预分配缓冲/游标落地后**必须重跑**该用例，
   并在报告中绑定新的 commit。
4. **sanitizer 未跑。** 本轮 C 的构建/测试命令限定在
   `gr-uwb/build-sc16-burst-opt`（Release）；内存边界类改动的 sanitizer 补验属
   任务书 §9 的主 agent 收尾项，不在本说明的通过项内。
