# SMT 关闭与内存 6000 MT/s 后的性能复测

日期：2026-11-16。代码 `487c5d9`（`feature/sic-research`，含 AVX-512 合并）。
数据：`docs/performance/data_perf_smt_mem_20261116/`。
对照基线：`docs/performance/data_demod_sic_avx512_20261116/`（2026-11-16 早先测得）
与 `docs/performance/data_avx512_20261116/abba_final/`。

状态：**软件/回放复测**。未上板，未做 UHD 实机、paced 硬件到达、MATLAB 交叉验证、
负载下 P99、多径/AWGN/ISR。本文不宣称这些项通过。

---

## 1. 结论摘要

- **端到端单窗 DSP 快了约 6%**：同一份代码、同一条命令、同一夹具，把内核强制回
  全 AVX2（A 臂）后，整包 **371.89 → 348.50 µs（−6.29%）**、preamble
  **269.80 → 252.48 µs（−6.4%）**。A 臂完全不用 AVX-512，所以这 6% 只能来自
  机器状态，不是代码。
- **AVX-512 的相对收益没变，略增**：同二进制配对 A/B，整包 **−6.13% → −6.60%**、
  preamble **−7.68% → −8.32%**。说明测量链路仍然自洽，且宽内核从这次机器调整里
  拿到的比 AVX2 多。
- **重采样收益明显变大**：`H_pad 48`（quality）AVX-512 相对 AVX2 从 **+20.11%
  → +27.54%**（65/48，3 会话 27.48/27.57/27.54）、**+21.62% → +29.02%**（65/32，
  29.08/29.02/28.98）；`H_pad 24`（realtime）**+9.40% → +9.81%**；`H_pad 16`
  （eq16，live 默认）三轮 6.53/2.56/3.08%，**仍低于 5% 门槛且不稳定**，默认表不动。
- **实机回放 5 ms 周期**：4/8 worker 都是 203/204 FCS（99.5%）、0 丢样点、0 gap。
- **实机回放 1 ms 周期：8 worker 现在会崩**。4 worker 两轮都是 99.5% FCS、0 丢样点；
  8 worker 两轮分别丢 16.7M / 55.4M 原始样点、FCS 掉到 89.9% / 72.0%。SMT 关闭后
  8 个 worker 加 reader/main 超过 8 个物理核，**`--workers 4` 仍是 1 ms 的唯一可用
  选择，比之前更硬**。
- **6 worker 只在 1 ms 下"倾向"更好**：每包 `compute` 中位数 2166 → 1877 µs
  （−13.3%）、`demod` 1268 → 1043 µs（−17.7%）、p95 −9%，但单次波动 ±50%、区间
  重叠，CPU 时间反而多 3.1%；**5 ms 下 6 worker 明确更差**（compute +1.7%、
  p95 +13.9%）。默认仍用 4 worker。
- **一个未解释的小退化**：`subtract & validate` 阶段 **+8.1%**（21.98 → 23.77 µs），
  三轮会话稳定复现，占整包 0.5%。同阶段的内核级 `sub n=135568` 反而快了 3.9%，
  所以不是纯带宽问题，原因未定位。

| CPU | AMD Ryzen 7 9700X（Zen 5），8 核 | 与早先相同 |
| SMT | **关闭**（`smt/active=0`，`smt/control=notsupported`） | 固件级关闭，**无法在运行时切回**做真 A/B |
| 逻辑 CPU | 8（此前 16） | `Thread(s) per core: 1` |
| 内存 | SPD 4800 MT/s，**Configured 6000 MT/s**（EXPO 生效） | 早先运行的 Configured 速度**未记录**，无法量化这一步的贡献 |

| L1d/L2/L3 | 384 KiB / 8 MiB / 32 MiB | 与早先相同 |

**关键限制**：SMT 与内存频率都需要重启，无法在同一会话里做真 A/B。因此"前后对比"
只能是**跨会话**比较；能守住的控制是：代码提交相同、构建参数相同、命令相同、夹具
相同、A 臂强制 AVX2、loadavg 量级相当。

## 3. 方法

1. **端到端**：`bench_unified_timing`，用仓库自带的
   `tools/perf/run_demod_sic_abba.py` 跑 A/B/C/D 矩阵，**3 个会话 × 5 轮 ABBA**
   （每轮 4 次独立进程）。A 臂把 `sync/cir/sic_*` 全部强制 AVX2，是机器状态的
   干净对照；B/D 臂给出 AVX-512 的配对收益。
2. **重采样**：`tools/perf/run_avx512_abba.py`，5 个生产格（56k 窗，65/48 与 65/32），
   3 轮 ABBA，校验 FNV 校验和一致。
3. **内核级**：`bench_demod_sic_kernels`，3 次独立运行取中位数。
4. **实机回放**：`uwb_dw3000_live --replay`，5 ms 夹具
   `rx_ch3_rx1_1s_trim6b.sc16` 与 1 ms 夹具 `rx_1ms_1s.sc16`，`--sync locked`，
   4 与 8 worker 交替。
5. 数值等价性：ABBA 驱动每次都比对 A 臂与 D 臂的 SIC dump，本次仍是
   **逐字节相同（各 1,084,544 B）**，抑制比 63.29 / 63.33 dB 不变。

## 4. 端到端结果（A 臂 = 全 AVX2，机器状态对照）

| 场景 | 早先 | 现在 | 变化 |
| --- | --- | --- | --- |
| 整包 A 臂 | 371.89 µs | **348.50 µs** | **−6.29%** |
| preamble A 臂 | 269.80 µs | **252.48 µs** | **−6.4%** |

三个会话的 A 臂整包中位数：348.50 / 347.77 / 349.04 µs（离散 1.3 µs），
preamble：252.27 / 252.48 / 252.53 µs。**会话内离散远小于会话间差异**，说明
−6% 不是噪声。

## 5. 阶段分解（A 臂整包，早先 → 现在）

| 阶段 | 早先 µs | 现在 µs | 变化 |
| --- | --- | --- | --- |
| `phr` | 11.02 | 9.00 | **−18.3%** |
| `cfo` | 6.00 | 5.00 | **−16.7%** |
| `payload` | 41.06 | 35.02 | **−14.7%** |
| `sfd`（tail refit） | 56.58 | 51.06 | −9.8% |
| `estimate_channel` | 34.53 | 31.21 | −9.6% |
| `comm_rx`（合计） | 237.08 | 218.33 | −7.9% |
| `cir`（equalizer） | 35.06 | 33.04 | −5.8% |
| `timing` | 79.06 | 77.12 | −2.5% |
| `reconstruct`（FIR） | 32.83 | 32.33 | −1.5% |
| `subtract & validate` | 21.98 | 23.77 | **+8.1%** |

`timing` 只降 2.5% 是合理的：它是 8-lag 点积，属于纯计算、L1 常驻，本来就不吃内存
带宽，SMT 关闭对它的好处也有限。真正吃到红利的是 `payload`/`phr`/`cfo`/`sfd` 这类
带内存访问和分支的中小阶段。

## 6. AVX-512 配对收益（同二进制，会话内 A/B）

| 场景 | 早先 | 现在（3 会话中位数，区间） |
| --- | --- | --- |
| B（`sync=avx512`）整包 | −6.13% | **−6.60%**（−6.56…−6.75） |
| B preamble | −7.68% | **−8.32%**（−8.19…−8.43） |
| D（全开）整包 | −6.06% | **−6.46%**（−6.12…−6.66） |
| A 臂自身漂移（噪声地板） | +0.78% | +0.11%（−0.42…+0.12） |

噪声地板 ≤0.42%，配对收益 −6.6%，**结论方向与早先一致，幅度略增**。

## 7. 重采样（56k 生产窗，3 个独立会话 × 3 轮 ABBA）

| 格 | AVX2 早先→现在 | AVX-512 早先→现在 | AVX-512 相对收益（3 会话） |
| --- | --- | --- | --- |
| 65/48 quality（H_pad 48） | 230.10 → 221.70（−3.6%） | 183.61 → **160.58**（−12.5%） | +20.11% → **+27.54%**（27.48/27.57/27.54） |
| 65/32 quality | 339.24 → 328.21（−3.3%） | 266.50 → **233.30**（−12.5%） | +21.62% → **+29.02%**（29.08/29.02/28.98） |
| 65/48 realtime（H_pad 24） | 121.24 → 105.61（−12.9%） | 110.12 → 95.26（−13.5%） | +9.40% → **+9.81%**（9.70/9.85/9.81） |
| 65/48 eq16（H_pad 16，live 默认） | 96.97 → 78.91（−18.6%） | 94.27 → 76.77（−18.6%） | +2.22% → +3.08%（**6.53/2.56/3.08，不稳定**） |
| 65/48 quality fp0（1 会话） | 239.20 → 222.13（−7.1%） | 198.47 → **165.92**（−16.4%） | +17.02% → **+25.49%** |

重采样是纯带宽/计算混合负载，AVX-512 臂降幅（−12.5%）明显大于 AVX2 臂
（−3.3…−3.6%），所以宽内核的相对优势变大。`H_pad 48` 的 +27.5% 三个会话几乎
完全一致（离散 0.09 个百分点），是本次最稳的一项。

`H_pad 16`（eq16，live 默认）**没有**稳定过门槛：三个会话 6.53 / 2.56 / 3.08%，
中位数 3.08%。按规划"未过门槛保持 AVX2"的规则，**默认表不改**，`H_pad 16/32`
仍走 AVX2；`set_kernel("avx512")` / `--kernel avx512` 仍可强制。

## 8. 内核级（3 次运行中位数）

| 内核 | AVX2 臂 | AVX-512 臂 |
| --- | --- | --- |
| 8-lag 点积（L=1016） | 45.2 → 39.6 ns（−12.4%） | 28.4 → 26.9 ns（−5.3%） |
| `fold_sfd_window` | 488.5 → 435.6 ns（−10.8%） | 366.8 → 332.1 ns（−9.5%） |
| `scale n=1053` | 91.4 → 69.6 ns（−23.9%） | 39.6 → 27.2 ns（−31.3%） |
| `accumulate n=1053` | 61.9 → 65.1 ns（**+5.2%**） | 44.2 → 39.8 ns（−10.0%） |
| `sub n=2032` | 111.9 → 121.9 ns（**+8.9%**） | 106.6 → 74.9 ns（−29.7%） |
| `accumulate n=135568` | 16080 → 15480 ns（−3.7%） | 15465 → **16510 ns（+6.8%）** |
| `sub n=135568` | 16168 → 15543 ns（−3.9%） | 15425 → **16369 ns（+6.1%）** |
| `scale n=135568` | 12946 → 10968 ns（−15.3%） | 8473 → 6787 ns（−19.9%） |
| 20-tap SIC 脉冲累加 | 28437 → 28318 ns（−0.4%） | 29023 → 28487 ns（−1.8%） |

两个值得记录的信号：

- **小 n 元素级内核（1053/2032）在 AVX2 臂上变慢了 5–9%**。这些是 L1/L2 常驻的
  纯吞吐循环，不吃带宽；变慢说明这次机器调整不是"所有东西都变快"，而是
  **带宽相关变快、部分纯吞吐路径变慢**（可能与 EXPO 的时序/频率策略有关，未定位）。
- **大 n（135568）元素级内核上，AVX-512 从领先 4% 变成落后 6–7%**。这些内核本来就是
  带宽受限，内存变快后 AVX-512 的计算优势被抹平，而它的 store 模式没有优势。
  这正好印证了当初"`sic_reconstruct`/`sic_energy` 保持 AVX2"的决定是对的。

## 9. 实机回放

### 9.1 5 ms 周期（`rx_ch3_rx1_1s_trim6b.sc16`，`--sync locked`）

| worker | FCS | 丢样点 | gap | demod mean |
| --- | --- | --- | --- | --- |
| 4（3 轮） | 203/204（99.5%） | 0 | 0 | 910.5 / 914.0 / 910.8 µs |
| 8（2 轮） | 203/204（99.5%） | 0 | 0 | 941.2 / 954.2 µs |

两档无差别：`--replay` 是 paced 的，1 s 数据用 0.995 s 读完，流水线没有饱和，
worker 数不是瓶颈。8 worker 的 `demod` 略高（+3%）但仍在噪声内。

### 9.2 1 ms 周期（`rx_1ms_1s.sc16`，`--period-ms 1`）

| worker | 轮 | FCS | 丢样点 | gap | demod mean / p95 |
| --- | --- | --- | --- | --- | --- |
| 4 | 1 | 1012/1016（99.6%） | **0** | 0 | 1354 / 2200 µs |
| 4 | 2 | 1011/1016（99.5%） | **0** | 0 | 1060 / 1635 µs |
| 8 | 1 | 974/1083（89.9%） | **16,711,680** | 110 | 2410 / 7305 µs |
| 8 | 2 | 860/1194（72.0%） | **55,377,920** | 352 | 4099 / 11213 µs |

**这是本轮最可操作的结论**：SMT 关闭后 8 个 worker 加 reader/main 超过 8 个物理核，
reader 被抢占 → 环形缓冲打满 → 大量丢样点。`--workers 4` 仍然稳（0 丢、99.5%）。
早先"SMT 下 4 worker 已够、N>4 不建议"的结论现在更强：**8 worker 在 1 ms 下不可用**。

### 9.3 4 vs 6 worker 的端到端开销

同一夹具、同一命令，只改 `--workers`，交替顺序跑（1 ms 各 15 次、5 ms 各 3 次）。
`compute` = 每包 resample+demod+retry 的服务时间，`demod` 是其中解调部分；
两者都是**每包端到端开销**，不含队列等待。墙钟被 paced 源钉在 1.01 s，所以看
CPU 时间与每包开销。

**1 ms 周期（1016 包/1 s）**

| 指标 | 4 worker | 6 worker | 变化 |
| --- | --- | --- | --- |
| `compute` 中位数 | 2166.0 µs | **1877.3 µs** | **−13.3%** |
| `compute` 区间 | 1641–2537 | 1617–2524 | 重叠 |
| `demod` 中位数 | 1267.9 µs | **1043.1 µs** | **−17.7%** |
| `demod` 区间 | 925–1517 | 893–1497 | 重叠 |
| `compute` p95 中位数 | 3431.6 µs | **3130.6 µs** | −8.8% |
| `demod` p95 中位数 | 2003.4 µs | **1821.3 µs** | −9.1% |
| `resample` 中位数 | 942.4 µs | 853.1 µs | −9.5% |
| 丢样点 / gap | 0 / 0 | 0 / 0 | — |
| FCS | 1011–1012/1016 | 1011–1015/1016 | — |
| CPU 时间（user+sys） | **3.19 s** | 3.29 s | +3.1% |

**5 ms 周期（204 包/1 s）**

| 指标 | 4 worker | 6 worker | 变化 |
| --- | --- | --- | --- |
| `compute` 中位数 | **1621.8 µs** | 1648.7 µs | +1.7% |
| `demod` 中位数 | **910.8 µs** | 933.8 µs | +2.5% |
| `compute` p95 | **2131.0 µs** | 2428.6 µs | **+13.9%** |
| `demod` p95 | **1313.4 µs** | 1554.1 µs | **+18.3%** |
| 丢样点 / gap | 0 / 0 | 0 / 0 | — |
| FCS | 203/204 | 203/204 | — |
| CPU 时间（user+sys） | **0.85 s** | 0.86 s | +1.2% |

读法：

- **5 ms 下 4 worker 明确更好**：区间很紧（compute 1621.4–1629.7 vs 1627.1–1657.7），
  p95 差 14–18%。负载低时多出来的 worker 只增加调度开销。
- **1 ms 下 6 worker 的中位数更好**（compute −13%、demod −18%、p95 −9%），但两者
  单次波动都接近 ±50%（4w 1641–2537、6w 1617–2524），区间重叠，**只能算"倾向更好"，
  不是确定结论**。CPU 时间反而多 3.1%，说明它买的是延迟分布，不是总吞吐。
- 两档都是 0 丢样点、99.5% FCS；8 worker 才是真正的断崖。
- 结论：**默认保持 4 worker**；1 ms 且在意尾部时可以试 6，但必须在板上复核，
  且不要上 8。

## 10. 未解释项

- `subtract & validate` **+8.1%**：三轮会话稳定（23.71/23.77/23.81 µs），不是噪声；
  但同内核的 `sub n=135568` 快了 3.9%，所以不是纯带宽。未定位。
- 小 n 元素级内核 AVX2 臂 +5…+9%：同上，未定位。
- 内存频率从多少升到 6000 MT/s **未知**（早先未记录 Configured 速度），所以无法
  把 −6% 拆成"SMT 关闭"与"内存提频"两部分。

## 11. 局限与未验证

- 跨会话比较，不是受控 A/B；SMT 与内存频率都无法在运行时切换。
- 未上板、未做 UHD 实机、paced 硬件到达、MATLAB 交叉验证、负载下 P99、
  多径/AWGN/ISR、CFO 扫频与 SFO。
- 实机回放是 `--replay` 文件回放，不证明 ADC/RF 侧行为。
- 1 ms 夹具是未 trim 的采集（约 27 ppm），`fused` 路径被网格门限拒绝后走
  Full→Bypass；它的绝对 FCS 不代表 trim 后的水平，只用于 4 vs 8 worker 的相对比较。

## 12. 复现

```bash

  -DUWB_SIMD=AVX512 -DUWB_BUILD_GNURADIO=OFF -DUWB_BUILD_EXPERIMENTS=ON \
  -DENABLE_UHD_BACKEND=OFF
cmake --build gr-uwb/build-avx512-smtcheck -j8

# 端到端 A/B/C/D，3 会话 × 5 轮
for s in 1 2 3; do
  python3 tools/perf/run_demod_sic_abba.py \
    --bench gr-uwb/build-avx512-smtcheck/apps/bench_unified_timing \
    --out /tmp/abba_s$s --rounds 5

# 重采样
python3 tools/perf/run_avx512_abba.py \
  --bench gr-uwb/build-avx512-smtcheck/apps/benchmark_sc16_burst_core \
  --out /tmp/resampler --rounds 3 \
  --only "65_48:quality:56000:1,65_48:quality:56000:0,65_48:realtime:56000:1,65_48:eq16:56000:1,65_32:quality:56000:1"

# 内核级
for i in 1 2 3; do gr-uwb/build-avx512-smtcheck/apps/bench_demod_sic_kernels; done

  --replay testdata/x410_fixed_tone_live_20261115/rx_1ms_1s.sc16 \

  /usr/bin/time -f "wall=%e user=%U sys=%S" \
  gr-uwb/build-avx512-smtcheck/apps/uwb_dw3000_live \
```
