# 解调与窗口执行的代码边界

更新：2026-11-18。原生 core/native 的构建方式见
[使用说明](原生UHD与C++构建使用说明.md)。

## 解调依赖

| 文件 | 职责 |
| --- | --- |
| `uwb_hrp_codec.h` | TX/RX 共用 CRC、GF、SECDED、spreading；只依赖标准库 |
| `uwb_hrp_mod_core.h` | TX 调制；不包含接收流水线 |
| `uwb_demod_pipeline.h` | 完整包接口及 worker scratch 定义入口，链接 uwb_core |
| `uwb_demod_core.h` | 兼容聚合头，提供全部单阶段 API，主要用于 QA/实验 |
| `uwb_demod_grid.h` / `uwb_demod_execution.h` | 网格物理约束、一次包准入及有效 profile |
| `uwb_demod_sync.h` / `timing.h` / `cfo.h` / `sfd.h` | 同步公共计算与各阶段实现 |
| `uwb_demod_softchips.h` | CIR / soft-chip，包括分数网格和按需生成 |
| `uwb_demod_fec.h` | Viterbi、RS、软判决与救援；RX detail 兼容 codec 别名 |
| `uwb_demod_phr.h` / `payload.h` | NS-SFD、PHR 与 payload 阶段 |
| `uwb_demod_finalize.h` | 所有退出路径的子计时发布和既有坐标 rebase |
| `lib/uwb_demod_pipeline.cc` | 包内阶段编排、CFO 重估、前缀/融合/回退选择 |

表中省略前缀的阶段头均在 `gr-uwb/include/gnuradio/uwb/`。
阶段头可独立包含；生产完整包消费者不必解析全部阶段实现。
`demodulate_one` 从 header-only 改为库内实现，外部 native 消费者需重新链接
`uwb::uwb_core`（或传递链接它的 `uwb::uwb_native`）。单独包含头不再提供完整入口定义。

## 状态与坐标

一个 `DemodScratch` 只属于一个 worker，不跨 worker 共享；保留已有字段与容量。

| 生命周期 | 内容 | 初始化责任 |
| --- | --- | --- |
| 跨包模板缓存 | cached_seq、SFD/SYNC 模板、PN | 各缓存按 code/mode/template 键更新 |
| 包内决策 | fused_phr 的 g0/g1/LLR、decisions_valid | 入口统一 begin_packet；每次完整重试也调用 |
| 阶段状态 | softchip prepared/generated/phase、initial_timing | 所属阶段按原顺序重置，不在入口扩大清理 |
| 工作区 | work/corr/derotated/soft_chips 等 | reserve 保留容量，各阶段按有效范围读写 |

为了保留 source compatibility，本轮没有把这些字段改成新的嵌套布局。
`corr` 会被 CIR 重用；已经生成的 soft-chip 前缀使用独立 `softchip_corr` 保存。
不能因为两个数组都是 complex vector 就合并。

完整包入口接收 work 速率的绝对 predicted_start/window_start，内部阶段使用
窗口相对样点。finalize 在每条退出路径调用一次，转换原来约定的 timing/CFO/SFD/CIR
样点字段；chip 索引和其他局部诊断字段保持既有语义。单阶段 API 不自行 rebase。
不要将所有 int64 字段一概加上窗口起点。

PacketExecutionPlan 统一决定整数网格准入。旋转范围、前缀长度和融合选择共同服从
该决策。分数网格按请求的 CIR 模式计算完整 soft-chip 流。

## 窗口与调度

两种策略保留不同的业务约束：

| 项目 | live | UhdSc16Pipeline |
| --- | --- | --- |
| 规划者 | 自相关捕获、目标锁定、timed replay | 已知 t0/周期 |
| 缓冲 | 历史环，保留多个待装配候选 | 按单调窗口释放的连续缓冲 |
| 分发 | 共享有界任务池与 pending 队列 | 各 worker 独立 SPSC 池 |
| DSP | PacketProcessor：解调与 auto CIR 重试 | SIC / sensing CIR |
| 反馈 | 完成即推 TargetObservation；RX 线程应用 | 结果按 window_id 顺序提交 |
| 完成输出 | Reporter 有界输出队列 | results_ 留存与有序回调 |

`apps/uwb_live_packet_processor.h` 负责单包计算；它不持有队列、Reporter 或
TargetLockCore。PacketRequest 保存 id/slot/generation 和 native/window-relative
work 坐标；纯函数 make_target_observation 生成反馈，worker 负责推送，RX owner
负责应用。profile 选择仍由 worker 的目标/采集策略决定。

两套运行时共用 `uwb_resample_window.h`：独立窗口 reset、SC16 缩放、重采样和尾部
flush；支持两套已有 65/48 与 65/32 core。每 worker 私有 resampler/output，
预分配容量足够时没有新增缓冲分配。队列选择不属于该 helper。

控制反馈不经过顺序输出通道。假设前一个包走慢速重试，后一个包已完成，不能为了
日志有序而延迟后者参与锁定。pipeline 原来的顺序提交合同则保持不变。

停止时停止 source，然后排空已接纳任务与观察。不得把 requested-stop 直接当作
所有 worker 的退出条件，也不得把 planned timed gap 当作连续采样中的意外 gap。
两套运行时的这些合同继续由既有 QA 验证。

## 解调循环与共用原语

原生 live 从 SC16 延迟自相关或锁定预测取得候选，截取原生样率窗口。worker 经 65/48
重采样后进入 `demodulate_one`。包内先找 SYNC 峰并拟合符号周期，再估计 CFO、定位
并复核 SFD。随后用对齐的 SYNC 估计 CIR；完整帧继续生成 soft chips，或在整数网格上
融合 CIR 匹配滤波和 PHR/payload 解扩频，最后执行信道解码和 FCS 校验。

| 审查位置 | 共用实现和调用约定 |
| --- | --- |
| 波形检测、SYNC 定时、SFD、radar 精定位 | `uwb_matched_filter.h` 提供逐项累加与 VOLK 共轭点积、功率和归一化平方度量。粗检测的幅度分数及 detector 对平方度量的截断由各自调用者处理。 |
| 普通局部定时、折叠捕获、折叠锚点、锁定网格 | `uwb_rx_matched_filter.h` 根据模板选择实数、复数或稀疏点积。调用者给定合法起点数，扫描按起点升序，分数相等时取较早的峰。普通定时的初始功率采用八累加器，折叠采用原标量计算。 |
| 波形 SFD、CIR | SFD 的快路复用八点批处理及尾部单点点积，分母仍取未折叠的整段 SFD 功率。CIR 复用有序的稀疏单点点积和模板缓存，分母是码能量。稀疏 AVX2 批路径分别累加正负项，不能用批路径替换 CIR 的有序单点累加。 |
| 周期和 CFO 估计 | `uwb_linear_fit.h` 共用最小二乘计算。定时按 SYNC 索引拟合峰的末样点，再换算到首样点。CFO 按相对秒数拟合展开的相位，各自检查退化门限。 |
| CIR 匹配滤波、soft-chip 前缀和扩展 | `uwb_cir_fir_simd.h` 共用整数与分数网格的窗口边缘点积。`uwb_rx_softchip_opt.h` 共用相位投影、限长和 chip 预算。整数网格、分数网格插值、RAKE、bypass 与融合分别使用各自的滤波核和坐标。 |
| BPM 判决、CL-3、RS 和 FCS | `uwb_rx_bpm.h` 共用四候选的硬判决和 LLR。`uwb_hrp_codec.h` 共用 TX/RX 扰码、CL-3 转移和 RS 符号转换。`uwb_demod_fec.h` 共用硬软 Viterbi 的常规回溯、RS 缩短块展开、纠错复验及 PSDU/FCS 装配。救援路径还要保存次优路径和擦除位置。 |
| live、固定周期运行时和离线工具 | `uwb_resample_window.h` 提供独立窗口的重置、SC16 缩放、重采样和尾部 flush。解码、失败窗诊断与预处理导出使用同一函数。 |

另有几类计算承担不同的输入或边界契约。SC16 自相关用信号自身的延迟副本找候选，
Q15 验证用整数累加，NS-SFD 在 chip 域使用有符号幅度和自己的分母。雷达把搜索限制在
已知发送时刻的窗口内，通信 SFD 还可回退符号偏移和低 SNR 网格。融合模板使用预共轭
的 CIR 和 PN，在工作采样率直接做四候选点积。SIC 保有按模型筛选样点的 LS 与撤销
安全门。MATLAB 和 QA 中的独立公式仍可用于检查生产实现。

### 2026-11-19 重构验证

- 基线取 `8a9c7b2` 加开始工作时已有的 Sensing 工作树改动。回放使用 Ryzen 7 9700X、
  GCC 11.4、Release、AVX2/FMA、UHD OFF，两侧都清除 `LD_LIBRARY_PATH`。
- AVX2 全套串行复测 56/56，含独立安装消费者。与其他 ISA 测试同机运行时，单音
  source 用例曾丢样，单项及全套串行复测通过。SCALAR 与 AVX-512 各通过 7 项
  解调、调制、融合、CFO 和重构相关 CTest。
- 用 `tools/rx/low_snr_eval/fixed_scenarios.py` 生成六组各 40 个固定窗口，载荷种子为
  1729、2718，噪声种子为 11729、12718。逐包核对成功且载荷正确的帧数依次为
  40、38、40、37、38、37，两侧一致。条件包含 −12 dB、+10/+40 kHz CFO 和 +27 ppm SFO。
  用稠密、稀疏融合、稀疏 CIR-only 和稀疏锁定四种配置对比共 960 条逐包记录。
  SYNC 峰样点、SFD 首尾样点、周期、CFO、CIR 复数 taps 及可用的 PSDU/FCS 均一致。
- 原生 live 使用 200 帧、−12 dB、1 ms、种子 1、`eq16/full/fused`、tone off、1 worker、
  队列 256。SC16 的 SHA-256 为
  `6b8e14cc2b4666bd364addf49d92503edddc94524d9c13236e2c7377aa2f46ad`。
  串行 ABBA 并交换顺序复跑，四次基线为 189–191/200 FCS，四次重构版为 190–191/200。
  各次均进锁一次，队列和原始样点丢弃均为 0。两轮的批次解调均值中位数分别从
  596.2 到 598.0 µs、从 582.5 到 613.4 µs，两轮实际提交的窗口受反馈时序影响。
- 从对照日志提取两组各 194 条实际目标窗请求，在相同原生起点、窗长和锁定 profile 下
  交叉回放，388 条记录逐包一致。对两组中的各 192 个短目标窗做串行 ABBA，
  `stage_total_us` 的窗口均值中位数分别从 578.2 到 592.1 µs、从 597.9 到 616.0 µs，
  重构版增加约 2.4% 和 3.0%。
- 稠密 MATLAB golden 的样点、CIR 和解码用例随现有 QA 验证。当前证据来自软件和文件
  回放，新一轮 MATLAB 逐包对比、稀疏群延迟及 CIR-only 对照、UHD 上板仍待验证。

## 后续演进边界

后续各批的实施顺序、解调等价性验收与性能回退条件见[原生接收与解调重构执行方案](原生接收与解调重构执行方案.md)。

本轮没有合并两种队列拓扑。若进一步抽取公共执行器，先建立共同任务/终态协议和
确定性完成事件测试，再比较共享队列与 SPSC 的分发成本和反馈延迟。
pipeline 的长期结果留存、顺序回调持锁与乱序缓冲上限仍是独立待办；本轮保留行为。
编译拆分也不代表吞吐自动提高，测试记录以本次重构报告为准。
