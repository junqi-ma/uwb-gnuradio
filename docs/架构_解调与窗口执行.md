# 解调与窗口执行的代码边界

更新：2026-11-17。原生 core/native 与可选 GR adapter 的构建方式见
[使用说明](原生接收与GNU_Radio构建使用说明.md)。

## 解调依赖

| 文件 | 职责 |
| --- | --- |
| `uwb_hrp_codec.h` | TX/RX 共用 CRC、GF、SECDED、spreading；只依赖标准库 |
| `uwb_hrp_mod_core.h` | TX 调制；不包含接收流水线 |
| `uwb_demod_pipeline.h` | 完整包接口及 worker scratch 定义入口，链接 uwb_core |
| `uwb_demod_core.h` | 兼容聚合头，提供全部单阶段 API，主要用于 QA/实验 |
| `uwb_demod_grid.h` / `uwb_demod_execution.h` | 网格物理约束、一次包准入及有效 profile |
| `uwb_demod_sync.h` / `timing.h` / `cfo.h` / `sfd.h` | 同步公共计算与各阶段实现 |
| `uwb_demod_softchips.h` | CIR / soft-chip，包括分数网格和按需生成 |
| `uwb_demod_fec.h` | Viterbi、RS、软判决与救援；RX detail 兼容 codec 别名 |
| `uwb_demod_phr.h` / `payload.h` | NS-SFD、PHR 与 payload 阶段 |
| `uwb_demod_finalize.h` | 所有退出路径的子计时发布和既有坐标 rebase |
| `lib/uwb_demod_pipeline.cc` | 包内阶段编排、CFO 重估、前缀/融合/回退选择 |

表中省略前缀的阶段头均在 `gr-uwb/include/gnuradio/uwb/`。
阶段头可独立包含；生产完整包消费者不必解析全部阶段实现。
`demodulate_one` 从 header-only 改为库内实现，外部 native 消费者需重新链接
`uwb::uwb_core`（或传递链接它的 `uwb::uwb_native`）。单独包含头不再提供完整入口定义。

## 状态与坐标

一个 `DemodScratch` 只属于一个 worker，不跨 worker 共享；保留已有字段与容量。

| 生命周期 | 内容 | 初始化责任 |
| --- | --- | --- |
| 跨包模板缓存 | cached_seq、SFD/SYNC 模板、PN | 各缓存按 code/mode/template 键更新 |
| 包内决策 | fused_phr 的 g0/g1/LLR、decisions_valid | 入口统一 begin_packet；每次完整重试也调用 |
| 阶段状态 | softchip prepared/generated/phase、initial_timing | 所属阶段按原顺序重置，不在入口扩大清理 |
| 工作区 | work/corr/derotated/soft_chips 等 | reserve 保留容量，各阶段按有效范围读写 |

为了保留 source compatibility，本轮没有把这些字段改成新的嵌套布局。
`corr` 会被 CIR 重用；已经生成的 soft-chip 前缀使用独立 `softchip_corr` 保存。
不能因为两个数组都是 complex vector 就合并。

完整包入口接收 work 速率的绝对 predicted_start/window_start，内部阶段使用
窗口相对样点。finalize 在每条退出路径调用一次，转换原来约定的 timing/CFO/SFD/CIR
样点字段；chip 索引和其他局部诊断字段保持既有语义。单阶段 API 不自行 rebase。
不要将所有 int64 字段一概加上窗口起点。

PacketExecutionPlan 统一决定整数网格准入与 Full→Bypass 的有效 profile；
旋转范围、前缀长度和融合选择必须共同服从该决策。不是新增可独立调节的三个开关。

## 窗口与调度

两种策略保留不同的业务约束：

| 项目 | live | UhdSc16Pipeline |
| --- | --- | --- |
| 规划者 | 自相关捕获、目标锁定、timed replay | 已知 t0/周期 |
| 缓冲 | 历史环，保留多个待装配候选 | 按单调窗口释放的连续缓冲 |
| 分发 | 共享有界任务池与 pending 队列 | 各 worker 独立 SPSC 池 |
| DSP | PacketProcessor：解调与 auto CIR 重试 | SIC / sensing CIR |
| 反馈 | 完成即推 TargetObservation；RX 线程应用 | 结果按 window_id 顺序提交 |
| 完成输出 | Reporter 有界输出队列 | results_ 留存与有序回调 |

`apps/uwb_live_packet_processor.h` 负责单包计算；它不持有队列、Reporter 或
TargetLockCore。PacketRequest 保存 id/slot/generation 和 native/window-relative
work 坐标；纯函数 make_target_observation 生成反馈，worker 负责推送，RX owner
负责应用。profile 选择仍由 worker 的目标/采集策略决定。

两套运行时共用 `uwb_resample_window.h`：独立窗口 reset、SC16 缩放、重采样和尾部
flush；支持两套已有 65/48 与 65/32 core。每 worker 私有 resampler/output，
预分配容量足够时没有新增缓冲分配。队列选择不属于该 helper。

控制反馈不经过顺序输出通道。假设前一个包走慢速重试，后一个包已完成，不能为了
日志有序而延迟后者参与锁定。pipeline 原来的顺序提交合同则保持不变。

停止时停止 source，然后排空已接纳任务与观察。不得把 requested-stop 直接当作
所有 worker 的退出条件，也不得把 planned timed gap 当作连续采样中的意外 gap。
两套运行时的这些合同继续由既有 QA 验证。

## 后续演进边界

本轮没有合并两种队列拓扑。若进一步抽取公共执行器，先建立共同任务/终态协议和
确定性完成事件测试，再比较共享队列与 SPSC 的分发成本和反馈延迟。
pipeline 的长期结果留存、顺序回调持锁与乱序缓冲上限仍是独立待办；本轮保留行为。
编译拆分也不代表吞吐自动提高，测试记录以本次重构报告为准。
